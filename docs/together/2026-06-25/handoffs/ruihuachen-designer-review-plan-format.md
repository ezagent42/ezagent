## 要做什么
设计两个可外发版式（中文）：
1. **review 版式**：怎么排"昨日 PR 列表 / 暴露的问题 + 根因 / 改进建议"，按系统功能层面组织；明确**哪些是团队需要的、哪些是内部讨论不该外发的**。
2. **plan 版式**：怎么排"本周目标 / 各人 track（用完整 github 名）/ 依赖 / 协作约束 / off-plan 预算"，让一眼能看清谁今天做什么、依赖什么。

参考现状：`docs/together/2026-06-24/review.zh_cn.md`（外发版）、`docs/together/2026-06-25/plan.md`。指出它们版式上还能怎么更清晰/更好读。
