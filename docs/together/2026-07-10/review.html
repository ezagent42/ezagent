§方法增量（促进，不只收集）

三源：两份周末 return 的 Method-friction + kanban-rework-final + 窗口协作实况。每条给出规则映射 + 处置（skill 改动 vs process-debt）。

  1. D1 无 stack.md → 台账靠 PR 反推（process-debt，owner lead）：常态走直接-PR、returns 稀，stack.md 事实停用。→ 建议把 accounting 的"stack 计数"降为可选、把双源对账（returns/ ∪ GitHub 合并）升为必跑。
  2. D2 spec 源须绑完整 commit SHA，不绑"v5"/名字（skill 改动）：composition-cap spec 中途 v4→v5、HEAD 从中间 commit 更正。→ 写进 handoff-standard「Required-reading」——spec 引用 = 分支@完整SHA，返回核 tree 携带该文件。
  3. D3 "no core global flip" = LOCKED decision，须显式钉死（skill 改动）：0a(b) core 全局翻转被提出后又 descope；无 LOCKED 极易在 core 过度伸手。→ touches CapBAC/core 的 handoff 必列 "Locked decisions / must-not-do" 节。
  4. D4 phased-handoff target-branch 一次性审查 ≠ 默认机器闸（skill 改动）：无 PR 的 target-branch 返回，DoD PR-CI/rebase/canary 变为 lead-owned。→ return.md 认可此返回态：三项机器闸标 deferred(lead-owned)，不视违规、不得自宣 READY。
  5. D5 证据须带出处；"没重跑" ≠ 绿；agent 自述 gate-绿永不替代 PR-CI（skill 改动）：→ 扩"return 前看 PR CI 全绿"为"证据出处三条"——① 每条证据标 re-run/prior-run/read-only；② "gates green" 散文永不替代 PR-CI；③ 无 PR 时本地绿只作 local 证据、显式标 NOT remote CI。本窗口核心方法产出。
  6. D6 codex-rescue relay-break（process-debt）：codex 长任务会孤儿化 → 交有界可验证子步（两条车道正是切成 6/8 commits 才走通），relay 断即以 target-branch 现状对账。→ 写进 contributing/ codex 协作节。
卫生类：mix ci.local 会改写 pnpm-lock.yaml——return 前必还原 · default-SessionTemplate 并发 seed flake（隔离重跑绿）单列独立 CI-稳定债，不归因 composition-cap。
