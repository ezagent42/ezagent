C · 双层模式

返回总目录 · 这个方向把 Agent Console 分成两种界面：`工作台` 和 `控制台`。工作台给任务导向用户，控制台给高级用户和管理员。

第一屏：用户先选模式
工作台 | 控制台 | 模板 | 运营视图
工作台模式
  • 继续上次工作
  • 创建 Claude 助手
  • 加入 Session
  • 看待处理问题
控制台模式
  • 对象列表
  • 系统状态
  • 高级配置
  • 调试和日志
工作台页长什么样

更像 B 方向：

  • 按任务组织
  • 首页即动作入口
  • 弱化技术术语

适合 PM / 运营 / 一般内部同学。

控制台页长什么样

更像 A 方向：

  • 按对象组织
  • 强系统参数可见
  • 技术细节集中在这里

适合工程 / 管理员 / 高级用户。

它解决了什么

它试图同时满足两类诉求：

  • 普通用户不被复杂度淹没
  • 高级用户仍能直接进入系统底层

但代价是：产品会像两个界面并存，心智成本上升。

什么时候值得选它

当你明确知道 Agent Console 要服务两类差异很大的用户，而且两类都必须做得不错。

什么时候不该选它

当产品还在早期、信息架构还没稳定时，它很容易把复杂度翻倍。

优点

  • 兼顾任务导向和系统导向
  • 不同用户群都能找到适合自己的入口
  • 长期上限高

缺点

  • 实现和维护成本最高
  • 产品心智最容易变复杂
  • 如果切换关系没设计好，会让人迷路
