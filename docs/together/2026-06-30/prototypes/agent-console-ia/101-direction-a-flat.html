顶部标签：

  • 详情
  • caps
  • api-keys
  • extensions
  • terminal

重点是技术详情和系统状态，而不是下一步任务。

它适合谁

管理员、工程同学、已经熟悉 flavor / cwd / caps / template 的内部高级用户。

它的问题

PM/运营进来会先看到对象和参数，而不是“我要做什么”。

它为什么容易让人卡住

因为“创建 Claude 助手”和“邀请同事”在产品任务里很近，但在对象模型里是两件完全不同的事。

优点

  • 系统结构清晰
  • 实现成本相对低
  • 适合内部运维和调试

缺点

  • 不符合任务导向用户心智
  • 容易把高级参数提前暴露
  • 产品感弱，像管理后台
