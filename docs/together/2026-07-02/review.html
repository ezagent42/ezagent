§4 流程沉淀（method deltas）

MD-1（新规则 → dev-together PR）：落地大改名后，比它早切的分支合 main 前必须做旧符号 grep 门禁

大改名（T1：Behavior→ActionSet、config://→结构化 subject）落 main 后，任何比改名早切的分支即使自身 CI 绿，合 main 也会红 —— 它的 CI 跑在改名前的基线上，门禁那时还不存在。fork #1139 正是如此（→ #1141）。 要加到 close 的规则：合并任何 merge-base 落后于改名 commit 的分支前，对其新增行跑一遍改名 grep（git diff main...branch | grep '^+' | grep <旧符号>），要求 0 命中；非零则先 rebase+改名。本质是「对 rebase 后的 main 验门禁」，而不是「在过期基线上验」。

MD-2（流程债，owner=lead）：双工作流的一天要有一份 plan

当日 plan 只覆盖了 app-package 线，官网线跑在台账之外（§3）。规则「无空 plan / 清点所有任务」今天只落在 app-package 一条线上。0703 的 plan 要把两条线都登记（即使标注「携带、owner X、非关键路径」）。

MD-3（确认有效，保留）：前置对抗评审值回票价

码前 5 轮 codex 评审，把 500 文件改名做成了首次即净合。保留「SPEC/plan → codex 对抗评审 → 再实现」的规则。
