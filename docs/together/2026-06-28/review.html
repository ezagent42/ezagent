§2 周末开发效能（method deltas）

逐 PR / 任务效能与依赖

  • codex-handoff 自驱合约（沉淀为 memory → standing practice）：codex/subagent 自驱合并到唯一目标分支（base main），不开 PR、不合并 main，返回目标分支由 lead 验收+合并。lead 预置 goal + 分阶段 gate。用于 socialware P1-P10、#127、#1071、Q1-C。结论：大块实现分派的可控默认范式——monitor + stall 重派，commit-per-step + fresh re-dispatch 恢复了 3 次 transient API stall。
  • 大/险 PR 独立对抗评审（ROI 验证）：#1076 plugin-package 的独立 opus 评审抓出作者漏掉的 H-1 路径穿越安全洞（公开 /plugin-assets/ 端点可经恶意 manifest file 外泄 EZAGENT_HOME 凭据）。规则确立：任何触及 (a) 公开/未认证端点、(b) BEAM code-purge/unload、(c) 文件服务路径、(d) >300 行 core 机器的 PR，合入前必须独立 opus 评审。doc-only PR 跳过（开销不值）。
  • "known-flake" 不是免死金牌（纪律守住）：#1069 唯一的 CI 红是 PresenceReadReceipts——合入前先验证它在 main 也红（非回归）才放行。整周末 0 个 flake-masked regression 漏进 main（#108 深层 race 仍 in_progress，但未遮蔽任何真实回归）。
