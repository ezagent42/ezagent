§4 流程沉淀

新规则（process-debt，owner: lead）：任何对安全/授权不变量或数据迁移的改动，在考虑 enforce/flip 之前必须先过一次真 canary 数据的 E2E。 干净 fixture 上的绿单测是必要、非充分——6/196 的回填缺口只在真数据上才出现。（本可提前抓住“回填会签下全部”的过度乐观假设。）
强化规则（doc-why-must-be-code-verified / reproduce-before-benchmark）：先读代码再 spec 行为，不要把读代码外包给 reviewer。 entity-caps 的 spec 反复来自于未读代码就断言其行为；规则本已存在，这次的失手就是信号，止住循环的做法是停下来读代码、再重新收敛范围。
强化规则（subagent-worktree-wrong-repo）：从 scratchpad worktree push/PR 前，先核对 git remote -v。 cbac spec 在一个 cc-openclaw worktree 里撰写，差点 PR 到错误的仓库（靠“所有 sibling spec 都在 esr-ng”兜住）。
确认有效的做法：经验性差分测试（re-issue → 审计未签名 = 找出绕过路径）胜过纯代码审计，已折入 cap-signing 调查 handoff。
