方法沉淀
• ★ authz 正确性必须结构化, 不能靠纪律: 错的 cap / 错的 subject / 错的 boundary 必须让该 ActionSet 根本无法构造, 而不是依赖一处「记得检查」—— C8 use 侧 codex 复评审据此把 signing-oracle + publish-authz(绑 worker 非 session-current)判为 CRITICAL, 早前的 SOUND 结论被复评审取代。教训: 「对抗性评审 SOUND」是一次结论不是终判, 结构没封死前不能当验收。
• ezagent_actor = core 与 domain 共同依赖的运行时地基(钻石依赖, 非线性 domain→core→actor): dep-boundary allowlist 据此放行 :ezagent_actor 为 foundation dep(#1595), 清掉 #1579 抽取遗留的 2 处 #189 arch 红 —— 抽取制造的 arch 红要靠「承认真实依赖形状」解, 不是靠反向依赖。
• domain_git URI-解耦取 option A: 通用 git 设施存完整 task_uri, 不引入 task_kind 参数 —— 设施只认 task URI 不认 Kind(#1588), Kind 语义不泄漏进 git 层。
• owner-gate facade 保留 (uri, pid) 签名(registries 是 plugin-local, codex 提的 registry-resolve 不可行): 10 处 owner-bypass 收敛到 OwnerGatedExecutor/OwnerGatedWorkspace facade 债清零(#1593), 残余「AST-scan 任意 GenServer receiver + gate Kind.spawn」落 follow-up issue #1592。
• ★ actor 抽取结构篇(C0–C7)全部塌进 main(#1579 收口): actor runtime 经 ports 物理迁入 apps/ezagent_actor, 边界靠 gate 强制而非口头约定 —— 结构隔离走完「抽取」半程, 剩「寻址/写路封口」(C8)。
• C8 定式为「delete-the-holes」pid-纪律(#200 决策): Kind 只经 URI 寻址(obtain 侧)、写只经 sealed %Signal{}、读只经 SliceChange(use 侧) —— 删掉裸 pid 通路本身, 而非在通路上加检查; obtain 侧以可复算闸值收口(genserver_to_pid=0 · domain-lookup gate=0)。
• #189 从「系统性红」根因化为 2 真 bug(① #201 credential-path race · ② ExternalMirror #189-B authz)+ 4 测试缺陷 —— 修病因不修症状; #1577 落地 2 因后 flavor-store 面在更广目录暴露回归 → 当日 #1578 回退恢复 store-before-instantiate。教训重申: store 时序/语义改动须验证全部消费方目录。
