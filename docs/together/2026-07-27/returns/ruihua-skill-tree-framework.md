## 2. 提案：技能/经验分离框架

**一句话：计数只能证明活跃，不能证明水平。技能树只吃质量被认证过的信号；计数全部降为经验条。**

| | 技能（水平） | 经验（交付成功的计数） |
|---|---|---|
| 定义 | 这个人/这家公司**能做到什么水平** | 这个人/这家公司**做过多少次** |
| 衡量 | 课程学分 / 资格认证 / 竞赛评级（质量被第三方认证的信号） | 订单数 / 打工次数 / 作品数 / 人脉数 / 复盘数（只能计数，难以衡量品质） |
| 表现 | **成长树节点解锁** | **进度条展示**，派生信用与声望，不解锁树 |
| 举例 | 「接了 20 单的美工」设计水平可能仍很差；「从未接单的专业设计师」水平可以很高——水平不由接单记录证明 | 20 单证明的是活跃与履约历史 → 信用、声望、Scouting 信号 |

**配套规则：**

1. **安全阀（干中学不归零）**：质量被认证的交付可折算技能——真单评级 A 级以上、且环节由本人亲自交付 → 计入学分认可。计数本身永不直接解锁技能
2. **公司页与个人页同构**：两个页面都是「上半经验条 + 下半技能树」。技能/经验的区分不依赖公司/个人的区分——每家公司和每个人都有这两套度量
3. **多树结构（已订 D35）**：主干树（企业经营）+ 资质树（N-12 教练 / N-13 孵化 / N-14 平台运营，认证节点同节点兼作树根）+ 个人技能树
4. **学分代理（已订 D40，demo 临时）**：练习单重新定义为「课程作业」，加质量门（班内竞赛排名前 50% 才计学分）——这是学校教务系统数据的简化模拟，未来接真实教务数据
5. **Agent 成长归属（已订 D39）**：Agent 的成长属于其所有者实体（公司资产），不算个人成长；Agent 不设成长树，progression 用能力分 + 资产清单 + 里程碑徽章表达

**支持论据（引用 v0.13 已有决策，无需新批）**：

- D7（「亲自干质量高」已废除）——本提案是 D7 的延伸：亲自干连技能都不必然涨
- D15（真实对抗）——计数解锁技能树 = 鼓励刷量
- D2 / §5.2——Agent 能力分 = 训练资产 + 实战**评价**史，Agent 早就是质量信号驱动；本提案让人与公司遵循同一标准
- §1 高概念——「我在成长（判断力、信用、人脉）」本就未列「专业技能」，与 §5.4 相比，本提案更贴合原始幻想

## 4. 顺带确认：GDD v0.14 开放问题 #12（D34）的倾向回答

**问题**：企业科技树是否 = 所有成员（含 Agent）个人科技树的并集？
**我的倾向：否。** 理由：Agent 是公司资产（D19，可出售/转让）——若企业树 = 成员树并集，则买卖 Agent 等于买卖树上的能力，撞 D17（金钱买不到能力）；且个人树的积累会失去独特性。已记为 D39（成长归属 = 资产归属）。
