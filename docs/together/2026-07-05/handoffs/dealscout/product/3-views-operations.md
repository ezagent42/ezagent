# dealscout 产品文档 3：视图与操作（V 层）

> **一句话**：把用户旅程（J 层）落成 **9 个能看能点的界面**，按**两条腿**组织——**发现腿（地基·找）**：千人千面发现流、单条深挖追问、配置面板、主动搜索面板、下载区；**撮合腿（亮点·涌现）**：公开机会页、公开面聊天、founder 身份看板、invite 深聊面。撮合机制不是"申请加入你的 session + owner 审核 pending"，而是 **hello 公开面聊天**——DealScout 组合 hello 拿到公开面 + concierge 客服 agent；**登录用户**在公开面**自助 join、发消息供线索**，非 owner member 永远路由到 concierge 客服（`router.ex:13-14` 结构性规定，访客到不了 builder、不为访客发 LLM 调用）；**匿名只读**看渲染好的公开快照、不能写；**founder 本人**在同一 session **全量白板互见**、看到发言者身份，想深聊就**主动 invite** 对上的人进私有 session。
>
> **追溯**：本文是编号树的 **V 层**，每个视图锚点 `↑` 指向 `../README.md §3.3` 的某个 J 阶段（发现腿 J-1..J-5 + 撮合腿 J-6..J-9）；本文的下游是 `product/4-features.md` 的 F 功能点（F-x `↑` V-x）。**严格单亲树**：每个视图恰一个 J 父、每个子元素恰一个 `↑`（同层视图锚点或对应 J 步）——2026-07-05 找为主重构后**需求/供给降级为贯穿颜色属性**，不再有多父弥合节点（弥合概念保留、交汇内化进撮合腿，见 `../README.md §3.8`）。编号规则见 `../README.md §3.1`：`V-层.序`，V-n 是视图锚点，V-n.1/V-n.2… 是该视图的具体元素/操作。
>
> **颜色属性（非层，贯穿标注）**：🔵 需求（founder 找钱）/ 🟢 供给（investor 找项目）是标在节点上的**贯穿颜色**，标注"这个视图两类用户怎么对称地走"，**不参与父子结构**。两类用户都是"找机会的人"，对称地用同一批视图。
>
> **技术底（产品视角，一句话）**：发现流视图不是独立网页，而是一个**嵌进对话的 session tab**——走 `Definition.views` 管线拉 dealscout plugin 的 `DealScoutRender`（照 `hello_render.ex:29`）+ SessionView（照 `page_view.ex`）渲染。**组合**靠多个 Definition 的 `installs` merge（`definition_editor.ex:63` `config_for_template`）+ 单个 Definition 内 `bases`/`shape`/`views` union（`definition.ex:124` `behaviors/1`）拿到 hello 的公开面 + concierge；`uses` 只是声明"依赖 hello 这个 plugin 已装"（`manifest_resolver.ex:41` `ensure_plugins_installed`），**不是组合轴**。发布 = **今天仿 hello code-seed**（写 config map + boot 经真 governance publish；未来 registry P3 从外部 config 源发布、不写 Elixir）。公开面上不上匿名靠 Definition 的 `visibility_policy.web_anon_access`、**发布者自助即可**（`admin` 只管全域——只有 `scope: :public` 跨 workspace 发现才要 admin，`socialware.ex:197` `authorize_public_scope` → `:228` `authorize_admin`）；真正"上不上公网"靠**域名分配（infra 层）**、合规是外部审批、平台不背。发布后匿名/他人打开公开机会页看流、跟 concierge 聊；登录用户还能自助 join 发言。撮合腿直接 riding hello 公开面聊天——公开面 + concierge 客服（`hello_orchestrator.ex` off 到 `EzagentPluginHello.Router`；`router.ex:13-14` 非 owner member → 永远 concierge）+ 登录自助 join/post（`session_feed_channel.ex:197-228`）+ founder 全量白板互见（`external_feed.ex:85-98`）+ founder invite 深聊（`conversation_actions.ex:683`），不再是缺口。

# 发现腿视图（地基·找）

## V-1 · 发现流视图（千人千面机会列表·session tab） ↑J-2

**这是 dealscout 的主界面**。用户在自己的对话里多出一个 tab，点开就是一张张**机会卡片**——不只是"最新爬回来的一堆信息"，而是 **AI 副驾按你的 profile 千人千面主动挑出、按匹配度排好**的机会流。它长得像一个"给你一个人定制的投融资/商机墙"，嵌在 chat 里，不用跳出去。

🔵 需求方（founder）看到的是"匹配我在找的钱/路演/商机"的线索；🟢 供给方（investor）看到的是"匹配我在找的项目/标的"的线索——**同一个视图，副驾按各自 profile 推不同的内容**。

**文字版布局示意**：

```
┌─ [对话] [发现流] ← tab 切换 ─────────────────┐
│  🔄 上次爬取 10:32   [手动刷新]  🤖 副驾已按你的 profile 挑选 │
│ ┌───────────────────────────────────────┐ │
│ │ 🔵需求 · 🏷投融资 · 匹配度 ●●●●○ · 2h 前 │ │
│ │ 某 AI 公司完成 A 轮 2000 万美元融资      │ │
│ │ 来源：36氪 · 副驾：跟你找的出海赛道对得上 │ │
│ │                          →点开深挖       │ │
│ └───────────────────────────────────────┘ │
│ ┌───────────────────────────────────────┐ │
│ │ 🟢供给 · 🏷路演 · 匹配度 ●●●○○ · 5h 前   │ │
│ │ XX 加速器开放 Demo Day 报名             │ │
│ │ 来源：官网 · 副驾：符合你找早期标的的偏好 │ │
│ └───────────────────────────────────────┘ │
│              … 继续下滑 …                   │
└─────────────────────────────────────────────┘
```

- **V-1.1 千人千面卡片列表（副驾主动挑、按匹配度排）** ↑V-1
  主体是一列机会卡片，但排序不是纯时间倒序——**副驾按你的 profile 打匹配度、把最对得上的顶上来**（对应功能 F-2 AI 主动发现）。用户一眼扫过去就知道"副驾今天替我挑出了哪些跟我最相关的机会"。滚动加载更多。

- **V-1.2 每张卡片的要素：标题 + 来源 + 时间 + 匹配度 + 需求/供给颜色标** ↑V-1
  - 需求/供给颜色标（🔵/🟢）：一眼看出这条是"找钱线索"还是"找项目线索"；
  - 来源标签（🏷 投融资 / 路演 / 商机…）：一眼分类；
  - 时间（"2h 前"）：知道新旧；
  - 匹配度（●●●●○）：**副驾按 profile 打的分**，帮用户判断值不值得点；
  - 标题 + 一句"副驾为什么推它"：不点开也能读个大概。

- **V-1.3 点开单条 → 进详情追问** ↑V-2
  点卡片上的"→点开深挖"（或整卡片可点），跳到 V-2 单条机会详情 + 追问。这是从"扫机会"到"挖一条"的动作入口。

- **V-1.4 手动刷新 / 爬取状态条** ↑V-1
  顶部有一条状态："上次爬取 10:32" + 一个"手动刷新"按钮。定时爬取之外，用户想立刻抓一轮就点这里（对应功能 F-1 的手动触发）。

- **V-1.5 最近 N 次爬取 + pin 标记的展示** ↑V-1
  发现流只展示**最近 N 次爬取**的批次（默认最近 10 次 / 1 个月，取先到者——见 F-1 数据保留），超期未 pin 的批次会被保留 sweeper 回收、不再出现。被 **pin 的批次带一个 📌 标记长期留存**，即使超期也不被清。pin 动作本身是配置层、成员限定（见 V-3.6）。

## V-2 · 单条机会详情 + 追问 ↑J-4

从发现流点开一条后进到这里。上半是这条机会的原文与摘要，下半是一个**多轮对话区**——用户可以像聊天一样对着这一条反复追问、越问越深，把一条机会挖透。

🔵 需求方在这里挖"这家投资方偏好、怎么接触"；🟢 供给方在这里挖"这个项目团队背景、值不值得投"——**同一个追问界面，两类用户对称地深挖**。

**文字版布局示意**：

```
┌─ ← 返回发现流 ───────────────────────────────┐
│ 某 AI 公司完成 A 轮 2000 万美元融资           │
│ 来源：36氪 · 2h 前 · [查看原文链接]           │
│ ─── 摘要 ─────────────────────────────────  │
│ · 投资方：XX 资本领投                          │
│ · 赛道：企业级 AI                             │
│ ─── 追问 ─────────────────────────────────  │
│ 你：这家的创始团队背景？                       │
│ agent：创始人来自…（多轮上下文记住这条源）      │
│ 你：有联系方式或 BD 入口吗？                    │
│ agent：…                                     │
│ ┌─────────────────────────────┐ [发送]      │
│ │ 继续追问…                     │             │
│ └─────────────────────────────┘             │
└─────────────────────────────────────────────┘
```

- **V-2.1 原文 + 摘要区** ↑V-2
  顶部固定展示这条机会：标题、来源、时间、原文链接，以及 agent 生成的结构化摘要（投资方/赛道/金额等）。用户不点原文也能快速了解。

- **V-2.2 追问输入框** ↑J-4
  底部一个输入框 + 发送按钮，对着这一条源提问。追问 = 对同一 agent 连发消息，agent 带着这条源的上下文回答（对应功能 F-6 多轮追问 agent，走 cc/cc-headless）。

- **V-2.3 多轮对话区** ↑V-2
  输入框上方是问答历史，一问一答往下叠。多轮上下文保留（agent 记得前面问过什么、这条源是什么），支持"越挖越深"而不用每次重述背景。

- **V-2.4 返回发现流** ↑V-1
  顶部"← 返回发现流"回到 V-1，继续挖下一条。追问过的卡片在发现流里可标记为"已深挖"（可选）。

## V-3 · 配置面板（profile + 关键词 / 源 / token + 爬取触发） ↑J-1

用户第一次用、或想调整探查范围时进这里。设定"我是谁（profile，副驾靠它做千人千面）、我关心什么关键词、抓哪些源、需要登录的源怎么给凭证、爬取怎么触发"。是整个 app 的起点配置。

🔵 需求方填"我是找早期 AI 融资的 founder"；🟢 供给方填"我是找出海 AI 标的的投资人"——**同一个 profile 底座，副驾按它给两类用户各自千人千面**。

**文字版布局示意**：

```
┌─ 配置 ──────────────────────────────────────┐
│ 我的 profile   ┌───────────────────────────┐ │
│（副驾靠它匹配） │ 我是做企业级 AI 的 founder， │ │
│               │ 在找早期融资和出海路演机会…  │ │
│               └───────────────────────────┘ │
│ 关键词        [企业级 AI] [出海]  [+ 添加]    │
│ 抓取源        ☑ HackerNews  ☑ 36氪         │
│               ☐ 某需登录源  → [配置 token]   │
│ 访问凭证      [+ 添加 access token]           │
│               已配置：xx源 ****（已保存）      │
│ 爬取触发      定时 ☑ 每日 09:00   [立即爬一轮] │
│                                  [保存配置]   │
└─────────────────────────────────────────────┘
```

- **V-3.1 profile 编辑（千人千面的底座）** ↑J-1
  一段自然语言 profile 告诉副驾"我是谁、在找什么类型的机会"。这是 **AI 主动发现（V-1.1 / F-2）的底座**——副驾拿 profile 给每个人挑不同的机会。**配置层动作、成员限定、群聊提交**——改 profile 改的是 DealScout 本身的定义，只有持配置 cap 的房间成员能做（认证 = session 成员身份，见 `../model.md`）。

- **V-3.2 关键词 + 情报描述输入** ↑V-3
  填关键词（可加多个 tag）+ 一段描述，比关键词更能表达意图，agent/副驾拿它判断相关度。对应功能 F-4。**配置层动作、成员限定、群聊提交**（同 V-3.1）。

- **V-3.3 源选择** ↑V-3
  勾选要抓的源（公开源直接勾；需登录源勾了会提示配 token）。控制探查范围。**配置层动作、成员限定、群聊提交**。

- **V-3.4 token 配置入口** ↑V-3
  "+ 添加 access token"：给需要登录才能看的源填凭证，让 agent 能代替用户访问（存储照 kanban `write_creds` idiom，`github.ex:32-54`）。填过的显示"已保存"（值打码不回显）。对应功能 F-4。**配置层动作、成员限定**——匿名/房外人不可见、不可改。

- **V-3.5 爬取触发（定时开关 + 立即爬一轮）** ↑V-3
  设定时爬取节奏（定时兜底），也能点"立即爬一轮"手动触发（对应 F-1）。这里的手动触发和 V-1.4 的"手动刷新"是同一条链路的两个入口。

- **V-3.6 pin 保留某次爬取** ↑V-3
  在发现流（V-1.5）里把某一次爬取批次 **pin 住长期保存**，让它不被数据保留 sweeper 按"最近 N 次 / 1 月"回收（保留策略见 F-1）。pin/取消 pin 是**配置层动作、成员限定、群聊提交**——只有配置成员能钉。

- **V-3.7 保存配置** ↑V-3
  保存后配置生效，下一轮爬取/发现（定时或手动）按新 profile/关键词/源/凭证跑。

## V-4 · 搜索面板（新） ↑J-3

**这是发现腿的"主动"那一半**：V-1 是副驾**替你推**（被动收），V-4 是你**主动搜**——手里有个明确的东西想找（"最近有没有投出海 AI 的早期基金"），直接敲一条 query，让 agent 现场去全网/指定源搜一轮，把结果拉回来。对应功能 F-3 主动搜索。

🔵 需求方搜"投我这个赛道的基金"；🟢 供给方搜"某某方向的早期项目"——**同一个搜索框，两类用户对称地主动找**。

**文字版布局示意**：

```
┌─ 主动搜索 ──────────────────────────────────┐
│ ┌───────────────────────────────────────┐ │
│ │ 搜：最近有没有投早期出海 AI 的基金？      │ │ ← 关键词 or 自然语言
│ └───────────────────────────────────────┘ │
│ 搜索范围  ( ) 全网   (•) 指定源：☑36氪 ☑HN   │
│                                   [ 搜一下 ] │
│ ─── 结果 ─────────────────────────────────  │
│ ┌───────────────────────────────────────┐ │
│ │ 🟢供给 · XX 资本新设 5 亿出海 AI 基金     │ │
│ │ 来源：投中网 · [深挖] [加入发现流]        │ │
│ └───────────────────────────────────────┘ │
│              … 更多结果 …                    │
└─────────────────────────────────────────────┘
```

- **V-4.1 搜索输入框（关键词 + 自然语言 query）** ↑J-3
  一个搜索框，既能敲关键词，也能用大白话问一句（"最近有没有投出海 AI 的早期基金"）。agent（cc-headless）拿这条 query 现场去搜（对应 F-3）。这是**主动找**，不等定时爬取。

- **V-4.2 搜索范围选择（全网 / 指定源）** ↑V-4
  选"全网"广撒，或勾"指定源"（复用 V-3.3 配的源）精准搜。控制这一轮主动搜索的覆盖面。

- **V-4.3 搜索结果列表（可转追问 / 加入发现流）** ↑V-4
  搜回来的结果排成一列，跟发现流卡片同构（带需求/供给颜色标）。每条能直接"[深挖]"（进 V-2 追问）或"[加入发现流]"（把好结果固化进 V-1 的流里长期留存）。主动搜的结果不孤立，能接回发现腿的其余环节。

## V-5 · artifact / 下载区 ↑J-5

追问深挖之后，agent 能把结论整理成一份可下载的材料（outreach 邮件模板、项目速览、素材包等）。这个区块列出这些产出，一键下载。

🔵 需求方下载"给投资方的 outreach 材料"；🟢 供给方下载"某项目速览/尽调预备"——**同一个下载区，两类用户对称地把成果攒下来**。

**文字版布局示意**：

```
┌─ 产出材料 ──────────────────────────────────┐
│ 由追问生成的可下载材料：                       │
│ ┌───────────────────────────────────────┐ │
│ │ 📄 XX公司-outreach邮件模板.md   [下载]   │ │
│ │    来自：某 AI 公司 A 轮 · 10:45          │ │
│ ├───────────────────────────────────────┤ │
│ │ 📄 出海赛道-项目速览.pdf        [下载]   │ │
│ │    来自：多条汇总 · 昨天                   │ │
│ └───────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

- **V-5.1 生成的材料列表** ↑J-5
  列出 agent 追问后产出的每份 artifact：文件名、类型图标、来自哪条源/哪次追问、生成时间。让用户知道"我挖出来的东西攒了哪些"。

- **V-5.2 下载按钮** ↑V-5
  每份材料一个"下载"。点了走平台的下载令牌链路（限时、类型锁），拿到文件。对应功能 F-7。产出 → upload seam 是**协调项**（agent-facing upload 是 core seam，见 `../README.md §4`）。

- **V-5.3 材料来源回链** ↑V-2
  每份材料标注"来自：某条源/某次追问"，可点回到 V-2 对应的追问上下文，看它是怎么被挖出来的。

# 撮合腿视图（亮点·涌现）

> **撮合腿是交汇点**（弥合概念保留，`../README.md §3.8`）：需求/供给降级成颜色属性后，**同一批撮合视图两类用户对称地走**——一方公开机会页（V-6）、双方公开面聊天（V-7）、founder 身份看板（V-8）、founder invite 深聊（V-9），角色可互换。
>
> **本版换轨（撮合腿机制彻底换）**：旧玩法"别人 `#1178` 申请加入你的私有 session → 落 pending 私密 → owner 审核 approve_admission → 聊聊看"是过度设计，DealScout 用不上（`#1178` 是 agent 门、防偷用别人 agent 刷凭证）。新玩法 = **hello 公开面聊天**：DealScout **组合 hello** 拿到公开面 + **concierge 客服 agent**（`hello_orchestrator.ex` 手 off 到 `EzagentPluginHello.Router`；`router.ex:13-14` 结构性规定"非 owner member → 永远 concierge"，访客到不了 builder、不为访客发 LLM 调用）。**登录用户**在公开面**自助 join + 发消息**（`session_feed_channel.ex:197-228` `handle_participatory_join`/`handle_participatory_post`；post 走 `dispatch_post` 带 `mentions:[orchestrator_uri]` → 非 owner 永远路由 concierge 回帖；成员 cap 授予见 `membership.ex:1200-1208` `member_cap_actions`，confirmed 用户才拿 chat actions）——**能聊、能供线索**。**匿名只读不能写**：`session_feed_channel.ex:325-330` `signed_in_principal` 对 anon（`AnonUser.anon_uri?`）返回 nil → join/post 都 `not_logged_in`（两处硬禁），匿名只看渲染好的公开快照。**founder 本人**在同一 session **全量白板互见**（`external_feed.ex:85-98` `chat_messages` = FULL collaborative chat、shared whiteboard，每个 viewer 看到所有参与者消息、每条驱动一次 hello 页编辑），看到发言者身份（`session_feed_channel.ex:353` `principal_name`、登录者显示 `logged_in:true` + name），想深聊就 **owner 主动 invite** 对上的人进私有 session（`conversation_actions.ex:683` `invite_member`，`:join` 需 live member Kind）——**是 owner 主动拉、不是申请人申请**。代码底座：`apps/ezagent_plugin_hello/`（公开面 + concierge） + `apps/ezagent_web/.../session_feed_channel.ex`（登录自助 join/post、匿名硬禁） + `apps/ezagent_domain_world/lib/.../conversation_actions.ex:683`（owner invite）。

## V-6 · 公开机会页视图（组合 hello 拿到的公开面） ↑J-6

🔵🟢 两类用户都可能是 founder/owner——身份看板对称：founder 看"来发言的投资人"、investor 看"来发言的 founder"，**同一个身份看板**。

## V-9 · invite 深聊面（owner 主动拉进私有 session） ↑J-9

founder 在身份看板挑出对上的发言者后，**owner 主动 invite** 他进自己的**私有 session** 深聊——`conversation_actions.ex:683` `invite_member`（owner 主动拉、`:join` 需 live member Kind）。这里是撮合真正落地的地方：私有对话 + **owner 控制对方看到什么**（选择性披露）+ 聊出结果。**是 owner 主动邀、不是申请人申请**——founder 手里握着"拉谁进来深聊"的主动权。

🔵🟢 两类用户对称——发主动 invite 的 founder 一方和被邀进来的一方都在这个私有面里，一边聊一边按信任逐步开放，**角色可互换、同一个深聊界面**。

**文字版布局示意**：

```
┌─ 深聊 · 与 张三(VC) 的私有会话 ────────────────┐
│ 🔒 私有 · 你主动 invite 进来的、只有你俩         │
│ 张三：我这笔基金关注早期出海 AI，想多了解你项目 │
│ 你：先给你看下我们的一页纸…                    │
│ ─── 选择性披露（你控制对方看到什么）─────────  │
│ ☑ 一页纸速览   ☑ 团队背景   ☐ 详细财务         │
│ ☐ 完整发现流   ☐ 我的联系方式（更进一步再开）   │
│ ─── AI 辅助撮合 ─────────────────────────── │
│ 🤖 副驾：你俩在"出海 AI 早期"高度对齐，建议下一步 │
│         约个电话 / 交换一页纸                   │
│ ┌─────────────────────────────┐ [发送]      │
│ └─────────────────────────────┘             │
│ ─────────────────────────────────────────  │
│ 撮合达成？ [ 标记为一次成功撮合 ] → 记账        │
└─────────────────────────────────────────────┘
```

- **V-9.1 owner 主动 invite（拉发言者进私有 session）** ↑J-9
  founder 对身份看板里对上的发言者点"invite 深聊"，走 `invite_member`（`conversation_actions.ex:683`，owner 主动拉，`:join` 需 live member Kind）——把这个人**从公开面拉进 founder 的私有 session**。这不是公开面、不是 concierge 客服——是 owner 主动邀请后双方直接对话的关系通道。

- **V-9.2 选择性披露控件（owner 控制对方看到什么）** ↑V-9
  被邀进来后，owner 用一组开关**控制对方能看到哪些卡片/材料/信息**（一页纸速览 / 团队背景 / 财务 / 完整发现流 / 联系方式…）。被邀成员默认看得很少，owner 按聊的进展逐项开放。这是"深聊"区别于"公开面"的核心——**披露是 owner 手里的、逐步的**。

- **V-9.3 按信任分层披露（逐步开放）** ↑V-9
  披露不是一次性全开或全关，而是**跟着信任逐层加**：先开一页纸 → 聊得对路再开团队/财务 → 真要建联再交换联系方式。界面把"当前开放到哪一层"标清楚，双方都知道进展。

- **V-9.4 AI 辅助撮合（副驾建议匹配点 / 下一步）** ↑V-9
  副驾在私有对话里给辅助：指出双方对齐的点、建议下一步动作（约电话 / 交换材料 / 该披露什么了）。撮合作为"涌现亮点"，副驾在这里降低双方的撮合摩擦。

- **V-9.5 撮合成功记账（记双向连接）** ↑V-9
  聊出结果后，可"标记为一次成功撮合"，系统记一条**双向连接**（谁 ↔ 谁、什么方向撮成的）。这是**撮合北极星的采集点**——**撮合成功 = 公开面真实互动 / 被邀深聊**（登录用户在公开面 join+发言的真实互动量、founder invite 进私有 session 深聊的数量、以及聊成的双向连接，质量加权），**不是"申请通过数"**（旧的 admission 通过数指标作废）。私密关系网就是这样从"公开面聊 → 被邀深聊 → 聊成"一条条涌现出来的。
