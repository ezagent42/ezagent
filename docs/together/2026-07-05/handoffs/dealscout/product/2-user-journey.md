# dealscout 产品文档 2：用户旅程（J 层）

> **一句话：** dealscout 是**一个帮"找机会的人"对接的 AI 网络**。找钱的 founder（🔵需求）和找项目的 investor（🟢供给）**都是"找机会的人"**，两类用户对称、角色可互换——他们走的是同**两条腿**的旅程：
> - **发现腿（地基·↑P-3.1）**：我建好 profile、配好关注什么，系统天天替我把机会捞进来（J-1）；AI 副驾按我的调性千人千面**主动**把匹配的机会推到我面前（J-2）；我想找什么就**主动搜索**全网/指定源（J-3）；盯上一条就深挖追问（J-4）；聊出的东西打包成材料下载（J-5）。**这是天天用的地基——"我在找商机所以要搜、AI 懂我所以替我发现"。**
> - **撮合腿（亮点·涌现·↑P-3.2）**：撮合不当地基、是发现之上**长出来的亮点**。我**组合 hello** 把自己的机会公开成一个带 concierge 客服的公开面让别人发现（J-6）；别人看到后**登录就能在公开面自助 join、发言供线索**、跟 concierge 客服聊（J-7）；我（founder）本人也在同一 session、**全量白板互见、看到发言者身份**（J-8）；我看到对上的人就**主动 invite 他进私有 session 深聊**、撮合成了就记一笔（J-9）；连上之后（后续）走 email 持续往来（J-10）。**机制 = hello 公开面聊天——组合 hello 公开面 + concierge / 登录自助 join+发言 / 匿名只读 / founder invite 深聊**（不是 `#1178` 申请加入——那是 agent 门、DealScout 用不上）。
>
> **贯穿属性（不是分层）：** 🔵需求 / 🟢供给是标在**每个旅程步**上的**颜色**，说明"这一步两类用户怎么对称地走"，**不参与父子结构**。同一个 J 节点，founder 和 investor 对称地各走一遍；撮合腿里申请方和审核方的角色还能互换。

## 旅程总览

**我是谁：** 我是一个"找机会的人"。如果我是 founder，我在找钱、找路演位、找商机（🔵）；如果我是 investor / 机会方，我在找项目、找标的、找情报出口（🟢）。**两种身份用的是同一套两条腿旅程，对称地走。**

**发现腿（我的一天，地基）：** 我先建好 profile、告诉系统我关心什么，系统随即天天替我把机会捞进来（J-1）→ 我打开就看到 AI 副驾按我调性**主动**推来的千人千面发现流（J-2）→ 临时想找什么我就**主动搜一把**（J-3）→ 挑一条最有戏的深挖到底（J-4）→ 让 agent 把深挖结果打包成材料下载（J-5）。这条腿今天就能跑，是我天天回来的理由。

**撮合腿（涌现的亮点）：** 发现腿跑顺了，撮合就自然长出来——我**组合 hello** 把攒出的机会**公开成一个带 concierge 客服的公开面**让别人发现（J-6）→ 有人看到、觉得对上了，**登录后就在公开面自助 join、发言供线索**、跟 concierge 客服聊（J-7）→ 我（founder）本人也在同一 session，**全量白板互见、看到每个发言者的身份**，想直接跟真人聊也行（J-8）→ 我看到某人对上了，就**主动 invite 他进一个私有 session 深聊**，撮成了就记一笔（J-9）→ 连上之后（后续）走 email 把话继续谈下去（J-10）。

**两条腿的关系：** 发现腿是地基、天天动；撮合腿是地基跑顺后涌现的亮点。撮合腿里**founder 和访客角色可互换**——我今天可能是公开机会页、别人登录进来发言的 owner，明天就是去别人公开面登录发言、被对方 invite 深聊的人；🔵需求方和🟢供给方在这条腿上对称地相遇（一方公开、一方登录进来发言），这就是"双方在撮合腿交汇"（`../README.md §3.8`）。

# 发现腿（地基）

## J-1 · 建 profile + 配置关键词/源/token、自动 + 手动爬取机会流入 ↑P-3.1

> 挂 P-3.1（地基北极星）：一切从"我告诉系统我是谁、我在找什么"开始，而**配置即触发爬取**——配好 profile + 关注清单，系统就按它把机会捞进来。这是一条旅程，不是两段。
> 🔵🟢 **两类对称**：🔵 founder 建的 profile 是"我在找什么方向的钱 / 机会"；🟢 investor 建的 profile 是"我这支基金 / 这个路演位在找什么样的项目"。同一个配置面，两类用户各填各的调性。

**J-1.1 我第一次进来，想让系统知道我是谁、在找什么，于是在 chat 里建好我的 profile + 报上关键词，得到一份被系统记住的关注清单。**
作为一个找机会的人，我打开 dealscout 的会话，直接用大白话说清我的调性——🔵 若我是 founder："我做 AI infra 早期项目，在找种子轮的钱、也想找开发者工具赛道的路演机会"；🟢 若我是 investor："我管一支专注 AI infra 种子轮的基金，单笔 50-150 万美金，在找对口的早期项目"。系统把我的 profile 连同关键词一起存下来，之后**AI 副驾按这份 profile 千人千面地替我发现**（J-2），每轮爬取也按这份清单来。我不用填表、不用建项目，说一句话就配好了。

**J-1.2 我想让某些只有登录才能看的源也能被抓，于是把我的 access token 交给系统，得到"这个源以后归你抓"的确认。**
有些好料在需要登录的地方（某个付费投融资库、某个圈子内的 feed）。作为找机会的人，我在 chat 里说"这个源要登录，token 我给你"，把自定义 access token 贴进去。系统安全存好这个凭证，之后抓这个源时自动带上，我不用每天手动登录复制粘贴。

**J-1.3 我随时想调整关注点，于是在 chat 里改 profile / 增删关键词，得到即时生效的新清单。**
过了两周我发现某个赛道没戏、另一个赛道热起来了。作为找机会的人，我直接说"去掉 X，加上 Y"，系统当场更新我的 profile 和关注清单，下一轮爬取 + AI 主动发现就按新调性走。关注点是活的，跟着我的判断随时变。

**J-1.4 我不想每天守着到处搜，于是把爬取交给系统定时跑，得到每天自动流进来的新机会。**
作为找机会的人，我配好 profile 就不用管了——配置本身就是爬取的触发器。系统每天按固定节奏，自己去全网和我指定的源里，把和我调性相关的新闻、投融资动态、路演机会、商机线索捞回来，注入我的会话。我早上打开就有新东西看，不用自己动手搜。

**J-1.5 我临时想立刻看某个热点的最新情况，于是在 chat 里发一条手动爬取命令，得到当下最新的一批结果。**
比如我听说某个大 round 刚官宣。作为找机会的人，我不想等明天的定时任务，直接在 chat 里敲一条"现在抓一下"的命令，系统立刻发起一轮爬取，把最新结果马上推进来。定时兜底 + 手动即时，两种都在同一个对话里、同一份 profile 上。

**J-1.6 我担心抓回来的东西是不是漏了或重了，于是看系统给的爬取回执，得到"这轮抓了几条、来自哪些源"的交代。**
作为找机会的人，我需要对信息流有基本信任。每轮爬取跑完，系统告诉我这轮进了多少条、覆盖了哪些源。没抓到不会悄悄吞掉，会明说。我知道信息流是完整的，才敢基于它做判断。

## J-2 · 浏览千人千面发现流（AI 副驾按 profile 主动推匹配机会）↑P-3.1

> 挂 P-3.1（地基北极星）：这是发现腿的**新重点之一**——不是我去翻一堆原始爬取结果，而是 **AI 副驾读懂我的 profile、千人千面地把匹配我调性的机会主动挑出来、排好、推到我面前**。"AI 懂我，替我发现"是地基天天兑现价值的地方。
> 🔵🟢 **两类对称**：🔵 founder 的发现流是"匹配你融资阶段 / 赛道的钱和路演机会"；🟢 investor 的发现流是"匹配你基金射程的早期项目和标的"。同一套 AI 主动发现，按各自 profile 出不同的千人千面结果。

**J-2.1 我早上打开会话，想直接看 AI 替我挑好的机会，于是进到发现流视图，得到一份按我 profile 排过序的匹配机会列表。**
作为找机会的人，我不想在几十条原始爬取结果里大海捞针。我打开发现流 tab，看到的是 AI 副驾**已经按我的调性筛过、排过**的机会：每条都标了"为什么这条匹配你"（对上了你哪个关键词 / 融资阶段 / 赛道）。我扫一眼就知道今天最该看的是哪几条。

**J-2.2 我想知道 AI 为什么把某条推给我，于是点开它看匹配理由，得到"这条对上了你 profile 的哪一点"的解释。**
作为找机会的人，我不想盲信 AI 的排序。我点开某条推荐，看到副驾给的匹配理由——比如"这家刚拿种子轮、赛道是你关注的 AI infra、投资方历史偏好和你的阶段吻合"。理由讲清楚了，我才决定要不要深挖。AI 主动发现不是黑盒推送，是可解释的副驾。

**J-2.3 我觉得 AI 推得不够准，于是给它一句反馈调调口味，得到之后更贴合我的发现流。**
作为找机会的人，我可能觉得"这类我不感兴趣、那类多推点"。我在 chat 里说一句，副驾把这条反馈并进我的 profile 理解，下一轮千人千面发现就更贴我。发现流是越用越懂我的，不是一成不变的推送。

## J-3 · 主动搜索机会（手动 query 全网 / 指定源）↑P-3.1

> 挂 P-3.1（地基北极星）：这是发现腿的**另一个新重点**——除了 AI 替我主动发现（J-2）、系统定时爬取（J-1），我还得能**主动搜**。"我在找商机，所以我要能随时搜一把"是找机会的人最直接的诉求。J-3 是我手里的主动搜索入口，和 J-2 的 AI 主动发现互补：一个是 AI 推给我、一个是我去拉。
> 🔵🟢 **两类对称**：🔵 founder 搜"投我这阶段的基金 / 这赛道的路演"；🟢 investor 搜"符合我射程的早期项目 / 某赛道最新融资"。同一个搜索面，两类用户按各自意图 query。

**J-3.1 我心里有个明确要找的东西，于是在搜索面里敲一条 query，得到系统当场跨全网 / 指定源搜回来的结果。**
作为找机会的人，我不想干等定时爬取或 AI 推送。我直接在搜索框里敲"最近三个月投 AI infra 种子轮的活跃基金"，系统当场发起一轮主动搜索，扫全网和我配置过的指定源，把结果收敛成一份可看的列表。我要什么就搜什么，即时拿到。

**J-3.2 我想把搜索范围收窄，于是在 query 里限定源或加过滤条件，得到更聚焦的结果。**
作为找机会的人，全网搜可能太杂。我可以限定"只搜我给过 token 的那个投融资库"或加上"只看华东、只看单笔 100 万美金以上"。系统按我给的范围搜，结果更贴题。主动搜索是我能精确控制范围的一把工具。

**J-3.3 我搜到一条有戏的想接着动作，于是就地把它转进深挖，得到"从搜索结果直接追问这条"的入口。**
作为找机会的人，搜到一条对口的，我不想再复制粘贴到别处。搜索结果里每条都带一个"深挖这条"的入口，点一下就进到 J-4 的追问对话。从"搜到"到"追问"是一次点击，主动搜索和深挖缝在一起。

## J-4 · 单条机会深挖多轮追问 ↑P-3.1

> 挂 P-3.1（地基北极星）：对着一条机会反复追问、把它挖透，是把一条线索变成"看得懂、拿得出手"的材料的核心动作。发现流（J-2）、主动搜索（J-3）、信息流（J-1）里挑出的任何一条，都收进这条追问线深挖。
> 🔵🟢 **两类对称**：🔵 founder 追问"这家投资方偏好什么、我该怎么措辞去接触"；🟢 investor 追问"这个项目的团队 / 进展 / 估值合不合我的标准"。同一条追问对话，两类用户各挖各的角度。

**J-4.1 我盯上一条机会想弄清它的来龙去脉，于是对着它问第一个问题，得到 agent 基于这条机会给的回答。**
作为找机会的人，我在某条投融资信息上问（🔵）"这家的投资方历史偏好是什么、最近还投了谁"，或（🟢）"这个项目现在到哪一轮、团队背景如何"。系统把这条机会交给追问 agent，agent 结合它给我一段有针对性的回答。我像在和一个懂行的研究员对话。

**J-4.2 我顺着回答想再往深挖，于是接着追问下一层，得到带着上文记忆的连贯回答。**
作为找机会的人，我顺着上一个答案追下去（🔵"那按这个偏好我该怎么接触他们"／🟢"那按这个进展这个估值合理吗"）。agent 记得我们前面聊的这条机会和上一轮的结论，接着往下答，不用我重新交代背景。多轮追问是连贯的一条线，越问越深。

**J-4.3 我想换个角度或补充资料再问，于是在同一条追问里继续发消息，得到围绕这条机会不断累积的深挖上下文。**
作为找机会的人，我可能问着问着想到新角度，或者贴一段我自己找到的补充材料进去。系统始终围着这条机会攒上下文，我问几轮都行。一条机会被我挖到什么程度，取决于我愿意问几轮，系统不设墙。

## J-5 · 追问后生成 artifact 下载 ↑P-3.1

> 挂 P-3.1（地基北极星）：深挖聊出来的东西要能落成"一份拿得出手的材料"，这一步就是把对话变成可交付物——发现腿的产出闭环。
> 🔵🟢 **两类对称**：🔵 founder 产出"给这家投资方的 outreach 简介 / BP 摘要"；🟢 investor 产出"这个项目的尽调备忘 / 内部推介材料"。同一个 artifact 生成能力，两类用户产出不同用途的材料。

**J-5.1 我聊出了有用的东西想让它变成一份材料，于是让 agent 把深挖结果整理成 artifact，得到一份成型的文件。**
作为找机会的人，追问到位后我说"把刚才这些整理成一份材料"。agent 把多轮对话的结论收敛成一份成型文件（简介 / 模板 / 备忘 / 素材），不再是散在对话里的碎片。

**J-5.2 我想把这份材料拿到手用，于是点系统给的下载入口，得到可以直接下载的文件。**
作为找机会的人，agent 产出的材料会带一个下载链接。我点一下就把文件拿到本地，可以直接发出去、也可以再改。从"聊出来"到"手里有文件"是闭环的，不用我自己复制粘贴重新排版。

**J-5.3 我想让材料再改一版，于是接着让 agent 调整重出，得到更新后的可下载版本。**
作为找机会的人，第一版材料我可能觉得语气太硬或漏了点。我直接说"改得客气点、加上这段"，agent 重出一版，给我新的下载链接。材料是可迭代的，直到我满意为止。

# 撮合腿（亮点·涌现）

> **机制说明（`../README.md §3.8` 权威）：** 撮合腿 = **hello 公开面聊天**——**不是** `#1178` 申请加入私有 session（现读代码确认 `#1178` admission gate 是 agent 门、防偷用别人 agent 刷凭证，DealScout 用不上）。而是：我 DealScout **组合 hello** 拿到公开面 + **concierge 客服 agent**（`router.ex:13-14`：非 owner 访客永远只跟 concierge 聊、到不了 builder；`hello_concierge.ex:43` 回帖）→ 别人**登录后在公开面自助 join、发消息**（`session_feed_channel.ex:197-228`），发的消息 @orchestrator → 非 owner 永远路由 concierge 回帖；**匿名只读不能写**（`session_feed_channel.ex:325-330` + `membership.ex:1200-1208` 两处硬禁）→ 我（founder）本人也在同一 session、**全量白板互见**（`external_feed.ex:85-98`）、**看到发言者身份**（`session_feed_channel.ex:353`）→ 我看到对上的人就**主动 invite 他进私有 session 深聊**（`conversation_actions.ex:683`，owner 主动拉）。**公开面只读/写靠登录身份分档，深聊靠 founder 主动 invite，正是撮合作为"涌现亮点"该有的形态。**
> 🔵🟢 **双向对称、角色可互换**：撮合腿里"公开机会页的 founder"和"登录进来发言的访客"不是固定绑定某类用户——我可能是公开机会页、别人登录进来发言的 owner（J-8/J-9），也可能是去别人公开面登录发言、被 invite 深聊的人（J-7）。🔵 founder 和🟢 investor 在这条腿上对称地相遇：一方公开机会、一方登录进来发言，撮合就发生在交汇处。

## J-6 · 组合 hello 公开自己的机会页（公开面 + concierge 客服）↑P-3.2

> 挂 P-3.2（撮合北极星）：撮合的入口是"我组合 hello 把自己的机会亮成一个带客服的公开面让别人能看到"。我发现腿攒出的东西（profile + 关注方向 + 深挖过的情报）经 hello 挂成一个公开页 + concierge 客服，别人顺着它发现我、登录进来发言。
> 🔵🟢：🔵 founder 公开"我在找什么方向的钱 / 机会"；🟢 investor 公开"我这支基金 / 这个机会在找什么样的项目"。都是把自己的机会亮给对面那一类人看。

## J-9 · founder invite 深聊者进私有 session + 选择性披露 + 撮合记账 ↑P-3.2
