# 片8 实现 spec：drop 闭环（指标不达标 → 砍子树 → 反哺痛点）

> 写于 2026-06-23。带 file:line 实证。真相源 = ezagent mindmap domain（SQLite KindSnapshot）。
> 范围：一个原子动作 `mindmap.drop_subtree(id)` = 级联删 + 在 pain 祖先记一笔；判"不达标"= 软提示标记 + 人工触发；反哺 = pain 阶段节点挂 artifact。

---

## 0. 设计决策（落地前先定）

- **D-drop-1：drop 是人工触发，不自动。** 指标不达标只产**软提示标记**（沿用"gate 全软"决策），由 owner/admin 人工 `drop_subtree`。不达标判据（`current` vs `target`）只用于**前端打红 + 可选警告**，不触发任何 effect。这跟 `behavior/mindmap.ex:277` 的 R1 软插入校验是两类东西——R1 是硬拒（结构不变式），drop 判据是纯展示提示。
- **D-drop-2：drop 不是新删除路径，是 `remove_node` 的语义包装 + 一条 pain 反哺。** 复用现成级联（`behavior/mindmap.ex:259` `Map.drop(subtree_ids)`）和 `normalize_artifact`（`:501`）。**不新增级联逻辑，不改 `subtree_ids/2`。**
- **D-drop-3：反哺落点 = 被删子树根的"最近 pain 祖先"。** 沿 `parent_id` 链上溯（复用 `ancestors/2`，`behavior/mindmap.ex:537`）找第一个 `stage == :pain` 的节点，在它上面 `attach_artifact` 一条 `%{tool: "mindmap", kind: "drop_record", ref: <被删id>, content: <原因>}`。找不到 pain 祖先 → **静默不反哺但仍删**（返回里带 `pain_anchor: nil`，不报错——不能因为"没地方记"就阻断删除，但要让调用方看见没记上）。
- **D-drop-4：授权 = 复用 `owner_or_admin?`（`behavior/mindmap.ex:470`）。** drop 一棵子树需子树根的 owner 或 admin。**不要求**对 pain 祖先单独授权——反哺 artifact 是系统记账，绕过 pain 节点 owner 检查（否则"我 drop 我的子树却因为不是 pain 节点 owner 而失败"自相矛盾）。这是 drop 内部直接构造 effect、**不走** `attach_artifact` handler 的原因（handler 会查 pain 节点的 `owner_or_admin?`）。

## 2. Behavior diff 要点（mindmap.ex）

### 2.1 action 声明（插在 `:remove_node` 之后，`behavior/mindmap.ex:66` 后）

```elixir
action(:drop_subtree,
  args: %{id: :string, reason: :string},
  returns: %{dropped: :integer, pain_anchor: :string},
  caps: [:drop_subtree],
  modes: [:call],
  description: "砍整棵子树(=级联删)+在最近 pain 祖先记一笔 drop 反哺;reason 可空"
)
```

`required_caps/0`（`behavior/mindmap.ex:150` 那个 list）加 `:drop_subtree`。

### 2.2 handler

```elixir
@doc false
def handle_drop_subtree(%{id: id} = args, ctx) do
  reason = Map.get(args, :reason, "") |> to_string()
  t = tree(ctx)

  cond do
    not Map.has_key?(t.nodes, id) ->
      {:error, :node_not_found}

    # 授权：子树根的 owner 或 admin（复用 owner_or_admin?）
    not owner_or_admin?(ctx, t.nodes[id]) ->
      {:error, :forbidden}

    true ->
      ids = subtree_ids(t.nodes, id)                       # 复用 :545
      dropped = length(ids)
      pain_id = nearest_pain_ancestor(t.nodes, id)         # 上溯找 :pain

      # 先在 pain 祖先记账（若有），再级联删子树。
      # 注意：pain_id 不在被删子树内——它是 id 的祖先，subtree_ids 只含后代。
      nodes_after_record =
        case pain_id do
          nil -> t.nodes
          pid ->
            art = drop_record_artifact(id, reason)
            pnode = t.nodes[pid]
            Map.put(t.nodes, pid, %{pnode | artifacts: pnode.artifacts ++ [art]})
        end

      new_nodes = Map.drop(nodes_after_record, ids)        # 级联删，复用 :259 同款
      new_root = if id == t.root_id, do: nil, else: t.root_id

      {:ok, %{dropped: dropped, pain_anchor: pain_id},
       [commit(%{t | nodes: new_nodes, root_id: new_root})]}
  end
end

# 沿 parent 链找第一个 stage==:pain 的祖先（不含自己）；复用 ancestors/2(:537)。
defp nearest_pain_ancestor(nodes, id) do
  Enum.find(ancestors(nodes, id), fn aid -> nodes[aid].stage == :pain end)
end

defp drop_record_artifact(dropped_id, reason) do
  normalize_artifact(%{
    tool: "mindmap",
    kind: "drop_record",
    ref: dropped_id,
    url: nil,
    content: "drop:#{dropped_id} 原因:#{reason}"
  })
end
```

**关键正确性点（写代码时核对）**：
1. `pain_id` 是 `id` 的**祖先**，`ids = subtree_ids(id)` 只含 `id` 及其**后代**——两集合不相交，所以"先在 pain 记账再 `Map.drop(ids)`"不会把刚记的账删掉。**必须先记后删，且记账写进 `nodes_after_record` 再 drop**（顺序写反会丢账或删错）。
2. 反哺直接构造 `%{pnode | artifacts: ...}` + 唯一 `commit/1`（`:447`），**不调 `attach_artifact` handler**——绕过 pain 节点 owner 检查（见 D-drop-4），且保持"全文唯一 `{:set` 字面"约定（`behavior/mindmap.ex:446` 注释）。
3. `content` 走 `normalize_artifact` → `cap_content`（`:515`）自动截到 8192，复用现成上限。
4. drop 根节点（`id == root_id`）：`new_root = nil`，和 `handle_remove_node`（`:260`）一致——整图清空合法。

## 4. "不达标"判定 + 前端（软提示，不产 effect）

判据是**纯读侧展示逻辑**，放 read model 不放 Behavior（Behavior 不为展示算东西）。在 `mindmap_data.ex` 加一个纯函数，`jsonable_node` 里加一个布尔字段：

```elixir
# metric breached = 任一 metric 的 current 严格不达 target（数值可比时）。纯展示用。
defp metric_breached?(metrics) do
  Enum.any?(metrics, fn m ->
    with t when is_number(t) <- Map.get(m, :target),
         c when is_number(c) <- Map.get(m, :current) do
      c < t
    else
      _ -> false   # 非数值 metric 不参与红标
    end
  end)
end
```

`jsonable_node/1`（`mindmap_data.ex:149`）加 `"metric_breached" => metric_breached?(Map.get(n, :metrics, []))`。

前端（`MindmapCanvas.tsx` 节点渲染 / `NodePanel`）：
- `metric_breached == true` → 节点标红/角标（软提示，不挡操作）。
- NodePanel 对 owner/admin 显 **"砍子树"按钮 + 原因输入框** → `pushEvent("mindmap.drop_subtree", {mindmap_uri, id, reason})`。
- 删后 `world:state` 推回的 tree 已无该子树；若 `pain_anchor` 非空，可 toast"已在痛点节点 X 记一笔"。`pain_anchor` 走 `last_dispatch_status` 之外的回传（如需，扩 `status_of`/push payload；v1 可只看 tree 变化，不显 anchor）。

**判据阈值是展示侧、可调，不写死进真相源**——和 D-drop-1 一致。

## 5. 单元测试点（mindmap_test.exs，复用现成 `seed/0` + `committed/1`）

新 `describe "drop_subtree（级联删 + pain 反哺 + 授权）"`：

1. **基本级联删**：`seed` 建根→功能子，admin `drop_subtree(c)` → `dropped == 1`，`committed(e).nodes` 不含 `c`，含根。
2. **删根清空整图**：admin `drop_subtree(r)` → `committed(e).root_id == nil`，`nodes == %{}`，`dropped == 子树全量`。
3. **多层级联计数**：根→pain→feature→issue 链，drop feature → dropped 含 feature+issue 两个，pain/根 还在。
4. **pain 反哺命中**：构造 根(positioning)→pain→feature 子树，admin `drop_subtree(feature, reason: "指标不达标")` → 返回 `pain_anchor == <pain_id>`；`committed(e).nodes[pain_id].artifacts` 多一条 `%{tool: "mindmap", kind: "drop_record", ref: <feature_id>}`，`content` 含 "指标不达标"。
5. **pain 反哺 miss**：根→feature（无 pain 祖先）drop feature → `pain_anchor == nil`，子树仍被删（`dropped >= 1`），无任何 artifact 被加（除被删节点本身）。
6. **授权：非 owner 非 admin 被拒**：用户 A 认领 feature 子树根，用户 B（`user_ctx`，非 admin）`drop_subtree(feature)` → `{:error, :forbidden}`，树不变。
7. **owner 可 drop 自己的子树**：A 认领 feature，A `drop_subtree(feature)` → `{:ok, ...}`。
8. **node_not_found**：`drop_subtree("nope")` → `{:error, :node_not_found}`。
9. **reason 可空**：`drop_subtree(c)`（不带 reason）→ 不崩，pain 命中时 content 形如 `"drop:c 原因:"`。
10. **反哺 artifact 走 8192 截断**：传超长 reason，命中 pain 后 `content` 长度 ≤ 8192（验 `cap_content` 复用）。
11. **不变式：pain 祖先记账不被级联删掉**（防顺序写反回归）：根(positioning)→pain→feature，drop feature 后 pain 节点**仍在** `committed(e).nodes` 且带 drop_record。

`required_caps/0` 含 `:drop_subtree`（断言 `Map.has_key?(Mindmap.required_caps(), :drop_subtree)`）。

## 6. E2E 验收点

1. **World dispatch 闭环**（`mindmap_data_test.exs` 同款风格 / capbac_test.exs）：登录 admin 经 `MindmapActions.handle_dispatch("mindmap.drop_subtree", %{"mindmap_uri"=>u, "id"=>id, "reason"=>"砍"})` → `last_dispatch_status == "ok"`，re-read tree 不含子树，pain 节点带 drop_record。
2. **per-node CapBAC 真判**（对齐 `e2e/capbac_test.exs`）：非 owner 非 admin 经 world dispatch drop → `last_dispatch_status` 形如 `"error:forbidden"`，树不变（world 层不放水，`mindmap_actions.ex:8` 承诺）。
3. **持久化**（对齐 `e2e/persistence_test.exs`）：drop 后 Kind 重启，被删子树不复现，pain 节点 drop_record 仍在（验 `{:set,:tree}` 进了 KindSnapshot）。
4. **不达标软提示**（read model）：节点带 `metric{target:3,current:1}` → `read_tree` 出的该节点 `"metric_breached" == true`；`current>=target` → `false`；非数值 metric → `false`。
5. **markmap 导出不受影响**：drop 后 `export_markmap` 不含被删子树标题（pain 的 drop_record 是 artifact，不入 markmap 拓扑，验导出仍干净）。

## 8. 对抗审查（2026-06-23，必改/风险）

整体可行：贴合现有 behavior（`commit/1:447`、`subtree_ids:545`、`ancestors:537`、`owner_or_admin?:470`、`normalize_artifact/cap_content:505/515`）、world `act/4:94`、read model `jsonable_node:149`。守单一真相源（账落 `{:set,:tree}` 进 KindSnapshot，不在外部建真相），不破 per-node CapBAC（D-drop-4 的"绕过"经核实成立：`attach_artifact`→`update_node`→`owner_or_admin?(t.nodes[pain_id])` 确会查 pain 节点 owner，故直接构造 effect 是对的、不是放水）。不冲突已定决策（gate 软=软提示不产 effect ✓；CI inline ✓；本片不碰 GitHub 出站）。gate 安全：mindmap.ex 549 行远低于 oversized 1000/1500；`metric_breached?` 是 defp 不进 doc.scan 计数；无 raw URI（`with_action` 已 sanctioned，本片不碰 URI 构造）。

**必改 1（doc.scan ratchet 会红）**：`handle_drop_subtree/2` 是新 public `def`，必须带 `@doc false`（与现有 11 个 handler 一致），否则 `undocumented_public_defs` counter +1 超 baseline 触发 FAIL——除非同时改 `arch_baseline_manifest.exs` 加 `# arch-cap-bump:`。spec §2.2 模板已写 `@doc false`，落地时**不要漏**。`nearest_pain_ancestor`/`drop_record_artifact` 是 defp，不计数。

**必改 2（`nodes[aid].stage` 在 string-key 边界会炸）**：`nearest_pain_ancestor` 用 `nodes[aid].stage == :pain`。Behavior 内部 tree 的 node 是 atom-key map（`new_node/1`），handler 侧 OK；但 `ancestors/2` 已是内部调用、安全。真正风险在 **R1 单调链**：测试要造 `pain`(index2) 祖先 + `feature`(index5) 后代，得先 `set_stage` 把中间节点抬到 pain——seed 默认全 `:positioning`，直接 `drop_subtree(feature)` 时若没人是 pain 必走 miss 分支。§5 用例 4/11 必须显式 `set_stage(mid,"pain")` 再挂 feature 子，否则测不到 hit 分支（命中分支零覆盖=埋坑）。建议补一句断言 `nodes[pain_id].stage==:pain` 锁前提。

**风险 3（前端 `pain_anchor` 反馈丢失 + 两处 push 不一致）**：`act/4` 经 `push_tree` 只回 `last_dispatch_status`（`status_of` 仅 ok/error），**吞掉 `{:ok,%{dropped,pain_anchor}}` 的 result**——前端拿不到 `pain_anchor`，§4 的"已在痛点 X 记一笔"toast 无数据。要么 §3 给 drop 单开一条子句把 result 并进 push payload（别动通用 `act/4`），要么明确降级为 v1 只看 tree diff（spec §4 已留口，但要在 D-drop 决策里点名 Allen 拍：**drop 的 result 是否需回前端**）。另注：`metric_breached?` 加进 `jsonable_node` 会让**所有** mindmap 读路径（session_board/board_state/read_tree）都多算一遍，量小可接受，但确认前端不依赖旧 node 字段集（加字段是兼容的，删/改才破）。

次要：reason 经 `cap_content` 截 8192 ✓ 复用现成；删根 `new_root=nil` 与 remove_node 一致 ✓；mix format 不会坑（无特殊宏）；纯单 BEAM handler 单测，无两 BEAM 序列化坑（atom-key tree 不跨节点）。待 Allen 拍：D-drop-3（miss 静默仍删）、D-drop-4（绕 pain owner）、上面风险 3 的 result 回传。
