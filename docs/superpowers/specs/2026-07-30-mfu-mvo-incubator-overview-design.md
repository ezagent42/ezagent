# MFU · MVO 组织孵化总览 Demo 设计

> 日期：2026-07-30
>
> 状态：方向已确认，待 ruihua 审阅本文
>
> 首要观众：孵化器运营者

## 1. 概念重置

下一版 Demo 不再以学生怎样完成一个任务为主线，而是以学校、孵化器和企业怎样持续创造有效组织为主线。

三类客户使用同一套玩法，只拥有不同的资源和任务。第一版采用孵化器视角。

核心价值：

> 孵化器把零散的人才、Agent、IP、资金和算力，持续转化为能够执行任务的 MVO。

MVO 是 `Minimum Valuable Organisation`，即“最小有效组织”。

学生在该视角下是被培养和配置的人才资源。学生自己的 ToDo List、工作台和个人成长暂不进入本 Demo。

旧的猎人教学订单保留为未来下钻机制原型，不再承担下一版 Demo 的首页叙事。

## 2. 首页就是高潮

Demo 打开后直接进入“MVO 组织孵化总览”，不先播放教学、不先介绍背景，也不要求用户完成复杂操作。

首页必须让不了解 MFU 的观众立即看懂四件事：

1. 孵化器拥有多少组织资源；
2. 这些资源还可以组成什么；
3. 已经孵化出了哪些 MVO；
4. 哪些 MVO 正在执行任务并产生结果。

核心成果文案：

> 本孵化器已把 12 名学生转化为 6 个可运行的 MVO。

“转化”表示学生从零散人才进入能够持续创造价值的组织，不代表学生失去个人身份或自主权。

## 3. 三个核心机制

### 3.1 ToDo List：任务与机会

学校课程任务、孵化器验证任务和企业真实订单统一称为“任务”。

任务进入 ToDo List 后，平台自动推荐适合执行的 MVO，由玩家确认。

宏观状态：

```text
To Do → Doing → Done
```

首页只展示任务、匹配的 MVO、进度和结果，不展示内部执行细节。

### 3.2 物品栏：组织资源

第一版物品栏包含：

| 资源 | 首页表达 | 关键规则 |
|---|---|---|
| 人才 | 卡牌 + 数量 | 显示能力、经验、认证；同一时间只能加入一个 MVO |
| Agent | 卡牌 + 数量 | 显示能力和算力消耗；租用 Agent 可以跨 MVO 使用 |
| IP / 工具 | 卡牌 + 数量 | 包括方法、行业数据、渠道、品牌和内容资产 |
| 算力 | 顶部数字 | 装入 MVO 后被占用 |
| 资金 | 顶部数字 | 装入 MVO 后被占用 |

首页采用的示例数字：

- 人才 12
- Agent 6
- IP / 工具 4
- 可用算力 240
- 可用资金 ¥20,000

资源同时区分：

- 已投入 MVO；
- 当前空闲；
- 可租用或复用。

### 3.3 组织图：组织结构

组织图结合岗位、流程和能力需求，但在宏观首页只显示简化的三步图：

```text
发现需求 → 形成方案 → 验证结果
```

每一步都是一个需要填充资源的“孔”。一个孔可以放入多种资源。

玩家深入编辑时可以：

- 添加、删除和移动步骤；
- 连接协作关系；
- 定义输入与输出；
- 设置任务流；
- 把人才、Agent 和 IP 拖入步骤。

第一版 MVO 的最低成立条件：

1. 三个关键步骤都存在；
2. 每一步至少有一个负责执行的人或 Agent；
3. 第一步到最后一步存在完整连接；
4. 拥有完成一次任务所需的最低算力。

资金和 IP 默认是增强资源，不是所有 MVO 的统一必需项。特殊任务可以要求特定预算、IP 或认证。

## 4. 从资源到 MVO

```text
组织图
+ 人才 / Agent
+ IP / 工具
+ 算力 / 资金
= MVO
```

MVO 最初是为某类任务形成的临时组织。完成第一个任务后不会自动消失，可以继续执行同类任务。

若更换关键成员或修改组织图，则形成新的 MVO。

人不能同时加入多个 MVO；租用 Agent 可以作为共享服务被多个 MVO 使用。

## 5. 组织图验证

玩家可以自己设计组织图并消耗算力验证，也可以购买其他玩家、学校、孵化器、企业或平台已经验证的组织图。

验证展示：

- 结构是否完整；
- 输入与输出是否衔接；
- 预计完成时间；
- 预计资源成本；
- 预计成功率或质量；
- 主要风险；
- AI 优化建议。

验证失败只消耗算力。平台不替玩家做绝对判定，玩家根据结果决定继续启动、调整结构、更换资源或购买其他组织图。

组织图可以提供一次使用权、永久模板、复制权或可改造授权。授权市场暂不进入首版 Demo。

## 6. 首页信息结构

首页使用一个完整的宏观看板，同时展示四个区域。

### 6.1 资源总览

展示人才、Agent、IP / 工具、算力和资金，以及空闲与占用状态。

### 6.2 可以创造什么

平台根据空闲资源和 ToDo 自动推荐：

- 校园增长 MVO；
- 短视频交付 MVO；
- 用户研究 MVO。

每个推荐只显示：

- 能解决什么任务；
- 已具备多少资源；
- 还缺什么；
- 是否可以立即创建。

### 6.3 已经产出的组织

用多个简化三步图展示：

```text
校园增长 MVO
洞察 → 制作 → 验证

短视频交付 MVO
策划 → 生产 → 发布

用户研究 MVO
招募 → 访谈 → 结论
```

每个 MVO 显示名称、三个步骤、装入的代表资源、声望和认证状态。

### 6.4 正在运行的组织

示例：

- 校园增长 MVO：执行中 72%；
- 短视频交付 MVO：等待验收；
- 用户研究 MVO：今日完成；
- 品牌设计 MVO：声望 58，接近认证。

只展示进度和结果，不展开内部操作。

## 7. 第一幕动画

首页加载时用一个短动画强化核心价值：

```text
零散人才 + Agent + IP
→ 装入三个简化组织图
→ 形成 3 个 MVO
→ 3 个 MVO 同时开始运行
```

动画结束后突出显示：

> 已孵化 MVO 6 · 正在运行 3 · 已认证 1 · 还可创建 3

首页加载前不设置欢迎页或说明页。用户打开 Demo 就看到资源正在形成组织。

## 8. Demo 流程

### 第一幕：组织孵化总览

首页同时展示资源、机会、已形成组织和运行状态。这一幕本身就是 pitch 高潮。

主要按钮：

- 再孵化 3 个 MVO；
- 查看正在运行的组织；
- 查看全部资源。

### 第二幕：再创造更多 MVO

点击“再孵化 3 个 MVO”后，平台展示三个自动推荐组合。玩家可以直接确认，也可以选择“调整组织图”进入下钻层。

确认后，空闲资源流入三个三步图，形成新的 MVO。

### 第三幕：观察组织运行

多个 MVO 同时执行任务，任务从 To Do 流向 Doing 和 Done。

其中一个 MVO 完成任务后展示：

- 任务结果；
- MVO 声望；
- 人才经验；
- Agent 能力；
- 组织图验证记录。

达到示例条件“完成 3 个任务且声望达到 60”后，获得“认证 MVO”身份。

### 可选下钻层

用户点击 MVO 或“调整组织图”后，才查看：

- 组织图编辑；
- 资源孔；
- 组织图验证；
- 任务执行详情；
- 成员与 Agent 成长。

下钻层用于证明宏观结果背后有完整机制，不阻碍首页表达核心价值。

## 9. MVO 成长

任务完成后分别积累：

- MVO：声望与履约记录；
- 人才：经验；
- Agent：经验或能力；
- 组织图：验证记录；
- 主理人：组织经验。

MVO 的孔和资源在本 Demo 中保持固定。升级不会增加孔或更换资源，只会使 MVO 获得更高声望、履约记录和“认证 MVO”身份。

## 10. Demo 边界

首版不实现：

- 学生自己的 ToDo List 和个人工作台；
- 学生自主确认机制；
- MVO 内部具体执行操作；
- 组织图授权交易；
- 大型 Organization 的扩张；
- 不同客户类型的不同玩法；
- 详细失败惩罚；
- 猎人教学订单的完整流程。

首版优先证明：

> 同一套平台可以把组织拥有的零散资源，快速转化成更多能够运行和产生收入的 MVO。

## 11. 验收标准

1. 不了解 MFU 的观众打开首页后，能在十秒内说出“这是把资源组合成组织的平台”；
2. 首页不经过操作就能看到资源、机会、已产出的 MVO 和运行中的 MVO；
3. 首页明确展示“12 名学生 → 6 个 MVO”的转化成果；
4. 至少同时展示 3 个正在运行的 MVO；
5. 用户能一键确认平台推荐的 3 个新 MVO；
6. 新 MVO 的形成有清晰的资源流入组织图动画；
7. 任务可以从 To Do 自动推进到 Doing 和 Done；
8. 至少一个 MVO 能获得“认证 MVO”身份；
9. 具体组织图操作只在用户主动下钻时出现；
10. 整个主流程不要求理解卡牌拖拽、Agent 调教或个人成长规则。
