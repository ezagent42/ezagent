# MFU 首个猎人教学订单 v0.3 设计

> 日期：2026-07-29
>
> 状态：v0.3 已实现；v0.3.1 连续新手引导设计待 ruihua 审阅
>
> 目标原型：`mfu-demo/MFU-协作阵列-v0.1-可玩原型.html`

## 1. 目标

把当前协作阵列原型收窄成学生 / OPC 首次进入平台时的“猎人教学关卡”。

首关只让玩家理解三件事：

1. 面对分配给自己的步骤，怎样编排本人和 Agent；
2. Agent 会真实执行并产生可能出错的成果，人需要检查和负责；
3. 玩家可以花费时间、算力和现金调教 Agent，使同类工作变得更可靠。

首关不再同时教授主动连接、成立组织和拆解完整订单。这些内容属于取得组织资格后解锁的独立教学关卡。

## 2. 采用的方案

采用“聚焦式教学关卡”：

```text
输入昵称
→ 了解订单背景
→ 学会拖拽
→ 编排本人和 Agent
→ Agent 产生错误成果
→ 玩家发现需求偏差
→ 调教 Agent
→ 安装 Form 并写守则
→ Agent 用 Form 确认
→ 重新执行并完成步骤
→ 等待完整订单完成
→ 统一结算
→ 领取自由订单
```

不采用以下方案：

- 不在首关结算后增加可选的组织支线；
- 不保留当前“第二幕：用连接组成一个新组织”；
- 不用明确选择题代替真实成果检查；
- 不在教学关卡制造截止倒计时压力。

## 3. 关卡边界

### 3.1 首关负责教授

- 玩家是完整订单中的一名猎人；
- 玩家只负责其中一个步骤，但能看到完整订单路线；
- 玩家可以把本人和 Agent 安排到任务位置；
- Agent 执行会消耗算力；
- 人检查成果、提供反馈并承担最终责任；
- 安装工具需要现金；
- 写守则需要本人时间；
- 调教后的 Agent 可以在同一订单中重新执行；
- 玩家步骤交付不等于完整订单已经交付；
- 正式结算发生在完整订单完成之后。

### 3.2 首关不负责教授

- 保存其他真人的卡牌；
- 邀请真人建立长期合作；
- 给组织命名；
- 取得成立组织的资质；
- 拆解完整订单；
- 把步骤分配给组织成员；
- 联合竞标、公开评审、认证或孵化；
- 真实订单的截止倒计时。

## 4. 页面与交互流程

### 4.1 输入昵称

首次进入时先让玩家输入自己的昵称。

- 输入框示例可以使用“小满”，但不再默认假设玩家就是小满；
- 昵称保存在浏览器本地状态；
- 后续页面使用“你 · 昵称”“昵称的步骤”“昵称待确认”等表达；
- 已有存档的玩家不重复询问，重置教学后重新输入。

唯一主要按钮：

> 进入教学订单

### 4.2 订单背景

背景页继续讲述社区旧书店的开学推广需求，只回答：

- 谁需要帮助；
- 发生了什么；
- 完整订单要交付什么；
- 玩家负责哪个步骤。

页面可以显示只读的完整订单路线。玩家节点使用其昵称高亮。

唯一主要按钮居中并增强视觉层级：

> 准备好了，开始闯关

### 4.3 第一次拖拽教学

进入编排页后，用局部 Tour 引导第一次拖拽：

1. 高亮本人卡牌；
2. 高亮适合本人的第一个任务位置；
3. 用短文案和动态虚线提示“把你的卡牌拖到这里”；
4. 玩家完成第一次拖入后，自动进入下一提示；
5. 高亮 Agent 卡牌和制作位置；
6. 玩家完成关键拖拽后，Tour 自动结束。

Tour 不覆盖整个页面，不要求连续点击“下一步”，也不重复解释已经通过动作学会的内容。玩家可以跳过 Tour。

### 4.4 编排与资源区

资源状态移出“我的步骤”区域，作为订单层级的独立信息区。

教学关卡显示：

| 资源 | 初始值 | 用途 |
|---|---:|---|
| 截止时间 | 教学关卡不限时 | 提示正式订单才使用现实世界时间 |
| 本人时间 | 2 小时 | 检查成果、反馈和写守则 |
| Agent 算力 | 24 点 | Agent 首次执行与返工 |
| 公司现金 | ¥200 | 购买并安装 Form 工具 |

资源区补充说明：

> 正式订单与现实世界时间同步。离开平台后，订单和 Agent 仍会继续推进。

教学关卡不显示倒计时，不因停留或离开导致失败。

### 4.5 首次执行

玩家确认阵列后，Agent 开始执行。

- 页面仍可表现 Agent 在玩家离开时继续工作；
- Agent 消耗一部分算力生成真实可见的成果；
- 第一次成果故意误解目标用户，例如把“面向新生”理解成“面向全校学生”；
- 错误应体现在海报标题、渠道或文案中，而不是仅由系统文字宣告；
- 页面不弹出“请选择 A/B/C”的判断题。

### 4.6 检查成果

玩家看到 Agent 的第一版成果，并通过对照订单要求发现偏差。

页面明确显示：

- 原始要求；
- Agent 实际产出；
- 不一致之处；
- 本次已消耗的算力；
- 若直接提交可能影响哪个下游步骤。

玩家执行一个真实操作：

> 给 Agent 反馈

反馈可以采用预填内容，玩家必须能够编辑后发送。第一版不需要自由对话系统。

### 4.7 调教 Agent

页面标题统一为：

> 调教 Agent

本页包含两个连续动作。

#### 动作一：安装 Form 工具

- 显示 Form 工具卡及用途；
- 价格为 ¥80；
- 玩家点击“购买并安装”；
- 公司现金从 ¥200 减少为 ¥120；
- 工具进入小角的工具列表；
- 购买前说明该工具能收集缺失信息，但不会自动知道何时使用。

#### 动作二：写入守则

- 玩家在文本框中亲自填写守则；
- 默认建议文本为“缺少必要信息时，先用 Form 向我确认”；
- 玩家可以编辑，不能只点击一条自动答案完成；
- 保存守则消耗本人时间；
- 守则进入小角的训练资产。

安装工具和写守则属于 Agent 调教过程。只有当新配置在后续执行中成功避免同类错误后，才标记为一次经过实践验证的卡牌成长。

### 4.8 Form 确认

玩家重新启动 Agent 后，小角根据新守则发现缺失信息，并调用刚安装的 Form。

Form 作为平台内真实工具界面呈现，至少询问：

- 本次推广的目标人群；
- 最希望用户采取的行动。

玩家提交后：

- 本人时间发生相应消耗；
- Agent 获得结构化信息；
- 页面显示守则和工具已经被实际触发；
- Agent 继续执行。

### 4.9 重新执行与步骤交付

第二版成果必须可见，并能与错误版本直接比较。

页面标题：

> 你的成果已交付

页面同时显示完整订单路线，例如：

```text
用户洞察 ✓
→ 视觉方案 ✓
→ 内容表达 进行中
→ 你的增长验证 ✓
→ 整合交付 等待中
```

提示：

> 你的步骤已经完成，但完整订单仍在进行。

首关可以用短暂模拟推进其他步骤，但不能让玩家误以为自己的提交等于整单交付。

### 4.10 完整订单结算

只有完整订单全部完成后，进入正式结算。

结算页展示：

- 完整订单最终交付物；
- 玩家负责的成果最终如何被使用；
- 客户或拆单方反馈；
- 本人时间、Agent 算力和现金的消耗；
- 本次形成的作品记录；
- 小角新增的 Form 工具；
- 小角新增并经过本次重试验证的守则；
- 本人和 Agent 各自的贡献。

本页不出现建立组织、邀请伙伴或保存真人卡牌的操作。

唯一主要出口：

> 领取第一份自由订单

次要出口：

> 重新体验教学

## 5. Agent 成长的概念边界

本关把 Agent 成长拆成三个可理解的动作：

```text
购买并安装工具
+ 写入工作守则
+ 在真实执行中验证
= 一次经过验证的 Agent 卡牌成长
```

- Form 工具是 Agent 可使用的能力组件；
- 守则是玩家投入时间形成的训练资产；
- 执行结果是该配置是否可靠的证据；
- Agent 成长属于人或公司的资产，不计入玩家个人能力；
- 玩家本人在检查、反馈和调教中形成的证据，可以进入个人经验与相关能力评价。

界面短标题使用“调教 Agent”，结算时再说明“小角获得了一项经过验证的新能力”，避免在流程中使用过长标题。

## 6. 时间规则

教学订单不限时，不展示运行中的截止倒计时。

页面在资源区或确认执行时说明：

> 正式订单与现实世界时间同步。离开平台后，订单和 Agent 仍会继续推进。

第一份自由订单才首次教授：

- 真实截止时间；
- 页面关闭后倒计时继续；
- Agent 离线执行；
- 截止临近提醒；
- 等待本人判断会占用真实时间。

这样首关先教“如何正确工作”，第二关再教“如何在期限内工作”。

## 7. 组织与拆单方教学的后续分支

当前第二幕从首个教学订单中移除。

用户后续的角色演进为：

```text
完成多个步骤
→ 看见同单协作者的真实表现
→ 保存可信协作者的卡牌
→ 获得成立组织的资质
→ 解锁组织教学关卡
→ 邀请真人并由对方接受
→ 给组织命名
→ 学习拆解完整订单
→ 把步骤分配给组织成员和 Agent
→ 组织承接完整订单
```

保存他人的卡牌只代表“把这个人加入可联系的能力网络”，不代表：

- 对方已经加入组织；
- 玩家可以直接调用对方；
- 玩家拥有对方或对方的 Agent；
- 对方已接受某次订单。

已获平台认证的孵化器、协会等组织，可以直接解锁“组织与拆单方教学关卡”；普通学生 / OPC 需先取得相应资质。

生命周期 roadmap 的后续修订：

- 阶段 1 删除主动邀请和组成新组织；
- 阶段 2 首次引入真实截止时间；
- 阶段 4 先定义保存可信伙伴卡牌；
- 在阶段 4 与阶段 5 之间增加“组织者 / 拆单方角色分支”；
- 单独设计组织与拆单方教学关卡，并由主 roadmap 引用。

## 8. v0.3.1：贯穿首单的连续新手引导

### 8.1 要解决的问题

当前教学只引导玩家完成两次拖拽，存在三个问题：

1. Tour 浮层可能遮挡玩家需要操作的卡牌；
2. 玩家在认识卡牌前就被要求拖拽，不知道“小角”是谁；
3. 拖完两张卡后引导结束，玩家仍不知道怎样完成后续首单。

v0.3.1 将教学改为从“认识卡牌”持续到“完成整单结算”的连续引导。引导只负责说明当前第一次遇到的新机制，不替玩家完成任务。

### 8.2 分层引导

采用两种互补的提示：

- **关键机制 Tour**：第一次认识卡牌、第一次拖拽、第一次调教 Agent，以及第一次区分“自己的步骤”和“完整订单”时出现；
- **当前目标条**：其余流程持续显示下一步行动，例如“检查小角的第一版成果”。

关键机制 Tour 可以暂停当前操作；当前目标条不遮挡页面，也不要求玩家点击“下一步”。玩家可以跳过单个 Tour，但当前目标条会保留，直到教学订单完成。

### 8.3 先认识本人和第一个 Agent

进入编排页时，首先展示“你当前拥有的角色卡牌”，同时完整显示两张卡：

| 卡牌 | 玩家需要理解的含义 |
|---|---|
| 你自己 | 使用本人时间，负责理解、判断、检查和最终责任 |
| 小角 | 玩家的第一个 Agent，执行速度快、消耗算力，但可能误解需求 |

此时不要求玩家拖拽。唯一操作为：

> 知道了，开始编排

点击后才进入拖拽教学。

### 8.4 不用阅读也能理解的拖拽示范

拖拽教学不得用浮层覆盖手牌或任务位置。

页面使用循环示意动画：

1. 从一张角色卡生成半透明副本；
2. 副本沿弧线移动到一个任务位置；
3. 目标位置同步呼吸高亮；
4. 副本淡出并重新播放。

玩家开始拖拽、点击卡牌或完成第一次安排后，示意动画立即停止。页面仍保留“也可以先点卡牌，再点任务位置”的无障碍备用操作。开启“减少动态效果”的系统设置时，不播放移动动画，只显示箭头和目标高亮。

### 8.5 自由编排与风险提醒

教学不规定本人和小角必须进入唯一正确的任务位置。玩家可以根据自己的判断安排卡牌；同一张角色卡可以承担多个连续任务位置。

系统根据分工显示即时风险，而不是直接阻止执行。例如：

- 让小角负责需求理解，但没有安排本人检查：提示可能产生需求误解；
- 全部工作都由本人完成：提示质量可控，但消耗较多本人时间；
- 小角负责制作、本人负责理解和检查：提示分工较稳妥。

明显不合理的编排仍允许执行。玩家可以根据提示修改，也可以坚持自己的安排；首次成果、资源消耗和结算评价会反映该选择。

为了保持首关聚焦，v0.3.1 不制作复杂的通关失败分支。不同编排共享“首次成果出现需求偏差”的教学主线，但反馈文案会说明该分工怎样增加或降低了风险。

### 8.6 引导贯穿首单

完成拖拽后，页面继续通过“当前目标条”和少量关键 Tour 引导：

```text
认识本人和小角
→ 编排角色卡牌
→ 查看分工风险并确认执行
→ 等待小角产出第一版
→ 检查需求偏差
→ 给小角反馈
→ 购买并安装 Form
→ 写下工作守则
→ 回答小角调用的 Form
→ 检查修正版
→ 交付自己的步骤
→ 等待完整订单完成
→ 查看结算与分工评价
```

每个页面只强调一个当前目标。完成操作后目标自动推进，不要求玩家额外确认“已完成”。

以下节点再次使用短 Tour：

1. **调教 Agent**：说明工具需要现金、守则需要本人时间；
2. **步骤交付**：说明自己的成果已交付，但整单尚未完成；
3. **订单结算**：说明本轮编排、资源和改进如何形成评价。

### 8.7 结算评价

结算新增三项可解释的评价：

| 评价 | 判断依据 |
|---|---|
| 分工 | 是否合理安排理解、执行、检查和最终责任 |
| 资源 | 本人时间、Agent 算力和公司现金的使用情况 |
| 改进 | 是否通过反馈、工具和守则解决真实问题 |

评价不使用单一“正确答案”。系统展示每项得分或等级，并用一句自然语言解释原因。玩家即使采用高风险分工也能完成教学，但会看到风险带来的返工和资源代价。

### 8.8 状态与恢复

浏览器存档增加：

- 是否已完成卡牌认识；
- 当前教学目标；
- 已跳过的 Tour；
- 玩家首次编排的风险与评价；
- 结算三项评价。

刷新页面后回到当前场景和当前目标，不重复已经完成的卡牌介绍。点击“重新体验教学”才清空这些状态。

### 8.9 验收标准

1. 卡牌介绍和拖拽提示不会遮挡本人或小角卡牌；
2. 玩家在第一次拖拽前能解释“你自己”和“小角”分别代表什么；
3. 不阅读说明文字，也能从动画看懂卡牌需要移动到任务位置；
4. 本人和小角可以被安排到不同任务位置，不存在唯一强制答案；
5. 高风险编排会得到即时提醒，但不会被禁止执行；
6. 每个后续场景都有明确的当前目标，直到完整订单结算；
7. 结算能解释玩家的分工、资源和改进评价；
8. 刷新后不会重复已完成的引导。

## 9. 状态与恢复

浏览器本地状态需要保存：

- 玩家昵称；
- 当前页面；
- 卡牌编排；
- 已消耗的本人时间、算力和现金；
- Agent 第一版成果；
- 玩家反馈；
- Form 是否已经购买和安装；
- 玩家写入的守则；
- Form 答案；
- Agent 第二版成果；
- 玩家步骤与完整订单的状态；
- 是否已完成结算。

刷新页面后恢复到当前阶段。教学关卡不限时，因此恢复时不因经过的现实时间扣减截止时间。

重置教学必须清除上述本关状态，并回到昵称输入页。

## 10. 验收标准

### 10.1 首次理解

- 新玩家知道“小满”只是示例，并使用自己输入的昵称；
- 背景页只有一个醒目的居中主按钮；
- 玩家无需他人说明即可完成第一次拖拽；
- 资源区不再被误解为某个任务位置的属性；
- 所有资源都有单位或清晰状态。

### 10.2 核心机制

- 玩家能看到 Agent 错误成果，而不是回答抽象选择题；
- 第一次错误真实消耗算力；
- 玩家能够编辑并发送反馈；
- 玩家亲自花 ¥80 安装 Form；
- 玩家亲自填写或修改守则；
- 购买工具后现金正确减少；
- 写守则后本人时间正确减少；
- Agent 第二次执行时真实调用 Form；
- 第二版成果能明显看出已修正目标人群。

### 10.3 结算边界

- 玩家步骤完成时，完整订单路线仍显示未完成步骤；
- 只有完整订单完成后才出现正式结算；
- 结算能区分本人贡献和 Agent 资产；
- 首关中不出现组织建立、伙伴邀请和拆单教学；
- 结束页只有“领取第一份自由订单”一个主要出口。

### 10.4 技术与回归

- 刷新后能恢复昵称、资源、调教和执行进度；
- 重置后能够重新开始；
- 所有按钮都有实际效果；
- 鼠标拖放与点击选择均可完成编排；
- 提取脚本后通过 `node --check`；
- 静态契约测试覆盖新文案、资源和场景；
- 浏览器测试覆盖从昵称输入到完整订单结算；
- 常用桌面尺寸无横向滚动；
- 不修改旧 `MFU-v0.14-可试玩原型.html`。
