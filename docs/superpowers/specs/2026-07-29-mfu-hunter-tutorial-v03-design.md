# MFU 首个猎人教学订单 v0.3 设计

> 日期：2026-07-29
>
> 状态：设计已在讨论中确认，待 ruihua 审阅本文
>
> 目标原型：`mfu-demo/MFU-协作阵列-v0.1-可玩原型.html`

## 1. 目标

把当前协作阵列原型收窄成学生 / OPC 首次进入平台时的“猎人教学关卡”。

首关只让玩家理解三件事：

1. 面对分配给自己的步骤，怎样编排本人和 Agent；
2. Agent 会真实执行并产生可能出错的成果，人需要检查和负责；
3. 玩家可以花费时间、算力和现金调教 Agent，使同类工作变得更可靠。

首关不再同时教授主动连接、成立组织和拆解完整订单。这些内容属于取得组织资格后解锁的独立教学关卡。

## 2. 采用的方案

采用“聚焦式教学关卡”：

```text
输入昵称
→ 了解订单背景
→ 学会拖拽
→ 编排本人和 Agent
→ Agent 产生错误成果
→ 玩家发现需求偏差
→ 调教 Agent
→ 安装 Form 并写守则
→ Agent 用 Form 确认
→ 重新执行并完成步骤
→ 等待完整订单完成
→ 统一结算
→ 领取自由订单
```

不采用以下方案：

- 不在首关结算后增加可选的组织支线；
- 不保留当前“第二幕：用连接组成一个新组织”；
- 不用明确选择题代替真实成果检查；
- 不在教学关卡制造截止倒计时压力。

## 3. 关卡边界

### 3.1 首关负责教授

- 玩家是完整订单中的一名猎人；
- 玩家只负责其中一个步骤，但能看到完整订单路线；
- 玩家可以把本人和 Agent 安排到任务位置；
- Agent 执行会消耗算力；
- 人检查成果、提供反馈并承担最终责任；
- 安装工具需要现金；
- 写守则需要本人时间；
- 调教后的 Agent 可以在同一订单中重新执行；
- 玩家步骤交付不等于完整订单已经交付；
- 正式结算发生在完整订单完成之后。

### 3.2 首关不负责教授

- 保存其他真人的卡牌；
- 邀请真人建立长期合作；
- 给组织命名；
- 取得成立组织的资质；
- 拆解完整订单；
- 把步骤分配给组织成员；
- 联合竞标、公开评审、认证或孵化；
- 真实订单的截止倒计时。

## 4. 页面与交互流程

### 4.1 输入昵称

首次进入时先让玩家输入自己的昵称。

- 输入框示例可以使用“小满”，但不再默认假设玩家就是小满；
- 昵称保存在浏览器本地状态；
- 后续页面使用“你 · 昵称”“昵称的步骤”“昵称待确认”等表达；
- 已有存档的玩家不重复询问，重置教学后重新输入。

唯一主要按钮：

> 进入教学订单

### 4.2 订单背景

背景页继续讲述社区旧书店的开学推广需求，只回答：

- 谁需要帮助；
- 发生了什么；
- 完整订单要交付什么；
- 玩家负责哪个步骤。

页面可以显示只读的完整订单路线。玩家节点使用其昵称高亮。

唯一主要按钮居中并增强视觉层级：

> 准备好了，开始闯关

### 4.3 第一次拖拽教学

进入编排页后，用局部 Tour 引导第一次拖拽：

1. 高亮本人卡牌；
2. 高亮适合本人的第一个任务位置；
3. 用短文案和动态虚线提示“把你的卡牌拖到这里”；
4. 玩家完成第一次拖入后，自动进入下一提示；
5. 高亮 Agent 卡牌和制作位置；
6. 玩家完成关键拖拽后，Tour 自动结束。

Tour 不覆盖整个页面，不要求连续点击“下一步”，也不重复解释已经通过动作学会的内容。玩家可以跳过 Tour。

### 4.4 编排与资源区

资源状态移出“我的步骤”区域，作为订单层级的独立信息区。

教学关卡显示：

| 资源 | 初始值 | 用途 |
|---|---:|---|
| 截止时间 | 教学关卡不限时 | 提示正式订单才使用现实世界时间 |
| 本人时间 | 2 小时 | 检查成果、反馈和写守则 |
| Agent 算力 | 24 点 | Agent 首次执行与返工 |
| 公司现金 | ¥200 | 购买并安装 Form 工具 |

资源区补充说明：

> 正式订单与现实世界时间同步。离开平台后，订单和 Agent 仍会继续推进。

教学关卡不显示倒计时，不因停留或离开导致失败。

### 4.5 首次执行

玩家确认阵列后，Agent 开始执行。

- 页面仍可表现 Agent 在玩家离开时继续工作；
- Agent 消耗一部分算力生成真实可见的成果；
- 第一次成果故意误解目标用户，例如把“面向新生”理解成“面向全校学生”；
- 错误应体现在海报标题、渠道或文案中，而不是仅由系统文字宣告；
- 页面不弹出“请选择 A/B/C”的判断题。

### 4.6 检查成果

玩家看到 Agent 的第一版成果，并通过对照订单要求发现偏差。

页面明确显示：

- 原始要求；
- Agent 实际产出；
- 不一致之处；
- 本次已消耗的算力；
- 若直接提交可能影响哪个下游步骤。

玩家执行一个真实操作：

> 给 Agent 反馈

反馈可以采用预填内容，玩家必须能够编辑后发送。第一版不需要自由对话系统。

### 4.7 调教 Agent

页面标题统一为：

> 调教 Agent

本页包含两个连续动作。

#### 动作一：安装 Form 工具

- 显示 Form 工具卡及用途；
- 价格为 ¥80；
- 玩家点击“购买并安装”；
- 公司现金从 ¥200 减少为 ¥120；
- 工具进入小角的工具列表；
- 购买前说明该工具能收集缺失信息，但不会自动知道何时使用。

#### 动作二：写入守则

- 玩家在文本框中亲自填写守则；
- 默认建议文本为“缺少必要信息时，先用 Form 向我确认”；
- 玩家可以编辑，不能只点击一条自动答案完成；
- 保存守则消耗本人时间；
- 守则进入小角的训练资产。

安装工具和写守则属于 Agent 调教过程。只有当新配置在后续执行中成功避免同类错误后，才标记为一次经过实践验证的卡牌成长。

### 4.8 Form 确认

玩家重新启动 Agent 后，小角根据新守则发现缺失信息，并调用刚安装的 Form。

Form 作为平台内真实工具界面呈现，至少询问：

- 本次推广的目标人群；
- 最希望用户采取的行动。

玩家提交后：

- 本人时间发生相应消耗；
- Agent 获得结构化信息；
- 页面显示守则和工具已经被实际触发；
- Agent 继续执行。

### 4.9 重新执行与步骤交付

第二版成果必须可见，并能与错误版本直接比较。

页面标题：

> 你的成果已交付

页面同时显示完整订单路线，例如：

```text
用户洞察 ✓
→ 视觉方案 ✓
→ 内容表达 进行中
→ 你的增长验证 ✓
→ 整合交付 等待中
```

提示：

> 你的步骤已经完成，但完整订单仍在进行。

首关可以用短暂模拟推进其他步骤，但不能让玩家误以为自己的提交等于整单交付。

### 4.10 完整订单结算

只有完整订单全部完成后，进入正式结算。

结算页展示：

- 完整订单最终交付物；
- 玩家负责的成果最终如何被使用；
- 客户或拆单方反馈；
- 本人时间、Agent 算力和现金的消耗；
- 本次形成的作品记录；
- 小角新增的 Form 工具；
- 小角新增并经过本次重试验证的守则；
- 本人和 Agent 各自的贡献。

本页不出现建立组织、邀请伙伴或保存真人卡牌的操作。

唯一主要出口：

> 领取第一份自由订单

次要出口：

> 重新体验教学

## 5. Agent 成长的概念边界

本关把 Agent 成长拆成三个可理解的动作：

```text
购买并安装工具
+ 写入工作守则
+ 在真实执行中验证
= 一次经过验证的 Agent 卡牌成长
```

- Form 工具是 Agent 可使用的能力组件；
- 守则是玩家投入时间形成的训练资产；
- 执行结果是该配置是否可靠的证据；
- Agent 成长属于人或公司的资产，不计入玩家个人能力；
- 玩家本人在检查、反馈和调教中形成的证据，可以进入个人经验与相关能力评价。

界面短标题使用“调教 Agent”，结算时再说明“小角获得了一项经过验证的新能力”，避免在流程中使用过长标题。

## 6. 时间规则

教学订单不限时，不展示运行中的截止倒计时。

页面在资源区或确认执行时说明：

> 正式订单与现实世界时间同步。离开平台后，订单和 Agent 仍会继续推进。

第一份自由订单才首次教授：

- 真实截止时间；
- 页面关闭后倒计时继续；
- Agent 离线执行；
- 截止临近提醒；
- 等待本人判断会占用真实时间。

这样首关先教“如何正确工作”，第二关再教“如何在期限内工作”。

## 7. 组织与拆单方教学的后续分支

当前第二幕从首个教学订单中移除。

用户后续的角色演进为：

```text
完成多个步骤
→ 看见同单协作者的真实表现
→ 保存可信协作者的卡牌
→ 获得成立组织的资质
→ 解锁组织教学关卡
→ 邀请真人并由对方接受
→ 给组织命名
→ 学习拆解完整订单
→ 把步骤分配给组织成员和 Agent
→ 组织承接完整订单
```

保存他人的卡牌只代表“把这个人加入可联系的能力网络”，不代表：

- 对方已经加入组织；
- 玩家可以直接调用对方；
- 玩家拥有对方或对方的 Agent；
- 对方已接受某次订单。

已获平台认证的孵化器、协会等组织，可以直接解锁“组织与拆单方教学关卡”；普通学生 / OPC 需先取得相应资质。

生命周期 roadmap 的后续修订：

- 阶段 1 删除主动邀请和组成新组织；
- 阶段 2 首次引入真实截止时间；
- 阶段 4 先定义保存可信伙伴卡牌；
- 在阶段 4 与阶段 5 之间增加“组织者 / 拆单方角色分支”；
- 单独设计组织与拆单方教学关卡，并由主 roadmap 引用。

## 8. 状态与恢复

浏览器本地状态需要保存：

- 玩家昵称；
- 当前页面；
- 卡牌编排；
- 已消耗的本人时间、算力和现金；
- Agent 第一版成果；
- 玩家反馈；
- Form 是否已经购买和安装；
- 玩家写入的守则；
- Form 答案；
- Agent 第二版成果；
- 玩家步骤与完整订单的状态；
- 是否已完成结算。

刷新页面后恢复到当前阶段。教学关卡不限时，因此恢复时不因经过的现实时间扣减截止时间。

重置教学必须清除上述本关状态，并回到昵称输入页。

## 9. 验收标准

### 9.1 首次理解

- 新玩家知道“小满”只是示例，并使用自己输入的昵称；
- 背景页只有一个醒目的居中主按钮；
- 玩家无需他人说明即可完成第一次拖拽；
- 资源区不再被误解为某个任务位置的属性；
- 所有资源都有单位或清晰状态。

### 9.2 核心机制

- 玩家能看到 Agent 错误成果，而不是回答抽象选择题；
- 第一次错误真实消耗算力；
- 玩家能够编辑并发送反馈；
- 玩家亲自花 ¥80 安装 Form；
- 玩家亲自填写或修改守则；
- 购买工具后现金正确减少；
- 写守则后本人时间正确减少；
- Agent 第二次执行时真实调用 Form；
- 第二版成果能明显看出已修正目标人群。

### 9.3 结算边界

- 玩家步骤完成时，完整订单路线仍显示未完成步骤；
- 只有完整订单完成后才出现正式结算；
- 结算能区分本人贡献和 Agent 资产；
- 首关中不出现组织建立、伙伴邀请和拆单教学；
- 结束页只有“领取第一份自由订单”一个主要出口。

### 9.4 技术与回归

- 刷新后能恢复昵称、资源、调教和执行进度；
- 重置后能够重新开始；
- 所有按钮都有实际效果；
- 鼠标拖放与点击选择均可完成编排；
- 提取脚本后通过 `node --check`；
- 静态契约测试覆盖新文案、资源和场景；
- 浏览器测试覆盖从昵称输入到完整订单结算；
- 常用桌面尺寸无横向滚动；
- 不修改旧 `MFU-v0.14-可试玩原型.html`。

设计通过后，按以下顺序推进：

1. 修改 [`mfu-demo/doc/core-gameplay-card-array.md`](../../../mfu-demo/doc/core-gameplay-card-array.md)，将当前 v0.2 教学设计演进为 v0.3；
2. 修改 [`mfu-demo/doc/student-opc-lifecycle-roadmap.md`](../../../mfu-demo/doc/student-opc-lifecycle-roadmap.md)，更新阶段 1、阶段 2 和组织者分支；
3. 新建详细实施计划；
4. 修改 `mfu-demo/MFU-协作阵列-v0.1-可玩原型.html`；
5. 同步静态测试和浏览器流程测试；
6. 完成试玩验证后，再决定第一份自由订单的设计。

本轮不实现独立的组织 / 拆单方教学关卡，只在 roadmap 中记录它的角色、解锁条件和依赖关系。
