## 1. 评价的三条判据（从真相源读，全部可自动判）

PR 节点 = `stage: :pr`，artifact 里挂了 `%{tool: "github", kind: "pr", ref: "#123", url:..., content: <changed_files JSON>}`。
评价 = 沿 **祖先链**（`parent_id` 往上）回溯，逐棒查 §2.1 表里 6→9 的可自动判据：

| 判据 | 怎么从 mindmap 读 | pass 条件 |
|---|---|---|
| **C1 上游 done** | 祖先链上每个 `stage ∈ {:feature,:issue,:test}` 的节点，查 `node.status` | 全部 `== :done` |
| **C2 PR 在 spec scope 内** | 找最近的 `:feature` 祖先 → 它的 `:spec_card` artifact → parse `content` 取 `scope:` glob 列表；PR artifact `content` 取 `changed_files` 列表 | `changed_files ⊆ scope`（每个文件至少匹配一条 glob） |
| **C3 Gherkin 被测试覆盖** | `:feature` 祖先 spec_card `content` 的 Gherkin 块（`Given/When/Then` 计数）；`:test` 祖先 `:test_suite` artifact `content` 的覆盖映射（引用了几条 Gherkin） | test 覆盖的 Gherkin 条数 ≥ spec 卡 Gherkin 条数（≥1 且无缺口） |

> 三条都只 **读** `node.status` / `artifact.content`——数据全在 KindSnapshot 真相源，无外部 IO。
> C1 复用现成 `ancestors/2`（`behavior/mindmap.ex:537`）；scope/Gherkin 都从 inline `content` parse，不碰飞书/外部 ref（content 已有 8KB 上限 `mindmap.ex:503`）。

## 2. scope / Gherkin 怎么声明（inline content 约定）

不新增节点字段、不新增 artifact 字段——复用已落地的 `artifact.content`（`mindmap.ex:511` `normalize_artifact` 已带 `content`，`cap_content/1` 截 8KB）。约定 content 是一段**带 frontmatter 风格小标记**的纯文本，纯函数 parse：

**spec_card artifact（feature 节点，`kind: "spec_card"`）content 形如：**
```
scope: apps/ezagent_plugin_mindmap/**, apps/ezagent_plugin_github/**

## Gherkin
Given 用户在 PR 节点
When CI 轮询到该 PR
Then 评价报告 post 成评论
---
Given changed_files 超出 spec scope
Then 报告标 out_of_scope
```
- `scope:` 行 = 逗号分隔的 glob 列表（`Path.wildcard` 不用——用纯字符串 glob 匹配，见 §4 `glob_match?/2`）。
- Gherkin 块 = 数 `Given`/`When`/`Then` 三元组的条数（一条 = 至少一个 Given+一个 Then）。

**PR artifact（pr 节点，`kind: "pr"`）content 形如：**
```
changed_files:
apps/ezagent_plugin_github/lib/github_sync.ex
apps/ezagent_plugin_mindmap/lib/ezagent/world/mindmap_ci.ex
```
- `changed_files:` 后每行一个文件路径。GithubSync 轮询 `GET /pulls/{n}/files` 拿到后写进 content（出站轮询填回，仍走 `attach_artifact` dispatch，P14）。

> 为什么 inline 不外链：scope/Gherkin 是 CI 判据的**真相**，必须随节点快照走（冷启动 rehydrate 后仍可判），不能依赖飞书 docToken（死链/权限墙）。任务已锁"CI 内容 inline 存 ezagent"。

## 3. 评价结果形态：一份结构化报告（评分 + markdown 评语）

`check_pr_gate/2` 返回纯 map（JSON-safe），既能给前端 NodePanel 当软提示徽章，又能给 GithubSync 渲成 PR 评论：

```elixir
%{
  passed: false,                       # 三条全 pass 才 true（仅作徽章颜色，不拦任何东西）
  score: 2,                            # 0..3，pass 的判据条数
  checks: [
    %{id: :upstream_done, ok: true,  detail: "feature/issue/test 均 done"},
    %{id: :in_scope,      ok: false, detail: "2 个文件超出 spec scope: [\"lib/foo.ex\", ...]"},
    %{id: :gherkin_covered, ok: true, detail: "3/3 条 Gherkin 被测试覆盖"}
  ],
  markdown: "### CI 评价（软提示，不拦合并）\n- ✅ 上游 done\n- ⚠️ 超范围：...\n- ✅ Gherkin 覆盖 3/3\n"
}
```
- **软提示落地**：GithubSync 用 `markdown` 字段 `POST /issues/{n}/comments`；commit status 永远用 `state: "success"`（或干脆不发 status），靠评语传达——never `failure`。
- **score** 给前端节点徽章用（绿 3/3、黄 1-2、灰 0）。

## 4. 这逻辑放哪：新建纯函数模块 `Ezagent.World.MindmapCi`

**不放 Behavior**（避免给 mindmap.ex 加只读动作膨胀 LOC + Behavior 应是写动作处理者）；**不放 GithubSync**（领域判据不该埋在 github 插件里，github-outbound spec §2.3 也说"判据是 ezagent 领域逻辑、放插件会散"）。

### 4.1 模块骨架

```elixir
defmodule Ezagent.World.MindmapCi do
  @moduledoc "PR 节点 CI gate 的纯函数评价（软提示）。读真相源树，算三条判据，出报告。无副作用、无 IO。"

  @auto_stages [:feature, :issue, :test]   # 可自动判 done 的上游棒

  # 入口：给一棵已读出的树（nodes map）+ pr 节点 id，算报告。
  # tree 由 caller（GithubSync 或 NodePanel）经 MindmapData.read_tree 拿到，本函数不 dispatch。
  @spec check_pr_gate(%{nodes: map()}, String.t()) :: map()
  def check_pr_gate(%{nodes: nodes}, pr_id) do
    case nodes[pr_id] do
      nil -> %{passed: false, score: 0, checks: [], markdown: "节点不存在"}
      pr_node ->
        chain = ancestor_chain(nodes, pr_id)        # [pr_node | 祖先...]
        c1 = check_upstream_done(nodes, chain)
        c2 = check_in_scope(nodes, chain, pr_node)
        c3 = check_gherkin_covered(nodes, chain)
        compose([c1, c2, c3])
    end
  end

  # --- C1 上游 done ---
  defp check_upstream_done(_nodes, chain) do
    pending = Enum.filter(chain, fn n -> n.stage in @auto_stages and n.status != :done end)
    %{id: :upstream_done, ok: pending == [],
      detail: if(pending == [], do: "上游 feature/issue/test 均 done", else: "未 done: #{...}")}
  end

  # --- C2 scope 子集判 ---
  defp check_in_scope(nodes, chain, pr_node) do
    scope = chain |> nearest(:feature) |> spec_card_content(nodes) |> parse_scope()   # [glob]
    changed = pr_node |> pr_content() |> parse_changed_files()                        # [path]
    out = Enum.reject(changed, fn f -> Enum.any?(scope, &glob_match?(&1, f)) end)
    %{id: :in_scope, ok: scope != [] and out == [], detail: ...}
  end

  # --- C3 Gherkin 覆盖 ---
  defp check_gherkin_covered(nodes, chain) do
    want = chain |> nearest(:feature) |> spec_card_content(nodes) |> count_gherkin()
    got  = chain |> nearest(:test) |> test_suite_content(nodes) |> count_covered_gherkin()
    %{id: :gherkin_covered, ok: want > 0 and got >= want, detail: "#{got}/#{want}"}
  end

  # --- 纯 helper（无 IO）---
  # ancestor_chain/2  复用 mindmap behavior 的 ancestors 思路（这里自带一份，因 behavior 不暴露）
  # nearest(chain, stage) 沿链找最近的某 stage 节点
  # spec_card_content/test_suite_content/pr_content 按 artifact.kind 取 content（白名单 kind）
  # parse_scope / parse_changed_files / count_gherkin / count_covered_gherkin 纯文本 parse
  # glob_match?(glob, path)  支持 ** 和 * 的纯字符串匹配（不碰文件系统）
  # compose/1  汇总 score=Enum.count(ok)、passed=all ok、markdown=渲染
end
```

## 6. 单元测试点（`test/.../mindmap_ci_test.exs`）

纯函数，构造 tree map 直接测，无需起 Kind：

- **C1 上游 done**
  - 祖先链 feature/issue/test 全 `:done` → `upstream_done.ok=true`
  - issue 节点 `:doing` → `ok=false`，detail 列出未 done 节点
  - 链上有非 auto_stage 节点（如 ux）`:claimed` → 不影响 C1（只看 feature/issue/test）
- **C2 scope 子集**
  - changed_files 全在 spec scope glob 内 → `in_scope.ok=true`
  - 1 个文件超出 → `ok=false`，detail 列出超范围文件
  - spec_card 无 scope 行（空 scope）→ `ok=false`（不能默认全过）
  - glob `apps/foo/**` 匹配 `apps/foo/a/b.ex`；`*.ex` 匹配 `x.ex` 不匹配 `x.exs`
- **C3 Gherkin 覆盖**
  - spec 卡 3 条 Gherkin、test 覆盖 3 条 → `ok=true`，detail `3/3`
  - 覆盖 2 条 → `ok=false` `2/3`
  - spec 卡 0 条 Gherkin → `ok=false`（want=0，没写验收不算过）
- **报告组合**
  - 三条全 ok → `passed=true score=3`
  - 两条 ok → `passed=false score=2`，markdown 含 ⚠️ 行
  - pr_id 不存在 → `passed=false score=0` 不崩
- **纯净性**：同一 tree 调两次结果相等（无副作用）；不触发任何 dispatch/IO（用 `:meck` 断言无 Invocation 调用，或纯函数天然保证）
- **回溯正确性**：pr 节点的祖先链跨越多 stage（pr←test←issue←feature←...）时 `nearest(:feature)` 取到正确的 feature 祖先（非别的子树的 feature）

## 8. 对抗审查（2026-06-23，对照真实代码逐条核）

实证基线核对：`@artifact_content_limit 8_192`（`behavior/mindmap.ex:503`）、`normalize_artifact`+`cap_content`（`:505/:511/:515`）、`ancestors/2` 是 **defp**（`:537`）、9 阶段链 `@stages`（`:32`）、节点 shape `new_node/4`（`:428`，键为 atom，stage/status 为 atom）——spec 引用全部准确。下面是**必改**：

### M1（阻断）— `check_pr_gate` 的 tree 形态与 `read_tree` 产物不匹配
`MindmapData.read_tree/2`（`mindmap_data.ex:114-132`）返回的是 **string-key、JSON-safe** 树：`%{"nodes" => %{id => %{"stage" => "pr", "status" => "done", "artifacts" => [%{"content"=>...}]}}}`（`jsonable_node/1` `:149-160`，`to_str` 把 atom 转 string）。但 §4.1 `check_pr_gate(%{nodes: nodes}, ...)` 解构的是 atom key `:nodes`，且 `n.stage in @auto_stages` 拿 `"feature"` 字符串跟 `:feature` atom 比——**恒不相等，C1/C2/C3 全静默判 false**。而原始 dispatch 结果 `{:ok, %{tree: %{nodes: nodes}}}`（`:126`）才是 atom-key/atom-value。**必须二选一并写死**：要么 caller 传**原始 atom-key tree**（不经 read_tree 的 jsonable 化，自己 dispatch `:get_tree` 拿 `%{nodes: ...}`），要么 `check_pr_gate` 接受 string-key 并把 `@auto_stages` 写成 `~w(feature issue test)` 字符串集。§4.1/§4.2 现在两处口径含糊（§4.1 注释说"经 MindmapData.read_tree 拿"=string-key，§4.2 步骤3 也说 read_tree），按现样写出来就是 silent-false 的 dead gate——违反 CLAUDE.md「不要 silent 失败」。

### M2（阻断）— doc.scan ratchet 会卡新 public def
`mix ezagent.doc.scan` 是 **green-at-baseline ratchet**（`ezagent.doc.scan.ex:12-35`）：任何**新增 public def 无 `@doc`/`@doc false`** 都顶高 `undocumented_public_defs` 计数 → CI 红。`check_pr_gate/2` 只写了 `@spec`，**没 `@doc`**。`@moduledoc` 有（`:97`）但 module doc 不豁免 def。**必改**：给 `check_pr_gate/2` 加 `@doc`（其余是 defp，不计）。否则过不了 gate。（arch.scan 的 oversized 是 per-module 锚定 manifest，~150 LOC 新模块不触发；uri_query.scan 本模块不构造/不字符串化 URI，无暴露面——这两条 OK。）

### M3（阻断/决策）— D-CI-1 必须开工前定，且证据偏向"下沉 mindmap"
`apps/ezagent_plugin_github` **当前不存在**（`ls apps/` 无）；`ezagent_plugin_world/mix.exs:31-42` 的 deps **不含 ezagent_plugin_mindmap**——world 现在是靠 umbrella 全编译"runtime 调 `EzagentPluginMindmap.*`"（`mindmap_data.ex:37/101`）这种软耦合在跑，没有 compile-time 依赖边。若 `MindmapCi` 留 world，未来 GithubSync 要么 github→world（领域读模型反被出站插件依赖，方向脏），要么继续软耦合（无 dep 边、靠全编译，脆）。**建议采纳 D-CI-1 的"下沉到 `EzagentPluginMindmap.Ci`"**：world 和未来 github 都已指向 mindmap 模块，方向干净。spec 正文 §4/§5 仍写 world，**自相矛盾**——开工前必须落定，否则文件清单（§5 路径）是错的。

### 其余风险（非阻断，需在 spec 写明约定否则后续返工）
- **R1/CapBAC 不被破坏 ✓**：本片是**纯只读函数**，不加 Behavior 动作、不 dispatch、不开 inbound、不碰 `set_stage`/`move` 的 R1 单调校验（`behavior/mindmap.ex:235-303`）、不绕 per-node CapBAC（读仍走 `get_tree` 带登录者身份，`mindmap_data.ex` moduledoc）。守"单一真相源 ✓"：scope/Gherkin/changed_files 全 inline 进 `artifact.content` 真相源，不在外部建真相，对齐 8KB cap。决策一致性 ✓：gate 软（D2 全软提示）、GitHub 纯出站、CI inline——与 github-outbound spec 不冲突。
- **快照膨胀**：三类 content（scope+Gherkin、test 覆盖映射、changed_files）都吃同一个 **8KB/artifact** 上限（`:503`）。大 PR 的 `changed_files` 列表（几百文件）会被 `String.slice` **静默截断**（`cap_content/1` `:515` 直接切，不报错），导致 C2 把"被截掉的文件"误判 out-of-scope 或漏判。**必在 spec 写明**：changed_files 超 8KB 时的退化语义（建议：截断即 C2 标 `:truncated` 而非 false，或 GithubSync 端只回填"超范围文件"而非全量）。
- **祖先链多 feature/test 祖先的 `nearest`**：链上理论可有多个同 stage 祖先（R1 只保证 stage 单调不回退，**不保证 stage 唯一**——`stage_fits?` 允许父子同 stage `:293-303`）。`nearest(:feature)` 取"最近一个"是否就是该 PR 的 spec 卡所属 feature，需在 §4.1 写死定义（最近 = 沿 parent 链第一个命中），并加 §6 已列的"跨多 stage"测试。当前 §6 有这条测试点 ✓，但 §4.1 注释没定义 "nearest" 语义，补上。
- **D-CI-2/D-CI-3 格式未定 = parser 无法实现**：§2 的 `scope:` 行 / `## Gherkin` 块 / test_suite `covers:` 行全是"待对齐"自定约定，产品文档没给。`count_gherkin`/`count_covered_gherkin`/`parse_scope` 三个 helper 的正确性**完全依赖**这套格式锁定。开工前必须把 D-CI-2/D-CI-3 从"待定"升级为"已定约定"，否则 §6 单测构造的 fixture 是凭空假设、测了个寂寞。
- **两 BEAM / formatter 坑 ✗ 不适用**：纯函数、无跨节点、无 erlexec、无外部进程；mix format 对纯 `.ex` 无特殊坑。这条无需担心。

> **结论**：方案**架构上可行且干净**（纯只读、不破 R1/CapBAC、守真相源、不与已定决策冲突）。但**当前 spec 直接照抄会写出过不了 gate、且 gate 恒静默 false 的死代码**。必改优先级：**M1（tree 形态 string/atom 对齐，否则判据全 false）> M2（`check_pr_gate/2` 补 `@doc` 过 doc.scan）> M3（D-CI-1 模块归属定死，正文 §4/§5 当前自相矛盾）**。次级：8KB 截断退化语义 + D-CI-2/3 格式锁定，否则 §6 测试与 parser 实现无依据。
