# MFU 世界市场与节点级外包设计

## 目标

在现有 MVO 组织牧场 Demo 中区分“世界上等待承接的订单”和“玩家已经承接、等待内部组织执行的订单”，同时让 MVO 能以组织图节点为单位把工作重新发布到市场。

首版必须让玩家直观理解以下闭环：

```text
世界订单
  → 玩家承接
  → 进入我的工作台
  → 分配给 MVO
  → MVO 节点运行
  → 必要时把节点发布为新订单
  → 外部玩家承接
  → 结果返回原 MVO
  → MVO 继续执行
```

## 一级页面

顶部状态栏下方增加两个一级 Tab：

- `我的工作台`
- `世界`

使用“我的工作台”而不是“我的孵化器”，因为相同页面架构未来需要适配学校、孵化器、企业和其他玩家。不同玩家拥有的任务和资源不同，但使用同一套核心玩法。

### 我的工作台

保留现有四区布局：

- 左侧 `订单板`：玩家已经承接的订单；
- 中央 `孵化中的组织`：玩家拥有的 MVO 及其运行状态；
- 右侧 `待处理`：需要玩家决定的事项；
- 底部 `资源栏`：人才、Agent、工具/IP、算力和资金。

### 世界

首版包含三个区域：

- `订单市场`：尚未被当前玩家承接的外部订单；
- `世界动态`：其他组织完成订单、升级和发布成果的消息；
- `新闻与公告`：平台活动、竞赛和系统通知。

世界页用于建立多人平台的存在感，不承担当前玩家内部经营管理。

## 三类订单状态

### 市场订单

市场订单仍在世界中等待玩家承接，不属于当前玩家，不出现在“我的工作台”的订单板。

首版点击“承接订单”后：

1. 市场订单从当前世界列表移除；
2. 生成一张当前玩家持有的订单；
3. 新订单进入订单板的`待分配`；
4. 玩家可以把它交给空闲 MVO，或为它创建新 MVO。

首版省略报价、竞标、合同确认和客户反悔。

### 工作台订单

工作台订单是当前玩家已经承接的订单，沿用现有生命周期：

```text
待确认 → 待分配 → 进行中 → 待结算 → 已完成
```

首版从世界承接的订单直接进入`待分配`。

### 节点外包订单

节点外包订单由一个运行中的 MVO 发起。它是原订单的一部分，同时也是一张可以被其他玩家承接的新市场订单。

节点外包订单必须保存：

- 来源 MVO；
- 来源订单；
- 来源节点；
- 节点所需输入；
- 预期输出；
- 预算；
- 截止时间；
- 当前承接状态。

## 进行中的项目

删除当前“一键支付 ¥400 并增加 10% 进度”的`外包子任务`按钮及对应行为。

“进行中的项目”改为展示当前 MVO 的组织图。组织图中的每个节点显示一种状态：

- `已完成`
- `正在运行`
- `未开始`
- `等待外部承接`

首版节点按组织图定义的任务流依次推进。完成的节点保留结果摘要，正在运行的节点突出显示，未开始节点弱化显示。

### 节点操作

点击节点可以查看：

- 节点任务；
- 输入来源；
- 预期输出；
- 当前使用的人才、Agent、工具和算力；
- 当前状态。

对`正在运行`或`未开始`且允许外包的节点，提供`发布为订单`操作。

发布流程：

1. 系统带入节点名称、预期输出和原订单截止时间；
2. 玩家确认预算与截止时间；
3. 订单进入世界市场；
4. 原节点变为`等待外部承接`；
5. 外部玩家承接后，节点显示外部协作者；
6. 外部结果返回后节点完成，原 MVO 继续后续任务流。

## 首版模拟方式

Demo 仍是单机 HTML，不模拟真实在线用户。

为了演示完整闭环：

- 世界市场提供固定的示例订单；
- 玩家承接后，订单真实进入自己的订单板；
- 玩家发布的节点订单真实进入世界市场；
- 节点订单提供`模拟外部玩家承接`；
- 模拟承接后，在推进一天时返回结果并完成该节点；
- 世界动态同步记录承接、完成和组织升级事件。

这里的模拟按钮代表未来真实市场中的其他玩家行为，不代表正式产品会由订单发布者替对方承接。

## 状态与数据

在现有共享 `state` 中增加：

- `activeMainTab`：`workspace` 或 `world`；
- `marketOrders`：世界市场订单；
- `worldFeed`：世界动态、新闻和公告；
- 每个 MVO 的 `nodeStates`；
- 节点订单的 `sourceOrderId`、`sourceOrgId` 和 `sourceNodeId`。

同一张订单只能属于一个层级：

- 未承接时存在于 `marketOrders`；
- 承接后存在于当前玩家的 `tasks`；
- 节点外包订单存在于 `marketOrders`，但通过来源字段回连原 MVO 节点。

## 交互反馈

- 承接世界订单后，页面提示“订单已进入我的工作台”，并提供跳转；
- 发布节点订单后，原节点立即显示“等待外部承接”；
- 外部玩家承接后，世界动态出现对应消息；
- 外部结果返回后，原 MVO 节点显示“已完成”，后续节点开始运行；
- 不允许重复承接、重复发布或对已完成节点发起外包。

## 首版不做

- 真实多人同步；
- 报价、竞标与合同谈判；
- 市场匹配算法；
- 订单搜索、筛选和分页；
- 外包方信用争议、退款与仲裁；
- 多层无限外包；
- 新闻评论和社交互动。

## 验收场景

### 世界订单进入工作台

```text
打开世界
→ 在订单市场承接订单
→ 返回我的工作台
→ 在待分配中看到该订单
→ 分配给 MVO
```

### MVO 节点外包

```text
打开进行中的项目
→ 看到节点的完成、运行和未开始状态
→ 对一个节点选择发布为订单
→ 在世界市场看到新订单
→ 模拟外部玩家承接
→ 推进一天
→ 返回原 MVO
→ 节点完成并继续后续任务流
```

### 回归要求

- 现有订单分配、组织图工坊、验收、开票、收款和组织成长仍可完成；
- 资源栏保持固定高度；
- 独立 ERP 入口不重新出现；
- 页面在 1440×900 和 1600×1000 下不发生横向溢出。
