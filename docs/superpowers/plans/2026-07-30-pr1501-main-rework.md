# PR #1501 Current-Main Rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make capability-grant idempotence observe held and pending capabilities without bypassing the #1621 identity-store cutover contract.

**Architecture:** Core owns durable outbox decoding and atomic pending semantic identity. `EntityCaps` owns a single checked held-cap read path: legacy list-returning APIs collapse errors to `[]`, while new tagged effective readers preserve errors and merge validated pending absorbs. Existing session grant chokepoints consume the effective view and fail closed.

**Tech Stack:** Elixir 1.19, OTP 28, Ecto/Ecto SQL 3.13, PostgreSQL 16, ExUnit.

## Global Constraints

- Frozen base is `main@81a90855c353aae7ed832a5b988bb5dff711ccc5`.
- Held capability authority remains #1621's epoch-gated `EntityCaps.Store` contract.
- The outbox supplements in-flight state only; it never becomes permanent capability authority.
- Domain code may call the core outbox seam but may not query or decode the outbox directly.
- All production behavior changes follow test-first RED → GREEN → REFACTOR.
- Use `SHELL=/bin/bash POSTGRES_PORT=15432 MIX_TEST_PARTITION=pr1501r` for local DB-backed verification.
- Finish with `mix precommit`.

- [x] **Step 5: Implement explicit conflict handling**

Populate semantic identity only for canonical identity-absorb envelopes. Use:

```elixir
Repo.insert(changeset,
  on_conflict: :nothing,
  conflict_target:
    {:unsafe_fragment,
     "(workspace_uri, target_uri, op, semantic_identity) " <>
       "WHERE status = 'pending' AND op = 'absorb_cap' " <>
       "AND semantic_identity IS NOT NULL"}
)
```

Keep producer-key reuse separate. After a semantic no-op insert, query the
winning pending row, decode it, compare `Capability.identity_key/1`, and then
reattempt that row. When both identities are present, add the existing named
idempotency unique constraint to the changeset: the semantic conflict target
handles the partial semantic index, while only that known producer-key
constraint may enter strict byte-identical producer reuse. Any other changeset
or database error remains `:durable_accept_failed`. Retry insertion once if the
semantic winner leaves pending state between conflict and lookup.

Add internal tagged readers. `load/1` and `load_persisted/1` call them and

The durable helper must branch exactly like current main:

```elixir

  :active -> checked_store_caps(uri)
  :inactive -> checked_legacy_caps(uri)
```

must not fall back. Add `UserStore.load_checked/1`; for non-user legacy reads,
use `Kind.read_durable/3` and reject malformed identity slices.

```elixir
with {:ok, pending} <- DeliveryOutbox.list_pending_absorb_caps(uri),

     {:ok, effective} <- verified_checked(held ++ pending, uri) do
  {:ok, Enum.uniq_by(effective, &Capability.identity_key/1)}
end
```

Normalize and log any error as `{:error, :effective_caps_read_failed}`.
