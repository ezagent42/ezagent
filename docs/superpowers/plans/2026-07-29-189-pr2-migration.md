## PR-2 scope = cutover step 2 (STILL reads-legacy — NO behavior change; the 9 reds stay red)

Two deliverables, both ADDITIVE. PR-2 does NOT flip any read to the store and does NOT change
the principal gate. Its job is to make the store a **complete, parity-verified mirror** of legacy
so PR-3 can atomically cut over.

### D1 — Backfill migration (the security-critical piece)

An **explicit, operator/provisioning-triggered, idempotent** migration that populates the store
from the legacy sources for every EXISTING live entity:

- **Users** → from `users.caps_json`.
- **Snapshot-backed entities** (agents, and any Kind whose `:identity` slice carries caps) → from
  the durable snapshot `:identity` slice, read through the PUBLIC `Kind.read_durable/3` surface
  (NOT a raw `SnapshotStore.latest` + `Map.get(:identity)` reach-in — actor-extraction C1 forbids
  that; see the existing `entity_caps.ex :snapshot_caps` precedent).

**THE RESURRECTION GUARD (codex design finding #2 — do not violate):**
> ONLY copy an ALREADY-VALID CURRENT license. NEVER auto-mint / auto-backfill for an entity that
> lacks a valid current license.

An entity that is `ever_created && has current authority-generation && has NO durable self-license`
is **EXACTLY a regenesis'd / retired / revoked principal** — auto-backfilling a license for it would
RESURRECT authority the revocation program intentionally stripped. The migration MUST:
- Copy a license into the store ONLY when the legacy source presents a license that is itself
  currently-valid (present + generation-current). Set `identity_status: "active"`.
- For an entity with legacy source present but NO valid current license → write the row with
  `identity_status: "revoked_unprovisioned"` (or leave absent), NEVER `active`. It stays inert
  until an authenticated `ProvisioningReceipt` reprovisions it.
- Be **idempotent** (`ON CONFLICT` — safe to re-run; re-running must not upgrade a
  `revoked_unprovisioned`/`tombstoned` row to `active`).
- Be an **explicit trigger** (a `mix ezagent.identity.backfill` task or a governed operator op),
  NOT auto-on-boot, NOT auto-on-first-ready.
- Preserve monotonic **tombstones**: a `tombstoned` row is never overwritten by backfill.

### D2 — Fleet-completion barrier (gates PR-3)

A **verifiable predicate** — a `mix` task and/or an invariant — that answers: *is the store a
complete, parity-correct mirror of the legacy self-license set for every live principal?* It must
enumerate the full principal worklist from the LEGACY source (not from the store — empty-store must
report "0% complete", never "done"), and confirm each has a store row whose caps match legacy
(byte/set parity) OR a justified non-active status. PR-3's atomic read-cutover is GATED on this
barrier returning complete — encode it so PR-3 can assert it in CI.

### D3 — Dual-READ parity instrumentation (log-only, legacy stays authoritative)

Wire an OPTIONAL, config-gated parity probe on the authoritative read path: when reading a
principal's durable caps from legacy, ALSO read `Store.fetch_durable_*`, compare, and LOG at
`:warning` on divergence (with URI + the diff). **Legacy remains the returned/authoritative value.**
This surfaces mirror drift before cutover. Must be zero-behavior-change and cheap (skip when the
config flag is off; default off in prod until fleet-parity is proven).

## Hard constraints (do not cross)

1. **Reads stay legacy-authoritative.** No authz decision may consult the store in PR-2. The 9
   `holder_revoked` reds (external_mirror publish/resubscribe/cold-restart + socialware settlement)
   MUST remain red after PR-2 — they go green only at PR-3.
2. **No auto-mint anywhere.** The only path to an `active` store license for a license-missing
   entity is an authenticated `ProvisioningReceipt`. Backfill copies existing-valid only.
3. **`Authority.open(:existed)` on empty history must still FAIL** (do not add a code path that
   births a generation for a license-missing principal).
4. Existing tests stay green; the migration + barrier + probe are new + additive.
5. Follow the PR-1 gate lessons: run `mix gate.arch` + `mix ezagent.uri_query.scan` + the pre-push
   gate LOCALLY before pushing (the app suites don't run the static arch/cap/URI gates). A new
   caps_json writer / raw-cap accessor / duplicate-fn / doc-coverage change needs the corresponding
   allowlist/baseline update with a justification.

## Acceptance (fail-before/pass-after where applicable)

- `mix ezagent.identity.backfill` (or the governed op) run on a seeded fixture populates the store
  for all valid-license entities as `active` with matching caps; a deliberately license-missing
  (regenesis'd) fixture entity lands `revoked_unprovisioned`/absent, NEVER `active` — a regression
  test proves the resurrection guard (fail-before: naive copy → `active`; pass-after: guarded).
- The fleet-completion barrier returns incomplete on a partially-backfilled store and complete on a
  fully-backfilled one (test both directions).
- Re-running backfill is idempotent and never upgrades a revoked/tombstoned row.
- external_mirror + socialware `holder_revoked` tests STILL red (unchanged) — PR-2 is not the fix.
- `mix gate.arch` + full identity/actor/session suites green; no new reds vs main.

## Codex impl-review round 2 (c0c11adab) — resolution log

Codex's adversarial impl-review returned FIX-NEEDED with 3 blocking findings (D3 dual-read
deferred to PR-3 by design). Resolution in the security-fix round on `fix/189-identity-plane-p2`:

- **Finding 1 (resurrection guard bypasses + verify/write race) — FIXED.** Every active-transition
  (`persist/2`, `backfill/2`, `update/2`, `provision/4`, `reprovision/4`) now routes its
  license decision through ONE guarded primitive (`Store.licensed_under_lock?/2`) that verifies the
  self-license INSIDE the transaction, under a `FOR SHARE` lock on the URI's current authority
  generation (`Cap.Authority.lock_current_generation/1` → `KindCapAuthority.lock_active/1`) so a
  concurrent `regenesis/2` cannot rotate the generation between the verify and the row write.
  `update/2` no longer inherits the schema `"active"` default; `provision`/`reprovision` require a
  current self-license in addition to a valid receipt. Fail-before/pass-after regressions: (a)
  `update/2` unlicensed → revoked; (b) provision/reprovision license-missing → `:no_current_self_license`;
  (c) mid-transition regenesis via a test seam → revoked (proves verify-inside-txn).
- **Finding 3 (fleet barrier false-complete) — FIXED.** Full-signed cap parity (`to_map` minus the
  round-trip-fragile `granted_at`, so signature/key_id/provenance divergence is caught); legacy
  snapshot read failures surfaced as `:legacy_read_error` discrepancies (never silent); the
  canonical-admin exemption tightened to still flag a stale `:active` admin row; the holder-
  classification ratchet scanner extended to catch the macro `use Ezagent.Kind, type_name:` form
  (→ `:git_task_access` classified `:non_holder`); the point-in-time/quiescence caveat restated as
  an explicit PR-3 precondition.

### FIX 3 — `Authority.open(:existed)` cold-rehydration — FLAGGED for coordinator/Allen decision (NOT auto-resolved)

Codex finding 2: the `[] when :existed -> Repo.rollback(:no_authority_for_existing)` guard in
`Cap.Authority.genesis/3` (added in this PR-2) is locally fail-closed and correct for the
resurrection vector, BUT it regresses a **pre-authority durable Lifecycle entity** — one whose
snapshot says `ever_created` yet has NO `kind_cap_authorities` row (created before the cap-signing
rollout #1457 and not re-opened since). On its first cold restart after this guard lands,
`Kind.Server.init` classifies it `:existed`, `open/3` rolls back, and the Kind terminates
(`{:stop, {:authority_load_failed, :no_authority_for_existing}}`).

**Determination (why this is flagged, not coded):** a GOVERNED legacy-authority adoption cannot be
made cryptographically safe automatically:
1. **Circularity.** A truly pre-authority entity's legacy self-license was signed before #1457
   (strict born-signed verify). There is no authority to verify it against, and the strict verifier
   rejects it — so "adopt iff it presents an eligible legacy self-license" cannot establish
   eligibility. (This is exactly the "verify a license with no authority to verify against" case the
   handoff names as a stop condition.)
2. **`ever_created` is not a sufficient witness.** The marker is never cleared on revoke/regenesis,
   so adopting authority for any `ever_created` entity would resurrect a deliberately-revoked one.
   There is no safe *automatic* criterion.
3. **The safe answer needs deployment evidence OR an operator decision** — neither of which an
   implementer can synthesize.

**The single discriminating question for the coordinator/Allen:** *Since #1457 (2026-07-18), has
every durable Lifecycle entity in each target DB acquired a `kind_cap_authorities` row (been
opened/restarted at least once under the old lazy-genesis code, which minted gen-1 on `:existed`)?*
- **Yes → the regression population is empty → the guard is safe to keep and deploy as-is.**
- **No / unknown → keep the guard but gate deploy on a governed authority-history backfill, OR defer
  the guard to PR-3** (land it atomically with the read-cutover under the write-quiescence fence).

**Current PR-2 state:** the guard is LEFT IN PLACE (status quo of `c0c11adab`; honors Hard
Constraint #3; breaks NO tests — test DBs always mint gen-1 via `:created`; the regression is
deploy-time only). This is deliberately NOT a unilateral revert, because removing the guard is
itself a security-posture decision (reopens Constraint #3) the coordinator should own — symmetric
with why the adoption is not auto-built.

**Sketch of the governed adoption for PR-3 (do NOT build in PR-2):** an operator-supplied allowlist
of vouched pre-authority URIs → each `reprovision`'d (fresh authenticated receipt + freshly-minted
current self-license + a new gen-1 authority-history record) so `open(:existed)` succeeds for exactly
the vouched set, while a purged/never-authorized principal still fails. This is a per-entity operator
decision, not an automatic migration.
