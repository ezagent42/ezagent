## Task 3: Make `finalize_ci_local/1` HONEST — capture real `mix test` failures (ITEM 2 — THE CORE FIX)

**Files:**
- Create: `apps/ezagent_core/lib/ezagent_core/ci_local_result.ex`
- Create: `apps/ezagent_core/test/ezagent_core/ci_local_result_test.exs`
- Modify: `mix.exs` (add `&arm_ci_local_result_capture/1` as the FIRST `ci.local` step; rewrite `finalize_ci_local/1`)

**Interfaces:**
- Produces: `EzagentCore.CiLocalResult.record_result/1` (an ExUnit `after_suite` callback: `(map()) :: :ok`) and `EzagentCore.CiLocalResult.failed?/0 :: boolean()`. `mix.exs`'s `finalize_ci_local/1` consumes `failed?/0`; `arm_ci_local_result_capture/1` registers `record_result/1`.

### Background (read before coding)

- `finalize_ci_local/1` (`mix.exs`, currently `defp finalize_ci_local(_args) do IO.puts(...); System.halt(0) end`) is the LAST `ci.local` step and does an UNCONDITIONAL `System.halt(0)`.
- `mix test` does **NOT** raise on failures — it reports them by registering `System.at_exit(fn _ -> exit({:shutdown, 1}) end)`. `System.halt/0` exits the VM immediately and **bypasses `at_exit`**, so every `mix test` failure is silently swallowed → false green.
- The `halt(0)` exists for a real reason: on a graceful VM shutdown the app's erlexec-backed OS-process ports (PtyServers, python ports) are reaped asynchronously, and a port EXITing mid-teardown pollutes the VM exit code to `2` even with **0** test failures — a false RED that blocked the canary. So we must keep an explicit `System.halt/1` (never a graceful shutdown), but choose `1` vs `0` from the CAPTURED test result rather than the process exit code.
- **Mechanism (empirically validated):** register an `ExUnit.after_suite/1` callback (runs synchronously at the end of `ExUnit.run/0`, BEFORE any `at_exit` or shutdown, so it is immune to the `halt` bypass). It writes a sentinel file when the suite reports failures. `finalize_ci_local/1` then `halt(1)` iff the sentinel exists, else `halt(0)`. Because we STILL `halt/1` explicitly, the erlexec graceful-shutdown race is never entered — the false-RED stays fixed.
- **Validated facts** (from probes; captured here so kimi need not re-derive):
  1. Pre-setting `Application.put_env(:ex_unit, :after_suite, [fun])` **before** `ExUnit.start/1` DOES fire the callback — but ONLY if `Application.ensure_loaded(:ex_unit)` was called first. `arm_ci_local_result_capture/1` does both, in that order.
  2. The `ExUnit.run/0` result map is `%{total:, failures:, excluded:, skipped:}`. A `setup_all` crash (an "invalid" module) is **folded into `:failures`** (observed: 1 real failure + 1 invalid → `failures: 2`). So `failures > 0` catches setup_all crashes too. We also defensively OR `Map.get(result, :invalid, 0)` in case a future ExUnit un-folds it.
  3. A remote capture `&EzagentCore.CiLocalResult.record_result/1` is created safely even before the module is compiled (resolved at call time), so registering it in `arm_ci_local_result_capture/1` (which runs before `precommit` compiles the umbrella) is safe.
  4. `mix ci.local` runs all alias steps in ONE BEAM; `arm` runs before `precommit`'s recursive `test`, so every umbrella child's `ExUnit.start/1` inherits the `:after_suite` app env in the same BEAM.

```elixir
defmodule EzagentCore.CiLocalResult do
  @moduledoc """
  Honest exit-code capture for `mix ci.local`.

  `mix test` signals failures via an ExUnit `System.at_exit` hook (it does NOT
  raise). `mix.exs`'s `finalize_ci_local/1` ends `ci.local` with an explicit
  `System.halt/1` — which exists to DODGE the erlexec port-EXIT graceful-shutdown
  race that pollutes a CLEAN run's exit code to 2 — but `halt` bypasses
  `at_exit`, so failures were silently swallowed (false green).

  This module captures the ExUnit result via an `after_suite` callback
  (synchronous, runs before any exit/shutdown, immune to the `halt` bypass) into
  a sentinel file named by the `EZAGENT_CI_LOCAL_SENTINEL` env var (set by
  `arm_ci_local_result_capture/1` in mix.exs). `finalize_ci_local/1` then
  `halt(1)` iff `failed?/0`, else `halt(0)` — honest failures WITHOUT
  reintroducing the shutdown-timeout false-red.

  A no-op outside a `ci.local` run (env var unset), so registering it globally is
  harmless to a plain `mix test` or the CI `gate`.
  """

  @env "EZAGENT_CI_LOCAL_SENTINEL"

  @doc "ExUnit `after_suite` callback. Sticky-marks the sentinel when the suite reports failures."
  @spec record_result(map()) :: :ok
  def record_result(result) when is_map(result) do
    # ExUnit folds `invalid` (setup_all crashes) into `:failures`; OR `:invalid`
    # defensively in case a future ExUnit exposes it separately.
    failures = Map.get(result, :failures, 0) + Map.get(result, :invalid, 0)

    with path when is_binary(path) <- System.get_env(@env),
         true <- failures > 0 do
      File.write!(path, "FAIL failures=#{failures}\n", [:append])
    end

    :ok
  end

  def record_result(_), do: :ok

  @doc "True iff any suite in this ci.local run reported a failure."
  @spec failed?() :: boolean()
  def failed? do
    case System.get_env(@env) do
      path when is_binary(path) -> File.exists?(path)
      _ -> false
    end
  end
end
```
