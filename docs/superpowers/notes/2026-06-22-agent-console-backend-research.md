## ⭐ Headline (reverses the task premise)
**The orchestrator tools are NOT MCP-bridge-only.** Each is a plain public function `Ezagent.Orchestrator.Tools.<fn>(args, opts)` in the session domain (`apps/ezagent_domain_session/lib/ezagent/orchestrator/tools.ex`, 956 lines). The cc `McpServer` is "pure transport, ZERO authority"; `SessionManager.run_tool/4` adds only (a) bridge-token verify + (b) caps reconstruction, then calls the same domain fn. **A world Console replaces (a)+(b) with operator-derived URI+caps — no new backend dispatch path needed.** The REAL gap is an **authorization-principal design question** (§5), not missing code.

## 1. Agent contract data model
- **`Ezagent.Entity.AgentTemplate`** (`apps/ezagent_domain_agent/.../entity/agent_template.ex`): named pointer to a sandbox (config_dir w/ settings/MCP/hooks/skills) + cap policy. Behaviors `[Identity, Template]`. URI historically versionless `template://agent/<name>`, can mint versioned `template://<ws>/agent/<name>@<hash>` (`build_versioned_uri/3`, `compute_version_hash/1`). Content: name/description/flavor (cc/codex/curl/echo), project_cwd→"cwd", config_dir, settings_path, mcp_config_path, api_key_helper, parent_template_uri, default_caps, desired_skills/desired_caps, flavor extras via `template_data_extra/1`. Ops: `to_template_data/2`, `fork/3` (caller+caps, config-only), `persist_version_as_system/2` (system path only — **no caller-threaded `create/3` exists; minor gap**).
- **`Ezagent.Entity.SessionTemplate`** (`apps/ezagent_domain_session/.../entity/session_template.ex`): the production multi-agent team config. URI `template://session/<ws>/<name>@<hash>` (SHA-256 over content sans timestamps/created_by/name/agent_slots). Slice: name, description, **members** (`%{uri, role_name, in_session_template, source_template_uri}`), prompt_templates, legends (`%{member_set, bound_rule_set, fold}`), orchestrator_template_uri (nil=plain), routing_rules, default_workspace_uri, parent_template_uri, version_hash/tag, public_view. Ops (all caller-threaded, UI-ready): `create/3` (root, cap preflight, grants owner Template cap, workspace REQUIRED), `fork/3`, `persist_version/3` (HIGH-9: threads caller caps, no admin fallback), `compute_version_hash/1`. Instantiation is SEPARATE: `SessionCreator.create_session/3`.
- **Member model**: `role_name` = stable per-session alias routing/legends target (regen keeps rules valid). `source_template_uri` = AgentTemplate to recreate from. `agent_slots` REMOVED (PR-8: "a slot was a member with extra facets").
- **`Ezagent.TemplateTags`** (`apps/ezagent_core/.../template_tags.ex`): mutable `(name,tag)→version_hash` registry; "current" tag = git-branch-like live pointer.

## 2. The orchestrator (two-layer)
- **Transport (cc, ZERO authority):** `Ezagent.Orchestrator.McpServer` (`apps/ezagent_plugin_cc/.../mcp_server.ex`) — decodes `tools/call`, looks up the per-orchestrator `SessionManager`, `GenServer.call`s `{:run_tool, tool, args, bridge_token}`. Live `claude` reaches it via `priv/orchestrator_bridge.py` over WS. Bridge token (not caps) is the credential.
- **Authority+exec (session domain):** `Ezagent.Session.SessionManager.run_tool/4` (`session_manager.ex:256-292`): verify bridge token → structural caller check → **reconstruct orchestrator caps session-side via `Ezagent.Identity.list_caps_for(orch_uri)`** → call `Ezagent.Orchestrator.Tools.<fn>(args, opts)`. CapBAC enforced at each underlying `Invocation.dispatch`.
- **Tool surface:** `Ezagent.Orchestrator.Tools` — every fn takes trailing `opts` with `:caller, :caps, :session_uri, :workspace_uri`. LLM never supplies caller/caps/session.
- **Tools (cc catalog = 10; domain also has `add_participant` = 11th, a superset of add_managed_member accepting entity/template/manifest):** add_managed_member (tools.ex:134), update_member_template (MemberTemplate), remove_member (tools.ex:407), add_participant (Participants), define_rule_set_rule (tools.ex:554→RuleStore), define_prompt_template (tools.ex:660), define_legend (tools.ex:705), update_template (Templates), save_template_as (Templates), migrate_session (Migration, tools.ex:830 defdelegate), list_templates (Templates). Generic `Tools.invoke/2` (tools.ex:846). No new cap shapes; manage-cap `{:manages,_}` DEFERRED (#533).
- `Behavior.OrchestratorAdmin` = cap-only shim, ONLY action `:restart` (owner holds it); NOT where member ops live.

## 3. Team routing (`apps/ezagent_core/lib/ezagent/routing/`)
- **`RuleStore`** (`rule_store.ex`): rule = `routing_rules` row (table_name, matcher_data JSON AST, receivers, created_by, source, enabled, applies_to_users, workspace_uri (nil=global), rule_set (nil=standalone), position, prompt_template_ref). CRUD: `add/5` (single-receiver enforced for named rule-sets), list, delete (system_default protected), `update_receivers/3` (in-place repoint), disable/enable, `find_by_identity/4` (idempotent re-materialization), `load_into_registry/1` → ETS `RoutingRegistry` (Resolver reads ETS).
- **`Matcher`** (`matcher.ex`): leaves `{:mention,s}`,`{:from,s}`,`{:text_contains}`,`{:text_matches,regex}`,`{:in_session}`,`{:always}`; combinators and/or/not; JSON `%{"type","arg"}`. `{:from,uri}` matches on sender only. `:mention` also fires on virtual `legend_triggers`.
- **`Resolver`** (`resolver.ex`): on every `Session.handle_send` — filter rows by match+sender+workspace → pair receivers w/ `{rule_id, rule_set, prompt_template_ref}` → expand magic tokens ($session_members/$mentions) → sort by rule_id (lowest wins), dedup, drop sender. **Deterministic relay, NO model-emitted baton**: `{from:X}→[Y]` matches on who sent; chain lives in the rule table, not the message.
- **`Legend`** (`legend.ex`): session-scoped `%{name, member_set, bound_rule_set, fold}` in slice `:legends`; `entry_rule/2` = lowest-position rule in bound set; fires via normal Resolver; `fold` = pure UI collapse.
- **`PromptTemplate`** (`prompt_template.ex`): named map in slice `:prompt_templates`; attached via rule `prompt_template_ref`; rendered at delivery, `{var}` substitution, `{body}` required.

## 5. Agent Console surface + gap analysis ⭐
- **Premise reversed** (see headline): tools already have plain-Elixir entrypoints. No new dispatch path needed.
- **The REAL gap = authorization principal.** Tools authorize against the **orchestrator's** `Cap #1 {:within_session,S}` (any/any). At session creation: orchestrator gets `{:within_session}` authority; owner gets manage-cap + `:restart`; a fresh non-admin user holds `[]`. So `Tools.add_managed_member(args, caps: list_caps_for(operator))` → `{:error,:unauthorized}` for non-owner operators. **The Console must decide which principal it dispatches as.**
- **Two preconditions (don't blur):** COLD path (template authoring — `SessionTemplate.create/fork/persist_version`, `AgentTemplate.fork`; caller-threaded, UI-ready, acts on durable snapshots) vs LIVE path (managing a running session — add/update/remove member, define rule/legend/prompt, migrate_session; reads the live Session slice, needs a running session + within-session authority).
- **Net gaps:** (1) the authorization-principal decision for LIVE tools; (2) AgentTemplate lacks caller-threaded `create/3`; (3) no UI write-actions wired for LIVE tools / cap grant-revoke / api-key put-delete / template tagging / legend+prompt editors. **None need new backend tool logic** — they need world `*_actions.ex` clauses + the principal decision.

## 6. Auth / cap model
- Capability = 5 axes (kind, behavior, action[:any], instance, workspace_uri) + provenance. `matches?/2`: all 5 match; held `:any`=wildcard, needed `:any` matches only held `:any`; instance honors `{:within_session/_workspace/spawned_by,_}`; workspace_uri symmetric. Genesis admin = five-`:any` wildcard.
- Op gates: template create/fork/instantiate → `Behavior.Template :write/:fork/:instantiate`; add/remove member → `Behavior.Session :join/:leave`; routing → `Behavior.Routing :add_rule`; legends/prompts → `Behavior.Session :set_legends/:set_prompt_templates` (trusted-principal class); migrate → Template cap + `{:within_session}` cap.
- Fresh user holds `[]` (`User.default_caps/1`); template creation NOT default-granted. CapBAC enforced inside the Kind GenServer at `Ezagent.Kind.Runtime.authz_check/5` (not in dispatch).
- **World caller authorizes via** `Ezagent.Identity.list_caps_for(operator_uri)` → ctx caps. For LIVE tools this FAILS for non-owners. Options: (A) operator-as-owner only; (B) **mirror SessionManager** — verify operator may-manage via a coarser cap, then dispatch under reconstructed orchestrator authority (world = a 2nd "transport" onto the same authority-reconstruction seam); (C) new manage-cap `{:manages,_}` (#533).
