## ezagent 是什么

一句话：**它是一个消息路由运行时**——把各渠道进来的消息路由给各个 agent/会话处理，再把结果送回。它跑在 Elixir/OTP 上，单文件 SQLite，多租户（租户 = workspace）。

它**不是**普通"点一下返一下"的网页后端：消息没人接收默认会**静默丢失**，所以处处要人为制造可观测性（遥测出口 + 死信队列 + 未就绪先接住）。

## 两种"在它上面搭东西"的方式（产品设计必须先分清）

| | **plugin（加平台能力）** | **socialware app（做客户产品）** |
|---|---|---|
| 加什么 | 新 agent 类型/新渠道/新行为 | 公开会话 + 客户体验 |
| 形态 | 一个编译进来的 OTP app | 一个带 `public_view` 的会话模板（数据，不写代码）|
| 谁做 | 平台开发者 | 产品设计者 |

**产品工作主要是后者**（组合现有能力，不写底层代码）。详见 [09 如何搭建新 app](./09-如何在ezagent上搭建新app.md)。

## 整体形态：21 个 app 的三层 + 传输

```
传输层   ezagent_web(Phoenix) · ezagent_cli
插件层   cc · codex · curl_agent · np · echo · advisor(agent) · feishu(渠道) · world(统一前端/管理面)
领域层   session(会话) · agent(物化agent) · socialware(客户面) · identity(身份) · workspace(租户)
         · pty · python · ui · external_mirror · agent_bridge
核心层   ezagent_core —— Kind / Behavior / 分发 / 权限(CapBAC) / URI / 可靠性原语
```
依赖只能往下。判断一段代码放哪层，看它**读什么数据**。

## 产品方向（决定这条线往哪走）
两条把客户产品"产品化"的线**已落地 main**：
- **world** = 已落地的**统一前端**（React/shadcn + Vite，跑在一层 LiveView SSR/通信壳上）。**已退役并取代 LiveView 管理面**（运营/作者面现在就是 world）→**这就是"统一 ezagent app / 统一出口"的方向**。注意：world **当前只接管运营/作者面**，**收编客户面仍是 future**（`/socialware/chat`、`/socialware/customer` 还在旧栈 `ezagent_web` 上）。
- **agent-schema / agent-contract** = 已落地的编排契约：声明式 agent manifest（`Ezagent.AgentManifest`）+ 每 flavor 的 `flavor.compile` + `executor` 后端 fallback + dispatch 撑起的 `tools[]` + versioned 模板 pin + ledger 追踪的 `migrate_session`。定义客户体验里的 agent 怎么被声明、换后端、版本化、迁移。
- **loom / autoservice** = 只是设计词汇，**没进代码**，别当已有实现引用。

## 三个必须知道的现状
1. **工具链用 mise（OTP27/1.18）**，跑测试/服务用 `mise exec --`；系统默认 1.19.5/OTP28 会放大数据库测试连接不稳定。
2. **这个仓库没有 CI**：主线可能带红测试（前端这层现在是 world，liveview 已删；如有确定性失败，多属测试基础设施/版本兼容，非产品功能坏——以 world 当前测试产物为准核对）。
3. **bug 主线在修**，本 worktree/分支定位是**产品设计 + 工作流**，不是修 bug/做底层开发。
