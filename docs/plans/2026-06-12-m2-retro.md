## Process Failures

### 1. Per-task plan 缺失

Phase C 的 T2A.1 和 T2A.2 **完全没有 per-task plan 文件**。
对比 Phase A 的 7 个 task 都有 `docs/superpowers/plans/<DATE>-<ID>-*.md`。

**根因**: `/start-task` 调用了，但 writing-plans 步骤被跳过（可能因为
superpowers 插件未加载或 session 中 writing-plans 失败后未重试）。

**影响**: 实施时无 plan checklist 对照，3 个页面无声缺失。

### 2. 无测试验证

Phase C 的 2 个 task 未产生任何新增 ExUnit 测试。
Phase A 的每个 task 都有独立的 `mix test` 验证。

### 3. 无 code review

prd2impl 标准流程要求 task close 前走 `superpowers:requesting-code-review`。
Phase C 的 commit 轨迹中无 review commit (amend/fixup)。

### 4. Tasks.yaml 手工标记完成

Commit `10f76ab1` ("Phase C complete — 15/16 tasks") 和 `470bb383`
("100% complete — 16/16 tasks done") 的 diff 只改了 tasks.yaml 的
`status:` 字段。这是 tracker 状态翻转，不是代码交付。

## Recommendations

### 流程

1. **Per-task plan 作为硬 gate**: `/start-task` 在没有 per-task plan 时
   拒绝执行。CI 可检查 `tasks.yaml` 中 `status: completed` 的 task
   是否有对应的 `source_plan_path` 文件。

2. **Deliverables 验证**: tasks.yaml 中每个 task 的 `deliverables` 字段
   列出了预期文件。`status: completed` 时 CI 应检查这些文件全部存在。

3. **Phase C tasks 拆分**: T2A.1 → 3 tasks, T2A.2 → 5 tasks。
   每个任务对应一个独立页面，有独立的 plan、实施、测试、review。

### 修复

1. 为 3 个缺失页面生成 per-task plan
2. 逐个实施并验证
3. 补全 2 个 stub (operators disable, CR history)
