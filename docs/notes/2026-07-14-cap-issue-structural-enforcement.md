# 用源码扫描去证明一个运行时性质 —— 这场军备竞赛赢不了

**状态:** 待 Allen 决策。**不是 bug 报告 —— 是"我们守错了地方"。**

**性质:** Decision #162 说 `Cap.issue/3` 是唯一的 grant constructor。我们用**源码扫描**去强制它。**扫描器被绕过了三轮。第三轮之后我才明白:它永远绕得过。**

---

## 事实先摆着

我们想要的性质是一句关于**运行时**的话:

> **每一个进入 `users.caps_json` 的 cap,都经过了 `Ezagent.Cap.issue/3`。**

(这一列**就是**用户的权限 —— user Kind 开机时从它对账出自己的 cap slice。)

我们拿**源码长什么样**去证它。三轮:

| 轮次 | 扫描器"修好"之后,还漏 | 谁发现 |
|---|---|---|
| 1 | `Users.create_read_only/2` · `scripts/*.exs` | 自查 + codex |
| 2 | 管道 · 别名 · `apply` · capture | codex |
| 3 | `import` · `@attr` · **`Module.concat`** | 自查 |

前两类都补上了(现在 7 种写法全抓,见 `cap_issue_chokepoint_boundary_test.exs`)。

**但第三类补不上:**

```elixir
m = Module.concat([:Ezagent, :Users])
m.create(uri, pw, forged_caps)          # 模块名在【运行时】拼出来
```

**任何源码扫描都看不见它。** 不是扫描器写得不够好 —— **是原理上看不见。**

而且我此前声称的"守列(leg 3a)是它的结构性兜底"—— **那句是假的**。绕过的**调用方**并不写 `caps_json:`,写它的是 `users.ex`。leg 3a 抓的是「`Users` 里新增写入函数」,**不是**「没登记的调用方」。

---

## 所以这道 gate 到底证明了什么

**只证明这个,一个字不多:**

> **每一个【静态可解析】的调用点都被枚举了,且这一列的每一处赋值都被枚举了。**

**它没有证明** "每一个进入 `caps_json` 的 cap 都经过了 `Cap.issue`"。

**这个缺口不是"再聪明一点的扫描器"能补的。**

## 真正的修法:让它在运行时不可违反

```elixir
# Ezagent.Cap —— 发放时记指纹
def issue(authorization, target, cap) do
  with :ok <- CapabilityRegistry.authorize_grant(...),
       {:ok, artifact} <- prepare_provenance(authorization, cap) do
    Ezagent.Cap.Issued.record(artifact)      # ETS,core 里已有同类表(KindRegistry / Idempotency)
    {:ok, artifact}
  end
end

# Ezagent.Users —— 拒收未发放的 cap
defp do_create(uri_str, password, caps, opts) do
  :ok = Ezagent.Cap.assert_all_issued!(caps)   # ← 结构性:跟【怎么拼那个调用】完全无关
  ...
end
```

**这样,`Module.concat`、宏、动态 atom —— 全都无所谓了。伪造的 cap 存不进去。**

源码扫描降级成 **review 锚点**,不再是保证。

### 必须一起定的三个边角(不能含糊过去)

| | 问题 | 备选 |
|---|---|---|
| **信任根** | genesis bootstrap 在开机时铸 admin 的通配 cap,**那一刻没有更早的权威可依** | 给它一个**刺眼命名**的显式豁免口(`Users.create_genesis_admin/2`),让"信任从这里开始"在代码里**看得见** |
| **结构性默认 cap** | `do_create` 会自动 prepend `User.default_caps/1`(自省用的 `identity.list_caps`)。这些也没经过 `Cap.issue` | 要么一起发放,要么显式豁免 —— **但必须选一个,不能默认漏过** |
| **ETS 生命周期** | 指纹表随 owner 进程死。重启后旧 artifact 不在表里 | issue → store 在同一条调用链里完成,窗口极短。但**要显式确认**:有没有跨重启的 issue-then-store? |

## 更值得记住的那条(这才是我写这份 note 的原因)

这不是一次"扫描器写得不够仔细"。**它是一个系统性的形状,而且我能说清它的根。**

### 表层:验证了一条路,却声称整个性质成立

同一个形状,在这个仓库里至少四次:

| | 验证了什么 | 声称了什么 |
|---|---|---|
| **Codex PR #356 r1** | 收窄了**谁能进** `create_user` 这扇门 | 把 *"could mint users with arbitrary caps"* 标成已处理 —— **门修了,房间里的炸弹没碰**。三个月后工作区管理员仍能造出全局 admin |
| **I7 leg 1 & 2** | 守住 cap **构造** + `{:set, :caps}` **slice 写入** | 声称 chokepoint 已强制 —— **`caps_json` 那条路一直没人守** |
| **`spawn_plan.ex` 的注释** | *"Verified empirically: `--continue` degrades gracefully"* | **某个条件下**的观察,写成了**普遍性质**。它是假的 —— **而且它就是 #1294 的根因** |
| **`CredentialPrecondition` moduledoc** | 假定"用户可以进自己 agent 的 PTY 打 `/login`" | **那个出口从来没被实现过。没人验证过它存在** |

**每一条单独看都是真话。合起来是假的。**

### 但这只是症状。真正的根在下面

跳过枚举可以理解 —— **枚举没反馈,产出还是句坏消息,人会躲。**

**可是躲开枚举之后,完全可以老实写"我只堵了 2 个出口"。没人这么写。为什么?**

因为在我们的工作流里:

```
代码   → 被机械检查(编译 / 测试 / CI)
测试   → 被机械检查
─────────────────────────────────────
注释   → 自由文本,不被检查
commit → 自由文本,不被检查
PR     → 自由文本,不被检查
决策记录 → 自由文本,不被检查
```

**而"这个洞堵上了"这句话,只活在下面那一栏。**

测试证明的是"给定这些输入,这段代码这样跑"。声明说的是"**这个性质成立**"。
**没有任何一步去检查这两者说的是不是同一件事。**

于是声明**浮空**。它从不与证据对质。它是**被创作的**,不是**被推导的**。

**而且它膨胀的方向永远一致 —— 往强了说。** 因为写弱声明,**感觉**像承认自己做得少。它其实只是承认自己**证明得少**;但在写的那一刻,那两件事感觉一样。

> **`X` = 声明与证据在工作流里是解耦的。测试被机械检查,声明不被。**
> **于是声明会系统性地膨胀到【我们希望的强度】,而不是停在【我们证明的强度】。**

### 一句没有 falsifier 的"已验证",比不写更糟

`spawn_plan.ex` 那句假的 *"Verified empirically"* —— **下一个人信了它,在上面盖了房子。它在生产里烧了 8 天,933 次重生。**

**假的强声明会传染。** 这不是文风问题,是**故障传播机制**。

---

## 正解:每一句声明,必须自带一个会红的实验

**不是**"更仔细"(当能力问题治 → 治不了)
**不是**"更多 review"(codex review 了,我照样发假声明 —— 因为我**没读它的 (E)**;而且它审的是**代码**,不是"你这句话跟你这个测试对得上吗")
**不是**"更多测试"(一堆绿测试 —— 它们测的是**机制**,不是**性质**)
**不是**"更好的扫描器"(那正是我做了三轮的 Y)

```
写下"已验证 / 已修复 / 已守住"之前,问:

    → 什么实验会让这句话变成假的?

  答不出来      → 这句话不该写
  答得出但没跑  → 先跑
  跑了不红      → 这句话就是假的
```

**这个问题只要 30 秒。贵的不是问,是【诚实地答】** —— 因为诚实的答案经常是"我没有那个实验,所以只能写一句更弱的话"。

### 三种具体形态(都是这次真跑出来的,不是设计出来的)

| | 声明 | 它的 falsifier |
|---|---|---|
| **Sabotage test** | "这个 fix 堵住了洞" | **拿掉 fix,测试必须红** |
| **Boundary test** | "抓得住 A/B/C,抓不住 D" | **四个全写成 fixture:前三必须红,D 必须【不】红** |
| **Enumeration assert** | "这条路只有 N 个入口" | **把 N 断言掉,加第 N+1 个必须红** |

**第二条最反直觉,也是这次才学会的:声明的边界,【两侧】都要钉。**

只钉"抓得住"那一侧 → 下一个人以为它什么都抓得住(**我就是这么骗了自己四次**)。
钉住"抓不住 `Module.concat`" → 谁哪天让它抓住了,**测试会红,逼他回来改声明**。

> **一个说少了的声明,也是错的声明。**

### 用这条 X 回头验:它能解释每一次失败吗

| 我写过的话 | 什么实验会让它变假 | 跑了吗 |
|---|---|---|
| "P4 修好了" | 拿掉 patch,测试该红 | ❌ 我信了脚本的 printf |

| "这条契约没写在文档里" | 认真 grep | ❌ 它在两处,还带决策编号 |

**九条全中。每一条都有一个便宜到离谱的实验能立刻证伪它。每一条我都没跑。**
