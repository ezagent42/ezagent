## 一、r3 新挖（㉟-㊶）+ 两条用户裁定

| # | 现象 | 根因/修法要点 | 归属 |
|---|---|---|---|
| ㉟ | 建会话「应用」下拉里内置 definition 直接以系统概念名「socialware」示人，用户误选（装成 builtin 而非 kanban，无看板 tab） | 表层=builtin（chat/socialware/orchestrator）在普通用户选择器里应改说明性名或隐藏；**深层=tab 出现与否取决于「装没装 kanban sw+render cap」（⑤门控模型），违背 ㉜「tab=plugin 级恒显」。㉜(D3)+㉛落地后此坑整体消失**；残余=⑩装了但角色静默跳过仍需提示 | zyli（向导）+ Allen（builtin 命名）；深层挂 D3 |
| ㊱ | 没有删除 session 的 UI（domain 有 teardown/retire 语义，界面无入口） | world 会话管理面加入口 | zyli（#1443 追加） |
| ㊲ | 节点产物「附件」点打开 → **forbidden** | uploads 下载 token 授权拒（疑 token 只对上传者/特定 receiver 有效，或 TTL 300s 过期）。查 DownloadToken 签发的 receiver/ttl | 我们 × uploads 授权（可能独立 PR） |
| ㊳ | 「链接」产物点打开被拼 localhost 前缀 | 前端 open 逻辑没区分绝对 http(s) URL，外部网址应原样新窗打开 | 我们（kanban 前端） |
| ㊴ | 链接产物填写是两个连续 prompt 弹窗；无编辑 | ㉗ 迭代规格：改**一个小表单窗**；产物加「打开/编辑」两选项，编辑=打开原值就地改保存 | 我们（kanban 前端） |
| ㊵ | 「分享到会话」气泡①文案错（「点击加入…按你的身份决定可编辑/可读」不准：链接恒只读 H4，编辑权只来自成员身份）②同会话点击误走跨会话 HTTP receive 整屏重定向被带去别的 session | 见下方**㊵-模型钉死**——不是修文案，是 receive 落点模型推翻重做 | 我们（receive 重做+tab 数据口径） |
| ㊶ | kanban tab 不做屏幕自适配（chat tab 会随窗口自适应，看板 tab 固定宽/溢出处理缺） | 看板容器与面板列改响应式（min-w/flex/overflow 对齐 Conversation 布局骨架） | 我们（kanban 前端） |

**㉛-设计意图澄清（2026-07-17 用户定）**：template 与 socialware **刻意不绑定**——一个 session 可关联**多个** sw；session template 可从某个 sw 出发继续搭 agent、**沉淀成新的 sw**，也可拉多个 sw 组合。⟹ ㉛「装 sw 面」按**多装/组合/存模板→发布成新 sw 的闭环**设计（非单选绑定）。已同步进 zyli #1443 的 ㉛ 节。

**㊵-模型钉死（2026-07-17 用户定）：kanban 与会话正交**——
- a 在会话A建 k1；b 把 k1 分享到会话B；c 点击 → k1 出现在 **c 自己的 kanban tab**（只读），**不跳任何会话**。
- 同会话分享同理：点击 = 跳当前 kanban tab 定位该板；gate 按点击者与板的关系判只读/可写。
- ⟹ **推翻** receive 落点「服务端解析目标会话+重定向」设计；**钥匙发给点击者本人**（person-scoped，非目标会话 assistant）；**kanban tab 内容 = 该用户持钥匙的板集合**（人本位，正交于会话）。
- 重塑分享二期与 D4 的实现前提；气泡文案改「查看看板（只读分享；会话成员按成员权限操作）」；已挂当前会话→原地切 tab 定位（零刷新），未挂→person-scoped receive。
