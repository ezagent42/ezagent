# 场景 09：LV 创建 session + 添加成员

**类别**：3 — Session 流程
**状态**：✅ implemented-and-tested
**最近验证**：2026-05-26（PR #408 合并 + Allen 合并后验证）

## 前置条件

- Phx 跑在 `http://100.64.0.27:10042`
- Admin 已登录
- 默认 workspace `workspace://system`
- 至少 1 个 agent（例如简单的 echo agent：`entity://agent/system/echo_1`）

## 角色

- **调用方**：admin（`entity://system/user/admin`）
- **目标**：workspace `workspace://system`（Behavior `Ezagent.Behavior.Workspace`，action `:create_session`）
- **生成的 session**：`session://system/<auto-generated-name>`

## 步骤

### 创建

1. 在 `/admin` 点 "New session"（或访问 `/admin/workspaces/system`）。
2. 填名字：`my-session`；提交。
3. 编排器（PR #408 统一路径）在 `Ezagent.Session.Supervisor` 下自动 spawn session。
4. LV 重定向到 `/admin/sessions/session%3A%2F%2Fsystem%2Fmy-session`。

### 加成员

5. 点 "Add member"；从 URI picker（cmdK 或下拉）选 `entity://agent/system/echo_1`。
6. Behavior `Workspace :add_member` 派发；PR #419 让此操作 spawn-then-grant 原子化（cap 授予在 worker spawn **之后**）。
7. 验证 session 成员名册面板显示 echo agent。

### 收发

8. 在 session 聊天输入框打 "hello echo"；提交。
9. echo agent（本场景 mention-gated 路由未生效 — 系统默认规则 `always → $session_members`）接收 + echo 回。
10. 验证 LV session chat 显示两条消息。

## 预期结果

- 存在一行 `sessions` + 一行 `session_members`。
- Session 的 `kind_snapshots` 行在 `:on_change` 更新。
- `invocations` 行：`create_session`、`add_member`、`chat.send`、`chat.receive`、`chat.send`（echo 回复）。
- 系统默认规则 `always → $session_members` 行匹配本消息。

## 失败模式

- 同 workspace 重名 session：`:already_exists`。
- 加不存在的成员 URI：`:target_not_found`。
- 缺 workspace cap：`:unauthorized`（admin 持 `:any` cap，仅经非 admin 用户可触达 — 见场景 15）。
- 编排器 create 后 spawn worker 失败：PR #419 排序为 create-then-grant；若 create 成功但 grant 失败，session 回滚。
