# Scenario 09: Create session via LV + add member

**Category**: 3 — Session flows
**Status**: ✅ implemented-and-tested
**Last verified**: 2026-05-26 (PR #408 merge + Allen post-merge verification)

## Pre-conditions

- Phx running at `http://100.64.0.27:10042`
- Admin logged in
- Default workspace `workspace://system`
- At least 1 agent exists (e.g. an echo agent for simplicity: `entity://agent/system/echo_1`)

## Actors

- **Caller**: admin (`entity://system/user/admin`)
- **Target**: workspace `workspace://system` (Behavior `Ezagent.Behavior.Workspace`, action `:create_session`)
- **Resulting session**: `session://system/<auto-generated-name>`

## Steps

### Create

1. In `/admin`, click "New session" (or visit `/admin/workspaces/system`).
2. Provide name: `my-session`; submit.
3. The orchestrator (PR #408 unified path) auto-spawns the session under `Ezagent.Session.Supervisor`.
4. LV redirects to `/admin/sessions/session%3A%2F%2Fsystem%2Fmy-session`.

### Add member

5. Click "Add member"; pick `entity://agent/system/echo_1` from the URI picker (cmdK or dropdown).
6. The Behavior `Workspace :add_member` dispatches; PR #419 makes this spawn-then-grant atomic (cap grant is sequenced AFTER worker spawn).
7. Verify the session roster panel shows the echo agent.

### Send + receive

8. Type "hello echo" in the session chat input; submit.
9. The echo agent (mention-gated routing inactive for this scenario — system default rule `always → $session_members`) receives + echoes back.
10. Verify the LV session chat shows both messages.

## Expected outcomes

- A `sessions` row + `session_members` row exists.
- `kind_snapshots` row for the session updated `:on_change`.
- `invocations` rows: `create_session`, `add_member`, `chat.send`, `chat.receive`, `chat.send` (echo reply).
- `routing_rules` row (system default `always → $session_members`) is matched for the message.

## Failure modes to test

- Duplicate session name in same workspace: `:already_exists`.
- Add a non-existent member URI: `:target_not_found`.
- Workspace cap missing: `:unauthorized` (admin holds `:any` cap so this is only reachable via a non-admin user — see scenario 15).
- Orchestrator fails to spawn the worker post-create: PR #419 sequences create-then-grant; if create succeeds but grant fails, the session is rolled back.
