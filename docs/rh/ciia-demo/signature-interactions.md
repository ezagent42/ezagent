# ezagent · Signature Interaction 筛选

## 产品独特价值

ezagent 的独特价值在于：**用户不是在操作一个软件，而是在和一个组织交互。** 这个组织有知识、有判断力、有资源。它的内部有多个职能角色在相互协作为用户服务。它不是工具——它是用户可以信任的对象。

## 筛选漏斗

```
所有交互
  │
  ├─ 过滤：这个交互是否让用户感受到下面三者之一？
  │   A. "我在和一个组织交互，不是一个软件"
  │   B. "这个组织记得我"
  │   C. "这个组织在为我调动资源"
  │   ├─ 否 → 功能性交互（做好就行，不需要签名级）
  │   └─ 是 ↓
  │
  └─ ★ Signature Interaction
```

## 三个 Signature Moment

---

### A · "我在和一个组织交互，不是一个软件"

**这个感觉来自哪里**

用户在做某件事的过程中，逐渐意识到：回应他的不是一个聊天机器人，而是 CIIA 这个组织。这个组织内部有展厅顾问、匹配引擎、企业对接人——不同的职能角色在内部协作，轮流出来与他交互。每个角色有自己的职责和风格，但他们属于同一个组织。

**关键交互场景**

| 场景 | 用户感知 |
|:--|:--|
| **Agent 角色交接** | "展厅顾问"说"让我请匹配助手帮您检索"→ Agent 头像切换、语调变化。用户感知："这不是一个 AI 在说话，是不同的职能角色在接力服务我" |
| **企业方真实回复** | 客户联系企业后，收到来自企业对接人的消息。用户感知："对面是真实的企业方，不是自动回复" |

**当前状态**：Agent 切换无动画，仅靠消息文本区分角色。

**优化方向**

Agent 角色交接是 A 的核心交互。需要让用户**看到**组织内部的接力：

- 交接瞬间，旧 Agent avatar 缩小 + 淡出，新 Agent avatar 从侧边滑入 + 放大
- 两个 avatar 短暂并列（~300ms），一个交接指示器（光线/波纹）从旧传到新——"信息已传递"
- 新 Agent 有微妙的风格差异（匹配助手更结构化、企业对接人更对话化）
- 交接完毕，新 Agent 开始打字

**动画时序**：
```
0ms     旧 Agent 发出交接语句（"让我请匹配助手帮您检索"）
300ms   旧 avatar 缩小，新 avatar 从右侧滑入
400ms   两个 avatar 并列 + 交接指示器（光线从左传到右）
700ms   旧 avatar 消失，新 avatar 到位
800ms   新 Agent 的 greeting 以新风格出现
```

### B · "这个组织记得我"

**这个感觉来自哪里**

用户不是每次从零开始。组织展现了积累——上次的对话、之前的偏好、历史的交互——组织的回应包含了过去的上下文。

**关键交互场景**

| 场景 | 用户感知 |
|:--|:--|
| **回到 Session** | 从 Session 列表进入一个已有的 Session，对话历史完整保留。用户感知："这个组织保存了我和企业的每一次交流" |
| **展厅记住偏好** | 用户之前搜索过"医疗AI"，再次回到展厅时看到相关推荐。用户感知："展厅记得我上次在找什么" |

**当前状态**：Session 列表展示消息数，但进入时没有"回归"的感觉。展厅搜索不记住历史。

**优化方向**

B 不是独立的动画，而是**在 A 和 C 的交互中叠加一层"记忆"信号**：

- 回到已有 Session 时，进入动画与新建 Session 不同——不是"连接中"过渡，而是"恢复中"（历史消息从底部渐显，暗示"这些是之前说过的"）
- Session 列表中的未读标记在进入后"消解"的动画（读过的气泡变成已读色）
- 展厅 header 在用户返回时短暂展示"上次搜索：医疗AI"

**优先级**：B 的交互密度不如 A 和 C，更多是在 A/C 的动画中加入"记忆"变体。暂不作为独立签名动画立项，但在 A/C 实现时预留"记忆版"差异。

---

### C · "这个组织在为我调动资源"

**这个感觉来自哪里**

用户不是在使用一个搜索功能。他看到一个组织在为他做事——匹配产品、连接企业、创建对接通道。这个过程不是瞬间黑盒出结果，而是可以看到组织在内部协调的痕迹。

**关键交互场景**

| 场景 | 用户感知 |
|:--|:--|
| **产品匹配展开** | 用户描述需求后，匹配助手不是直接丢出结果，而是展示了"检索→筛选→排序→呈现"的过程感。用户感知："这个组织在会员企业里帮我找" |
| **联系企业 → Session 创建** | 用户点"联系企业"后，不是跳出一个聊天窗口。而是看到双方身份、连接建立、Session 空间展开。用户感知："这个组织真的为我连接了一家真实企业" |

**当前状态**：联系企业 → Sheet 收起 → Session 全屏进入（sessIn 动画）。匹配过程无过程感（直接 showLoading → renderProducts）。

**优化方向**

Session 创建是 C 的最核心交互，也是全平台最高情感密度的时刻：

- 过渡状态："连接中"——双方头像从两侧向中心靠近，中间出现连接动画
- 连接建立后，产品名片从左侧滑入，对话框从下方升起
- Session 空间从中心径向扩展覆盖全屏（不是"弹出一个窗口"）
- 系统消息带组织标识："信息协会已为您连接 [企业名称] 的对接人"
- 新建 Session 和企业方 greeting 之间有不抢戏但能感知到的"组织在安排"的短暂停顿

匹配过程也需要过程感：

- 不再 showLoading 瞬间替换为结果
- Agent 先发出检索确认 → 短暂"检索中"指示器（卡片逐张浮现，而不是一次性铺满）
- 卡片以从匹配引擎到屏幕的"飞入"轨迹出现

**动画时序（Session 创建）**：
```
0ms     用户点"联系企业"
100ms   Sheet 开始下沉
150ms   双方头像从两侧向中心靠近（"连接中"）
350ms   头像相遇 → 连接光效
500ms   Session 空间从中心径向展开覆盖全屏
650ms   产品名片从左侧滑入
800ms   对话框从下方升起
1000ms  系统消息："信息协会已为您连接 [企业名] 的对接人"
1200ms  企业方 greeting 出现
```

### D · "我不是录入了一个产品，而是为这个组织创造了新的接口"

**这个感觉来自哪里**

会员录入产品时，不是在填写一个表单。他是在为 CIIA 这个组织**增加一个面向外部的接口**——这个产品将成为客户搜索、匹配、联系企业的入口。录入的瞬间，组织的"可服务能力"变大了一点。

**关键交互场景**

| 场景 | 用户感知 |
|:--|:--|
| **产品录入成功** | 录入的不是一条数据，是组织的新能力。会员感知："从今天起，客户可以通过 CIIA 找到我的产品了" |

**当前状态**：Toast "「产品名」已录入"

**优化方向**

- 录入成功后，Carousel 自动切换到产品展厅卡片——让会员看到"你的产品已经在这里了"
- 新产品卡片从提交按钮位置"飞出"，旋转 + 缩放，落入展厅产品网格首位
- 卡片入位后，一道微妙光波从新产品扫过整个网格——"组织的展厅里多了一件东西"
- Toast："已加入 CIIA 产品展厅"——强调归属，而非"录入"

**动画时序**：
```
0ms     提交 → loading spinner
500ms   新卡片从按钮位置飞出，旋转+缩放
800ms   卡片落入展厅网格首位
1000ms  光波从新卡片扫过网格
1200ms  Toast "已加入 CIIA 产品展厅"
```

## 优先级

| 优先级 | Moment | 核心交互 | 原因 |
|:--|:--|:--|:--|
| 🔴 P0 | **C · 组织在为我调动资源** | Session 创建 | 最直接体现"组织即服务"——用户在屏幕前看到组织为他在现实世界做了连接 |
| 🔴 P0 | **A · 我在和一个组织交互** | Agent 角色交接 | "组织内多角色协作"的唯一可视化窗口。如果这里不做，用户永远感受不到这个价值 |
| 🟡 P1 | **D · 为组织创造新接口** | 产品录入成功 | 从贡献者视角体现"组织越沉淀越生长"。频率低于 A/C，但情感价值高 |
| 🟢 P2 | **B · 组织记得我** | Session 回归 / 偏好回忆 | 叠加在 A 和 C 上的"记忆"变体。不独立立项，在 A/C 实现时预留差异版本 |

## 不做签名级的交互

以下是有意识排除的，以及排除原因：

| 交互 | 排除原因 |
|:--|:--|
| Button hover/press、Input focus | 功能性微交互，做到位是及格线 |
| Loading skeleton | 已有 shimmer，够用 |
| Toast 出现/消失 | 通用反馈 |
| 空状态 | 内容问题，不是动效问题 |
| 搜索匹配过程（完整） | 高频但太轻——每次搜索都放签名动画会变干扰。仅做卡片飞入的过程感即可 |
| 登录/退出 | 非平台独有价值 |
| 产品录入成功 | → 已提升为 D，见上方 |
| Sheet 上升/收起 | 功能性过渡——用户注意力在产品内容，不在 sheet 本身 |
