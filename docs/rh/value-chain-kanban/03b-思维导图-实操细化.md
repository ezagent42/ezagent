## 〇、定位锁死 + 用户价值公式（沿用 03 原文，不改）

> 定位已拍板：这是一个【内部工具】，同时它是 **ezagent 的第一个产品**（内部先 dogfooding，适时开放外部）。用 ezagent 规范 ezagent 团队自己的产品开发流程，让价值闭环从根源被跟踪、每个开发都有产品和运营同步跟进（三位一体）。

**唯一用户情境（情境 A）**：ezagent 团队自己——用这个 workspace 开发 ezagent 面向不同用户群体的真实产品。旧体验=飞书+GitHub+群+脑子（散、对齐靠会），几乎无历史数据要迁 → 替换成本低、净值明显为正。

**用户价值 = 新体验 − 旧体验 − 替换成本**。每个功能/节点挂一张**价值卡**（模板见 `06-操作模板库.md` §复用模板），强制回答：给谁 / 创造了什么真实价值（新−旧）/ 替换成本（学习+运维+信任，往死里挖）。**判定线**：损失厌恶 2.5×——换回价值 > 替换成本 2.5 倍才成立。

**外部（情境 B）= 后续阶段**：当前不做对外 PMF/PLG/差异化，只标"待内部跑通后再议"。

## 附：工具层总原则（取 API/插件，真相源在库）

| 环节 | 我们的需求 | 取谁的 API/插件 | 产物怎么挂回库 |
|---|---|---|---|
| 可视化导图 | 团队能直观看/拖整棵树 | **Miro API**（姚）/ markmap 渲染 / 二者并存 | 结构镜回 ezagent 库；节点 id 当外键 |
| 框架/线框图 | 画架构图、线框 | excalidraw（文件 JSON / React 组件） | `.excalidraw` 路径挂节点 |
| 开发 | issue/PR/看板 | GitHub REST + GraphQL + webhook | issue/PR URL 挂节点；assignee=认领人 |
| 文档/spec | 团队协作写文档 | 飞书 OpenAPI（docx/bitable）——ezagent 已有插件 | docToken/record_id 挂节点 |
| 真相源 | 节点↔认领↔产物 | **ezagent 自带 SQLite**（不是外部工具） | 它**就是**真相源 |
| 个人 agent | 盯节点、跨 agent 对话 | ezagent Entity.Agent + curl flavor | — |
| 网页出口 | 一页对齐 | socialware public_view + 编排器 | 视图 |
| 进出通道 | 外部事件接入 | 入站 Invocation.dispatch（P14）/ 出站 external_mirror | — |

> 一句话：**外部工具只贡献"能力"（取其 API/插件），不贡献"真相"（真相在 ezagent 库）**。Miro 不是我们要变成的东西，是我们取来画图的一只手。
