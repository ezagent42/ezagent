### 为什么必须用 `world.localhost`（含登录！）

- router 里世界 UI 是 `scope "/", EzagentPluginWorld, host: "world."`——只在 `world.` 开头的域名上响应。
- `*.localhost` 浏览器/macOS 会自动解析到 127.0.0.1，且不会被 HSTS 升级成 https（用 `world.ezagent.chat` 会白屏）。
- **登录必须在 `world.localhost` 上做**。`/login` 没有 host 限制（localhost 也能开），但：
  - 在 `localhost/login` 登录 → 跳 `/sessions` → 此时 host=localhost → **`localhost/sessions` 不存在 → 404「此路径无处可去」**。
  - cookie 按 host 隔离，localhost 登的 cookie 带不到 world.localhost → 新标签开 world UI = 未登录 → 白屏/弹回登录。
- ✅ 正确入口：**http://world.localhost:10042/login**（不是 `localhost/login`）。一句话：**从头到尾只用 `world.localhost:10042`**。

### 端口 55432 不是笔误

项目 config 默认 pg 在 55432（对齐它的 docker-compose），brew 的 postgres 已被配成 55432，这样所有 `mix` 命令零环境变量即可跑。

## ⚠️ 白屏排查（踩过的坑）

**症状**：`world.localhost:10042` 和 `/plugins/kanban` 打开是白屏，但 `/login` 正常。

**根因**：这个 umbrella 有**两个独立前端**，各自有 `package.json`，必须都装依赖：
1. `apps/ezagent_plugin_world/assets`（Vite，世界 React UI，:5173）→ `npm install`
2. `apps/ezagent_web/assets`（esbuild，编译出 `/assets/js/app.js` = LiveView 客户端）→ **`pnpm install`**（有 `pnpm-lock.yaml`）

如果只装了第 1 个、漏了第 2 个 → esbuild 解析不到 `react`/`@json-render/react` → **不产出 app.js** → 浏览器 `<script src="/assets/js/app.js">` **404** → 没有 JS → **白屏**。
（`/login` 是纯服务端 HTML，不依赖 JS，所以照常显示——这是判断这个坑的关键线索。）

**修复**：
```bash
cd /Users/chenruihua/Documents/Vaults/projects/ezagent
PATH="$HOME/.local/bin:$PATH" pnpm -C apps/ezagent_web/assets install
PATH="$HOME/.local/bin:$PATH" MIX_ENV=dev mix esbuild ezagent_web   # 强制出一次 app.js
# 然后浏览器 Cmd+Shift+R 硬刷新
```

**自检**（必须是 `200` + `text/javascript`，不能是 404 HTML）：
```bash
curl -I http://localhost:10042/assets/js/app.js
```

> ⚠️ 修好 app.js 后还白屏 = **浏览器缓存了之前 404 的 app.js**。普通 Cmd+Shift+R 有时不够。
> 最干净的验证：**开一个无痕窗口**（Chrome `Cmd+Shift+N`）打开 `http://world.localhost:10042`。
> 或：F12 → Application → Storage → "Clear site data" → 重新加载。
> （已确认无 Service Worker，纯 HTTP 缓存。）

## 看板在哪里建树（重要：/plugins/kanban 只是配置页）

`/plugins/kanban` 这一页**只配置出站凭证**（Miro / GitHub token），页面上自己写着：
> 「建树/认领/编辑在会话(session)里的 Kanban 子视图，本页只配置。」

也就是说——**真正建节点、认领、改状态、挂产物，是在某个 session 的 Kanban 子视图里做**，不是在这个独立页。
独立页只负责：填 Miro/GitHub 凭证（存到 `system://credentials/*.yaml`，节点级、仅 admin 可改）。

流程:先去 **Sessions** 建/进一个会话 → 在会话里切到 Kanban 子视图 → 在那里按 9 棒接力链建树。
