## 一、核心判断：03 缺的是"工艺级"模板

03 的细是**结构级**——每个叶子都有【节点名 / 认领 / 产物 / 验收】，9 大主干层层下钻。
它缺的是**工艺级**——告诉你"1.1 要产出一句话价值主张"，却没给**这句话用什么句式写**（你举的"让谁能够如何"正是这种缺失）。

> 一句话：**03 回答了"每个节点要什么"，没回答"每个节点怎么做出来"。我们要补的是后者。**

04 已经补了一部分（用户故事、验收、ICE、价值卡、挂钩牌、四角色旅程都有**填好的实例**），所以下面严格区分三种状态：
- **[缺失]**：任何地方都没有这个模板/句式 → 要新造。
- **[有实例待抽]**：04/research 有填好的例子，但没抽成"可复用空白模板" → 要抽象成模板。
- **[修正]**：现状有错/不一致/需校准。

## 二、修正点（corrections —— 需先拍板，影响写法）

### C1【最重要，需姚/Allen 确认】定位错层：流程 vs 被流程开发的产品

- **现状**：03/04 把"这个 workspace 工具**自身**"框定为"ezagent 的第一个产品（先内部 dogfooding）"，并因此在"内部 vs 外部"之间反复收口（俞军评审已点名"脚踏两只船"）。
- **问题**：录音里姚最新的说法是——**第一个产品是"官网/卖课站"（对外、要引流、要客户）**；而这套思维导图/方法论是**自举开发流程**（用来开发产品的"形/META 层"）。两者不是一个层级：
  - 思维导图 = 自举开发流程（形，META）
  - 官网/卖课站 = 跑进这条流程的**第一个产品（内容）**
- **后果**：03 把 META 层自己当成"产品"，于是被迫纠结"这个工具对内还是对外"，而真正该对外的是"官网"。这跟我们已锁的"通用框架=形、官网=第一个内容"也一致。
- **建议**：把 03 的定位校准为——**流程本身不纠结对内对外；官网作为第一个内容实例跑进来验证流程**。
- **影响面**：牵动 03 §〇（用户价值/情境 A）、§1 定位、§7 运营（对外动作全后置的措辞）、§8 北极星。**改动最大，必须先定。**

### C2 残留口径不一致（stale）

- mermaid 版 `3.1` 写"3-10 人早期团队 / ICP"，但正文 §3.1 已收口为"ezagent 团队自己、对外 ICP 后续"——**图文不一致**。
- §8.x / §9.2 仍留"PMF 测分"字样，正文 §7.2 已改为"对外才做"——`_completeness-check.md` 也点过"06 内部遗留口径"。
- **建议**：定位（C1）定下来后统一刷一遍措辞，图文对齐。

### C3 引用可信度 + 路径

- 全篇 file:line 引用基于 `/home/yaosh/...` worktree，**本机不可直接用**；且 `_completeness-check.md` 的头号缺口是"未声明哪些引用经 skill-1 实证、哪些待核"。
- **建议**：写副本时用 devloop/skill-1 核实关键引用，路径改相对根；加一栏"核查状态"。

### C4 商业模式在 03 几乎没承载（与录音脱节）

- 录音花大量篇幅讲**商业模式**（交易平台 / 以物换物 / AI 原生服务公司 / 不卖工具卖结果），但 03 §1 战略层只有"一句话价值主张 + PR/FAQ 占位"，**没有交易引擎/商业闭环的内容**。
- **建议**：若官网是对外产品（C1），L1 战略层要把商业模式写进去——**这正是俞军交易理论的用武之地**（见下方 G-a / G-p）。
