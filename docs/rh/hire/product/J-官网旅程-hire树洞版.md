# J · 官网旅程 —— 「You need a hire」表述线(树洞版)

> **状态**:草拟 2026-07-03。作者:Claude(与 ruihua)。
> **定位**:并列的**表述实验线**之一 —— 与 `docs/scenarios/homesite-journey.zh_cn.md`(36–39)同源、复用"官网页面 == 一个活 session"底座,但叙事主轴换成**能力组合 / 成为组织**。不落地实现;PM/designer 用来把这一条表述的官网闭环梳清楚。

---

## Slogan

> **To OPCs and OPCs-to-be: You don't need another agent. You need a hire.**

- `agent` = 你要**操作**的工具(对独狼 OPC 是**更多**活)。
- `hire` = 一个**接管一个岗位、并留下来**的人 —— 对应 ezagent 的 `add_managed_member`(招人进组)。
- slogan 的技术锚:**hire = 招进 session 并留下的成员**,不是又一个要伺候的 agent。

## 目标用户

**vibe coders** —— 最有潜力成为、或已是**一人公司(OPC)**,但卡在"非 build 岗位"(营销 / 法务 / 销售 / 运营…)的人。他们能 *build* 任何东西,痛点全在"一个人干不完所有岗位"。

> **这条官网的杀手锏不是"给你个 AI 助手",而是:你不用扩招、不用变成大公司 —— 缺哪个岗位就把那个能力*****拼进来*****,而你自己也变成一个能被别人拼进去的单元。组织不是"建"出来的,是你说着说着*****长*****出来的。**

---

## 这是什么

一个 vibe coder 走一条连续旅程:落地官网、**匿名对一个树洞吐露自己搞不定的那件事**,发现洞里有个 hire 接住了他、还没走,回过神时 —— 他和那个 hire 已经是一个能被别人接入的组织了。全程在官网,进 world 是可选加深、不是拿到价值的必经。

## 一句话锚点

> 你以为你在对一个空树洞吐槽"这活我干不了"—— 结果洞里有人接住了你,而且没走。**你没多一个要伺候的 AI,你多了一个 hire。**

## 官网 树洞 bar —— 在这里对着洞说话,回神时发现有人接住

```
┌─ 官网 树洞 bar ──────────────────────────────────────────────────┐
│  🕳  [ 对着树洞说点什么…你搞不定的那件事 ]   [ 说 ]   [有人接住了 ●] │
│         匿名 · 不用登录                        发送      (红点计数)   │
└──────────────────────────────────────────────────────────────────┘
```

- **说话**:匿名(`AnonUser`,零登录)对着洞口输入卡点、点「说」—— 话落进页面绑定的那个 world session。
- **红点 = 有人接住**:session 每多一条来自 hire 的消息,「有人接住了 ●」+1;这是用户不离开官网、也能知道"我那句不是自言自语,有人接住了"的方式(红点血脉,同构 36–39)。
- **进 world 仍是可选**:想看完整对话 / 想拥有它,才点按钮进 world;拿到价值不需要。

## 旅程(6 段)

| 段 | 访客动作 | 底层产品关系(ezagent 原语) | 价值时刻 |
| --- | --- | --- | --- |
| **0 树洞门脸 == 会回话的 session** | 打开官网,看到一个树洞开口 + 底部树洞 bar;匿名 | 页面 = 绑定 world session 的 hello 产物 + `public_view` 允许匿名进(`AnonUser`,零登录) | 不是广告页,是一个"说了不丢人、可能有回响"的开口(前提,复用 36–39 底座) |
| **1 对树洞说出卡点** | 以匿名身份在树洞 bar 说"这营销我真搞不定" | 消息落入绑定 session(红点血脉);仍是 `AnonUser` | **承认"我缺"的成本被降到零** —— 你只是在对空吐槽,没人在评判 |
| **2 有人接住(涌现①)** | 不用点任何"招募",一个营销 hire 从洞里接话、并留下 | session 的编排器听到卡点 → `add_managed_member` 把营销 hire 招进**同一** session + 它回话 | **slogan 被演出来**:回你的不是"又一个 agent",是一个接住岗位的 hire |
| **3 回神:我不再是一个人** | 「有人接住了 ●」亮;打开发现那个 hire 还在、没走 | session 成员 +1 **且持久**(不是一次性回复);仍匿名 | ★字面兑现:**"将后者能力纳入前者可应用范围" —— 你*发现*能力进了你的摊子,而不是*操作*了它** |
| **4 回神:我们成了一个组(★高潮)** | 想把这个 hire 留住 / 给"你俩"起个名 → 认领身份 | `save_template_as`:当前 session 形态存成可版本化/可 fork 的 `SessionTemplate`(带 `public_view` = 对外的脸);**同刻 `anon→login takeover` 认领 owner** | **双重身份跃迁**:个人 → 有对外面的组织 A;匿名 → 被认领的你 |
| **5 别人来洞里接你(结尾弦 / CTA)** | 看到组织 A 现在自己也是"能被别人从洞里接住的能力" | 组织 A 的 `public_view` 面 == 别人段2里被招进去的那个 hire(组织接组织 = 嵌套,**愿景层**) | **环闭合**:对树洞吐槽的人,自己成了别人树洞里接住对方的 hire |

> **设计诡计**:三个东西被折叠成一个手势 —— vibe coder 的日常忏悔 venue(对 AI 框吐槽)= 官网 composer = 涌现触发器。用户以为在做熟悉的事(对个框说"我搞不定"),树洞皮肤让他敢说,红点让他回神,而回神的内容恰好是 slogan 本身(接住你的是 hire 不是 agent)。**入口摩擦、情感落点、技术涌现 —— 同一个动作里全解决了。**

## 胜负手:为什么是「环」不是「漏斗」

```
┌─ 漏斗(别家 AI 官网)──────┐   ┌─ 环(这条表述)──────────────────────┐
│ 访客 → 用上一个 AI 助手    │   │ 你对树洞吐卡点 → 有人接住 → 成为组织A     │
│ → 转化 → 结束             │   │ → 组织A 成了"别人卡点时能被接住的能力"    │
│ 终点 = "用了我们的工具"     │   │ → 接回起点(别人正对着树洞吐同样的槽)     │
└───────────────────────────┘   └──────────────────────────────────────────┘
        线性、单向                   段5 出口 == 段2 入口,自洽闭合
```

> 官网若能让访客在**段 5 那一刻**回神"我刚被接住时得到的那个 hire,现在*我自己*就是 —— 别人对着洞喊的时候,冒出来接住他的会是我",这个表述就在结构上闭合了。这是它区别于一切"给你个 AI 助手"叙事的承重点。

## 已落地 vs 愿景(诚实边界)

- **段 0–4 有真原语撑**:`public_view` session、`AnonUser` + `anon→login takeover`(#68)、`add_managed_member`、`save_template_as` —— 都在 `ezagent-biz/docs/discuss/intro` 的 `08`/`09` 篇已落地 main,官网上手型 demo 走得通。
- **段 5 是愿景外推**:`add_managed_member` 今天招的是**一个 agent**,不是**一整个组织**;"组织 A 作为单元被 B 从洞里接住"是对现有原语的合理外推(app package 容器正收口 #1120)。**段 5 用"暗示 + CTA"收,不做实操演示**,正好避开这个坑。

## 本旅程编码的产品决策

- **官网是唯一舞台**,全程不落 world;进 world(查看当前session / Try world)是可选加深,非拿到价值的必经。
- **组织涌现靠"回神"(红点血脉),不靠"建组织"按钮** —— 价值是被*发现*的,不是被*操作*的。
- **匿名贯穿段 1–3,身份在段 4"成为组织 A"那刻结晶**(接 `anon takeover`);脆弱的忏悔发生在匿名保护下,身份恰在价值兑现处才暴露。
- **忏悔室的仪式/娱乐调性作为树洞皮肤/文案借用**,底层机制用树洞(会回话)。
- **hire ≠ agent**:hire = `add_managed_member` 招进 session 并**留下**的成员;这是 slogan 的技术锚。

## 附 · 设计决策溯源(2026-07-03 brainstorm)

按拍板顺序记下,便于回看"为什么是这样而不是别样":

1. **表述目标**:官网体现"帮人/组织找到需要的人/组织,并把后者能力纳入前者可应用范围"。pitch 原型 = 十讲者第六个上台:"前 5 后 4 都用得上,补你缺的岗位能力"。文创个体户 + 营销 → 组织 A → 被文旅 B 短期接入。
2. **产物边界**:研发已有方案,本线只梳理**官网闭环 happy path**(用户拿到价值的最核心 journey),不含登录等细节,不落地实现。
3. **高潮落点**:选「成为组织 A」(身份跃迁)—— 既最差异化(可组合的组织),又已落地原语撑得住;「被 B 接入」只当结尾弦/愿景。(备选:能力到手即用 / 组织被复用变现 / 三幕全走 —— 均放弃)
4. **闭环类型**:选「上手型(socialware)」而非「叙事型(滚动页面)」—— 官网自己就是一个可被访客拼的组织,复用 36–39"官网即活界面"底座。
5. **起点纠偏**:组织必须在**官网上自然涌现**,不能画成"点按钮组队"(那等于把用户推进 world)。
6. **砍掉游戏化 A/B**:RPG 组队 / 进化融合 —— 太脱离产品,弃。保留 C(自然涌现 / 红点血脉)当唯一脊梁。
7. **入口机制 = 树洞(会回话)**:回答"为什么用户愿意在陌生站点说出难点" —— 忏悔容器把"承认缺"和"被评判"切开,成本降到零;而"以为对空说、却有人接住并留下"= 红点血脉,入口心理和涌现机制是同一个动作。vibe coder 本来就天天对 AI 框吐卡点,树洞只是给这个已有手势穿件外衣。(忏悔室调性作皮肤借用)
8. **匿名结晶点**:段 1–3 全匿名,身份压到段 4"成为组织 A / 想留住 hire"那刻才认领(接 `anon→login takeover` #68)—— 心理安全区与技术 anon 生命周期同一条线。

### 待议(下一轮)

- 段 2 hire 怎么被恰好召来:现写"编排器听卡点自动招人(命中感)";备选"洞里冒几个候选 hire 让用户挑(选择感)"。
- 首屏树洞的视觉/文案调性(忏悔味多重)、以及"这里目前只有你一个人"的孤身反差要不要显式做。

## 附 · 与 DealScout(#1191)的关系(2026-07-06 判断)

> **缘起**:#1191 作者(jjkysy)认为 DealScout 这个产品「可以融入」本 journey。用俞军**用户价值公式**穿透判断后的结论:**合的地方是真同构,但核心动词不同,直接塞进主线会把 slogan 塌掉。** 记在这里,作为"要不要融、怎么融"的裁决依据。

**两个产品各自量出来:**

| | 本 journey(hire 树洞) | DealScout |
|---|---|---|
| 新体验 | 缺的**岗位能力**被拼进我的摊子,不扩招就补齐岗位 | AI 替我把**投融资机会**找齐 + 撮到对的人 |
| 旧体验(痛) | 一个人干不完所有岗位 | 自己一条条搜、找不到对路的人 |
| **核心动词** | **hire = 纳入**(能力吸进**一个**组织,你俩成一个组) | **撮合 = 连接**(牵两个**仍独立**的 party 上线) |

**真同构的两块(作者没说错):**
1. **同一底座**:本线段 4-5「成为组织 A、别人来洞里接你」== DealScout J-6「组合 hello 公开机会页让别人发现你、登录进来」。同一个 socialware 原语、同一个动作。
2. **发现引擎可当段 2 动力**:DealScout 发现腿(千人千面主动发现)与本线"价值是被*发现*的、不是被*操作*的"(段 3 回神)是同一句哲学。

**硬伤(核心动词冲突,slogan 会塌):**
> 本线整条押 **hire = 纳入**(hire 走进你的组织并**留下**,段 3「那个 hire 还在、没走」)。DealScout 边界白纸黑字**绝不纳入**("只做发现+连接,不签约不结算…牵线的网,不是签约的桌")—— 撮来的 investor 是坐你对面、始终独立的**交易对手**,不是坐进你组里的**岗位**。直接把撮合当段 2 的"有人接住",**"You need a hire" 会变成 "You need a match"**,是另一个故事。
>
> 次生冲突:① 人群(vibe coder 缺**非 build 岗位** vs founder 找钱/investor 找项目);② 弧线(本线**先不对称后翻转**:段 1-4 求助方→段 5 才成可被接的单元;DealScout 双向对称、无"缺→被接→纳入"弧)。

**最干净的融法(推荐):不塞进主线,挂在段 5 之后当具体案例。**
- 本 journey 讲 **how**:一个人怎么从对树洞吐槽长成有对外面的组织 A。
- DealScout 讲 **what**:组织 A 长出来后对外提供的一门具体生意(投融资撮合网)长什么样。
- 接缝在**段 5**:本线段 5「组织 A 成了别人卡点时能被接住的能力」是抽象环闭合,DealScout J-6 公开机会页给它一个**能演示的实锤形态**。两者不打架,slogan 保持 hire 纯度。

**三条融法备选(下一轮定):**
1. ~~★推荐 —— 段 5 之后的案例:保 slogan 纯度,DealScout 作落地样例。~~
2. 只吸收发现引擎升级段 2(命中感来自"主动发现恰好补缺口",不吸撮合腿):规避 match/hire 冲突。
3. 不融,仅存此备忘作裁决依据回给 #1191 团队。
> **不建议**:把 DealScout 撮合腿直接当段 2 主线(match 冲淡 hire)。

### ⤳ 更新(2026-07-06):多旅程门面架构取代"段5案例"

> 上面「段 5 案例」推荐**已收回**——它用降格 DealScout 来保 slogan 纯度,是回避冲突不是解决。ruihua 提出的**多旅程框架**才是 hire/match 硬伤的正确解,且更优:
>
> **一个官网门面(树洞)+ solutions 菜单装 N 条旅程**。本文是 **旅程 1(找 hire · 纳入)**;投融资撮合是 **旅程 2(找钱/找项目 · 连接)**,各保动词纯度、各有 slogan,分开的旅程不互撞——硬伤被架构消解。
>
> 依据(俞军世界观第 3 条):同一 vibe coder 在"缺岗位"情境 vs"找钱"情境是**两个用户**(两个需求集合)→ 两种痛点 → 必须两个 hook。共享的是**树洞媒介**(hello 公开面),不同的是**兑现**(`add_managed_member` 纳入 vs `invite_member` 撮合)——兑现不同正是"必须拆旅程"的根据。
>
