# hire 产品文档 1：定位 → 北极星（P 层）

> **一句话**：hire = **帮 OPC「说出缺什么岗位 → 把那份能力纳入自己可应用的范围」**。地基是**补能力腿**（对树洞说卡点 → 招一个 hire 进来并留下），亮点是**成为可组合单元腿**（你和 hire 长成一个能被别人拼进去的组织 A）。**找为主？不 —— hire 是"补为主、成为单元为亮点"**。
>
> **本文在追溯树的位置**：最上游 P 层（定位→北极星），全树的根。编号从 P-1.1「补能力/成为单元」根一路推导：因为要帮 OPC 补齐缺的岗位能力（P-1.1），所以看清靠哪几条腿支撑（P-2 两条腿），所以每条腿得能量出兑现（P-3 北极星，分期）。
>
> **编号规则**：`P-层.序`。§1 根（P-1.1）无上游；往下每层每节点恰一个上游 `↑`。🟦 补能力腿 / 🟨 成为单元腿是**颜色属性**，不参与父子结构。

---

## §1 根：补能力 / 成为单元（P-1.1 · 根，无上游）

**dealscout 为什么存在？** 因为一群 vibe coder / OPC —— 最能 *build* 任何东西的人 —— 全都卡在**非 build 岗位**（营销 / 法务 / 销售 / 运营…）。一个人干不完所有岗位，去扩招又不想变成大公司。

### P-1.1 帮 OPC「说出缺什么岗位 → 纳入能力范围」

hire 存在的理由：**让一个 OPC 不扩招、不变大公司，缺哪个岗位就把那份能力拼进来 —— 而且他自己也变成一个能被别人拼进去的单元。**

- **地基 = 补能力（找为主里的"补"）**：对树洞说出你搞不定的那件事 → 平台把一个 hire（可能是 agent / user / org）招进你的 session 并**留下** → 那份能力进了你可应用的范围。这是天天兑现价值的地基。
- **亮点 = 成为可组合单元（涌现，不当地基）**：当你和 hire 的协作稳定下来，**"成为组织"就作为涌现的亮点自然长出来** —— 你把这个 session 形态存成一个可对外的组织 A，别人卡点时能把组织 A 当作一个 hire 接进去。很重要、是网络效应来源，但**不是地基**：没有先把能力补齐，无所谓"成为单元"。

**边界（收进根，不单列节点）**：hire **只做到"把能力招进来、让协作留下"为止** —— 只做**发现 + 纳入一个 hire 进你的 session**，**不做**雇佣关系 / 薪酬 / HR / 绩效，也**不做**"把对方当独立对手方牵上线"（那是 DealScout 撮合腿）。hire 是"接管一个岗位并留下的成员"，是能力单元，不是劳动合同、不是一次相遇。

## §2 两条价值腿：补能力腿 × 成为单元腿（P-2.x · 各 ↑ P-1.1）

既然根是"补能力为地基、成为单元为亮点"，那第一个要拆的就是：**这件事靠哪几条腿支撑？** 两条 —— 一条地基腿（补能力）、一条亮点腿（成为单元）。

### P-2.1 ↑ P-1.1 🟦 补能力腿（地基）：说出卡点 → 招 hire 进来并留下

补能力腿是 hire 的**地基**，也是**天天在动**的那条腿：

- **说出卡点（匿名）**：OPC 对树洞说"这营销我真搞不定" —— 承认"我缺"的成本被降到零（只是对空吐槽，没人评判）。
- **招 hire 纳入**：session 的编排器听到卡点 → `add_managed_member` 把一个营销 hire 招进**同一** session 并回话 —— 回你的不是"又一个 agent"，是接住岗位的 hire。
- **hire 留下**：成员持久化，能力进了你的摊子（是被*发现*的，不是被*操作*的）。

> **旧体验重定义（承 `model.md` §0）**：这条腿的价值不是"AI 替你做营销"（那是旧体验，vibe coder 天天用），而是"**专家经验(承载在 hire 里)替你做**" —— 差异化在「非专家驱动的通用 agent vs 承载专家经验的 hire」。**⚠ 第一证伪点**：hire 必须真承载专家经验、不是通用 agent 换皮，否则 vibe coder 最快识破。

补能力腿**今天就能做**（`public_view` + `AnonUser` + `add_managed_member` + 成员持久化都在 main）；但"hire 真承载专家经验"是要优先验证的假设、且是平台质量门的 core job（`model.md` §6）。

### P-2.2 ↑ P-1.1 🟨 成为可组合单元腿（亮点·涌现）：成为组织 A → 被别人接入

成为单元腿是 hire 的**亮点** —— 在补能力腿之上**涌现**：

- **成为组织 A**：想把 hire 留住 / 给"你俩"起个名 → `save_template_as` 把当前 session 形态存成可版本化 / 可 fork 的 SessionTemplate（带 `public_view` 对外面）；同刻 `anon→login takeover` 认领 owner。个人 → 有对外面的组织 A，匿名 → 被认领的你（双重身份跃迁）。
- **被别人接入（愿景）**：组织 A 的 `public_view` 面 == 别人卡点时能被招进去的那个 hire（组织接组织 = 嵌套）。**这是愿景外推**：`add_managed_member` 今天招的是一个 agent、不是一整个组织，依赖 app package 容器收口（#1120）。

**为什么成为单元是亮点不是地基**：它完全站在补能力腿之上 —— 没有先招 hire 补齐能力、让协作稳定，无所谓"把它存成组织"。成为单元是补能力结出的果子。

## §3 北极星（P-3.x · 各 ↑ 对应腿，分期）

价值靠两条腿，就得能**量出来**每条腿有没有兑现。**分期**：地基腿指标是近期主指标、天天动；亮点腿指标是远期愿景、质量加权。为什么分期？把远期的"成为组织数"当唯一近期指标会误导 —— 成为单元是涌现的果子，急不得；补能力是地基，天天该有产出。

### P-3.1 ↑ P-2.1 🟦 补能力北极星（近期·主指标，天天动）

- **量什么**：① 招进并**留下**的 hire 数（留下 = 成员持久化、不是一次性回复）；② 卡点→能力补齐的转化率 & 时间（从"对树洞说出卡点"到"有一个 hire 接住并留下"，多少比例走通、平均多久）。
- **为什么反映定位**：P-2.1 说补能力腿是天天用的地基。如果卡点接不住、hire 招不进 / 留不下，地基就没立住，"成为单元"也无从谈起。
- **目标方向**：招进并留下的 hire 数 ↑；卡点→补齐时间从"以天计的招人/外包"压到**分钟级**（对树洞说一句话就接住）。

### P-3.2 ↑ P-2.2 🟨 成为单元北极星（远期·愿景，质量加权）

- **量什么**：① 成为组织 A 数；② 组织 A 被别人**接入深用**数（核心，质量加权）—— 不是"存了个模板"就算，要真被别人当 hire `add_managed_member` 拼进去、且产生持续协作。用可观测硬代理衡量（被接入后是否有持续 dispatch / 成员活跃），不用 owner 自报。③ **供给侧捕获**（交易模型闭合项，`model.md` §6）：被招方拿到的 **expertise 租金**（按招入 × 招方持续使用结算，**不用 owner 自报满意度**）—— 这条量的是供给侧的利益*分配*到没到位、专家愿不愿持续投入。
- **为什么反映定位**：P-2.2 说成为单元腿是补能力之上涌现的亮点。组织 A 被别人接入深用，直接量的就是这个亮点有没有真涌现。它随补能力地基的厚度水涨船高；而供给侧捕获（③）是这条腿**长期转得起来**的开关（供给方机会成本近零、但仍需真捕获才持续投入）。
- **目标方向**：成为组织 A 数 ↑；被接入深用数 ↑（质量加权，不刷"存模板"量）；供给侧 expertise 租金分配到位（激励相容：调得越好、被招越多、赚越多）。
