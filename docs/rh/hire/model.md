## 0. 核心命题：专家经验的可复用化（旧体验重定义，2026-07-06）

> yujun evaluate + 与 ruihua 对话后确立。**这一节是整条价值链的承重命题，其余各节都服务于它。**

**旧体验不是"我用 AI 做营销"，是"我(非专家)驱动通用 agent 做营销 → 结果很差"** —— 非专家既不会 steer、也不会 evaluate 产出。所以：

- **新体验 ≠ "AI 替你做"**（那是旧体验，vibe coder 天天在用）；**新体验 = "专家经验(承载在 hire 里)替你做，而你把这个承载专家经验的单元纳入自己的组"**。差异化从「agent vs hire」(UI 层、难感知) 挪到「**非专家驱动的 agent vs 承载专家经验的 hire**」(能力层、痛感清晰)。
- **为什么目标用户是 vibe coder / OPC**：① 有为模型付费的习惯（变现前提）；② 他们*恰恰*是唯一能 viscerally 感知这个差异的人 —— 亲手体验过"我+agent 干超出自己领域的活，结果就是差"。外行感知不到 expert-gap；懂 expert-gap 的付费者才是精准用户集合。
- **⚠ 第一证伪点（承重假设）**：**被招的 hire 必须真的承载专家经验**（专家 authored 的 AgentManifest / 真专家 human / 真专家 org），**不是又一个套了"营销"系统提示的通用 agent**。若产品交付的 hire 是通用 agent 换皮，vibe coder 是最快识破的人，整条 slogan 当场塌。**这是该被最小代价优先验证的第一假设**，也是平台的 core job（见 §6 底线需求 / 质量门）。

## 1. 核心动词：纳入（不是连接）

hire 价值链的每一步都是 **纳入 = 把一份能力吸进你的 session，成为你可应用范围的一部分**。

```
┌─ 纳入(hire 价值链)──────────────┐   ┌─ 连接(DealScout 撮合)────────────┐
│ 招一个 hire 进你的 session       │   │ 牵一个对手方进一次私聊            │
│ hire 留下,成为你的成员           │   │ 双方仍是两个独立的 party         │
│ 你的能力范围变大了               │   │ 你们连上了线,各回各家            │
│ add_managed_member               │   │ invite_member                    │
└──────────────────────────────────┘   └──────────────────────────────────┘
      成一个组(one org)                        牵一条线(two orgs)
```

> **一句话洞察**：hire 和 investor 共享同一个树洞媒介（hello 公开面 / 对话式页面），但**动词不同** —— 这就是官网"一门面装多条旅程"里，两条旅程必须各写各的根据。写 hire 的任何一格时，若冒出"两个仍独立的 party"，就是动词破了。

## 2. 三个状态跃迁（匿名 → 成员 → 组织）

一个 OPC 走完 hire 旅程，身份经过三次跃迁：

```
匿名 AnonUser ──说出卡点──► 有 hire 的个体 ──save_template_as+认领──► 有对外面的组织 A
  (J-1/J-2 零登录)            (J-3/J-4 hire 进来并留下)         (J-5 anon→login takeover 认领 owner)
```

- **匿名段（J-1..J-4）**：脆弱的"承认我缺"发生在匿名保护下。红点血脉让用户不离开官网也知道"我那句有人接住了"。
- **结晶点（J-5）**：身份恰在价值兑现处（"我们成了一个组"）才认领——接 `anon→login takeover`（#68）。心理安全区与技术 anon 生命周期是同一条线。

## 3. 四个支撑原语

| 原语 | 干什么 | 在旅程哪一步 | 现状 |
|---|---|---|---|
| **`public_view` + `AnonUser`** | 允许匿名访客零登录进入并写入树洞 | J-1/J-2（F-1） | 已落地（socialware + #68 anon-user） |
| **`add_managed_member`** | 从 AgentTemplate 招一个 worker 进 session、成为带稳定 `role_name` 的成员 | J-3（F-2）；**hire 的技术锚** | 已落地（orchestrator 工具） |
| **`save_template_as`** | 把当前 session 形态快照成一个可版本化 / 可 fork 的新 SessionTemplate 家族 | J-5（F-5） | 已落地 |
| **`anon→login takeover`** | 匿名足迹在用户登录时物理改名为确认用户 | J-5（F-7） | 已落地（#68 anon-user epic） |

> **hire ≠ agent**：hire = `add_managed_member` 招进 session 并**留下**的成员（`role_name` 稳定、成员持久化 F-3），不是又一个要 `dispatch` 去操作的 agent。这是 slogan「You need a hire, not another agent」的技术锚。

## 4. 边界（收进根 P-1.1，不做什么）

- **不做雇佣 / 薪酬 / HR / 绩效**：hire 是"接管一个岗位并留下的成员"，是能力单元，不是劳动合同。
- **不做"把对方作为独立对手方牵上线"**：那是 DealScout 撮合腿的活（连接，非纳入）。hire 旅程里进来的一律成为你 session 的成员。
- **组织嵌套（F-8）是愿景不是现状**：`add_managed_member` 今天招的是**一个 agent**，不是**一整个组织**。"组织 A 作为单元被别人接入"依赖 app package 容器（正收口 #1120）。**旅程 J-6 用"暗示 + CTA"收，不做实操演示**，正好避开这个坑。

## 5. 与 DealScout 骨架对读

| 层 | hire（本文档） | DealScout（旅程 2） |
|---|---|---|
| 根 | 说出缺什么岗位 → 纳入能力范围 | 帮找机会的人对接（发现为地基、撮合为亮点） |
| 地基腿 | 补能力（招 hire 纳入） | 发现腿（AI 千人千面发现 deal） |
| 亮点腿 | 成为可组合单元（成为组织 A） | 撮合腿（公开面聊天 → invite 深聊） |
| 核心动词 | **纳入** `add_managed_member` | **连接** `invite_member` |
| 共享媒介 | 树洞 = hello 公开面 / `public_view` 对话页 | 同左 |

> 骨架相同、叶子不同：正是"一个官网装多条旅程"在价值链层的印证。合进官网时，solutions 菜单按"用户对树洞说了什么"分流到对应价值链。

## 6. 交易模型（利益创造 + 利益分配 · 2026-07-06 yujun 核算）

> 闭合评审暴露的开口边：**成为单元腿（P-2.2）的供给侧利益分配 + 谁付 agent 成本**。地基腿（招 agent-hire）是单边、清晰；本节主要核算亮点腿的双边。

### 6.1 利益创造（利从何来）

核心有利可图价值 = **专家经验的可复用化**：把稀缺的"专家 steer"固化进 agent，让它服务多个非专家 —— 打破"专家时间不可复制"的旧约束，建立"专家经验可复制"的新产业链。

**效用四分类（决定在哪使劲）**：

| 类 | 对应 | 做到什么程度 |
|---|---|---|
| **底线需求（一票否决）** | **hire 真承载专家经验、不干砸** | **bad case 最小化 = 平台生死线**（= §0 第一证伪点制度化） |
| 够用就好 | hire 通用交互 / UI | 够用即停 |
| 越多越好（愿多付） | 专家经验的深度 / 领域覆盖 | 供给侧愿多投、需求侧愿多付 —— 做到极高 ROI |
| 惊喜（惠而不费） | hire 主动发现你没想到的岗位缺口 | 低成本增量 |

### 6.2 利益分配（利往何去）

**谁付 agent 成本**：**招方付 compute + expertise 租金**（招方本就有付费习惯，这条干净）；平台抽 platform fee；**供给方收 expertise 租金（真金白银）+ 声誉飞轮（辅）**。光曝光补偿不够 —— 损失厌恶 2.5×，供给方放弃独占 + 担招牌风险，必须真捕获。

**激励相容（利益分配的标尺）**：

```
招方   自利=多用好 hire ──┐
供给方 自利=把经验调深调真 → 越多人招 → 越多租金 ──┤ 三方自利方向一致 ✓
平台   自利=守质量门+撮合精准 → 越多真能力交易 → 越多抽成 ──┘
```
> 前提：平台守住底线需求（hire 真承载专家经验）。守不住 → 招方被坑一次即走 → 飞轮反向瓦解。

### 6.3 可持续性

- **机会成本近零是漂亮根基**：供给方把专家 agent 上架的机会成本 ≈ 近零（agent 化后被招不占专家真人时间，像顺风车顺路多接一单）→ "一份能力成就多份价值"经济上成立、供给侧易起量。
- **自我强化 vs 自我瓦解**：越多专家上架 → 越多非专家招到好 hire → 越多付费 → 越多专家来（强化）。唯一自我瓦解开关 = **质量门破**（劣质 hire 稀释）。
- **边际结构**：hire 干活边际成本 ≈ LLM compute（中等）→ "按用量付费"是合理经营模式。

### 6.4 交易模型三条致命项（→ 落到北极星与验证）

1. **平台质量门 = 底线需求 = 生死线**：把 §0 第一证伪点从口号变成平台 core job。
2. **expertise 租金要可观测硬结算口径**（按招入 × 招方持续使用，**不用 owner 自报满意度**，同 DealScout 北极星纪律）。
3. **供给侧冷启动**：F-8 未落地前双边转不起来 —— 先用平台/专家直供的 agent-hire 撑单边地基腿，等 F-8 + 租金机制上线再点双边。
