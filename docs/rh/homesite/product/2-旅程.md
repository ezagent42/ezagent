## 旅程编码的产品决策

- **官网 + gallery 是舞台，world 是可选加深**：seller S1 全程可在官网页面对话完成；进 world（查看当前 session / Try world）是加深，非拿到价值的必经（承 scenario 36–39 决策）。
- **fork 靠"复制配置→新 session"，不是"分享→同 session"**：S1'（加入·成员）与 S2/S3（fork·owner）是**互为失败模式**的两条路（scenario 38 vs 39），逼后端 session 语义精确 —— 分享该进同一 session，fork 该起新 session，串了就是 bug。
- **匿名贯穿 S0–S1，身份在 S2/S3"fork 认领 owner"那刻结晶**（接 `anon→login takeover`）；与 builder 的身份在 B3"开始认真造之前"结晶不同（供给方要长期经营，早认领）。
- **动词纯度 = fork**：seller 全程把一个完整产品复制成自己的起点，不是 hire 的"纳入成员"、不是 DealScout 的"连接对手方"（`model.md §3`）。
- **builder/seller = tool-first / value-first**（判别式 `model.md §1.1`）：builder（技术创作者）入口走通用 tech 面（B0 tech site）；seller（价值优先业务主）**S0 按行业气质分渠道变体** —— 各渠道落地链接用各自表述 + UX 迎合（同一 gallery 产品，N 副气质皮；harvest legacy persona-变体，`model.md §1.2`）。
