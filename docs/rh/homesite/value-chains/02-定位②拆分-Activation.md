# 定位② · Activation（→ 试用量/率）· 树状

> **官网 = 一个 loom 生成式对话页**：底部对话框 → 访客描述想看什么 → 页面即时重构。引擎（builder/发布助手/视图切换）为**平台给定底座，不展开实现**（参考 `/Users/chenruihua/Documents/Vaults/projects/loom`）。线框 = 重构后页面的**基本形式/默认骨架**，文案数据驱动。
> 流程见 `docs/rh/value-chain-kanban/07-定版-自举开发流程-10分钟.md`；模板见 `docs/rh/value-chain-kanban/06-操作模板库.md` + `00` §五卡模板；persona 见 `P-用户画像-personas.md`。
> **树状结构**：定位 → 北极星 → 输入指标 → **痛点** → 角色(persona) → spec卡 + 原型图。
> **边界**：本棒接住 ① 交来的「有效浏览量」，负责把「看进去」变成「真的试一把」。**发起对话 / 对话驱动重构 / 空框引导 / 上手体验都在本棒**；留资/订阅/再回来 = **③ Retention**，不在本棒。

---

## §1 定位稿（定位 → 北极星）

母定位（G-a，源自 `00`）：

> **让进站浏览的访问者，能在官网里直接跑一个对得上自己场景的 demo，而不必先注册、下载或联系销售才看得到产品到底怎么用。**

谁＝已进站、正在浏览的访问者 / 新体验＝零门槛跑通一个贴合自己场景的可跑 demo / 旧成本＝想体验得注册/下载/找销售、门槛劝退。AARRR 第 2 棒，交棒 = **有效试用量**。

---

## §2 北极星 → 输入指标（指标 + 精确定义）

> **关系**：北极星 = 结果（果）；输入指标 = 能动手推高它的杠杆（因），尽量与北极星成**公式分解**；链条 **痛点→角色→卡 拨动输入指标 → 抬北极星**。

**北极星：有效试用量** = 统计窗口内「真正跑通一次贴合自己场景 demo」的去重访客数（发起对话 → 命中需求 → 看到真实结果）。

**分解：`有效试用量 ≈ 有效浏览量 × 发起对话率 × 命中率 × 跑通率`**

这是一条转化漏斗：① 交来的有效浏览量，逐级被「敢不敢开口 → 重构对不对得上 → demo 跑不跑得通」三道乘数过滤。

| 输入指标 | 精确定义 |
|---|---|
| 〔承接①〕**有效浏览量** | 真正看进去的去重访客数（见 `01` §2） |
| **A 发起对话率** | 在对话框发起输入/触发重构的访客数 ÷ 有效浏览访客数 |
| **B 命中率** | 重构出的页面「对上访客需求、愿意往下试」的会话数 ÷ 发起对话会话数 |
| **C 跑通率** | 发起 demo 后成功看到真实结果的访客数 ÷ 发起 demo 的访客数 |

> **对话驱动重构本身 = loom 底座能力**，不在本棒重建；本棒只拨动「让人敢开口（A）、给重构喂对场景料（B）、让 demo 真能跑（C）」。
> **实验判读（取代二元 drop）**：每个指标按 `假设 + 窗口 N 天 + 判读{ 达标 T→继续 / 未达→先改方案 / 连续 M 窗口仍未达→drop }`，阈值待运营随上线拍板。

## §3 树主体（输入指标 → 痛点 → 角色 → spec卡 + 原型图）

```
定位② Activation
└─ 北极星：有效试用量 (≈ 有效浏览量 × 发起对话率 × 命中率 × 跑通率)
   ├─ 输入指标 A · 发起对话率
   │   └─ 痛点 P5 不知道这个框能干嘛、能输入什么
   │       └─ 角色 全体访客 → 功能卡 ②-A1 空框引导(示例提示) · 原型 对话框引导态
   ├─ 输入指标 B · 命中率（重构对上需求）
   │   ├─ 痛点 P6 给的是通用介绍、对不上我的场景
   │   │   ├─ 角色 赵全扛 → 内容卡 ②-B赵 单干场景样例 · 原型 赵全扛视角
   │   │   ├─ 角色 钱降本 → 内容卡 ②-B钱 客服降本样例 · 原型 钱降本视角
   │   │   └─ 角色 孙集成 → 内容卡 ②-B孙 集成场景样例 · 原型 孙集成视角
   │   └─ 痛点 P7 信息堆一起、看不出是什么/怎么用/给什么结果
   │       └─ 角色 全体访客 → 内容卡 ②-B1 价值分层骨架 + 功能卡 ②-B2 三步图 · 原型 默认骨架
   └─ 输入指标 C · 跑通率
       ├─ 痛点 P8 要注册/下载/找销售才看得到产品
       │   └─ 角色 全体访客 → 功能卡 ②-C1 内嵌可跑 demo · 原型 demo 容器
       ├─ 痛点 P9 试跑等很久、或给个假占位
       │   └─ 角色 全体访客 → 功能卡 ②-C2 即时反馈(streaming+兜底)
       └─ 痛点 P10 想多试/想深入却被强制注册打断
           └─ 角色 全体访客 → 功能卡 ②-C3 自由续试+软CTA(交接③)
```

> **卡型两类（模板见 `00` §五）**：内容卡＝不开发、只调内容；功能卡＝需开发。卡模板是 06 `G-r` 的官网精简版（省略 ICE 打分/价值卡/节点 id）。对话框/builder/发布助手/重构引擎 = loom 底座，引用不重建。
> **persona 视角触发（② 阶段）**：靠**访客在对话框自报场景 → 底座重构到对应视角**（① 阶段靠投放/分享落地变体，② 阶段靠对话）。persona 无关的输入指标（发起对话率/跑通率）挂「全体访客」节点。

### 输入指标 A · 发起对话率

#### 痛点 P5（G-c）
> 当访问者落到官网、看到底部一个空对话框时，他想知道「这框能帮我干嘛、我该说什么」，以便决定要不要开口；现状受阻于空框没有任何引导、像个冷启动的搜索框，导致他不知道能问什么就放弃、直接划走。 → 压低**发起对话率**

##### 角色：全体访客 · 原型：对话框引导态

**功能卡 ②-A1 · 空框引导（示例提示）**｜服务痛点 P5｜认领 研发(产品定提示语)
- 用户故事：作为刚落地、盯着对话框发愣的访问者，我想看到几个「可以这样问」的示例提示，以便知道这框能帮我做什么、敢开口。
- 范围：只做 对话框引导态（占位提示 + 2–4 个可点的示例 chip + 一句「描述你的场景，页面就为你重构」）；不做 重构引擎本身（loom 底座）。
- 验收(G-g)：Given 访客落地未交互；When 对话框渲染；Then 出现可点的示例提示 chip，点击即把示例填入并可一键发起；移动端不遮挡首屏主张。
- 优先级：P0
- 挂钩牌：拨动 发起对话率 / 验证假设「示例提示能把『看』变成『开口』」/ 闭环判据 发起对话率（含/不含引导 A/B）
- 产出去向：→ 开 issue 只引本卡

### 输入指标 B · 命中率（重构对上需求）

#### 痛点 P6（G-c）
> 当某一类小老板（如只做客服降本的）在对话框描述完自己的场景后，他想看到一个跟他场景一模一样的「输入 → 产出」真实例子，以便确认这东西真能用在他身上；现状受阻于重构出来的还是通用功能介绍、要他自己把通用能力往自己身上套，导致他觉得「对不上、没说到点」就不再往下试。 → 压低**命中率**

> 同一痛点对**多个 persona**成立，各 persona 一套场景样例料（喂给重构底座）+ 一个对应视角（原型）。

##### 角色：赵全扛·单干侠（→ personas）· 原型：赵全扛视角

**内容卡 ②-B赵 · 单干场景样例**｜服务痛点 P6｜认领 产品 + 运营(供真实输入产出)
- 信息内容：一个「单干侠全环节」的 before/after 样例（如「一句话 → 自动出选品+客服话术+物流提醒」），含真实输入与产出
- 数据来源：运营/产品供该类真实跑通案例的输入输出
- 落位：赵全扛视角（重构后的场景样例区）
- 候选形式：before/after 卡（默认）/ 短演示视频（形式实验暂缓）
- 验收(G-g)：Given 访客自报「我一个人全扛」；When 重构渲染；Then 出现单干全环节的真实输入产出样例，不虚构数据。
- 优先级：P1
- 挂钩牌：拨动 命中率(赵) / 验证假设「同场景样例比通用介绍更能让人想试」/ 闭环判据 赵视角发起 demo 率
- 产出去向：→ 内容就地维护，变更记 changelog

##### 角色：钱降本（→ personas）· 原型：钱降本视角

**内容卡 ②-B钱 · 客服降本样例**｜服务痛点 P6｜认领 产品 + 运营(供 ROI 样例)
- 信息内容：一个「客服降本」before/after 样例（如「重复咨询 → AI 自动答，人力从 X 降到 Y」），含真实工单与降本数据
- 数据来源：运营供真实客服场景工单 + 降本测算
- 落位：钱降本视角场景样例区
- 候选形式：before/after 对比 / ROI 数字（暂缓）
- 验收(G-g)：Given 访客自报「想砍客服人力」；When 重构渲染；Then 出现客服降本的真实样例 + 可核实数据。
- 优先级：P1
- 挂钩牌：拨动 命中率(钱) / 验证假设「降本样例能让降本型想试」/ 闭环判据 钱视角发起 demo 率
- 产出去向：→ 内容就地维护，变更记 changelog

##### 角色：孙集成（→ personas）· 原型：孙集成视角

**内容卡 ②-B孙 · 集成场景样例**｜服务痛点 P6｜认领 产品 + 研发(供集成样例)
- 信息内容：一个「接进现有系统」样例（如「调一个接口 → 嵌进自己后台」），含可核实的集成方式
- 数据来源：研发/产品供真实集成 demo
- 落位：孙集成视角场景样例区
- 候选形式：接口/架构样例 / 可跑代码片段（暂缓）
- 验收(G-g)：Given 访客自报「我想接进自己系统」；When 重构渲染；Then 出现可集成样例 + 真实接入方式。
- 优先级：P2
- 挂钩牌：拨动 命中率(孙) / 验证假设「集成样例能让技术型想试」/ 闭环判据 孙视角发起 demo 率
- 产出去向：→ 内容就地维护，变更记 changelog

#### 痛点 P7（G-c）
> 当访问者顺着重构后的页面往下看时，他想按「这是什么 → 怎么用 → 给我什么结果」的顺序看懂，以便不用自己在杂乱信息里拼；现状受阻于信息堆在一起、没有层次，导致他看不出门槛高不高、要不要继续试就走了。 → 压低**命中率**

##### 角色：全体访客 · 原型：默认骨架

**内容卡 ②-B1 · 价值分层骨架**｜服务痛点 P7｜认领 产品(信息架构)
- 信息内容：主体区「是什么 → 怎么用 → 给什么结果」的分层顺序与锚点
- 数据来源：定位稿 + 产品价值分层
- 落位：默认骨架主体区（section 顺序 + 锚点导航）
- 候选形式：纵向分层 + 锚点（默认）/ 标签切换（暂缓）
- 验收(G-g)：Given 访客往下滚；When 渲染主体区；Then 信息按「是什么/怎么用/给什么结果」分层出现、有锚点可跳。
- 优先级：P1
- 挂钩牌：拨动 命中率 / 验证假设「有层次的信息让人更愿意往下试」/ 闭环判据 滚动深度 + 发起 demo 率
- 产出去向：→ 内容就地维护，变更记 changelog

**功能卡 ②-B2 · 「3 步就能用」图**｜服务痛点 P7｜认领 研发 + 设计
- 用户故事：作为在评估复杂度的访问者，我想用一张「3 步用起来」的图秒懂上手路径，以便不用读长文档就敢试。
- 范围：只做 How-it-works 三步图组件（图形 + 步骤文案位）；不做 完整教程文档。
- 验收(G-g)：Given 访客看到上手区；When 渲染；Then 出现 ≤3 步的图，每步一句话，移动端纵向不挤。
- 优先级：P2
- 挂钩牌：拨动 命中率 / 验证假设「三步图降低『怕复杂』的劝退」/ 闭环判据 看过三步图 vs 没看的发起 demo 率
- 产出去向：→ 开 issue 只引本卡

### 输入指标 C · 跑通率

#### 痛点 P8（G-c）
> 当访问者想真的体验一下产品时，他想不离开官网、不注册就跑一个样例，以便先看到产品到底怎么用；现状受阻于旧站只能看图文、想跑得下载/注册/找销售，导致他在门槛前就放弃。 → 压低**跑通率**

##### 角色：全体访客 · 原型：demo 容器

**功能卡 ②-C1 · 内嵌可跑 demo**｜服务痛点 P8｜认领 研发(前端壳)
- 用户故事：作为正在浏览的访问者，我想不离开页面、不注册就跑一个预置样例，以便亲眼看到产品怎么用。
- 范围：只做 嵌入式 demo 容器（前端壳 + 接 1 个预置样例的只读接口）；不做 全功能产品 / 登录态。
- ⚠ 依赖：依赖后端「预置样例只读接口」。若该接口尚不存在 → 该卡会 > 1 天，需先备好接口或把「备一个只读样例接口」单列成一棒（与 ① §2 实验判读同理，先备底座再上卡）。
- 验收(G-g)：Given 访客点「试一下」；When demo 容器加载；Then 站内直接跑通一个预置样例、无需注册/跳转。
- 优先级：P0
- 挂钩牌：拨动 跑通率 / 验证假设「站内零门槛能把浏览变试用」/ 闭环判据 发起 demo→跑通 的转化率
- 产出去向：→ 开 issue 只引本卡（依赖接口单列追踪）

#### 痛点 P9（G-c）
> 当访问者点了「试跑」之后，他想在几秒内看到「像真的一样」的结果，以便相信这东西真能用；现状受阻于旧 demo 要么转圈很久、要么给个假占位图，导致他觉得「假的/不行」就退出。 → 压低**跑通率**

##### 角色：全体访客 · 原型：demo 容器（反馈态）

**功能卡 ②-C2 · 试用即时反馈**｜服务痛点 P9｜认领 研发
- 用户故事：作为点了试跑的访问者，我想几秒内看到真实结果或可信的进度，以便相信它真能用。
- 范围：只做 demo 结果渲染 + loading/streaming 态 + 失败兜底（重试/降级提示）；不做 真结果的算法本身（接 ②-C1 的接口）。
- 验收(G-g)：Given 访客发起试跑；When 等待中/出结果；Then 有 streaming/进度态、几秒内出真实结果；失败时给可重试的明确提示，不卡死、不假占位。
- 优先级：P1
- 挂钩牌：拨动 跑通率 / 验证假设「秒级真反馈能压住中途退出」/ 闭环判据 试跑→看到结果 完成率 + 失败率
- 产出去向：→ 开 issue 只引本卡

#### 痛点 P10（G-c）
> 当访问者试完一个样例、想再试别的或想深入时，他想自由地继续试、并在准备好时再留资，以便按自己节奏走；现状受阻于旧流程中途强制注册才能继续，导致他被打断、直接走人。 → 压低**跑通率**（并影响向 ③ 的交接）

##### 角色：全体访客 · 原型：demo 容器（续试态）

**功能卡 ②-C3 · 自由续试 + 软 CTA**｜服务痛点 P10｜认领 研发
- 用户故事：作为试了一次想深入的访问者，我想无障碍再试别的样例、并在想深入时一键转到留资，以便不被强制注册打断。
- 范围：只做 样例切换器 + 试用后软 CTA（继续试 / 留资解锁更多）；**软 CTA 的留资落点本身归 ③**（本卡只摆入口、连过去）。
- 边界：此卡是 Activation → Retention 的交接点；留资表单/兑现 = ③-A1/③-A2。
- 验收(G-g)：Given 访客试完一个样例；When 看结果区；Then 能一键换样例继续试、不被强制注册；同时出现软 CTA 指向留资（非强制弹窗）。
- 优先级：P1
- 挂钩牌：拨动 跑通率 + 向③交接 / 验证假设「自由续试 + 软引导比强制注册留住更多人」/ 闭环判据 续试率 + 软 CTA 点击率
- 产出去向：→ 开 issue 只引本卡（留资落点引 ③ 卡）

## §4 线框/原型（= 重构后页面的基本形式）
