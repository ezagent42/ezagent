# 官网 · 战略/定位 —— 需求雷达 · AARRR（重心后四棒 AARR）

> **站是什么**：真实展示我们**成果**、亮出未来**路线图**的官网。感兴趣的人进来可以：了解我们 / 试用成果 / 给路线图功能点投票 / 对成果评论点赞。
> **为什么**：**需求雷达 + build-in-public 社区**——产出 = 真实需求 ＋ 路线图投票 ＋ 关注者。**本站不收钱**，赚钱在 downstream，本站只收「意向信号」（试用/留资/waitlist/投票）。
> **形态**：用 loom 构建。**底部对话框 / 按需重构 / 按访客 AI 熟悉度调话术 = loom 底座自带，本需求不实现**。本需求要做的是**互动层**：试用、投票、评论、点赞，以及承载它们的页面。
> **重心**：不买量、不优化获客；**首要目标 = 后四棒 AARR**（① Acquisition 只做「被搜到/转到就承接得住」）。

---

## 一、AARRR 五棒（本站重定义）

| 棒 | 这一棒要发生什么 | 北极星 |
|---|---|---|
| ① Acquisition〔次要·只承接〕 | 感兴趣的人进站 | 有效浏览量（靠自然流，不买量） |
| ② Activation〔**头牌**〕 | 试用成果 / 投票 / 评论点赞，**留下真实需求** | 参与率（≥1 互动）· 真实需求·投票量 |
| ③ Retention | 回来看进展、订阅/关注更新 | 回访率 ＋ 订阅/关注数 |
| ④ Revenue→意向 | 留资 / waitlist / 认领「做出来我要用」 | 意向转化率 / 承诺线索量 |
| ⑤ Referral | 把成果/路线图转给同行、拉人投票 | 转发量 / 分享率 |

> ② 里**投票/评论（=真实需求）是头牌、试用是支撑**。④ 只收意向、**不收钱**。③ = 官网级留存（关注进展），非产品留存。

## 二、访客（persona 待重画）

- **A 潜在用户/共建者〔主〕**：有我们能解决的真实问题，愿投票/试用/提需求 → 真实需求 + 变现源。
- **B 同行/技术关注者〔传播副线〕**：对技术/路线感兴趣，点赞转发 → 喂 ⑤。
- **C 利益相关方〔顺带〕**：投资/合作/招聘。

口径：**不收垂直**（A = 有问题且愿共建即可）；但**成果在跨境真实展示 → 成果须带「领域/场景标签」**；AI 成熟度 = 软光谱、不当门槛、只影响话术。
⚠ 旧 `赵/钱/孙`（跨境买家）**作废**；新 persona 留 `P-用户画像-personas.md` 重画（待真实用户确认）。

## 三、内容模型（站子的主角）

访客看到的是一张**思维导图**（像 `01-demo-定位树-多角色视角.html`）：**定位 → 痛点**（可投票的主层）+ 浮上来的**成果**。具体 issue 是隐藏实现层。

- **定位 / 痛点**（导图·**主投票单元**）：来源 = GitHub Milestone ＋「痛点」追踪 issue。访客投这层、不投具体 issue。
- **成果（achievement）**：来源 = 已合并 PR；带**域/场景标签**；可 试用 / 评论 / 点赞 / 分享。
- **进行中**：来源 = open PR（成果的「即将上线」态）。
- 具体 **issue**：隐藏（实现层）。对话框 = loom 底座（不实现）。

定位/痛点（投票）+ 成果/进行中 + 互动信号 = 本站真相源。映射方案见 `W-成果生产工作流.md`。

**两条建设轨**：①**官网前端**（loom 搭：互动层 + 思维导图/成果页）；②**成果生产工作流**（GitHub → 拉 Milestone/痛点/PR → 处理成内容 → 喂官网，见 `W-`）。

## 四、五条战略/定位（G-a · 句式 `让<谁>，能<新体验>，而不必<旧成本>`）

「谁」随漏斗逐棒收窄（陌生人 → 共建者）。**重心 ②③④⑤。**

- **① Acquisition**〔次要〕：让在找「这事有没有人真做出来了」的人，搜到/被转到就一眼看清「真成果 + 做到哪了」，而不必在 PPT 愿景里猜。
- **② Activation**〔头牌〕：让进站的人能直接试已做出的成果、并对「接下来做什么」投票/评论，把真实需求留下，而不必干看一个单向展示页。
- **③ Retention**：让投过/试过/评过的人愿意订阅关注、回来看「我在意的那块推进到哪」，而不必关页就失联。
- **④ Revenue→意向**：让真有需求的人愿意留资/进 waitlist/认领「做出来我要用」，把意向变承诺信号，而不必现在谈钱（钱在 downstream）。
- **⑤ Referral**：让被某成果打动的人愿意转给同行、拉人投票，因为转出去是「这帮人做了个有用的东西」，而不是广告。

## 五、卡模板（06 `G-r` 官网精简版 · 省略 ICE/价值卡/节点id）

互动（投票/评论/点赞/试用）= **功能卡**；纯展示文案 = **内容卡**。loom 底座（对话/重构/发布助手）引用不重建。

**功能卡（需开发）**
```
功能卡 <id> · <名>｜服务痛点 <P>｜认领 <角色>
- 用户故事：作为<访客>，我想<做什么>，以便<达成什么>。
- 范围：只做<…>；不做<…>
- 验收(G-g)：Given… When… Then…
- 优先级：P<>
- 挂钩牌：拨动<输入指标> / 假设<…> / 闭环<…>
- 产出去向：→ 开 issue 只引本卡
```

**内容卡（不开发，只调内容）**
```
内容卡 <id> · <名>｜服务痛点 <P>｜认领 <角色>
- 信息内容：<那块信息> ｜ 数据来源：<从哪取真实数据>
- 落位：<哪个区块> ｜ 候选形式：<默认 + 备选>
- 验收(G-g)：Given… When… Then…
- 优先级：P<> ｜ 挂钩牌：拨动<输入指标> / 假设<…> / 闭环<…>
- 产出去向：→ 内容就地维护，记 changelog
```
