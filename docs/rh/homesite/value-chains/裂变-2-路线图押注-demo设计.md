# 裂变-2 路线图押注 · world.cup demo 设计

> **这份文档干嘛用**：把官网「成果与路线图」tab 重构成 **world.cup**——一个把路线图（Issue→PR→Merge）做成"需求众筹 + 赌球裂变"的页面，提升可玩性、可裂变性，且**能让团队学到真需求**。是 [[V-价值链总表]] 中**裂变-2 路线图押注**那一行的 demo 设计稿。
>
> **配套**：
> - 需求源：`V-价值链总表.md` →「裂变引擎段」**裂变-2 路线图押注**行（卡 `②-D1`）+ 文末附节。
> - 现状被重构对象：`../demo/官网原型-全站-暗黑玻璃.html`「成果与路线图」tab（价值/时间线/场景 三视角 + 弱投票）。
> - 同语境兄弟 demo：`../demo/components/02-demo-指挥官驾照.html`（裂变-1，canvas 卡片复用源）。
> - 产出：独立 demo `../demo/components/03-demo-路线图押注.html`（先验手感，暂不并入主站）。

> **设计演进（2026-06-25 brainstorm 关键转向）**：最初设计是"4 盘口对赌预测市场"。讨论中发现**押注 = 预测（会不会发生），结构性测不了"我个人需不需要"，会产出伪需求**。故转向**两层**：第一层用"我要用/候补"诚实采真需求（团队信号），第二层才用赌球（押注标的是第一层的需求指标，纯娱乐裂变、不污染信号）。下文是转向后的设计。

---

## 1 · 背景与问题

**不重复写，见 `V-价值链总表.md`**：

- 痛点 **P27**：普通点赞/投票是一次性弱互动（投完不回来、不转发、信号弱）。
- 团队真目标：这个页面要**学到用户真需要什么** + **让用户自提需求**。

**本轮新增的关键认知**（写在这，因为它是整个转向的根因）：

> 押注的最优策略是"猜大众/团队会怎么动"（凯恩斯选美悖论），所以它测的是**预测**，不是**个人需求**。直接用押注测需求 → 伪需求。必须把"采需求"和"赌着玩"分成两层。

## 2 · 目标与成功判据

**不重复写，见 `V-价值链总表.md` 裂变-2 行★指标**。本 demo 阶段只验四件事：
1. **真需求**——第一层能干净地采出"谁真要用什么"。
2. **可玩性**——第二层赌球让页面好玩、想动手。
3. **可裂变性**——有东西值得发给同行（且拉来的是真需求同行）。
4. **合规**——虚拟声望、不可提现、措辞避真钱。

---

## 3 · 核心概念定义（先定义后使用）

| 术语 | 定义 | 一句话锚点 |
|---|---|---|
| **路线图条目 item** | 一个需求，按研发生命周期处于 **Issue（想做）/ PR（在做）/ Merged（已上线）** 之一 | "Issue, PR, Merge!" |
| **🙋 我要用（候补）** | 第一层。点一下＝承诺"我会用这个"，加入该 item 候补 | "我只给真会用的点" |
| **候补数** | 一个 item 的"我要用"人数 = **真需求强度**（团队读它） | "想要的人越多越该做" |
| **凑人解锁** | 候补攒够阈值 N → "解锁"（团队承诺评估/插队） | "帮我凑够人，团队就会做" |
| **声望** Renown | 第二层虚拟货币。不可充值/提现/兑现。起始 ~1,000 | "押的不是钱，是眼光信誉" |
| **看多 / 看空** | 第二层。押声望赌"某需求的候补会不会在窗口内破阈值"（看多=会火 / 看空=火不起来） | "我赌这个会火" |
| **结算真相源** | 第一层兑现源 = **PR 合并**（候补者得上线通知）；第二层结算源 = **结算日的候补数** | "盯/催我们干活" |
| **眼光榜 / 声望榜** | 眼光榜=看多看空命中率；声望榜=总声望 | 傲慢 / 嫉妒 |

> **两层解耦（本设计的命脉）**：第一层产生干净需求信号；第二层押注的标的是第一层的指标，是**衍生品**，不回写团队信号。

## 4 · 整体结构

```
┌─ world.cup ──────────────────────────────────────────┐
│ header: world.cup / Issue, PR, Merge!                 │
│ 状态条: ⛁声望 · 🏆眼光榜 · ⛁声望榜 · 🙋我要用的 N      │
│         · 🎲我的预测仓位 · 🪪晒卡                       │
│                                                       │
│ 视图切换:  [⊹价值] [◷时间线] [⊞场景]                  │  ← 同一批 item 的三种排列
│   每个 item 按生命周期阶段渲染按钮：                    │
│     Issue(想做)   🙋我要用 (候补 N · 凑够 X 解锁)  🎲   │  第一层 + 🎲第二层入口
│     PR(在做)      🙋我要用 · 🔔订阅上线            🎲   │
│     Merged(已上线) ❤点赞 · 🧪试玩 · 战报(PR链接)        │  已兑现，不再押注
│   [+ 提个需求（开 Issue）]                             │
│                                                       │
│ 弹层: 我要用确认 / 看多看空下注 / 结算动画 / 裂变卡     │
└──────────────────────────────────────────────────────┘
```

**承重决策**：
- **价值 / 时间线 / 场景 = 同一批 item 的三种排列（视图切换），不是三种数据、不是三个 tab 内容**。三视图共享同一套按钮与信息（这是用户明确要求）。
- 时间线视图里 Merged 节点天然成为"战报"。
- 第一层是地基（主角、一眼可玩）；第二层赌球是锦上添花，挂在 item 的 🎲 入口，想玩才进，不挡需求表达。

---

## 5 · 第一层：真需求（地基）· 最简玩法 = 我要用/候补

每个 item 按阶段长出按钮：

| 阶段 | 按钮 | 含义 / 信号 |
|---|---|---|
| **Issue** | 🙋 我要用（候补 N · 凑够 X 解锁） | 承诺会用 = 真需求；候补数 = 需求强度排序 |
| **PR** | 🙋 我要用 · 🔔 订阅上线 | 继续累计需求；订阅 = 喂 ③ 留资 |
| **Merged** | ❤ 点赞 · 🧪 试玩 · 战报(PR 链接) | 满意度 + 真实使用；已兑现，关闭押注 |

- **凑人解锁**：候补进度条 `候补数 / 阈值`，满 → "✅ 已解锁（团队会评估/插队）"。
- **裂变**：「帮我凑够想要的人解锁这个功能」——拉来的全是真需求同行。
- **兑现闭环**：候补满 → 团队做 → **PR merge** → 候补者上线通知（③）+ 触发「需求先知卡」（见 §9）。

## 6 · 第二层：赌球裂变（锦上添花）· 最简玩法 = 看多/看空

- 每个 Issue/PR 卡上一个 **🎲** → 打开"看多/看空"下注：
  - 🟢 **看多**：押"它的候补会在结算窗口内破阈值（会火）"
  - 🔴 **看空**：押"火不起来（到不了阈值）"
- 押**声望**，同注分彩（parimutuel）。
- **结算**：结算日看该 item 的**候补数 vs 阈值**判定（≠ PR merge）。
- **对赌邀请**：「我看多这个需求，赌不赌？」→ 对赌战书（§9）。
- **双榜**：眼光榜（命中率）/ 声望榜（总声望）。

> **救活的对决**：因为标的换成"需求热度"，"A vs B 谁的候补多"现在是**赌需求**（合理），而非旧版"谁先上线=猜开发速度"（不合理，已删）。本轮先只做"单需求看多看空"，对决留作后续。

## 7 · 共享引擎（押声望 → 结算）· 复用现有

```
看多看空 = 一个 item 的双边池 {long, short}
odds(side) = 总池 / 该边池           （parimutuel）
stake(itemId, side, amount) → 扣声望 + 入池 + 记仓位(锁定赔率)
settle(itemId, winSide)     → 赢家 注额×赔率, 输家扣, 更新战绩
```
现有 demo 的 `odds/stake/settle/LEDGER/POSITIONS/双榜/modal/toast` 基本可复用，只是标的从"会不会 merge"换成"候补会不会破阈值"。

## 8 · 结算与真相源（两个不同的源）

| 层 | 结算/兑现源 | 时机 | 可操纵性 |
|---|---|---|---|
| 第一层 候补 | **PR 合并** = 候补兑现（上线通知 + 战报 + 先知卡） | 团队真做出来时 | 不可操纵（绑真实研发产物）|
| 第二层 看多看空 | **结算日的候补数** vs 阈值 | 窗口截止 | 可被刷候补影响 → 见 §11 红线 |

**demo 结算演示三件套**（复用现有）：顶部「刚刚结算」ticker + 「结算历史」面板（点开看 PR/候补快照）+ 右下「⏩ 快进结算」按钮（模拟结算窗口到期）。

## 9 · 裂变产物（3 卡 · canvas，复用指挥官驾照模式）

| 卡 | 层 | 触发 | 内容 |
|---|---|---|---|
| **需求先知卡** | 第一层/身份 | 我早期候补的 item 上线后 | "我在它只有 5 人想要时就要了，现在上线了" + 早鸟编号（诚实的傲慢） |
| **凑人解锁邀请** | 第一层/裂变 | Issue 卡「邀人解锁」 | "帮我凑够 N 人解锁 X 功能" + 候补进度 + ref 链接 |
| **看多对赌战书** | 第二层/对赌 | 🎲 卡「约同行对赌」 | "我看多这个需求会火，赌不赌？" + 盘口快照 + ref |

每卡：复制图（html2canvas）+ 复制链接（ref）+ toast。

## 10 · Mock 数据模型

- `ITEMS[]`：每条加 `stage:'issue'|'pr'|'merged'`（由原 planned/wip/live 映射）、`waitlist`（候补数 mock）、`unlockAt`（解锁阈值）、`prRef`。
- 第一层状态：`myWant`（Set，我点过我要用的 itemId）、`liked`、`subscribed`。
- 第二层：`MARKETS`（每个可押 item 一个看多看空双边池）、`POSITIONS`、`LEDGER`（声望+战绩）。
- 三视图 = 对 `ITEMS` 的三种 group/sort，复用同一 item 卡渲染。

## 11 · 合规与风险红线

- 合规：全程"声望/眼光/战绩/看多看空/预测玩法"；禁用真钱/赔付/提现；页脚「虚拟声望 · 娱乐预测 · 不可提现」。
- **风险红线（刷候补污染第一层）**：第二层赌候补 → 赌客有动机拉人刷候补。真实版必须让"我要用"带真实成本/身份（留邮箱/真账号），使"刷"出来的要么是真需求、要么可过滤。**demo 不实现，但写明此红线。**

## 12 · 范围（本轮）

- 两层都做，**每层只做一个最简玩法**：第一层＝我要用/候补/凑人解锁；第二层＝单需求看多/看空。
- 三视图（价值/时间线/场景）= 同批 item 的视图切换，共享按钮。
- 复用现有 demo 的引擎/双榜/modal/裂变卡/快进结算。
- 后续（不在本轮）：心愿点分配、A vs B 需求对决、并入主站。

## 13 · 不做（YAGNI）

真钱 / 真后端 / 真账号 / 跨设备 / 防刷候补实现 / 心愿点 / 需求对决盘。

# 实施计划（重构 · 分步执行）

> 现有 demo 已建成 4-盘口版（Tasks 旧 1–7）。本计划把它**重构**为两层 world.cup 版。每个 Task 产出可在浏览器独立验证的增量；提交点「按需」（仅用户要求时 commit）。

## 全局约束

- 视觉沿用暗黑玻璃 tokens / `.liquid-glass` / serif；红绿双色＝看多/看空。
- 合规措辞同 §11。
- 三视图共享同一 item 卡与按钮。

---

### R1 · 数据模型改造（item 生命周期 + 候补 + 看多看空市场）
- `ITEMS` 加 `stage`（issue/pr/merged，由 planned/wip/live 映射）、`waitlist`、`unlockAt`、`prRef`。
- 第一层状态：`myWant:Set`、`liked:Set`、`subscribed:Set`。
- `MARKETS` 改为：每个 issue/pr 一个看多看空双边池 `{long,short}`（含种子），绑 `itemId`。删除旧 conviction/duel/time/ipo 市场结构。
- **验收**：控制台 `ITEMS` 有 stage/waitlist；`MARKETS` 为看多看空双边；`odds()` 返合理值。

### R2 · 三视图切换骨架（价值/时间线/场景）
- 顶部视图切换 `[⊹价值][◷时间线][⊞场景]`；三者渲染同一批 item，仅 group/sort 不同（价值=按战略定位、时间线=按 stage/季度、场景=按 scene）。
- 统一 `itemCard(it)`（先只渲染标题 + stage tag + 绑定 #prId）。
- **验收**：三视图都能列出全部 item，切换正常，排列不同。

### R3 · 第一层按钮（我要用/候补/凑人解锁 + merged 点赞试玩 + PR 订阅）
- `itemCard` 按 stage 出按钮：issue/pr → 🙋我要用（候补进度条 `waitlist/unlockAt` + 已点状态）；pr 加 🔔订阅；merged → ❤点赞 + 🧪试玩 + 战报(PR 链接)。
- 点「我要用」→ `myWant` 加入、`waitlist+1`、满阈值显示「✅已解锁」、toast。
- **验收**：点我要用进度涨、状态变；merged 显示点赞/试玩；PR 可订阅。

### R4 · 提个需求（开 Issue）
- 视图内「+ 提个需求」→ modal 表单（标题/一句话/场景）→ 新增一个 `stage:'issue'` item（waitlist=1，自动我要用）→ 重渲 + toast。
- **验收**：提交后新 issue 出现在三视图，候补=1。

### R5 · 第二层 看多/看空（🎲 + 下注 + 仓位）
- 每个 issue/pr 卡加 🎲 → 打开看多/看空下注（复用 `openBet`，红绿＝看多/看空，"可赢=注额×赔率"）。
- 状态条「🎲我的预测仓位」面板复用 `renderPositions`。
- **验收**：押一注 → 声望降、池/赔率变、仓位记录、已押状态。

### R6 · 结算（快进结算按候补 + PR 兑现 + ticker/历史）
- `fastForwardSettle` 改为：选一个有仓位的看多看空市场 → 动画"结算窗口到期" → 按 `waitlist vs unlockAt` 判 winSide → `settle` → 战绩/声望更新 → ticker/历史刷新。
- 另设「PR 合并」事件 mock：把某 issue/pr 推进到 merged → 候补者触发「需求先知卡」钩子（§9）。
- **验收**：快进结算后看多看空有输赢、进历史；item 可被推进到 merged 显示战报。

### R7 · 裂变三卡（reframed）
- `shareForeseerCard()`（需求先知）/ `shareUnlockInvite(itemId)`（凑人解锁，接 R3）/ `shareLongChallenge(marketId)`（看多对赌，接 R5 🎲）。
- 复用 html2canvas + 复制 + toast；接线到对应触发点。
- **验收**：三卡可弹出、截图、复制 toast。

### R8 · 双榜 + 合规 + 收尾
- 复用 `openLeaderboard`（眼光/声望双 tab）。
- 合规措辞复查（看多看空/预测玩法，无真钱）；reveal 动效；窄屏自查；整页走查两层闭环。
- **验收**：榜单双 tab、你高亮；措辞合规；窄屏不裂。
