# 定位③ · Retention（→ 留资率·订阅率 + 回访率）· 树状

> **官网 = 一个 loom 生成式对话页**：底部对话框 → 访客描述想看什么 → 页面即时重构。引擎（builder/发布助手/视图切换）为**平台给定底座，不展开实现**（参考 `/Users/chenruihua/Documents/Vaults/projects/loom`）。线框 = 重构后页面的**基本形式/默认骨架**，文案数据驱动。
> 流程见 `docs/rh/value-chain-kanban/07-定版-自举开发流程-10分钟.md`；模板见 `docs/rh/value-chain-kanban/06-操作模板库.md` + `00` §五卡模板；persona 见 `P-用户画像-personas.md`。
> **树状结构**：定位 → 北极星 → 输入指标 → **痛点** → 角色(persona) → spec卡 + 原型图。
> **口径（待拍板，见 `00` §一）**：本文按**口径甲 = 官网级留存**（留资/订阅/回访），即官网负责把一次性访问沉淀成可持续触达的关系。
> **边界**：本棒接住 ② 交来的「有效试用量」，负责把「试过一次」变成「留得下、还会回来」。**自助注册/下单/预约 = ④ Revenue**，不在本棒（留资 ≠ 注册）。

## §1 定位稿（定位 → 北极星）

母定位（G-a，源自 `00`，口径甲）：

> **让有兴趣但还没决定的访问者，愿意留个联系方式或订阅更新、下次还能回来看进展，而不必一关页面就和我们彻底失联。**

谁＝体验过、有意向但尚未转化的访问者 / 新体验＝低成本留下一条可持续触达的线（留资/订阅）+ 有理由回访 / 旧成本＝旧站「看完即走」，关掉就再也找不回。AARRR 第 3 棒，交棒 = **留存率（留资订阅率 + 回访率）**。

## §2 北极星 → 输入指标（指标 + 精确定义）

> **关系**：北极星 = 结果（果）；输入指标 = 能动手推高它的杠杆（因），尽量与北极星成**公式分解**；链条 **痛点→角色→卡 拨动输入指标 → 抬北极星**。

**北极星：留存率** = 统计窗口内「沉淀为可持续关系」的访客占比 —— 既留下了可触达的线（留资/订阅），这条线又真的把人拉回来过。

**分解：`留存率 ≈ 留资订阅率 × 回访留存率`**

两步：先「建立关系」（留下一条能再触达你的线），再「关系被激活」（这条线真的把人拉回来）。前者无后者只是躺在库里的死线索，后者无前者无从发生。

| 输入指标 | 精确定义 |
|---|---|
| 〔承接②〕**有效试用量** | 真正跑通一次贴合场景 demo 的去重访客数（见 `02` §2） |
| **A 留资订阅率** | 留下联系方式或订阅的访客数 ÷ 有效试用访客数 |
| **B 回访留存率** | N 日内带着这条线回访的访客数 ÷ 留资订阅访客数 |

> **实验判读（取代二元 drop）**：每个指标按 `假设 + 窗口 N 天 + 判读{ 达标 T→继续 / 未达→先改方案 / 连续 M 窗口仍未达→drop }`，阈值（含「N 日」的 N）待运营随上线拍板。

   │   ├─ 痛点 P12 留资没对价、白填
   │   │   ├─ 角色 赵全扛 → 内容卡 ③-A2赵 (开箱试用额度)
   │   │   ├─ 角色 钱降本 → 内容卡 ③-A2钱 (ROI 测算报告)
   │   │   ├─ 角色 孙集成 → 内容卡 ③-A2孙 (接入指南/技术文档)
   │   │   └─ 角色 全体(机制) → 功能卡 ③-A2 对价兑现投递
   │   └─ 痛点 P13 暂不决定、靠自己记得回来
   │       └─ 角色 全体访客 → 功能卡 ③-A3 订阅入口

> **卡型两类（模板见 `00` §五）**：内容卡＝不开发、只调内容；功能卡＝需开发。卡模板是 06 `G-r` 的官网精简版（省略 ICE 打分/价值卡/节点 id）。对话框/builder/发布助手 = loom 底座，引用不重建。
> **persona 在本棒的用法**：留资的「对价」按 persona 不同（赵要试用额度、钱要 ROI 报告、孙要技术文档）→ **功能卡 ③-A2 建对价兑现的槽**，**内容卡 ③-A2赵/钱/孙 填各 persona 的兑现物**（① 的「功能卡建槽 + 内容卡填 persona」同构）。留资/订阅/回访的机制本身对全体一致，挂「全体访客」。

### 输入指标 A · 留资订阅率（建立可触达的线）

#### 痛点 P11（G-c）
> 当有意向但还没决定的访问者准备留个联系方式时，他想用最少的动作留下、之后再说，以便不被打断；现状受阻于旧站一上来就是一长串必填表单（公司/规模/电话…），导致他嫌麻烦直接关掉、一条线都没留下。 → 压低**留资订阅率**

##### 角色：全体访客 · 原型：留资条

**功能卡 ③-A1 · 低摩擦留资**｜服务痛点 P11｜认领 研发(产品定字段)
- 用户故事：作为有点意向的访问者，我想只填一个邮箱/微信就留下，以便不被长表单劝退。
- 范围：只做 极简留资组件（1–2 字段 + 提交 + 落库/通知）；不做 强制弹窗 / 多字段画像表单。
- 验收(G-g)：Given 访客触发留资（软 CTA / 试用后）；When 看到表单；Then 仅 1–2 字段、一步提交、有成功反馈；数据落库并通知。
- 优先级：P0
- 挂钩牌：拨动 留资订阅率 / 验证假设「字段越少留资越多」/ 闭环判据 留资表单曝光→提交 转化率
- 产出去向：→ 开 issue 只引本卡（承接 ②-C3 软 CTA）

#### 痛点 P12（G-c）
> 当访问者犹豫要不要留联系方式时，他想清楚「留了能换到什么」，以便判断值不值得留；现状受阻于旧站留资点没有对价、就是个干巴巴的「联系我们」，导致他觉得白填、不留。 → 压低**留资订阅率**

> 同一痛点对**多个 persona**成立：各 persona 想换的「对价」不同（内容卡分别填），兑现的投递机制对全体一致（功能卡建槽）。

##### 角色：全体（机制）· 原型：留资条（对价位 + 兑现）

**功能卡 ③-A2 · 对价兑现投递**｜服务痛点 P12｜认领 研发
- 用户故事：作为留了资的访问者，我想留完立刻拿到承诺的对价（额度/报告/文档），以便相信留资有用。
- 范围：只做 留资点的对价展示槽 + 留资后兑现物自动投递（解锁额度 / 发资料链接 / 触发邮件）；不做 各 persona 的具体对价文案（见内容卡）。
- 验收(G-g)：Given 访客在某 persona 视角留资；When 提交成功；Then 自动投递该视角对应的兑现物、并提示已发送。
- 优先级：P1
- 挂钩牌：拨动 留资订阅率 / 验证假设「即时兑现对价能提高留资」/ 闭环判据 含对价 vs 不含的留资率
- 产出去向：→ 开 issue 只引本卡

##### 角色：赵全扛·单干侠（→ personas）· 原型：赵全扛视角

**内容卡 ③-A2赵 · 单干侠对价**｜服务痛点 P12｜认领 产品 + 运营
- 信息内容：留资可换「开箱试用额度 / 一键跑通包」的对价文案 + 兑现物
- 数据来源：产品供试用额度策略 + 开箱包内容
- 落位：赵全扛视角留资点对价位
- 候选形式：额度卡 / 一键开通（暂缓）
- 验收(G-g)：Given 赵视角留资点；When 渲染；Then 对价为「开箱试用额度」，留资后自动解锁（接 ③-A2 投递）。
- 优先级：P1
- 挂钩牌：拨动 留资率(赵) / 验证假设「试用额度对单干型最有吸引力」/ 闭环判据 赵视角留资率
- 产出去向：→ 内容就地维护，变更记 changelog

##### 角色：钱降本（→ personas）· 原型：钱降本视角

**内容卡 ③-A2钱 · 降本派对价**｜服务痛点 P12｜认领 产品 + 运营
- 信息内容：留资可换「你的客服降本 ROI 测算报告」的对价文案 + 兑现物
- 数据来源：运营供 ROI 测算模板/真实样例
- 落位：钱降本视角留资点对价位
- 候选形式：测算报告 / 对比数字（暂缓）
- 验收(G-g)：Given 钱视角留资点；When 渲染；Then 对价为「ROI 测算报告」，留资后投递（接 ③-A2）；数字可核实。
- 优先级：P1
- 挂钩牌：拨动 留资率(钱) / 验证假设「ROI 报告对降本型最有吸引力」/ 闭环判据 钱视角留资率
- 产出去向：→ 内容就地维护，变更记 changelog

##### 角色：孙集成（→ personas）· 原型：孙集成视角

**内容卡 ③-A2孙 · 技术控对价**｜服务痛点 P12｜认领 产品 + 研发
- 信息内容：留资可换「接入指南 / API 文档 / 技术白皮书」的对价文案 + 兑现物
- 数据来源：研发供接入文档
- 落位：孙集成视角留资点对价位
- 候选形式：文档链接 / 沙箱 key（暂缓）
- 验收(G-g)：Given 孙视角留资点；When 渲染；Then 对价为「接入指南/文档」，留资后投递（接 ③-A2）。
- 优先级：P2
- 挂钩牌：拨动 留资率(孙) / 验证假设「技术文档对集成型最有吸引力」/ 闭环判据 孙视角留资率
- 产出去向：→ 内容就地维护，变更记 changelog

#### 痛点 P13（G-c）
> 当访问者这次还不想决定、但想跟进产品进展时，他想一键订阅、被动收到更新，以便不用自己记得回来；现状受阻于旧站只能靠自己记得回访，导致他一关页面就再也想不起来。 → 压低**留资订阅率**

##### 角色：全体访客 · 原型：订阅入口

**功能卡 ③-A3 · 订阅入口**｜服务痛点 P13｜认领 研发
- 用户故事：作为暂不决定但想跟进的访问者，我想一键订阅更新，以便被动收到进展、不用自己记得回来。
- 范围：只做 订阅入口（邮箱 / 公众号引导）+ 订阅状态落库；不做 邮件营销系统本身（接现成）。
- 验收(G-g)：Given 访客点订阅；When 提交邮箱/扫码；Then 订阅状态落库、有确认反馈；可退订。
- 优先级：P2
- 挂钩牌：拨动 留资订阅率 / 验证假设「一键订阅能接住『暂不决定』的人」/ 闭环判据 订阅转化率 + 退订率
- 产出去向：→ 开 issue 只引本卡

### 输入指标 B · 回访留存率（线被激活、人回来）

#### 痛点 P14（G-c）
> 当留过资/订阅过的访问者再次想起这个产品时，他想知道「上次来之后又更新了什么」，以便判断值不值得再追；现状受阻于旧站一成不变、回来也看不到新东西，导致他觉得「没进展」就不再回访。 → 压低**回访留存率**

##### 角色：全体访客 · 原型：进展页（changelog/路线图）

**功能卡 ③-B1 · 进展可见（changelog / 路线图）**｜服务痛点 P14｜认领 研发(组件)+运营(填条目)
- 用户故事：作为回访的访问者，我想看到「上次之后更新了什么 / 接下来要做什么」，以便觉得这产品值得持续追。
- 范围：只做 更新日志 / 路线图页（数据驱动列表组件 + 条目结构）；条目内容由运营就地维护。
- 验收(G-g)：Given 访客进更新页；When 渲染；Then 按时间倒序列出真实更新条目 + 路线图；条目可由运营增删改、无需发版。
- 优先级：P1
- 挂钩牌：拨动 回访留存率 / 验证假设「看得见进展能把人拉回来」/ 闭环判据 回访访客中浏览进展页占比 + 回访率
- 产出去向：→ 开 issue 只引本卡（条目内容走就地维护）

#### 痛点 P15（G-c）
> 当访问者再次回到官网时，他想接着上次的进度（如上次试到哪），以便不从零开始；现状受阻于旧站每次都把他当新访客、状态全丢，导致他像没来过、得重头来一遍很烦。 → 压低**回访留存率**

##### 角色：全体访客 · 原型：续接态

**功能卡 ③-B2 · 回访识别与续接**｜服务痛点 P15｜认领 研发
- 用户故事：作为回流的访问者，我想被认出来并续上上次的状态，以便不用从零开始。
- 范围：只做 轻量回访识别（localStorage/cookie）+ 续接上次状态（上次试到哪/看到哪）；不做 账号体系。
- ⚠ 依赖：跨设备识别需账号体系——**v0 只做同设备（localStorage）**，跨设备归 ④ Revenue 注册后。
- 验收(G-g)：Given 同设备回访；When 进站；Then 认出回访身份、续上上次状态（如「继续你上次的 demo」）；隐私可清除。
- 优先级：P2
- 挂钩牌：拨动 回访留存率 / 验证假设「续接上次状态能提高回访留存」/ 闭环判据 回访续接率 + 续接后行为深度
- 产出去向：→ 开 issue 只引本卡（跨设备依赖账号，引 ④）
