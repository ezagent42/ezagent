# 定位⑤ · Referral（→ 转发量 / 分享率）· 树状

> **官网 = 一个 loom 生成式对话页**：底部对话框 → 访客描述想看什么 → 页面即时重构。引擎（builder/发布助手/视图切换）为**平台给定底座，不展开实现**（参考 `/Users/chenruihua/Documents/Vaults/projects/loom`）。线框 = 重构后页面的**基本形式/默认骨架**，文案数据驱动。
> 流程见 `docs/rh/value-chain-kanban/07-定版-自举开发流程-10分钟.md`；模板见 `docs/rh/value-chain-kanban/06-操作模板库.md` + `00` §五卡模板；persona 见 `P-用户画像-personas.md`。
> **树状结构**：定位 → 北极星 → 输入指标 → **痛点** → 角色(persona) → spec卡 + 原型图。
> **边界**：本棒是 AARRR 末棒，负责把「用得满意」变成「愿意转发给同行」。**转发带来的新到站量闭环回 ① Acquisition**（转发是为别人的获取供料）。

## §1 定位稿（定位 → 北极星）

母定位（G-a，源自 `00`）：

> **让用得满意的访问者，愿意把官网转发给同行，因为转出去对方只会觉得「这有用」而不是「又来打广告」，而不必担心转发掉自己的面子。**

谁＝用得满意 / 被某页内容打动的访问者 / 新体验＝官网本身具备「值得转发、转了有面子」的形态 / 旧成本＝旧站没什么可转发的，转了像帮发广告、掉价。AARRR 第 5 棒，交棒 = **有效转发量 / 分享率**。

---

## §2 北极星 → 输入指标（指标 + 精确定义）

> **关系**：北极星 = 结果（果）；输入指标 = 能动手推高它的杠杆（因），尽量与北极星成**公式分解**；链条 **痛点→角色→卡 拨动输入指标 → 抬北极星**。

**北极星：有效转发量** = 统计窗口内「带来新到站」的转发次数（去重到带分享来源参数的访问）。

**分解：`有效转发量 ≈ 满意访客数 × 转发意愿率 × 转发完成率`**

两步：先「愿意转」（手里有值得转的料、转了有面子），再「顺手转出去」（零摩擦、一键带预览）。料不够好卡在前一步，转发动作麻烦卡在后一步。

| 输入指标 | 精确定义 |
|---|---|
| 〔承接全链〕**满意访客数** | 跑通/转化、对产品有正面体验的访客数 |
| **A 转发意愿率** | 愿意转发的访客数 ÷ 满意访客数 |
| **B 转发完成率** | 真的转出去（生成带 ref 的分享）的访客数 ÷ 想转的访客数 |

> **闭环**：有效转发量 ↺ 回 ① 的「到站量 / 分享链点击率」——本棒的产出是下一轮 ① 的输入，AARRR 在此首尾相接。
> **实验判读（取代二元 drop）**：每个指标按 `假设 + 窗口 N 天 + 判读{ 达标 T→继续 / 未达→先改方案 / 连续 M 窗口仍未达→drop }`，阈值待运营随上线拍板。

## §3 树主体（输入指标 → 痛点 → 角色 → spec卡 + 原型图）

```
定位⑤ Referral
└─ 北极星：有效转发量 (≈ 满意访客数 × 转发意愿率 × 转发完成率) ↺ 闭环回①到站量
   ├─ 输入指标 A · 转发意愿率（值得转、转了有面子）
   │   ├─ 痛点 P22 只有广告页、转了像帮发广告
   │   │   ├─ 角色 赵全扛 → 内容卡 ⑤-A1赵 (单干避坑清单/开箱指南)
   │   │   ├─ 角色 钱降本 → 内容卡 ⑤-A1钱 (降本测算/行业小报告)
   │   │   └─ 角色 孙集成 → 内容卡 ⑤-A1孙 (技术选型对比)
   │   └─ 痛点 P23 没有个性化产物可晒
   │       └─ 角色 全体(试出结果者) → 功能卡 ⑤-A2 个性化结果分享卡
   └─ 输入指标 B · 转发完成率（零摩擦顺手转）
       ├─ 痛点 P24 要自己复制链接、配图配文
       │   └─ 角色 全体访客 → 功能卡 ⑤-B1 一键分享(复用①-A2 OG)
       └─ 痛点 P25 转发无回报、动力弱
           └─ 角色 全体访客 → 功能卡 ⑤-B2 裂变钩子(v0 埋ref+手动兑现)
```

> **卡型两类（模板见 `00` §五）**：内容卡＝不开发、只调内容；功能卡＝需开发。卡模板是 06 `G-r` 的官网精简版（省略 ICE 打分/价值卡/节点 id）。对话框/builder/发布助手 = loom 底座，引用不重建。
> **persona 在本棒的用法**：「值得转的料」按 persona 不同（赵转避坑清单、钱转降本报告、孙转技术选型）→ 有用物 ⑤-A1 按 persona 拆内容卡；个性化结果卡/一键分享/裂变机制对全体一致，挂「全体访客」。
> **复用**：⑤-B1 直接复用 ①-A2 已做的 OG 分享卡能力；⑤-A2 的动态结果图复用 ①-A2 的 OG 输出管线。

### 输入指标 A · 转发意愿率（值得转、转了有面子）

#### 痛点 P22（G-c）
> 当满意的访问者想把这东西推荐给同行时，他想转一个「对方收到会觉得有用」的东西，以便不掉自己的面子；现状受阻于旧站只有广告页、没有本身有用的料，导致他转出去像帮发广告、干脆不转。 → 压低**转发意愿率**

> 同一痛点对**多个 persona**成立：各 persona 手里值得转的「有用物」不同，各填一套内容卡。

##### 角色：赵全扛·单干侠（→ personas）· 原型：赵全扛视角（有用物页）

**内容卡 ⑤-A1赵 · 单干侠有用物**｜服务痛点 P22｜认领 产品 + 运营
- 信息内容：一份「单干侠避坑清单 / 开箱即用指南」（本身有用、不靠产品也读得下去）
- 数据来源：运营/产品供单干场景真实经验
- 落位：赵全扛视角的有用物页
- 候选形式：清单文章（默认）/ 可下载 PDF（暂缓）
- 验收(G-g)：Given 赵视角访客；When 看到有用物；Then 是一份独立有用的避坑/开箱清单、转给同行不像广告；内容真实。
- 优先级：P1
- 挂钩牌：拨动 转发意愿率(赵) / 验证假设「有用清单比广告页更愿被转」/ 闭环判据 赵视角有用物的转发率
- 产出去向：→ 内容就地维护，变更记 changelog

##### 角色：钱降本（→ personas）· 原型：钱降本视角（有用物页）

**内容卡 ⑤-A1钱 · 降本派有用物**｜服务痛点 P22｜认领 产品 + 运营
- 信息内容：一份「客服降本测算 / 行业人力成本小报告」（带可参考的数据）
- 数据来源：运营供行业人力成本数据（接 ③-A2钱/④-A2钱 口径）
- 落位：钱降本视角的有用物页
- 候选形式：小报告 / 可交互测算器（暂缓，测算器若交互则升为功能卡）
- 验收(G-g)：Given 钱视角访客；When 看到有用物；Then 是一份带真实数据的降本报告、转给同行有参考价值；数字可核实。
- 优先级：P1
- 挂钩牌：拨动 转发意愿率(钱) / 验证假设「降本报告比广告页更愿被转」/ 闭环判据 钱视角有用物的转发率
- 产出去向：→ 内容就地维护，变更记 changelog

##### 角色：孙集成（→ personas）· 原型：孙集成视角（有用物页）

**内容卡 ⑤-A1孙 · 技术控有用物**｜服务痛点 P22｜认领 产品 + 研发
- 信息内容：一份「AI 自动化技术选型对比 / 自搭 vs 接现成」分析（中立、有技术含量）
- 数据来源：研发供技术选型对比
- 落位：孙集成视角的有用物页
- 候选形式：对比表/技术文 / 架构图（暂缓）
- 验收(G-g)：Given 孙视角访客；When 看到有用物；Then 是一份中立有技术含量的选型对比、转到技术群不像广告。
- 优先级：P2
- 挂钩牌：拨动 转发意愿率(孙) / 验证假设「中立技术对比比广告页更愿被转」/ 闭环判据 孙视角有用物的转发率
- 产出去向：→ 内容就地维护，变更记 changelog

#### 痛点 P23（G-c）
> 当试出了结果的访问者想分享自己的成果时，他想转一张「我的结果」、像晒成绩单，以便转得有面子；现状受阻于旧站没有任何个性化产物可晒，导致他没东西可转、转产品页又像广告。 → 压低**转发意愿率**

##### 角色：全体（试出结果者）· 原型：结果分享卡

**功能卡 ⑤-A2 · 个性化结果分享卡**｜服务痛点 P23｜认领 研发(OG 生成)+设计(卡版式)
- 用户故事：作为试出结果的访问者，我想得到一张带我数据/成果的「我的结果」卡，以便转出去像晒成绩而不是发广告。
- 范围：只做 结果分享卡生成（动态 OG 图 / 可截图的结果卡，复用 ①-A2 OG 管线）；不做 结果计算本身（接 ② demo 结果）。
- 验收(G-g)：Given 访客试出结果；When 点「生成我的结果卡」；Then 出一张带其结果数据的卡（动态 OG/可截图）、转发预览正常；不含他人隐私。
- 优先级：P1
- 挂钩牌：拨动 转发意愿率 / 验证假设「可晒的个性化结果比纯广告更愿被转」/ 闭环判据 生成结果卡→转发率
- 产出去向：→ 开 issue 只引本卡（复用 ①-A2 OG 管线）

### 输入指标 B · 转发完成率（零摩擦顺手转）

#### 痛点 P24（G-c）
> 当访问者已经想转发时，他想一键就转到微信/社媒、自带好预览，以便顺手完成；现状受阻于旧站要自己复制链接、再手动配图配文，导致他嫌麻烦、转的念头就没了。 → 压低**转发完成率**

##### 角色：全体访客 · 原型：分享按钮

**功能卡 ⑤-B1 · 一键分享**｜服务痛点 P24｜认领 研发
- 用户故事：作为想转发的访问者，我想一键分享到微信/社媒并自带好预览，以便不用自己复制链接配图配文。
- 范围：只做 分享按钮组件（各渠道入口 + 预置标题/图，复用 ①-A2 的 OG 卡 + ref 参数）；不做 OG 输出能力本身（① 已做）。
- 验收(G-g)：Given 访客点分享；When 选渠道；Then 一键带预览卡 + ref 参数转出；各渠道预览实测正常。
- 优先级：P1
- 挂钩牌：拨动 转发完成率 / 验证假设「一键带预览能把『想转』变成『转了』」/ 闭环判据 分享按钮点击→成功转发率
- 产出去向：→ 开 issue 只引本卡（复用 ①-A2 OG）

#### 痛点 P25（G-c）
> 当访问者衡量要不要转发时，他想转了能有点回报（自己和被拉来的人都得点好处），以便更有动力；现状受阻于旧站转发纯付出、没回报，导致动力弱、转的少。 → 压低**转发完成率/意愿率**

##### 角色：全体访客 · 原型：裂变钩子

**功能卡 ⑤-B2 · 转发有回报（裂变钩子）**｜服务痛点 P25｜认领 研发
- 用户故事：作为衡量要不要转的访问者，我想转发后自己和被拉来的人都得到一点好处，以便更有动力转。
- 范围：只做 轻量推荐机制（带 ref 参数的分享链 + 双边激励登记/追踪）；**v0 只埋 ref 追踪 + 激励手动兑现**。
- ⚠ 依赖：自动发放激励需账号/激励体系——v0 先只埋 ref + 手动兑现，自动发放归 ④ 注册后（账号体系）。
- 验收(G-g)：Given 访客通过带 ref 的链分享、对方到站；When 记录；Then ref 归因落库、双边激励可登记（v0 手动兑现）；可统计每个分享带来的到站。
- 优先级：P2
- 挂钩牌：拨动 转发完成率 + 闭环回①到站量 / 验证假设「双边激励能提高转发动力」/ 闭环判据 带 ref 分享数 + 带来的新到站量
- 产出去向：→ 开 issue 只引本卡（自动激励依赖账号，引 ④）
