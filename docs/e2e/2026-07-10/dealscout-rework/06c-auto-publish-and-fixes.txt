# 06c 页面自动重建证据 + 段5 e2e 揪出并修掉的两个真 bug（2026-07-10）

## 本次 e2e 的两个实测发现（都在本分支自己的段4 代码里，当场修 + 回归单测）

### bug① 自动发布腿在真实时序下必跳（读失败被折叠成"没有线索"）

- 现象：`crawl_now` 返回 `{:ok, %{injected: 20}}`，但 30s 内 settlements 恒 1
  （无新 committed 页；显式 publish_page 在安静会话上却成功）。
- 根因：注入 burst 后 session Kind 逐条消化 20 条 `session.send`（每条带
  snapshot 落盘，audit 行 422-445 印证），publish Task 的 `Kind.get_slice`
  撞 5s call 超时 → `items_for/1` fail-safe 折叠成 `[]` → `{:ok, :empty}`
  静默跳过（telemetry-only）。原 moduledoc 的"排在 mailbox 后面时序天然正确"
  在真实时序下不成立。
- 修：`CrawlerRender.items_result/1`（可辨别"确定为空" vs "读失败"）+
  `PagePublisher.publish/2` 读失败有界重试（10×3s），耗尽 fail-loud
  `{:error, {:items_read_failed, _}}`。回归单测 3 条
  （page_publisher_test.exs：busy 重试后照常发布 / 耗尽 fail-loud 不谎报空页 /
  确定性空读仍即时 skip）。

### bug② 公开页渲成 "Unsupported node: page"（词表用了已退役的 hello page-builder 集）

- 现象：匿名访客 `/socialware/external` 页面拿到 committed 树但渲染
  "Unsupported node: page"（首轮 06a 截图前身）。
- 根因：外部 SPA 现行 renderer 是 `catalog_jsonrender.mjs`（shadcn 36 组件 +
  `LEGACY_TO_SHADCN` 只补 container/text/table/code），`render_tree/1` emit 的
  `page`/`section` 是 `catalog_render.mjs` 的旧词表（viewer 已切走）。
- 修：`render_tree/1` 改 emit hello Spec 同源的 shadcn 词表
  （Stack/Heading/Text/Table），Table rows 用按 columns 对齐的 cell 数组
  （viewer `coerceRow` 对 map 行取 `Object.values`，键序不可靠）。
  crawler_render_test / dealscout_page_e2e_test 断言同步。

两修后全量 crawler 套件 `mix test apps/ezagent_plugin_crawler/test` 92/92 绿
（从 umbrella root 跑；per-app 跑法有已知 ezagent_web 未加载坑）。
