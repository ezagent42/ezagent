## 根因链（file:line + 运行时正反证）

1. #1209（commit 03136e446）给物化路加了宿主登录收养：
   `definition_agents.ex:158` 在 fresh 物化前调
   `Ezagent.Agent.HostLoginAdopt.ensure_installer_source(installer, ws, flavor)`。
2. 收养链第一关 `CredentialAdapter.host_login_source_dir(template_class)`
   （apps/ezagent_core/lib/ezagent/agent/credential_adapter.ex:124-137）要求
   template class `function_exported?(class, :host_login_dir, 0)`。
3. **cc-headless 的 template class `CcHeadlessAgent` 没导出 `host_login_dir/0`**
   （apps/ezagent_plugin_cc/lib/ezagent/template/cc_headless_agent.ex:24-33 只
   delegate 了 credential_env_var/credential_relpaths/secret_relpaths/auth_failure_signals
   等，唯独漏 host_login_dir；cc_agent.ex:228-229 有）→ gate 判 `:none` →
   HostLoginAdopt **静默 no-op**（设计上 :none 归为「无宿主登录概念的 flavor」清洁跳过）。
4. 于是全新库上 admin 装 kanban 后三张表全空（实测 count=0）：
   user_default_credential_sources / workspace_shared_credential_sources / credential_grants
   → #17 cascade 解析不到任何 source → 物化出的 config_dir
   （~/.ezagent/default/cc-headless-agents/system/<id>/）**根本没有 .credentials.json**
   （两个 agent 实测均无，不是「副本过期」而是「无副本」）→ cc CLI 报 Not logged in。

运行时正反证（erpc 进 server 节点）：

    template_class_for("cc-headless") → {:ok, Ezagent.PluginCc.Template.CcHeadlessAgent}
    CredentialAdapter.host_login_source_dir(CcHeadlessAgent) → :none            ← kanban 两角色走的路
    template_class_for("cc")          → {:ok, Ezagent.PluginCc.Template.CcAgent}
    CredentialAdapter.host_login_source_dir(CcAgent)         → {:ok, "/home/yaosh/.claude"}  ← 收养链本身是好的

盖章：#1209 的集成测试 socialware_cc_credential_inherit_test.exs 只测了 flavor `"cc"`
（:121 `flavor: "cc"`），没测 `"cc-headless"`——kanban manifest 两个 role 恰好都是
cc-headless，正好整个落在覆盖缺口里。
