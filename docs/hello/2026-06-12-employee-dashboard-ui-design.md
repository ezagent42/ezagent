## 0. 页面清单与导航关系

```
/workbench                     页面 A · 员工落地页(总览 dashboard)     [PR-1]
/workbench?session=<uri>       页面 B · 会话工作台(三栏)              [PR-2/3]

/workbench/sandbox             页面 D · 沙箱陪练                       [PR-5]
```

- 全部挂在 AppShell 统一外壳下（复用 avatar / 通知；**员工 perspective 不出
  ⌘K 命令面板**——那是 admin/操作员的工具，员工界面保持极简），新增
  `perspective: :workbench`
- 单 LiveView + `handle_params` 路由（A↔B 同一 LV 切视图，复用 admin_live 的
  `?session=` 模式）；C / D 独立 LV
- 身份：`:require_entity`。admin 进入看到的内容一致（admin 是员工超集）

### 区域功能

| 区 | 功能 | 数据源 | 交互 |
|---|---|---|---|
| 顶部问候条 | 姓名 + 需关注数（红色 SLA 会话计数），点击数字 → 页面 B 并筛"需要关注" | SLA 聚合 | 点击跳转 |
| **A1 我的渠道** | admin 授权给我的渠道列表；每行：渠道 icon+名、**聚合 SLA 点**（该渠道最差会话的颜色）、活跃会话数 | workspace member declaration 的 `channels:` 标注 | 点渠道 → 页面 B 左栏定位到该渠道分组 |
| **A2 我的业绩** | 今日 4 指标：会话数 / 接管次数 / 平均首响 / CSAT（占位"—"，标 tooltip"评分入口未开通"） | 业绩聚合查询（PR-4 前显示占位骨架） | [详情] → 页面 C；[问 operator-agent] → 页面 C 并聚焦聊天框 |
| **A3 活跃会话** | 跨渠道合并的活跃会话表，每行：SLA 点、客户标识、渠道、**当前处理者**（"AI 接待中" / "您已接管" / "王五处理中"）、最后消息摘要、距今时间。**卡头带"我的客户 N"计数**——手册 B.1②"您负责的客户群体"由本卡 + 页面 C3 客户类型分布共同承接 | `SessionContext.list_sessions_for` + 授权过滤 + 末条消息 | [进入] → 页面 B 打开该会话 |
| **A4 沙箱入口** | 一句话引导 + 进入按钮 | — | → 页面 D |

**空态**：无授权渠道 → A1/A3 显示"管理员还没有给您分配渠道，请联系 admin"；
无活跃会话 → A3 显示"暂无会话，客户来了会第一时间出现在这里"。

## 2. 页面 B · 会话工作台 `/workbench?session=<uri>`

> 手册 B.2 三栏 + B.3 三模式。**这是核心页面。**

```
┌──────────────────────────────────────────────────────────────────────────┐
│ AppShell                                                                  │
├──────────┬─────────────────────────────────────────────┬─────────────────┤
│ B1 导航栏 │ B2 会话区                                    │ B3 AI 协作面板  │
│          │ ┌─────────────────────────────────────────┐ │                 │
│ 筛选:     │ │ Marie · WhatsApp · EN→中  [Auto|Copilot|Takeover]│ │ 本会话 AI 同事  │
│ [全部]    │ ├─────────────────────────────────────────┤ │ ● 接待AI  空闲  │
│ [🔴需关注]│ │ 客户: Is it waterproof?            10:02 │ │ ● 业务AI  思考中│
│ [我接管的]│ │ 🤖接待AI: Yes! The ZL series is...  10:02 │ │ ● 翻译AI  空闲  │
│          │ │ 客户: reviews from US buyers?      10:04 │ │                 │
│ ▾ WhatsApp│ │ ┄┄🔒您→AI团队: 提一下 RE100 认证┄┄ 10:05 │ │ 客户上下文      │
│  🔴 Marie │ │ 🤖业务AI: We're RE100 certified...  10:06 │ │ 来源: WhatsApp  │
│  🟢 Tom   │ │ 👤您: 我帮您申请一个样品折扣       10:07 │ │ 本会话: 10:02起 │
│ ▾ 飞书    │ ├─────────────────────────────────────────┤ │ (跨会话上下文   │
│  🟢 李老板 │ │ B2c composer(随模式变化,见下表)          │ │  待身份打通)    │
│ ▾ Web     │ │ [🔒 私密建议,仅 AI 可见…        ] [发送] │ │ [+ 邀请AI同事]  │
│  🟡 visitor│ └─────────────────────────────────────────┘ │                 │

```

> 时序注（v3）：10:05 的建议**对客户下一条消息（10:06，图中省略）后的回复
> 生效**——orchestrator 无在飞插入能力；员工要立即纠错用 Takeover。

### B1 · 导航栏（左，可折叠）

| 功能 | 说明 |
|---|---|
| 筛选 chips | 全部 / 🔴需关注（SLA 红）/ 我接管的 |
| 渠道分组列表 | 按渠道分组的活跃会话；每行：**SLA 点 + 客户标识 + 未读数** |
| SLA 点语义（v0） | 最后一条**客户**消息未被回应的时长：🟢 <30s ｜ 🟡 30s–2min ｜ 🔴 >2min（Takeover 中员工的回复同样计入"已回应"）。阈值进 config，5s tick 刷新。会话处于 Copilot/Takeover 时**另加 owner 徽标**（"您" / "王五"），与 SLA 颜色互不干扰 |
| 实时性 | PubSub 订阅 session 事件（复用 admin_live 订阅模式），新消息即时插入 + SLA 重算 |

### B2 · 会话区（中）

**B2a header**：客户标识 · 渠道 · 语言对（翻译 AI 检测）· **三模式切换器**（页面最重要的控件）

| 模式 | 切换器状态 | 含义（手册 B.3） | loom 实现（决策 2026-06-12 v3：路线② + loom 旁路，见架构文档 §5） |
|---|---|---|---|
| **Auto** | 默认 | AI 独立处理，员工纯旁观 | 现状即是：orchestrator 正常应答 |
| **Copilot** | 一键切 | 员工私密建议给 AI，客户不可见 | composer 内容经 `:coach` dispatch 直达 orchestrator slice，**对客户下一条消息后的回复生效**（无在飞插入；立即纠错用 Takeover）；建议不进 session 消息流 |
| **Takeover** | 一键切 | 员工直接发消息，客户感觉是真人 | orchestrator `:standby`（对**下一条**客户消息生效；在飞回合可点"中断生成"）+ 员工 `chat.send` 直接回复（客户页渲染 **staff 气泡**） |

**模式指示器不是独立 UI 状态——它是 orchestrator slice 的 `collab_mode/owner`
投影**（字段命名与 socialware Turn 对齐，为迁移留直通道）。
切换规则：任何时候可发起切换（`:set_collab_mode` 走 `:cast`——orchestrator
LLM 调用期间 `:call` 必超时；UI 显示"生效中…"直到 slice_changed 确认）；
standby 期间客户新消息记入 `unanswered`，工作台高亮"客户有新消息待您回复"；
**每次切换在员工工作台的
消息流位置插入一条本地系统提示**（"您于 10:05 进入 Copilot 模式"）——
**该提示只存旁路记录 + audit，不写 session 消息**（否则客户 loom 页/飞书镜像
会看到）；Takeover → Auto 切回时弹一次确认（"AI 将恢复应答"）。
`owner` 是其他员工时切换器整体禁用（见 §5 会话占用）。

**B2b 消息流**（复用 ConversationView + 新消息类型样式）：

| 消息类型 | 样式 |
|---|---|
| 客户消息 | 左侧气泡 |
| AI 消息 | 左侧气泡 + 🤖 + AI 同事名 |
| 员工 Takeover 消息 | 右侧实心气泡 + 👤。客户侧渲染为 **staff 气泡**（非客户气泡）——依赖 PR-0 的 role_of 改造 + 前端新 role 渲染（独立 repo，rebuild+vendor） |
| **Copilot 私密建议** | 右侧**虚线边框 + 🔒 + "仅 AI 可见"角标**——视觉上必须与公开消息截然不同（防员工误判客户可见性，这是本页面最大的 UX 风险点）。**实现注记：它不是 session 消息**——是旁路存储的记录在员工工作台按时间线插画渲染，MessageStore 里不存在 |
| 模式切换系统提示 | 居中灰色细字。**同为旁路记录**（不写 session 消息），只在员工工作台渲染 |

**B2c composer**（随模式变形——同一个输入框三种皮）：

| 模式 | composer 状态 |
|---|---|
| Auto | **禁用**，占位文案："观察中——切到 Copilot 给 AI 提建议，或 Takeover 直接回复" |
| Copilot | 可输入；输入框带 🔒 前缀样式；placeholder "私密建议，仅 AI 可见"；发送按钮文案"发给 AI" |
| Takeover | 可输入；placeholder "以您的身份直接回复客户"；发送按钮"发送" |

### B3 · AI 协作面板（右）

| 功能 | 说明 |
|---|---|
| 本会话 AI 成员 | 列表：AI 同事名 + 状态点（空闲/思考中）。数据源：claude_code 后端下接 `loom:gen_progress` 事件；deepseek 后端无流式事件，退化为"最近 10s 有无消息产出" |
| 客户上下文卡 | v0 只显示：来源渠道 + 本会话开始时间。"历史会话数/上次意图"依赖跨会话客户身份——loom tmp_user 是 per-session 的，结构性不存在，标"待客户身份打通"（手册 C.3 的承诺挪到身份打通后） |
| [+ 邀请 AI 同事] | 从 AI 同事库选一个加入本会话（复用既有 invite 流） |
| （后置）转交员工 | 转给其他坐席，PR 范围外 |

## 5. 横切设计

| 项 | 设计 |
|---|---|
| **可见性安全** | Copilot 私密内容是本设计最大风险面。原则：**不靠过滤、靠根本不进 session 消息流**（loom 的 `/stream` SSE 与飞书镜像都是全量推送，写进去就等于泄漏）——建议/系统提示走 `:coach` dispatch + 旁路存储；PR-3 带不变式测试（coach 内容在 MessageStore 零记录）。样式上锁形角标 + 虚线必须无歧义 |
| 会话占用 | orchestrator slice 的 `owner` 是其他员工的会话：模式切换器禁用 + 显示"王五处理中"，可观察不可操作。互斥在 `:set_collab_mode` action 内校验 caller==owner 做实，UI 禁用只是表象 |
| 降级 | AI 成员全部无响应 >30s：B3 面板红色提示"AI 同事未响应，建议 Takeover" |
| 响应式 | v0 桌面优先；窄屏 B1/B3 折叠为抽屉 |
| i18n | 全部文案走 gettext（员工界面中文优先） |
| 视觉 | 沿用 EzagentDomainUi 的 Tailwind token / Components / Primitives，不引新 UI 库 |
