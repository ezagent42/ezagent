2. 三个关键设计时刻

时刻 A：Hello 入口页（第 1 步）

用户进入 hello 的第一眼。应参照 flywheel product-detail.html 的结构：

  • 产品标识：名称 + glyph + 描述（用 @json-render 的 Heading + Text + Badge）
  • 功能说明：这个 hello 能做什么（用 Grid + Card 列出能力）
  • 主 CTA：醒目的 "开始使用 / 派个任务" 按钮（参照 product-detail 的 primary button）
  • 公开可见：匿名 public_view 可访问（参照 flywheel 的 "public_view · live" 标签）

时刻 B：Hello↔Kanban 连接点（第 4 步）松耦合

这是自举链的关键衔接点。Flywheel 里是 Fork 按钮，这里应是 "派活到 kanban" 动作：

  • 触发方式：Concierge 确认需求后，显示 "创建开发任务" CTA
  • 视觉提示：按钮 + 简短的过渡说明（"将在 kanban 看板创建任务，agent 接单后自动开工"）
  • 松耦合标注：诚实标注 "当前为松耦合连接，最终将走 #1360 Layer B 跨-session 挂载"
  • 状态反馈：任务创建后 → 显示 kanban 任务卡链接 + agent 状态

时刻 C：闭环反馈（第 6 步）

任务完成后，用户应能感知到进展——参照 flywheel publish-landing 的闭环模式：

  • kanban 看板上任务卡状态切换（待派 → 进行中 → PR 已开 → 已合并 → 已部署）
  • 状态变更时视觉反馈（badge 颜色变化、卡片位置移动）
  • 最终 "三面绿 ✓" 作为 publish-landing 的等价物

4. 双流对照

Flywheel 飞轮（Homesite 视角）

🏠 官网 → Gallery 货架
→ 产品详情（看 + Try + Fork）
→ Try 试用（进 world 交互）
→ Fork 复制（到自己 workspace）
→ 改造 + 发布
→ ✨ 新产品上架（闭环）

Hello 自举链（World 视角）

🔑 登录 → Hello 入口（greeter）
→ 真 prompt → live 渲染
→ Concierge 确认需求
→ 🔌 派活到 kanban（连接点）
→ Agent 接任务 → 产 PR
→ ✨ merge → 三面绿（闭环）
两条链的共同模式：浏览/发现 → 深入了解 → 触发行动（Try/Fork vs 派活/接任务）→ 工作执行 → 结果可见（上架 vs 三面绿）
关键差异：Flywheel 是多租户 marketplace（Builder × Seller）；自举链是单次开发任务流（用户 × Agent）。
