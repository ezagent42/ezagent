1. Gallery 货架

Flywheel gallery.html

docs/website-demo/flywheel/gallery.html

产品货架：CSS columns 瀑布流卡片 + 搜索 + 分类筛选 chip + 产品数量计数。每个卡片含 glyph 头像、标题、作者、描述、标签（public_view · live）、统计（招过 N · 好评 M）+ "查看" CTA。

视觉特征：白色卡片 + 阴影，hover 上浮 3px；glyph/color 产品身份；"刚上架 · new" 时间徽章

WorldLive → React: workspace_plugins

缺口 W-G1：需要 Gallery 浏览/搜索/详情 API，从 DefinitionRegistry 拉取已发布产品。前端可用现有 shadcn Card + Grid 组件实现。

3. 构建 / Fork 中转

Flywheel world-step.html

docs/website-demo/flywheel/world-step.html

占位页：虚线框列出待建功能。build 模式显示发布前置步骤；fork 模式显示 "从官网一键触发 fork → 改造 → 发布"。

待建 W-G2：发布入口 + 表单；W-G3：Gallery→Fork 触发

4. 发布确认 + 闭环

Flywheel publish-landing.html

docs/website-demo/flywheel/publish-landing.html

绿色 ✓ + "已上架 / Published" + 产品卡片滑入动画 + "返回探索" CTA。卡片通过 `slotin` 关键帧动画入场。

视觉特征：成功色语义；缩略产品卡片；动画闭环反馈——发布后立刻在货架可见

自举链 闭环确认

kanban 看板 → 三面绿 ✓

自举链的 "闭环" 是看板任务状态流转（待派 → 进行中 → PR 已开 → 已合并 → 已部署）。每个状态变更都是 fliwheel 的 "publish" 等价物。

设计方向：kanban 任务卡的状态流转应参照 publish-landing 的闭环反馈模式——状态变更时视觉上可感知（badge 切换、卡片位置移动、动画过渡）。
