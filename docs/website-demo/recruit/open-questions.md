# recruit-v2「手搓挑战」demo — 三个待解问题与决策审查（待续）

> 状态：草拟 2026-07-07。同事对 recruit-v2 提了 3 个问题，本文记录问题、ruihua 的判断、以及一版俞军决策审查，供明天继续思考。**不改代码，纯梳理。**

## 背景：核心假设

这个 demo 想切中 OPC（一人公司）的痛点 —— **自己手搓的 agent，替代不了专业人士 / 专业人士提供的 agent 的效果。**

当前路径：抽职业卡 → 为该职能手搓一段 prompt → 按专家版关键要点覆盖度打相似度分 → 市场（专业人士发布的 agent 瀑布流）→ 招进 workspace → world（专业成员入组干活并留下）。

---

## 三个问题（同事提出）+ ruihua 的判断

### 问题 1（最重要）：一段 prompt 能代表专业人士的价值吗？
- 隐忧：prompt 优化如今很容易，用户拿 ChatGPT 生成一段贴进来可能就得高分，"你搓不过专业的"这个 punch 会被证伪。
- ruihua 的更深判断：产品真正支持的是 —— 专业人士通过 world build 自己的"组织"（多 agent + 人 + 可能含 hello 生成页的 session），并开放给 OPC 用。**价值单位应从 prompt 上移到 session / 组织**：让 OPC 自己创建一个多 agent / 人的 session，再发现专业人士创建的 session 效果更好。

### 问题 2：留存 / 完成率 —— 路径太长？
- 隐忧：用户如果不想自己输入 prompt，就在中途结束了。
- ruihua 的判断：需要一步步优化（抽卡更炫、有些环节不太费脑就能看到结果 等），但**重要性低于问题 1**。

### 问题 3（优先级最低）：hello 实现 —— 这个页面 hello 可能做不出来
- ruihua 的设想：必要时让 hello 直接吃 HTML 来 build —— 把 demo HTML 上传到 hello，对 hello builder 说"给它加个底部对话框"，即可快速 build。
- ruihua 的原则：业务上有重大价值的需求，即使当前难以实现，也要尽可能想办法实现。

## 决策审查（俞军框架，供参考）

核心结论：**ruihua 的排序 1 > 2 > 3 正确，而且问题 1 比同事说的更严重 —— 它是"目标被偷换"，不是打分 bug。**

### 问题 1 = 目标层错位（用用户价值公式一量就穿）

demo 的真正目标：让 OPC 相信 `用户价值(专业组织) ≫ 用户价值(自搓)`，然后去招人。但当前 puncture 屏把目标偷换成了"证明专业人士 prompt 写得更好"。

> 用户价值 = 新体验 − 旧体验 − **替换成本**
> - 若"专业的护城河 = 一段 prompt" → 替换成本 ≈ 0（贴一段 ChatGPT 的就抹平）→ demo **自我证伪**，还把我们产品贬成"prompt 中介"（已被商品化、没壁垒的生意）。
> - 若"专业的护城河 = 一整个 organization / session"（多 agent + 真人把关 + 沉淀的行业数据 / 工作流 + hello 对客界面，跑在 world 的路由 / 可靠性上）→ 替换成本真实且高 → claim 立得住，且正好等于产品的真实价值。

**公式本身给了逻辑证明：价值单位必须从 prompt 上移到 组织 / session。ruihua 方向对。**

好消息：后半程已经修对一半 —— 市场屏卖的是"专业人士发布的 agent（组织单元）"，world 屏演的是"这个单元进 session 干活并留下"。**错位只在 puncture 这一屏。** 所以修问题 1 ≠ 重做 demo，是换掉这一屏的"证法"。

### 修问题 1 的方案（穷举 + 权衡）

| 方案 | 证法 | 忠实 | 造价 | 留存 |
|---|---|---|---|---|
| A 现状：写 prompt 打相似度 | 护城河 = prompt | ✗ 定错位、可证伪 | 已建 | 有输入门槛 |
| B ruihua 版：OPC 自建 session → 对比专业 session | 护城河 = 组织 | ✓ 最忠实 | 高（难 mock + "建"很费脑） | 更差 |
| **C 反转"好 prompt 也不够"（推荐）** | 护城河 = 组织 | ✓ | 低（只改 reveal） | 可顺带修 |
| D 换成行业判断题（选择题探深浅） | 护城河 = 判断 | ~ 部分 | 中 | 更好 |

**推荐 C（必要时叠 D 的低门槛）**：把 puncture 从"比谁 prompt 写得好"改成 ——「把你能拿到的最好 prompt 贴进来（哪怕 ChatGPT 级），它还是干不成，因为差的根本不是 prompt，是整个组织 / session：真实客户数据、多 agent 协作、真人把关的边界情况、客户实际在用的 hello 面」。**把"我贴 ChatGPT"这个反对，变成 demo 的论点本身。** 顺手把输入改可选（"懒得写？给你一段现成的好 prompt →"），直接吃掉问题 2 一大半。

B（让 OPC 自建 session）方向最忠实，但"建"又难又费脑，忠实增量被造价 + 留存拖累吃掉，预期效用低于 C。

### 三问 triage
- **问题 1 → 现在就解，但不是重做**：只换 puncture 一屏的证法（C），市场屏、world 屏不动。这是全案唯一的"目标级"修复。
- **问题 2 → 不单独立项，并进问题 1 的改版**（可选输入、低脑力）；剩下的纯留存打磨（抽卡更炫、减步骤）之后做、低优先。ruihua 排序正确。
- **问题 3 → demo 内不解**：(a) demo 本就是独立 HTML，不需要真 hello；(b)"hello 吃 HTML 一键 build"是真有业务价值的产品能力，但应路由到 world / hello 路线图（world.cup），别拿它卡这条 demo。业务重大 ≠ 现在、在这里、由这个 demo 扛。

### 致命假设 + 最小验证
假设"C 的'好 prompt 也不够'比现状更能让 OPC 相信要招专业组织"。最小验证：拿现状版 vs C 版，给 5 个真实 OPC 看，只问一句"看完你信不信'该招一个专业的而不是自己搓'？" —— 不信就再调证法，别上来就全量重做。
