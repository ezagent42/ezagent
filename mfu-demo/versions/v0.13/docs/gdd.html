1. 高概念(High Concept)

一句话:和我的 AI 伙伴们一起,经营一家真的公司——我们一起工作,一起成长。

玩家幻想(Fantasy):我是主理人。我的公司是一个人机协同的组织:我教 AI 做事,AI 替我扩张产能;订单来自真实世界,收入是真的钱;我在成长(判断力、信用、人脉),我的 AI 在成长(能力、资产厚度)——直到真实的孵化器来敲门。公司可能会死,但我和我积累的一切不会清零。

核心动词:路由(把任务派给最合适的资源)· 调教(培养 AI)· 兜底(确认与担责)· 经营(接单、接入能力、管现金流)。

品类参照:开罗系经营模拟的节奏与亲和力 × 真实企业运营平台的数据与后果。

它不是什么:不是"AI 员工替你打工"的挂机游戏——AI-native 组织的核心是人机协同,人从不缺席,只是人做的事情变了。

2. 设计支柱(Design Pillars)

  1. 真实性(Real Referent):每个数值、每个按钮都对应真实世界的某样东西——算力是学校集群的真实配额,认证是协会颁发的真实资质,订单是真实商业需求,收入是真实资金,Agent 资产是真实可迁移可交易的配置与数据。检验方法:问"这个东西离开游戏还存在吗?"答"不存在"就删。
  2. 玩即生产(Play = Produce),贯彻到每个循环:每一个玩法循环必须能回答"它生产了什么真实价值"。调教生产 Agent 资产;交付生产真实交付物与信用记录;复盘生产 eval 规则;社交生产真实人脉。本文档 §5 每个系统均标注"生产什么"。
  3. 即点即玩(Kairosoft Simplicity):单次操作 ≤ 3 次点击;新玩家 60 秒内接到第一单。复杂度藏在成长与路由决策里,不藏在操作里。
  4. 对称性(Symmetry):平台上只有一种实体——AI-native 组织(人 + Agent + 接入能力)。学生 OPC、学校、孵化器、协会、老师工作室,都是同一种实体的实例,共享同一套底层。
  5. 真实对抗(Real Stakes):一切稀缺物——订单、转真名额、榜单位次、教练口碑——都在真实竞争中分配,不由系统施舍。竞争对手是真人组织,他们会回应你、反制你。但对抗必须配套两件事:分层匹配(防碾压劝退)与败者价值(落选也生产资产),否则竞争制会把多数玩家变成陪跑。

3. 世界观与角色(对称性原则的落实)

3.1 世界设定

Hyprial 平台即世界本身,不作为角色出现。世界里的一切都是组织(Org):

Org = { 人(角色持有者) + Agent(资产型伙伴) + 接入能力(Connector) + 资产(训练资产/信用/现金) }
人   = 跨组织的统一实体,档案(技能/信用/人脉/作品集)属于人本身(D20)
Agent = 组织的资产,不可跨组织自由流动,只能授权/出售/转让(D19)

角色与权利:"主理人"只是人可持有的一种角色(另有成员、顾问、教练等)。确认与担责权绑定"本公司主理人"角色——你在自己公司行使它,你去别家打工时由对方主理人行使。同题竞业回避:同一命题的竞争期内,不得同时受雇于同池竞争对手(纳入反串通检测)。

关键推论 1(产品):每类组织都有自己的管理面板,且面板是同一套系统的不同配置——协同确认、Agent 调教、资产沉淀对所有组织生效。协会的评审 Agent 也需要专家调教;孵化器的 Scouting Agent 也在积累资产。

关键推论 2(销售):给参与方的 demo = 给他们开自己组织的账号。DHS 登录后看到的是孵化器面板:发一道命题、看命题被多少 OPC 接走、看 Scouting Agent 推来的榜单摘要。参与方不是"参观游戏",而是"入驻世界"。

关键推论 3(教学):老师在系统里不是管理员,而是一个组织的经营者——老师也在调教自己的助教 Agent。全员示范人机协同。

4. 核心循环

4.1 三层循环

30 秒循环(操作):看面板 → 做一次路由/确认/调教交互 → 即时反馈(资产+1、算力消耗、进度)。

5–15 分钟循环(一单):接单 → 路由决策(每个环节派给谁:本人/Agent/外部资源)→ 生产 → 交付确认(兜底)→ 获得评价 → 评价回灌调教建议。

周循环(经营):领算力配额 → 规划接单组合与调教/生产取舍 → 考虑接入新能力(Connector)→ 周结算(现金、信用、资产增量)→ 教练 Agent 周复盘(个性化 debrief:本周决策回顾、短板定位、下周建议——对应体验式学习循环的反思环节)。

长线循环(生涯):认证进阶 → 真单准入扩大 → 榜单曝光 → 入驻邀请 / 或破产清算 → 主理人带资产重开 → 生涯档案累积。

4.2 决策深度来源(取舍)

  • 生产 vs 调教:赚今天的钱,还是养明天的能力?
  • 路由决策:这个环节谁干最好?判断错了真实地扣质量分。
  • 能力接入:接入数字人引擎开新业务线,还是深耕现有能力?(投资决策)
  • 现金流:接入有成本、Agent 有运行费、破产是真的——学的是真实的经营。

4.4 时间设计(Time Design,D26 v0.9 修订)

原则:世界一只钟,推演随便跑。

维度 🕹️ 私人推演器(沙盘) 🌍 世界时钟(唯一)
推进方式 私人沙盘,可加速/暂停/重来,不改变世界状态 服务器统一推进,锚定真实日历,任何人不可加速
用途 学技能(快反馈循环)、沙盘推演路由方案 真截止、真评审窗口、真竞赛开奖
半天块含义 回合内的抽象预算 真实日历上的时间预定,逾期即真实违约
节拍锚 无(自由) 课堂周节拍:每周一课=回合结算/发题/开奖;学期=赛季
失败 可重来 不可重来,进入档案

三条配套规则:
1. 推演器是资产:推演精度随公司数据积累提升,可感知、可对比——World Model 厚度的玩法化呈现。推演结果仅供参考,与真实结果的偏差本身是复盘素材。
2. 异步碎片玩法:调教(分钟级)、打工、官网维护设计为课间可完成的动作;真实计时器驱动回访(通知:Agent 完成/评审开奖/截止临近)。
3. 无死时间:两区并行开放;设计验收标准——任何时刻打开游戏,存在至少一件当天可完成并获得反馈的事。

4.3 可玩性设计(Fun Design,新增,D18)

直视风险:本案最大的可玩性风险是滑向 Capsim/Cesim 式的"表格地狱"——竞品调研证实这是品类通病(学习曲线陡、界面像报表、乐趣靠成绩单)。真实性与可玩性不天然冲突,但可玩性不会从经济系统里自动涌现,必须专门设计。

六大乐趣支柱

支柱 具体机制 防的病
成长快感 数值上涨之外的空间成长:办公室从宿舍书桌 → 共享工位 → 老厂房独立间(终局呼应孵化器园区);资产+1 的即时反馈 数字疲劳
养成情感 Agent 拟人化:名字、随机性格特质(影响任务适配度,带收集乐趣)、成长台词("老板,这个我练过!")、调教后的即时反应 调教沦为作业
决策张力 路由是每单的小赌注(判断对错真实兑现);竞标有押注与爆冷 决策无感
对抗戏剧 榜单实时变动;对手动态播报("隔壁队刚提交了!");赛季末冲刺 单机感
惊喜事件 开罗式随机事件:大单空降、Agent 灵光一现产出高质量守则、算力维护日、评审专家客串点评 节奏单调
节奏解锁 每 1–2 周必有新解锁(新单型、新 Connector、新事件);学期 = 赛季,赛季初部分重置悬念 中期倦怠

Juice 清单(工程 P1,不是装饰)

盖章动画、金币飞溅、升级闪光、像素小人忙碌态、交付倒计时的心跳感——开罗游戏的亲和力一半来自这些低成本高回报的反馈。列入垂直切片的必做项。

轻重分区

练习区保持纯游戏心态:可重来、无真实后果、允许瞎试;真实后果(资金、信用、违约)只存在于真单区。防止真钱压力压垮"像游戏一样简单"的承诺。

裁决原则

乐趣在原型中被发现,不在文档中被规定。唯一裁判是 playtest 指标:自愿重复率、课后主动登录率、调教交互的主动重复次数、落选后的次周留存。任何机制若在纸面原型/灰盒中不好玩,无论多"真实"都要重做。

5. 系统设计

每个系统末尾标注 【玩即生产】:该系统生产的真实价值。

5.1 订单系统

  • 来源:任何组织都可发单(对称性)——孵化器、协会、学校、未来其他 OPC 之间也可互相发单(生态内循环)。
  • 结构化 brief:目标 / 交付物 / 验收标准 / 奖金 / 准入规则。
  • 准入规则由发单方自定义(D4):可组合条件——协会认证等级、历史评分、已交付案例数、地域、所属学校、指定邀请。平台提供规则引擎,不做统一门槛。
  • 发放形态:竞赛/悬赏模式(命题 + 奖金池),规避劳动关系;结算走平台。
  • 流程:接单 → 路由生产 → 交付确认(主理人兜底,强制)→ 平台 QA 门槛(不达标打回,附原因)→ 评审(发单方 + 协会评审 Agent)→ 结算 + 评价入档。
  • 练习单(学校发)跳过 QA 与正式评审——低风险试错空间。

竞赛制分配(D15,默认形态)

  • 同一命题多队竞争:发单方设定参赛队数上限与阶梯奖金池(冠军 50% / 亚军 30% / 入围 20% 分摊,比例可配),而非一队独占。练习单即为班内对抗市场——同一命题全班竞争,互相看得见对手动作。
  • 分层匹配:按能力分与信用分层组池(类 ELO),新公司不与成熟公司同池;发单方可指定层级。
  • 败者价值:落选交付物脱敏后进入调教题库(生产者获题库分成)+ 计入公司作品集与主理人档案——参与即生产,落选不清零。
  • 反串通:同池队伍的关联关系检测(同 IP、资产互售异常、轮流让标模式),异常触发审计。

【玩即生产】:真实交付物、真实收入、信用记录、(打回时)eval 负例、(落选时)题库素材与作品集。

5.2 Agent 系统

能力模型(承 v0.1,保留)

能力分 = f(训练资产厚度, 实战评价史)
  • 金钱买不到能力,也买不到"效率"(D17):金钱只能购买投入品——算力、教练时长、优质题库/课程、外部资源、基座模型接入。投入品可能间接帮助你调教得更好,但能力增长只来自调教动作与实战评价。
  • 自有资产与租用基座分离(D17):能力展示拆为两部分——"自有资产"(调教出来的 prompt/案例库/守则,可迁移可交易)与"当前基座"(接入的底层模型,租用性质,停止付费即降级)。租的是底子,养的是本事;资产市场只交易前者。现实同构:换掉底层模型,你的 prompt 与数据资产依然在。
  • 能力分可点开看构成明细(哪些资产、哪些评价、当前基座)。
  • 真实所指:Agent 的 prompt/知识库/案例库 + eval 通过率——离开游戏依然存在,可迁移、可交易(见 §5.7)。

调教界面("带徒弟",玩法核心)

交互 产出的真实资产 题库供给(D10)
喂范例(二选一鉴别) few-shot 正负例 初期:学校/协会人工出题;中期:真实交付案例自动生成
写守则(填空模版) prompt 规则片段 模版由平台设计,内容玩家生产
复盘(点选打回原因) eval 规则 + 负例标注 完全由真实打回事件生成(天然自动化)
传帮带(守则复制) 配置模版复用 —

题库飞轮:每一笔真实交付(含打回)自动脱敏进入题库候选池 → 学校/协会审核上架 → 全平台调教题库越用越厚。这是平台级数据资产。

【玩即生产】:Agent 配置资产(核心);题库素材(平台级)。

5.3 资源路由系统(取代 v0.1 的"亲自干加成",D7)

执行与路由分离(重要澄清,D16)

"路由"是分派决策,"执行"是干活本身,二者不在同一个地方发生:

  • 路由发生在系统内:每个订单环节,主理人在系统里点选"给 Agent / 给本人 / 给外部资源"。
  • 执行可以在系统外:路由给 Agent → 系统内执行(调模型,耗算力,产物落任务卡);路由给本人 → 在 Photoshop/Figma 等外部工具中工作,完成后把文件或链接提交回系统;路由给外部资源 → 对方在系统外工作,通过市场或 Connector 交付进来。
  • 平台的定位是流转、承载与存证层——任务卡流转、成果版本管理、QA、确认、结算、数据沉淀。平台永远不做生产工具(不做 Photoshop);Connector 只是让部分外部工具(Figma、GitHub)的提交同步更顺滑的可选增强,MVP 的提交形式就是上传文件与链接。
  • AP 的消耗时机随之明确:AP 在路由时扣除(把环节路由给"本人"=承诺本周时间),不是对系统内操作的计量;到周结算未交付即承诺违约,信用受影响。系统看不见你在外部工具里的劳动,只看见承诺与交付。

任务的每个环节都要回答:谁来干?

资源选项 成本 质量 适用
本人 行动点 AP 取决于任务适配度,可正可负 判断、关系、担责、个人擅长领域
自家 Agent 算力 取决于能力分与任务匹配 高频、可重复、已调教领域
外部资源(Connector/外包/专家) 现金/分成 取决于资源规格 自己和 Agent 都不擅长的环节

设计要点:

  • 没有普适的"人工加成"。MCN 公司主理人亲自上镜,若"出镜魅力"适配度低,质量反而下降;但"客户关系维护"环节本人上几乎总是加分。适配度矩阵按任务类型 × 资源类型设计,部分适配度需要玩家通过尝试发现(探索乐趣)。
  • 玩家练的是编排力:路由判断正确率沉淀进主理人档案(§5.4)——这是 AI-native 组织最核心的能力,游戏机制直接训练它。
  • 交付确认(兜底)不可路由——责任永远在人。这是协同确认原则的机制化,也是全游戏唯一的硬规则。

【玩即生产】:路由决策数据(主理人判断力档案);真实的人工产出(本人干的部分)。

5.4 人的档案(原"主理人成长线",D20 更名)

档案属于人而非某个公司角色:同一份判断力/信用/人脉/技能档案,同时支撑你在自己公司当主理人、在别人公司打工、在市场上卖 AP 时长。打工线为通用机制:主理人可在打工市场出售自己的时间(AP → 工资),这是现金见底时先于桥贷的自救手段,也让"做业务 / 打工回血 / 调教养能力"构成创始人时间的三向机会成本——创业教育最核心的一课由机制直接教授。

AI 在成长,人也必须在成长——且成长要可见、可携带:

维度 如何成长 真实所指
判断力 路由决策的事后正确率 经营能力的可验证记录
信用 交付履约、确认担责的历史 平台信用分(跨公司永续)
人脉 社交动作、合作过的组织 真实关系图谱
专业技能 本人干的环节 + 学校培训 个人能力档案(可写进简历)

主理人档案独立于公司存在——公司破产,档案不清零(§5.8)。

【玩即生产】:个人创业信用档案——对孵化器与投资人而言,这是比商业计划书更硬的尽调材料。

5.5A 生态能力系统(D24/D25,取代"按身份"的生态角色描述)

资金 孵化器(grant/桥贷/投资)、订单奖金 投资 / 竞争
订单 孵化器、协会、学校(练习)、其他 OPC 竞争 / 交易

组织=配置,不是类型:表中的"学校/孵化器/协会"只是当前世界里三种常见配置;新组织(企业创新部、地方政府、社团)可用同一套原语自由组包入驻世界。

会籍机制

  • 资源流:会籍按周发放能力(算力配额、教练时长、题库访问、命题优先权)。
  • 准入:组织自定(认证等级/信用/作品集/邀请制),即 D4 规则引擎的会籍版。
  • 多会籍:玩家可叠加持有(学校学籍 + 孵化器预备营 + 协会会员……),会费与收益构成组合决策。
  • 转会/退出:退出即断资源流;再加入有冷却(默认 3–4 周);转会可能要求推荐或转会费。违约期内不可转会。
  • 组织侧竞争:会籍包公开可比,组织通过更好的包与 scouting(向高分玩家定向发 offer)争夺成员;成员流失率是组织的公开指标之一。孵化器"入驻邀请"= 其顶级会籍 offer,终局叙事不变、机制归一。

5.5 能力接入系统(Connector,新增,D8)

外部世界的数据/模型/API,在游戏中表现为可接入公司的"能力模块"——相当于开罗游戏里的设备投资,构成本作的科技树:

能力示例 开启的业务线 成本结构
数字人引擎 MCN/直播运营业务 接入费 + 按量
图像/视频生成模型 设计与内容业务升级 按量
电商后台对接 代运营业务 接入费 + 维护
社媒数据源 增长与投放业务 订阅
行业数据库 咨询与报告业务 订阅
  • 接入需要现金投入与维护成本 → 经营决策(不是越多越好)。
  • 某些真单的准入规则会要求特定能力("需已接入数字人引擎")→ 接入决策与订单市场联动。
  • 工程含义:Connector 生态是 Hyprial 的核心平台工程(接入协议、计费、合规),游戏只是它的呈现层。第三方能力提供商未来也是平台上的组织(对称性)。

【玩即生产】:真实的系统对接;公司真实的业务能力扩张。

5.7 资产市场(新增,随 D9 成立)

  • 可交易物:Agent 资产包(训练资产 + 评价史)、题库贡献、【待定】客户关系转介。
  • 交易场景:主动出售(公司战略调整)、破产清算(§5.8)、收购(整个公司连人带 Agent)。
  • 联机含义:玩家与玩家之间真实交易——一个学生调教出的"电商详情页设计 Agent"可以卖给另一个学生的公司。
  • 平台抽佣【待定 D12】——这也是 Hyprial 商业模式里"资产授权抽佣"收入流的游戏内原生形态。
  • 风险预案:防洗钱/刷分(交易双方信用门槛、异常交易审计)。

【玩即生产】:资产的市场定价——Agent 资产第一次拥有可观察的公允价值,这本身是给投资人讲"World Model 厚度即估值"的实证数据。

5.8 破产与生涯系统(新增,D9)

现金归零不是 game over,而是进入清算流程——破产也是真实经营的一部分:

  1. 预警期:现金低于阈值 → 触发事件(孵化器桥贷评估、发单方预付谈判、紧急出售资产)——救助方是真实组织的真实决策,不是系统施舍。
  2. 清算:救助失败 → 资产盘点(Agent 包、题库贡献、应收)→ 挂牌资产市场 → 清偿。
  3. 出路三选:
    - 转卖资产重开:主理人带着出售所得与个人档案,注册新公司;
    - 被收购:其他公司(玩家或组织)整体收购,主理人可选择加入对方(打工线,【待定】);
    - 休整:档案封存,随时回归。
  4. 主理人档案永续:信用、判断力、人脉、技能不清零——"公司可以死,人的资本积累不清零"。二次创业者的档案对孵化器反而更有吸引力(真实世界也如此)。

【玩即生产】:完整的失败经验与复盘记录;资产处置的真实交易。

5.9 教学系统(创业教练 Agent,新增,D13/D14)

竞品调研结论:成熟平台(Capsim/Cesim/MonsoonSIM)的真正壁垒是教学配套——教师控制台、自动复盘、学习证据。本作用 AI 时代的方式重做这一层:教学系统的核心实体是创业教练 Agent,而非管理后台。

教练 Agent 是什么

  • 一个可被雇佣的辅导型 Agent:回答经营问题、生成周复盘、诊断短板("你最近三单都败在报价环节")、赛前特训、路由建议的第二意见。
  • 出品方:平台基础款(保底)、老师工作室出品(老师用自己的方法论调教,是老师的核心资产)、未来第三方(对称性)。
  • 获取方式:学校免费时长配额(学校的第二项生态投入,与算力并列)或学生现金雇佣(高带队指数的教练更贵——真实市场定价)。

带队指数(D14,取代教师认证)

教练(及其背后的老师)的评价采用指数基金式的公开业绩:

带队指数 = 带队组合的超额表现(alpha),同起点分层内的相对提升
  • 必须是 alpha 而非绝对成绩:防止教练只挑好学生(selection bias)——衡量"被带后比同层对照组多进步多少",不是"带的学生名次多高"。
  • 最小样本门槛:带队组合不足 N 家不公布指数,防小样本刷分。
  • 滚动窗口:近 4 个学期加权,近期权重高——教练也要持续进步。
  • 指数公开可查,构成教练市场的定价基础;正式认证体系【待定,后续引入时与协会对接】。

老师的经济模型(开放问题 #3 的解)

老师调教教练 Agent → Agent 被雇佣/被学校采购时长 → 老师获得授权分成;带队指数是老师的公开履历。老师的知识以 Agent 资产形式变现——与平台资产逻辑完全同构,且老师自己每天都在示范"调教即资产"。

教师控制台(保留但降级为工具)

老师仍有班级视图:配置课程命题、看班级数据、导出学习证据(Evidence of Learning)。但日常辅导与复盘由教练 Agent 承担——老师管设计,Agent 管陪伴。

【玩即生产】:个性化复盘记录(学习证据)、教练 Agent 资产(老师的)、教学效果数据(带队指数)。

8. 原型与 Playtest 计划(v0.2 调整)

  1. 纸面原型(1 周):重点跑路由决策手感——用卡牌模拟任务环节 × 资源选项 × 适配度,验证"判断谁来干"是否构成有趣的决策(这是 v0.2 最大的玩法赌注)。
  2. 灰盒(2–3 周):HTML demo 升级:路由界面(替换"选人上阵")、调教之"喂范例"、能力接入商店(3 个 Connector)、破产预警事件。
  3. 对称性 demo(与灰盒并行):做一个最小的孵化器面板(发命题 + 看接单情况)——DHS 会议直接用。
  4. 课堂 playtest:新增观测指标——路由决策的讨论热度(学生会不会争论"这个该不该自己干");破产玩家的情绪与回归率;对抗性练习单的落选者情绪与次周留存(败者价值机制是否真的兜住了体验);教练 Agent 周复盘的阅读率与采纳率。
