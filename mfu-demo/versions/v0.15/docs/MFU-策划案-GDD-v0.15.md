## 1. v0.15 高概念补充

MFU 是面向学校和孵化器的“大学生创新创业课”教具。

学生通过经营一家 AI-native OPC，把课程知识放进持续发生的任务、决策、交付和复盘中。平台记录过程证据，并帮助：

- 学生知道自己已经证明了什么、下一步应练什么；
- 学校比较不同课程是否产生了预期学习成果；
- 孵化器发现潜在 OPC，并发出进一步验证任务；
- 企业和协会提供真实命题、评价与行业认可。

平台不把学生压缩成一个总分，也不自动替孵化器决定谁能入驻。

## 5.10 能力、经验与认可系统

### 5.10.1 四个并列界面

| 界面 | 回答的问题 | 内容 |
|---|---|---|
| 经验履历 | 做过多少、经历过什么 | 订单、打工、作品、人脉、复盘、带队、评审等 |
| 成长树 | 已经被证明能完成什么 | OPC 核心能力、专业能力、公司能力、角色实践能力 |
| 徽章架 | 谁认可了什么 | 信誉等级、专业认证、角色资质、荣誉背书 |
| 功能开放 | 现在能使用哪些平台功能，为什么 | 已开通/待达标功能及其条件 |

任何一个界面都不能替代另外三个。

### 5.10.2 个人 OPC 核心能力

v0.15 使用六项最小能力：

| 能力 | 代表性证据 |
|---|---|
| 机会判断 | 从场景中识别真实问题和可能的市场机会 |
| 客户理解 | 主动澄清需求、约束和验收标准 |
| 方案设计 | 把问题转化为可执行、可验收的方案 |
| 资源编排 | 合理安排本人、成员、Agent 与外部资源 |
| 交付负责 | 控制质量、确认结果并承担最终责任 |
| 复盘迭代 | 根据成败原因改变下一次行动 |

### 5.10.3 专业能力分支

专业领域是分类，不是达标节点。例如：

```text
内容与表达
├─ 图文内容
├─ 视频内容
└─ 长文内容
```

每个专业方向可以根据真实标准形成：

- 基础应用达标；
- 独立交付达标；
- 复杂项目达标。

专业评审、教学带教、方法创新和专业负责是可选高阶分支。

### 5.10.4 公司成长树

公司成长树关注组织能否稳定复用一种经营方式，候选方向包括：

- 稳定交付；
- 多专业协同；
- 提案与获客；
- 方法沉淀与复用；
- 质量管理；
- 合作网络；
- 组织治理。

公司能力不等于成员和 Agent 能力的并集。购买 Agent 或雇佣高手只能获得资源；公司仍需通过流程与结果证明组织能力。

### 5.10.5 角色成长树

取得教练、评审员、孵化平台等角色资质后，平台可以开通相应工作台。角色在真实履职中形成新的能力证据，并进入角色成长树。

以孵化器为例：

```text
取得孵化平台角色资质
→ 平台开通孵化器工作台
→ 执行 Scouting、验证任务、支持方案和投后工作
→ 形成候选判断、支持方案设计、投后管理等能力证据
```

Scouting、grant 和投后面板是工具，不是能力节点。

### 5.10.6 能力状态

| 状态 | 含义 |
|---|---|
| 未开始 | 尚无有效证据 |
| 证据积累中 | 已有证据，但未满足达标标准 |
| 已达标 | 有足够且合格的证据证明该能力 |

成长树节点只命名“已达标”结果，过程进度显示在节点详情或证据卡中。

## 5.11 多学校课程对应统一能力

### 5.11.1 平台与学校的分工

平台统一定义：

- 能力成果；
- 任务难度；
- 评价标准；
- 可接受证据；
- 达标要求。

学校自由定义：

- 课程名称与教学顺序；
- 学分与学时；
- 作业、考试和项目；
- 本校教学方法。

### 5.11.2 多对多关系

一门课程可以覆盖多个能力，多门课程也可以共同证明一项能力。

```text
A 校：建筑设计基础 1 + 建筑设计基础 2 ─┐
                                           ├→ 建筑设计基础应用达标
B 校：建筑设计初级 ──────────────────────┘
```

平台比较的是共同能力成果，不要求不同学校采用相同课程名称或课程数量。

### 5.11.3 学分与学时

学分和学时说明学习投入，不单独证明能力。能力达标至少需要课程覆盖、合格作品/任务评价和必要的综合测评。

v0.15 demo 只展示人工维护的对应关系，跨校审核与版本治理后续设计。

## 5.12 能力证据与贡献归属

每份成果分别写入三类记录：

| 记录 | 关注对象 |
|---|---|
| 公司交付记录 | 最终结果是否完成并通过验收 |
| 个人能力证据 | 学生承担了哪些关键判断与工作 |
| Agent 实战评价 | Agent 完成了什么、质量如何 |

贡献归属使用三种最小标签：

- 学生主导；
- Agent 主导；
- 共同完成。

Agent 主导的高质量成果可以提高公司履历和 Agent 评价，但不能自动证明学生具备相同专业能力。学生正确选择 Agent、定义验收并承担结果，可以形成资源编排与交付负责证据。

## 5.13 平台功能开放规则

平台功能独立维护“谁在什么条件下可以做什么”。

| 功能 | v0.15 示意条件 |
|---|---|
| 联合竞标 | 白银信誉 + 两个专业方向独立交付达标 + 无严重违约 |
| Agent 资产出租 | 白银信誉 + 公司方法沉淀/质量管理达标 + Agent 有评价史 |
| 公开评审 | 对应领域复杂项目达标 + 专业认证 + 评审员资质 |
| 孵化器工作台 | 孵化平台角色资质 + 平台开通 |

统一用语：

- 达标：能力证据满足标准；
- 获证：正式取得认证或资质；
- 有资格申请：达到门槛但关系未成立；
- 加入：会籍关系成立；
- 开通：平台功能可用；
- 受邀：真人作出选择。

## 5.14 OPC 候选档案与筛选

### 5.14.1 候选档案

候选档案最少展示：

- OPC 核心成长树；
- 专业方向；
- 经验与履约记录；
- 信誉等级；
- 专业认证与角色资质；
- 代表性证据和贡献归属；
- 尚未验证的风险；
- 建议的下一道验证任务。

不生成统一 OPC 总分。

### 5.14.2 孵化器筛选

```text
能力档案 + 经验履历 + 信誉与认证
→ Scouting 发现候选人
→ 孵化器查看证据
→ 发出高难度验证任务
→ 真人评估
→ 发出入驻邀请
```

黄金信誉只会加强关注信号，不自动触发入驻。最终决定属于孵化器。
