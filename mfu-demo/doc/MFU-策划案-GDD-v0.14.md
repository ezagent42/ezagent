## 5.10 科技树系统（新增）

> 📖 本节内容的持续迭代见 `doc/tree/skill-tree.md`（living doc，成长树单一事实源）。本节为 v0.14 版本快照，不再回改。
> 设计原则来源：GDKeys「7 Keys to Meaningful Skill Trees」——Committing Choice / Self-Expression / Gameplay Transformation / Balanced Size / Respec at Cost / Post-Game Completion / Innovation。
> 核心判定工具：The Verb Rule —— 每个节点的描述中放一个独特动词。如果动词在整棵树上只出现一次，大概率是好节点。
> 过程原则来源：Medium「Game Design Is Easy」——先做廉价草稿再迭代、匹配游戏特征（MFU：异步、回合制、可仔细阅读）、用 sprint 驱动。

### 5.10.1 核心模型

```
学分（课程培训 + 亲自交付）+ 资格认证（禀赋）
        ↓
解锁科技树节点
        ↓
获得新动词（改变与游戏世界的交互方式）+ 解锁功能模块/视角
```

**与 D28「三棵成长树」的关系**：

| D28 原模型 | 在科技树中的位置 |
|-----------|----------------|
| 人的树（技能连续 + 角色资格离散） | **左侧信息面板**：当前技能值、学分积累、资格认证状态。不独立成树——它们**是**科技树节点的解锁条件 |
| 企业资质树（发单→开公会→教练→…） | **Tier 2b–3b**（资质门 + 角色分叉） |
| 企业业务树（Agent×Connector×案例数） | **Tier 1–2**（专精分叉 + 深化） |

### 5.10.3 节点详细定义

| ID | 节点名 | 层级 | 解锁条件 | 给的动词 | 改变了什么 |
|----|--------|------|---------|---------|-----------|
| N0 | 公司注册 | T0 | 进入游戏 | **注册** | 获得公司实体、基础面板（Agent/订单/现金流） |
| N1 | 设计专精 | T1 | 完成 5 单设计练习单 | **调教** | 设计 Agent 训练时范例库解锁、设计命题适配星级更准确 |
| N2 | 文案专精 | T1 | 完成 5 单文案练习单 | **编写** | 文案 Agent 可使用品牌语气模板、模板可保存和复用 |
| N3 | 增长专精 | T1 | 完成 5 单增长练习单 | **投放** | 解锁 A/B 测试模拟器（同时跑两组投放策略、取优） |
| N4 | 设计提案 | T2 | N1 + 3 单设计真单 | **提案** | 可主动向孵化器发起设计提案，不等命题发布（反向 pitch） |
| N5 | 品牌模板 | T2 | N2 + 3 单文案真单 | **复用** | 品牌文案可保存为模板、在资产市场出售/license 给其他 OPC |
| N6 | A/B 实验 | T2 | N3 + 3 单增长真单 | **实验** | 同一命题可提交两套方案、取评审更优者（风险对冲） |
| N7 | 白银认证 | T2b | 声望 ≥ 30 + 信用 ≥ 70 | **入会** | 解锁预备营/协会会籍、真单准入、孵化器 Scouting 开始追踪 |
| N8 | 联合竞标 | T3 | N7 + 至少 2 条线到 T1 | **联合** | 可邀请其他 OPC 组队竞标复杂命题（2–3 家合投、共享奖金） |
| N9 | 资产出租 | T3 | N7 + 任一 T2 节点 | **出租** | 训练好的 Agent 可授权其他 OPC 使用、按周收取 license 费 |
| N10 | 公开评审 | T3 | N7 + 作品集 ≥ 10 | **评审** | 可对其他 OPC 的交付物发起公开评审、评审记录计入评审员资格积累 |
| N11 | 黄金认证 | T3b | 声望 ≥ 85 + 真单均分 ≥ 74 | **入驻** | 孵化器入驻邀请解锁（孵化器人做最终决策，系统不自动触发） |

| N13 | 孵化认证 | T3b | 孵化平台授予（外部资质） | **孵化** | 解锁场地运营视图：命题管理、Scouting 配置、投后面板、入驻管线 |

### 5.10.4 科技树的 7 条 GDKeys 原则如何落地

| 原则 | 在 MFU 树中的实现 |
|------|-----------------|
| **1. Committing Choice** | T1 专精一旦选择，该线享受「专精效率加成」（该领域 Agent 训练速度 +30%）。学生可解锁多条 T1 线，但**同一时间仅一条线获得效率加成**。切换激活线 = 2 周冷却（Agent 需要适应新方向）。已解锁节点永久保留 |
| **2. Self-Expression** | 不同专精路径的学生获得不同的**徽章和标识**（而非平台改变其官网外观）。例如设计专精学生获得「🎨 设计新秀」徽章，增长专精获得「📈 增长黑客」徽章。徽章出现在公司黄页和个人档案中。解锁 T2/T3 节点会获得更稀有的标识 |
| **3. Gameplay Transformation** | 每个节点新增一个**动词**（右列「改变了什么」）。没有纯数值节点（「Agent 能力 +5%」）。N4「提案」让学生从「被动的接单者」变成「主动的 pitch 方」——这是玩法质变 |
| **4. Balanced Size** | ~15 节点、3 层深。一学期（18 周）内一般解锁 6–10 个。不造成选择瘫痪 |
| **5. Respec at Cost** | 切换激活的专精线 = 2 周冷却。已解锁节点**不回退**、已训练 Agent **不降级**（旧 Agent 保持能力但不再享受专精效率加成）。成本是时间，不是损失 |
| **6. Post-Game Completion** | 入驻孵化器（N11）后，学生可以回头解锁之前跳过的分支——不是因为「要补课」，而是因为被投企业的业务需求可能要求新能力（例如设计起家的公司现在需要增长投放） |
| **7. Innovation** | MFU 的树不抄 RPG「花技能点」模板。解锁靠**真实积累**（学分 + 认证），不靠升级获得的点数。树结构公开但解锁路径由市场（命题供给/会籍需求）决定价值——不是系统预设「最优路径」 |

### 5.10.5 打工 vs 学分的区分

| | 打工（Gig） | 亲自交付（Route to Self） | 课程培训（School Training） |
|---|---|---|---|
| **给现金？** | ✅ 工资 | ❌（消耗 AP） | ❌ |
| **给经验（skill 微增）？** | ✅ 少量（+0.3/demo 单元） | ✅ 显著（+0.5/demo 单元） | ✅ 最大（结构化） |
| **给学分（推进科技树）？** | ❌ | ⚠️ 间接（高判断力 = 学分认可的前提） | ✅ 直接 |
| **给认证？** | ❌ | ⚠️ 构成作品集 | ✅ 构成考试/评估依据 |
| **给网络？** | ✅（认识雇主） | ❌ | ❌ |

**设计含义**：打工是**生存手段**（缺钱 → 打工 → 回血），不是成长手段。学生的核心成长（解锁科技树）依赖学分积累，学分来自课程培训和亲自交付的质量。这对应现实：兼职打工给你钱，但不给你学位。

**不新增第 5 个 tab**。理由：
- 现有 4 tab（办公室/订单/市场/生态）+ ERP 弹窗 sub-tab 结构已经覆盖成长树的访问路径
- 学生查看成长树属于「偶尔参考」——不需要常驻 tab。ERP 弹窗 + 头像按钮已提供两个足够的入口
- 减少导航改动风险——学生已经知道去哪里看自己的档案和企业状态

**树的可视化方式**（Demo 实现原则）：
- 已解锁节点：亮色 + 实线粗边框 + 动词标签 + 使用统计（「已提案 2 次，1 次被接受」）
- 下一个可解锁节点：黄色闪烁边框 + 「差 2 单设计练习单」提示
- 锁定节点：灰色 + 虚线边框。**显示解锁条件但不显示节点名**——学生知道这里有东西、知道达成什么条件能解锁，但不知道具体会获得什么能力（平衡 Achiever 需要方向和 Explorer 需要惊喜）
- 节点之间的连线用粗实线（已解锁）或虚线（未解锁）
- 点击任意节点 → 小弹窗展示详情

### 5.10.7 树的公开性与 ezagent 组织

- 树的结构（有哪些节点、依赖关系）对**所有登录用户公开**
- 每个节点的**解锁状态**对**所有登录用户公开**（D28：「树位置对外公开」）
- 这意味着：学生可以看到其他 OPC 的科技树解锁进度、可以看到 ezagent 团队的完整科技树（含 N14 平台运营）
- 用途：（1）野心机制——看到别人解锁了你没有的节点；（2）信任机制——孵化器看到 ezagent 的资质树完整；（3）竞争情报——了解对手的能力边界

**ezagent 团队在游戏世界中的存在**：
- 作为黄页上一个可见组织：「🦄 Ezagent 平台团队」——拥有 N14 平台运营认证
- 其科技树完整展示（作为参考/野心机制）
- 其官网展示 world.cup（目标面板）：当前 PR = 树上的目标节点，已关闭 PR = 已解锁的历史节点
- 可发布命题、可接单——与其他 OPC 行为一致（对称性原则 D5）

## 9. 开放问题（v0.14 新增）

9. **科技树泛化为「目标树」的边界**：ezagent 团队在 world.cup 中把每个 PR 视为技能树的 branch——完成 PR = 解锁节点。如果这个模式推广到所有组织（任何组织都可以自定义目标、完成后变成树上的永久节点），树就从「系统设计的内容」变成了「用户生成的内容」。这会不会让树失去 progression 骨架的清晰性？是否需要区分「系统预设节点」（不可自定义）和「组织目标节点」（可自定义、有时效性）？

10. **专精效率加成的数值**：T1 专精线激活后的「+30% 训练效率」是示例数值。实际数值需要 playtest 确定——太低则专精无感，太高则跨专精无意义。

11. **N12 教练认证的「带队 5 家」在单机 demo 中如何测试**：当前 demo 的对手是随机生成的 NPC，不存在真实的「带其他学生」场景。教练认证在单机版中可能需要替代触发条件（例如「完成 10 次教练诊断且采纳后交付质量提升」），联机版再切换到真实带队数据。

12. **【待定 D34】企业科技树是否 = 所有成员（含 Agent）个人科技树的并集？**：当前设计中个人成长树（主理人档案）和企业成长树（ERP）是分开的。一个值得探索的方向：企业的树 = 主理人 + 成员 + Agent 各自已解锁节点的并集。例如：公司雇佣了一个已解锁「设计提案（N4）」的设计 Agent → 公司自动获得该节点的能力。这会让招聘/资产购买决策直接影响公司的科技树——更有策略深度。但也可能让个人树的积累失去独特性。**先记作开放问题，v0.14 暂不实现**。
