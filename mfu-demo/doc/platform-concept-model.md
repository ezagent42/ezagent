# MFU 平台概念模型（living doc）

> 状态：持续迭代
> 建立：2026-07-28
> 适用范围：MFU（My First Unicorn）课程、demo、能力档案、认证、学校接入与孵化器筛选
> 规则：平台概念、概念边界或概念关系发生变化时，必须先修改本文。GDD 与 infographic 是版本快照，不回改。

## 0. 本文解决什么问题

MFU 过去用“成长树”和“解锁”两个词同时表达经验、技能、认证、会籍、角色与平台功能，导致以下概念被混在一起：

- 做过多少与做得多好；
- 学会了什么与平台允许做什么；
- 获得认证与加入一个组织；
- 达到候选门槛与被孵化器正式选中；
- 学生本人的能力、公司的能力和 Agent 的能力。

本文建立平台统一语言，并回答五个问题：

1. 平台正在帮助谁成长；
2. 什么事实可以证明成长；
3. 学校不同课程如何对应同一套能力标准；
4. 信誉、认证和角色资质分别代表什么；
5. 孵化器如何依据证据发现并验证潜在 OPC。

---

## 1. 平台定位

MFU 是面向学校与孵化器的“大学生创新创业课”教具。

学生不是通过填写一份静态测评来证明自己，而是在经营一家 AI-native 模拟公司（OPC）的过程中：

- 发现与理解需求；
- 编排本人、人类成员、Agent 与外部资源；
- 完成课程任务、模拟项目和真实命题；
- 接受教师、企业、协会和孵化器的评价；
- 积累可追溯的能力证据、经营履历与信用记录；
- 最终被真实孵化器发现，并通过额外验证后获得入驻邀请。

平台不替学校完成教学设计，也不替孵化器作最终录取决定。平台提供共同能力标准、实践环境、证据档案和筛选工具。

### 1.1 五方角色

| 角色 | 在平台中的主要责任 |
|---|---|
| 学生 | 学习、经营 OPC、完成任务、形成个人能力证据 |
| 学校 | 设计课程、提供教学资源、组织评价、观察教学效果 |
| 老师/教练 | 出题、辅导、评价、帮助学生根据能力缺口继续学习 |
| 孵化器 | 提供真实命题、发现候选人、发出验证任务、作出入驻决定 |
| 协会/评价机构 | 提供行业评价、信誉等级、专业认证或角色资质 |

## 2. 成长主体与归属

### 2.1 人（主理人）

人拥有：

- 个人经验；
- 个人能力；
- 专业认证；
- 角色资质；
- 荣誉与背书；
- 跨公司保留的能力证据和生涯档案。

公司失败、清算或更换不清除个人档案。

### 2.2 公司（OPC/组织）

公司拥有：

- 订单与履约经验；
- 公司声望与信用；
- 组织能力；
- 公司资产；
- 公司获得的信誉等级、资质与会籍；
- 公司可使用的平台功能。

公司能力不是主理人个人能力与 Agent 能力的简单相加。只有当流程、资产和协作方式能够被公司稳定复用时，才形成组织能力。

### 2.3 Agent

Agent 是人或公司的资产，不是独立成长主体，不设置能力树。

Agent 使用以下方式表达成长：

- 能力分；
- 训练资产；
- 实战评价史；
- 里程碑徽章；
- 版本与归属记录。

购买一个强 Agent 不等于购买了主理人的个人能力。

### 2.4 0 号 Agent（小 H）

小 H 跟随个人档案，保存偏好、复盘和长期陪伴信息。它属于个人资产，但它的能力仍不计入个人能力。

## 3. 核心概念

### 3.1 行为记录

行为记录是“发生过什么”的事实，例如：

- 打工次数；
- 完成订单数；
- 作品数；
- 人脉数；
- 复盘数；
- 评审次数；
- 带队次数。

行为数量只能证明参与和活跃，不能单独证明能力水平。

### 3.2 经验

经验是行为记录形成的履历，回答：

> 这个人或组织在平台上做过多少事、接触过多少情境？

经验以计数、进度条、时间线和案例列表呈现。经验不直接使能力达标，但可以：

- 为能力评价提供样本；
- 形成履约记录；
- 影响声望和信用；
- 帮助客户判断响应速度与熟练程度。

### 3.3 能力证据

能力证据是经过评价、能够说明某项能力水平的材料，例如：

- 课程作业及评分；
- 情境测评结果；
- 独立项目及验收结果；
- 复杂命题及多轮修改记录；
- 竞赛评级；
- 专家作品评价；
- 平台外证书或奖项；
- 失败后的复盘与下一次改进结果。

作品数量属于经验；经过评价的具体作品才可能成为能力证据。

### 3.4 能力

能力回答：

> 这个人或组织已经被证明能够完成什么？

能力必须满足三个条件：

1. 离开 MFU 平台后仍然存在；
2. 可以通过任务、作品、考试或专业评价证明；
3. 表达可观察的结果，而不是学习进行中的状态。

“A/B 测试器”“联合竞标按钮”不是能力；背后的“实验验证”“协作与资源组合”才是能力。

### 3.5 声望与信用

| 概念 | 回答的问题 | 主要依据 |
|---|---|---|
| 声望 | 市场是否看见并认可这个人/组织 | 公开成绩、竞赛、评价、影响力 |
| 信用 | 是否值得相信其会履行承诺 | 履约、违约、响应、责任记录 |

声望与信用不是专业能力。大量交付可以带来高经验和高信誉，但不自动证明高水平专业能力。

### 3.6 信誉等级

青铜、白银、黄金属于信誉等级，表达平台市场中的活跃度、可靠性与公开认可。

信誉等级：

- 可以由协会或平台规则颁发；
- 可以作为会籍、订单或功能开通条件；
- 不作为专业能力节点；
- 不自动等于孵化器入驻。

### 3.7 专业认证

专业认证证明某项专业能力达到规定标准，例如：

- MFU 判断力认证；
- 学校课程认证；
- 专家作品集评级；
- 行业证书；
- 竞赛奖项所证明的专业水平。

判断力认证属于 MFU 课程认证：学生完成至少 5 次路由判断，系统根据结果基准评价，达标率达到 60% 后获得认证。次数保证最低样本，达标率证明能力。

专业认证是能力证据之一，不等于能力本身。同一能力可以由不同证据组合证明。

### 3.8 角色资质

角色资质证明个人或组织被允许承担高责任角色，例如：

- 评审员资质；
- 教练资质；
- 孵化平台资质；
- 平台运营授权。

角色资质通常同时要求专业能力、实践经验、信誉和人工审核。取得资质后可以申请或开通相应工作台，但资质本身不进入成长树。

### 3.9 荣誉与背书

荣誉与背书表达社会认可，例如：

- 孵化器背书；
- 比赛冠军；
- 优秀团队；
- 机构推荐。

荣誉默认只用于展示；只有规则明确规定时，才参与功能开放判断。

### 3.10 会籍

会籍是人与组织之间已经成立的关系，例如：

- 学校学籍；
- 孵化器预备营；
- 协会会员；
- 孵化器入驻会籍。

“有资格申请”“已经申请”“获准加入”是三个不同状态。

### 3.11 平台功能

平台功能是 MFU/ezagent 提供的具体操作，例如：

- 联合竞标；
- Agent 资产出租；
- 公开评审；
- A/B 测试模拟器；
- 教练工作台；
- 孵化器 Scouting、grant 与投后管理。

功能依赖平台实现，因此不作为能力节点。功能可以读取能力、信誉等级、专业认证、角色资质、会籍、风险状态和人工审批结果。

### 3.12 功能开放规则

功能开放规则回答：

> 谁在什么条件下可以做什么？

示例：

```text
联合竞标可用
= 公司达到白银信誉
+ 至少两个专业方向具备独立交付能力
+ 当前没有严重违约
```

```text
公开评审可用
= 对应领域能力已达标
+ 获得评审员角色资质
```

```text
孵化器工作台可用
= 组织取得孵化平台角色资质
+ 平台完成开通
```

## 4. 个人能力框架

### 4.1 OPC 核心能力

v0.15 demo 使用六项最小核心能力：

| 能力 | 可观察结果 |
|---|---|
| 机会判断 | 能识别值得解决的问题与可能的市场机会 |
| 客户理解 | 能澄清需求、识别约束并判断真实价值 |
| 方案设计 | 能把问题转化为可执行、可验收的方案 |
| 资源编排 | 能合理安排本人、成员、Agent 与外部资源 |
| 交付负责 | 能定义验收标准、控制质量并为结果负责 |
| 复盘迭代 | 能从结果中提取原因并改变下一轮行动 |

后续可以增加商业判断、协作沟通、风险与伦理等能力，但 v0.15 不扩张节点数量。

### 4.2 专业能力方向

专业能力允许并行与放射状发展，例如：

```text
内容与表达（领域，不是达标节点）
├─ 图文内容
├─ 视频内容
└─ 长文内容
```

其他候选领域包括创意与设计、市场与增长、产品与技术及行业专项能力。领域名称用于分类，只有可评价的成果才成为节点。

### 4.3 能力达标层次

成长树不显示“学习中”这类过程节点。v0.15 使用三类达标标准：

#### 基础应用达标

在要求明确、范围有限、允许获得指导的任务中，能够正确使用基础方法完成作品。

证据要求：

- 任务被标记为基础难度；
- 使用共同评价标准；
- 核心指标达到最低门槛；
- 有足够样本避免偶然通过。

#### 独立交付达标

面对相对真实的需求，在没有教师代替关键决策的情况下，能够独立完成并通过验收。

证据要求：

- 存在真实或模拟真实的验收标准；
- 学生承担关键判断；
- 成果由合格评价者确认；
- 最好在不同情境中重复达标。

#### 复杂项目达标

能够处理多重约束、不确定信息、需求变化或多方协作的任务。

复杂任务应符合若干共同特征：

- 需求需要主动澄清；
- 多个目标存在冲突；
- 涉及多个专业领域；
- 需要多轮修改；
- 需要与客户或队友协调；
- 没有唯一标准答案；
- 结果接受真实用户或市场检验。

任务发布者不能仅靠自行标注使任务变成“复杂任务”；任务必须符合平台复杂度标准，成果仍需通过评价。

### 4.4 高阶分支

“专业评审”“教学带教”“方法创新”“专业负责”不是所有能力共同的第四等级。它们是复杂项目达标后可能出现的不同分支，并使用各自评价方式。

## 5. 多学校课程如何对应统一能力

### 5.1 两层结构

#### 平台统一能力标准

平台统一定义：

- 能力领域；
- 可观察的能力成果；
- 任务难度；
- 评价标准；
- 可接受的证据；
- 达标要求。

#### 学校课程

学校自由定义：

- 课程名称；
- 教学内容；
- 教学顺序；
- 学分与学时；
- 作业、考试和项目；
- 本校评价安排。

学校课程不直接等于平台能力节点。

### 5.2 多对多对应

平台允许：

- 一门课程对应多个能力；
- 多门课程共同证明一项能力；
- 不同学校用不同课程组合达到同一能力；
- 平台外课程与证书对应平台能力。

示例：

```text
A 校：建筑设计基础 1 + 建筑设计基础 2
                         └──→ 建筑设计基础应用达标

B 校：建筑设计初级
                         └──→ 建筑设计基础应用达标
```

### 5.3 学分与学时

学分和学时说明学习投入与课程完成情况，不单独证明能力。

```text
课程覆盖范围
+ 学习投入
+ 作业/项目评价
+ 必要的综合测评
= 能力是否达标
```

v0.15 demo 只展示人工维护的“课程 → 平台能力 → 评价任务”对应表。审核、版本与跨校校准机制留待后续。

## 6. 证据归属：学生、Agent 与公司

每份成果至少标记一种贡献方式：

| 标记 | 含义 | 对个人能力的作用 |
|---|---|---|
| 学生主导 | 学生作出关键判断并完成主要工作 | 可以形成对应个人能力证据 |
| Agent 主导 | Agent 完成主要判断与执行，学生仅确认 | 主要进入公司履历和 Agent 评价 |
| 共同完成 | 学生与 Agent/成员分别承担关键部分 | 按记录的个人贡献形成部分能力证据 |

同一成果可以同时产生不同记录：

- 最终作品质量 → 公司交付记录；
- 学生的任务拆解与路由 → 资源编排证据；
- Agent 的执行结果 → Agent 实战评价；
- 学生最终验收与担责 → 交付负责证据。

## 7. 三类成长树

采用多图结构，但每类图只表达一种成长。

### 7.1 个人成长树

展示学生已经证明的 OPC 核心能力与专业能力。节点全部表示“已达标结果”。

### 7.2 公司成长树

展示公司形成的稳定组织能力，例如：

- 稳定交付；
- 多专业协同；
- 提案与获客；
- 方法沉淀与复用；
- 质量管理；
- 合作网络；
- 组织治理。

具体平台按钮不作为节点。

### 7.3 角色成长树

个人或组织先取得角色资质并开通工作台，然后在真实履职中积累角色能力。例如孵化实践可以包括项目筛选、支持方案设计和投后管理。

角色资质本身不在图上。

## 8. OPC 候选档案

候选档案服务孵化器筛选，但不替孵化器作决定。

v0.15 最小档案包括：

- OPC 核心成长树；
- 专业方向；
- 经验与履约记录；
- 信誉等级；
- 专业认证与角色资质；
- 代表性证据及贡献归属；
- 尚未验证的能力缺口；
- 建议的下一道验证任务。

平台不生成一个统一“OPC 总分”。不同孵化器可以依据自己的方向使用同一份证据作不同判断。

黄金信誉或其他门槛只能使候选人“值得关注”，不能自动产生入驻邀请。正式入驻必须经过孵化器真人判断和验证任务。

## 9. 三个闭环

### 9.1 学习闭环

```text
学校课程
→ 学生完成任务
→ 获得评价与反馈
→ 积累能力证据
→ 能力达标
→ 推荐下一门课程或任务
```

### 9.2 经营闭环

```text
学生经营 OPC
→ 编排本人、成员、Agent 与外部资源
→ 完成模拟或真实任务
→ 分别形成个人证据、公司履历与 Agent 资产
→ 获得新的市场机会
```

### 9.3 筛选闭环

```text
能力档案 + 经验履历 + 信誉与认证
→ 孵化器发现候选人
→ 发出高难度验证任务
→ 真人评估
→ 发出入驻邀请
```

## 10. 统一用语

以后不再笼统使用“解锁”，应按实际事件使用：

| 用语 | 准确定义 |
|---|---|
| 达标 | 能力证据满足标准 |
| 获证 | 正式取得认证或资质 |
| 有资格申请 | 满足申请门槛，但关系尚未成立 |
| 加入 | 会籍关系成立 |
| 开通 | 平台功能已经可以使用 |
| 受邀 | 学校、孵化器或其他真人作出选择 |

“成长树”是平台正式产品名称；“技能树/科技树”只用于描述历史版本。成长树承载能力成长，但不承载经验、认证或平台功能。

## 11. v0.15 功能开放示例

| 平台功能 | 能力要求 | 信誉/认证要求 | 其他要求 |
|---|---|---|---|
| 联合竞标 | 两个专业方向达到独立交付 | 白银信誉 | 无严重违约 |
| Agent 资产出租 | 公司形成方法沉淀与质量管理能力 | 白银信誉 | Agent 有可展示评价史 |
| 公开评审 | 对应领域复杂项目达标 | 专业认证 + 评审员资质 | 评审记录可审计 |
| 孵化器工作台 | — | 孵化平台角色资质 | 平台完成开通 |

本表用于解释概念关系，不代表 v0.15 单机 demo 必须完整实现联机业务。

## 12. 状态与后续治理

### 已确认

- 经验、能力、认证与平台功能分离；
- 能力采用宽领域与可评价成果，不把细碎工具作为节点；
- 成长树允许进阶、放射、汇合与交叉；
- 信誉等级、专业认证、角色资质、荣誉背书是不同概念；
- 平台功能由独立规则开通；
- 平台统一能力标准，学校自由设计课程并建立多对多对应；
- 学分与学时不直接证明能力；
- 学生、Agent 和共同完成必须区分；
- 候选档案不使用单一 OPC 总分；
- 孵化器作最终筛选决定。

### v0.15 demo 简化

- 使用六项 OPC 核心能力；
- 使用人工课程对应表示意；
- 使用三种贡献归属；
- 使用示例性功能开放规则；
- 不实现跨校审核、评价者校准和完整防刷机制。

### 后续治理

- 能力标准与课程对应关系的审核、版本和撤销；
- 评价者资格与跨校评分校准；
- 任务难度审核；
- 证据防刷、小样本和异常行为识别；
- 学生授权、隐私、申诉和档案携带；
- 专业认证与角色资质的有效期、暂停和撤销。
