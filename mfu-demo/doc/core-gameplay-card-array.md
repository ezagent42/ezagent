## 0. 为什么重新定义核心玩法

当前 Demo 承担了经营、成长、认证、市场、孵化和教学等大量意义，功能较为完整，但玩家和 Pitch audience 很难迅速说出“MFU 最独特、最常重复的一件事是什么”。

MFU 真正的差异化不是普通的“赚钱—升级—扩大公司”，而是：

- 玩家可以被动连接到别人，在一个大项目中完成自己的一小步；
- 玩家也可以主动连接上下游，把一次协作变成长期组织，共同承担更大的完整价值。

因此，游戏最重要的玩法应当直接表现“连接如何产生价值”，其他系统围绕它服务。

## 1. 一句话核心玩法

> 面对一个任务，玩家用自己能够调动的人、AI 和外部伙伴组成一套协作卡牌阵列；阵列产出交付物后，玩家根据结果调整连接方式、卡牌组合和单张卡牌的能力。

这里的“卡牌”不是攻击牌或一次性技能，而是一个能够参与真实交付的能力主体。
“阵列”也不是简单的卡牌列表，而是带有先后、并行、输入、输出和检查关系的协作结构。

## 2. 所有角色共用同一种玩法

平台上的角色面对的任务规模不同，但都进行同一种核心操作：**为任务组织一套自己能够操作的卡牌阵列。**

| 玩家身份 | 面对的任务 | 可以放入阵列的卡牌 |
|---|---|---|
| 拆单方（协会、孵化器或课程团队） | 一个需要完整交付的大订单 | 自己能够邀请的 OPC |
| OPC 主理人 | 分配给自己的订单或步骤 | 本人、自己的 Agent、成员，以及受邀或租用的外部能力 |
| 独立猎人 | 一个具体步骤或子任务 | 本人、自己的 Agent，以及受邀或租用的外部能力 |

同一个结构可以逐层展开：

```text
完整订单
└── OPC 协作阵列
    ├── OPC A
    │   └── 人 + Agent + 外部伙伴阵列
    ├── OPC B
    │   └── 人 + Agent 阵列
    └── OPC C
        └── 人 + 外部伙伴阵列
```

第一版不必一次展示全部嵌套层级。玩家当前负责哪一层，就只操作和查看该层；需要了解某张 OPC 卡如何工作时，再进入它的内部阵列。

## 3. 卡牌代表什么

每张卡牌至少回答五件事：

1. 它是谁：本人、Agent、成员、外部猎人或 OPC；
2. 它能做什么：已经由证据证明的能力；
3. 它现在能否参与：档期、时间、算力或使用权限；
4. 调用它需要什么：本人时间、算力、费用或合作邀请；
5. 它过去做得怎样：相关作品、评价、履约记录和协作记录。

经验、成长树、声望、信用和认证继续存在，但不再与核心玩法平行争夺注意力，而是成为玩家选择卡牌时看到的依据：

| 概念 | 在卡牌玩法中的作用 |
|---|---|
| 经验 | 说明这张卡做过多少相关实践 |
| 成长树 | 说明这张卡已经证明能完成什么 |
| 声望与信用 | 影响别人是否愿意接受合作，以及发单方是否信任这套阵列 |
| 认证 | 证明特定专业能力或高责任角色资格 |
| 资产 | 记录 Agent、方法、流程和作品如何持续积累 |

这些数据不能被压缩成一个决定胜负的“总战力”。玩家必须根据任务位置和真实证据作出判断。

## 4. 卡牌连接代表什么

卡牌之间的连线代表实际协作关系，而不是装饰：

- 谁为谁提供输入；
- 谁等待谁完成后才能开始；
- 哪些工作能够并行；
- 谁负责检查谁的结果；
- 谁把多个局部成果汇总为完整交付；
- 谁对最终结果承担责任。

因此，相同的卡牌采用不同排列和连接方式，也可能产生不同结果。

阵列需要让玩家一眼看出：

- 当前任务如何被分成多个位置；
- 自己处在完整任务的哪里；
- 哪些上下游会受到自己的影响；
- 哪条连接可能导致等待、误解或返工；
- 最终交付如何从整个阵列中产生。

## 5. 两种连接方式

### 5.1 被动连接：在大项目中发挥小价值

平台或拆单方把完整订单设计成协作阵列，并将其中一个位置匹配给玩家。

玩家只需对自己的位置负责，但可以看到自己在完整阵列中的大概位置、上下游输入输出以及同单协作者。这样，尚不能负责完整订单的学生也可以参与真实复杂项目，并理解自己的小价值如何进入最终交付。

### 5.2 主动连接：和别人形成组织，发挥大价值

玩家在真实协作中认识上下游后，可以主动邀请合适的人长期合作。

已确认规则：

> 把别人的 OPC 或真人猎人卡放进阵列，不代表玩家可以直接调用对方，而是发出一份合作邀请。只有对方真人接受后，该卡牌和连接才会生效。

Agent 作为人或公司的资产，可以由其所有者安排；Agent 自己不能主动邀请别人、接受长期合作或成立组织。

当多名玩家反复协作并共同确认关系后，一次性的任务阵列可以沉淀为可重复使用的组织阵列。玩家由“大项目中的一张卡”，逐渐成长为“能够组织一组卡的人”。

## 6. 核心游戏循环

```text
收到任务
→ 看懂目标和约束
→ 把任务变成若干位置
→ 放入自己能够调动的卡牌
→ 连接上下游并确认责任
→ 阵列开始工作
→ 产出真实或模拟交付物
→ 检查交付结果与过程反馈
→ 调整阵列、卡牌组合或单卡能力
→ 再次挑战
```

第一轮体验必须让玩家完整经历这个循环，而不是先学习所有平台概念。

## 7. 可玩性从哪里来

如果玩法只是“选择几张高分卡，再自动计算一个总分”，玩家很快会找到固定最优组合。阵列设计必须带来真实取舍：

### 7.1 任务位置不同

理解需求、提出方案、制作、验证和最终检查需要不同能力。能力很强的卡放在错误位置，也可能带来差的结果。

### 7.2 资源有限

玩家不能同时使用所有好牌。本人时间、Agent 算力、预算、档期和外部合作成本共同限制阵列。

### 7.3 执行方式有不同风险

- 本人更了解背景，但时间有限；
- Agent 速度快、可积累训练资产，但可能误解或需要检查；
- 外部猎人拥有缺失能力，但需要邀请、沟通、等待和费用；
- 长期伙伴配合更稳定，但也需要维护关系。

### 7.4 连接方式影响结果

并行能够提速，但接口不清容易返工；串行更容易保持一致，但可能错过截止时间；增加检查节点能提高质量，但会消耗时间和预算。

### 7.5 失败必须可以解释

交付后不能只显示胜负或总分。系统应告诉玩家：

- 是否解决了客户问题；
- 是否按时完成；
- 是否超出预算；
- 哪个环节发生等待或返工；
- 哪张卡或哪条连接可能造成问题；
- 最终产生了什么作品；
- 评价者给出了什么真实反馈。

理想的失败反馈应让玩家能够说：

> “不是我的牌不够强，而是我把缺少判断力的 Agent 放在了最终检查的位置。”

这样玩家才会愿意调整阵列并再次尝试。

## 8. 阵列如何产生长期成长

每次交付后，玩家可以从三个层面优化：

1. **换连接**：改变先后、并行、检查和汇总关系；
2. **换组合**：邀请新的伙伴、租用外部能力或减少不必要的卡；
3. **练单卡**：训练 Agent、改进工作方法，或由本人完成新的能力证明。

作品、流程、路由记录和复盘进入公司资产，使阵列不只是一次解题，而是逐渐变成组织的稳定交付能力。

## 9. 竞标对战的延伸

高级玩法可以采用“同题异解”的对战，而不是让玩家互相攻击：

1. 两个协会或组织面对同一个订单；
2. 双方分别提交自己的 OPC 卡牌阵列；
3. 每个 OPC 再用本人、Agent 和外部能力组成内部阵列；
4. 双方产生真实或模拟交付物；
5. 企业、专家或大众依据公开标准评审；
6. 中标结果和评语回流到卡牌、阵列与组织档案。

这种玩法能够直观比较：

- 两套组织如何拆解同一个问题；
- 人和 AI 如何采用不同分工；
- 哪套阵列更快、更稳或更有创意；
- 为什么最终交付不同。

竞标应当作为核心循环成立之后的高级模式。第一版先证明：

> 一个任务 → 组成一个小阵列 → 产生交付 → 找到问题 → 调整阵列。

## 10. 初步可行性判断

### 有利条件

- 一个“组阵列”动作可以统一拆单方、OPC 和猎人的操作语言；
- 能直接表现 MFU 的被动连接与主动组建组织；
- 任务、成长、认证、市场和孵化都可以围绕交付阵列重新组织；
- 卡牌和连线具有很强的视觉辨识度，适合游戏演示与 Pitch；
- 阵列可从简单的三张卡逐步扩展到跨组织的大型拓扑。

### 主要风险

1. **把真人工具化**：真人卡必须通过邀请和接受进入阵列，卡面也要表现其意愿与档期；
2. **嵌套过深**：第一版只让玩家操作当前层级，不同时展开协会、OPC 和 Agent 三层；
3. **数值最优解**：不能用单一战力决定结果，需要位置、连接、资源和质量反馈；
4. **自动播放缺少参与感**：阵列运行期间需要出现少量值得玩家处理的接口、风险或检查决策；
5. **教学概念再次膨胀**：第一轮只教“任务—组阵—交付—调整”，其他概念在用到时再解释；
6. **真实评价成本高**：模拟任务可以自动给过程反馈，真实订单则需要客户、老师或专家完成最终评价。

## 11. 当前已确认的方向

- MFU 的核心差异是“通过连接共同创造价值”；
- 所有玩家共用“面对任务，给出可操作的卡牌组合阵列”这一核心动作；
- 卡牌可以代表本人、Agent、外部伙伴或 OPC，具体范围取决于玩家当前身份；
- 卡牌之间的连接关系会影响交付过程与结果；
- 阵列最终产生可查看和可评价的交付物；
- 玩家根据交付结果优化连接、组合和单卡能力；
- 使用别人的真人或 OPC 卡必须发出邀请，并由对方真人接受；
- 协会竞标可以成为“阵列对阵阵列”的高级玩法；
- 第一版先验证单层、小规模阵列的核心循环。

## 12. v0.1 最小 Demo 的目标

v0.1 不负责证明整个 MFU 平台，只验证一件事：

> 一个不了解 MFU 的人，能否通过亲手组建两次阵列，理解自己如何从“大项目中的一张卡”，成长为“能够连接一组卡的人”。

预计完整体验时间为 5–8 分钟。其他真人猎人由系统扮演，合作邀请会模拟对方接受；页面必须明确说明正式平台需要真人确认。

## 13. v0.1 两幕体验

### 13.1 第一幕：被动连接，发挥小价值

1. 玩家“小满”被平台匹配到“旧书店开学推广项目”中的“增长验证”步骤；
2. 页面先展示完整项目阵列，包括视觉猎人、内容猎人、小满和最终整合者；
3. 小满只操作自己的三格任务棋盘：

```text
理解实验目标 → 制作实验素材 → 检查并提交
```

4. 第一幕只有“本人小满”和“Agent 小角”两张可用卡；
5. 玩家把卡拖入三个任务位置，并选择串行、并行或检查关系；
6. 阵列运行中出现一次“客户要求存在歧义”的情况；
7. 玩家决定让 Agent 自行继续、由本人花时间确认，或询问上游猎人；
8. 完成后，玩家看到自己的小交付如何进入完整项目，并获得可解释的结果反馈。

第一幕的结果应当“可以完成，但明显存在改进空间”，避免新玩家第一次尝试就彻底失败。

### 13.2 第二幕：主动连接，组成更大价值

1. 项目完成后，玩家看到本次合作的上下游：视觉猎人“纸飞机”和内容猎人“长尾巴”；
2. 玩家向二人发出长期合作邀请；
3. Demo 模拟两名真人猎人接受邀请，并明确标注这一步在正式平台中需要真人确认；
4. 三张真人卡形成一个新组织的基础牌组；
5. 系统给出一份更完整的小订单；
6. 玩家第一次以组织者身份，把三名猎人放入新的任务棋盘，再为自己的位置安排本人和 Agent；
7. 新阵列运行并产生一份完整交付物。

结尾只强调一次清晰的身份变化：

> 上一单，你完成了大项目中的一步；这一单，你连接了三个人，共同完成了一份完整订单。

## 14. v0.1 的四种玩家操作

### 14.1 看任务位置

棋盘先出现三个清晰的位置。每个位置说明需要什么输入、要产生什么结果。

### 14.2 拖入卡牌

玩家把本人、Agent 或已接受邀请的真人猎人拖进合适的位置。一张卡可以承担多个位置，但会消耗更多时间或算力。除拖放外，页面还应提供点击选择作为备用操作。

### 14.3 调整连接

第一版只提供三种关系：

- 先做 A，再做 B；
- A 和 B 同时做；
- A 做完，由 B 检查。

第一版采用**半开放任务棋盘**：任务位置由系统给出，玩家决定卡牌和少量连接关系。暂不提供无限节点和自由连线。

### 14.4 启动阵列

玩家点击“开始执行”，观看信息和作品沿连线流动；中途只处理一次关键情况，最后检查交付物。

## 15. v0.1 卡面与棋盘

### 15.1 卡面只显示当前决策需要的信息

- 名称与身份；
- 最相关的两项能力；
- 当前可用时间或算力；
- 使用成本；
- 是否需要真人接受邀请；
- 一条相关作品或履约记录。

第一版不在卡面展示等级、稀有度、总战力、完整成长树和认证徽章。详细证据可以展开查看，但不与主要操作争夺注意力。

### 15.2 页面布局

- 上方：一句话任务目标、截止时间和资源限制；
- 中间：三个任务位置及其连接；
- 下方：玩家当前能够使用或邀请的卡牌；
- 右侧：预计时间、成本和主要风险，随着阵列变化更新；
- 底部：唯一主要按钮“开始执行”。

## 16. 执行反馈与再次调整

阵列完成后生成一张“交付结果单”，而不是抽象总分：

- 实际产生的交付物；
- 是否解决客户目标；
- 是否按时；
- 是否超出资源；
- 哪个位置发生等待或返工；
- 哪张卡作出了关键判断；
- 哪张卡或哪条连接影响了结果；
- 评价者给出的真实反馈。

示例：

> 小角很快生成了三版海报，但没有确认“面向新生还是全校学生”。小满在提交前增加了人工检查，因此避免了错误交付，但晚了一天。

看到反馈后，玩家可以：

- 更换某个位置的卡牌；
- 把并行改为先后执行；
- 增加人工检查；
- 邀请缺少的外部能力；
- 训练 Agent 后再次尝试。

长期成长在第一版只用三个结果表达：

- 这张卡完成过什么；
- 这套连接是否被验证有效；
- 哪些真人愿意继续合作。

经验条、成长树、认证和孵化器评价不进入主要操作界面。结束页只说明，本次结果未来会进入相应档案。

## 17. v0.1 实现边界

新建一个独立单文件原型：

`mfu-demo/MFU-协作阵列-v0.1-可玩原型.html`

不在现有 v0.15 上删改，避免旧 Demo 的功能、状态和代码干扰核心玩法判断。新原型沿用 MFU 的羊皮纸、卡片、印章和角色语义色，但视觉重心转为卡牌与连线。

原型只包含六个连续场景：

1. 被匹配进大项目；
2. 查看自己在完整阵列中的位置；
3. 为自己的步骤组成小阵列；
4. 处理一次执行中的歧义；
5. 查看交付反馈并邀请上下游；
6. 用三名真人猎人组成新阵列，完成更完整的订单。

技术与范围约束：

- 单文件 HTML，可以直接打开；
- 拖放卡牌，并提供点击选择；
- 状态只保存在当前浏览器；
- 可以随时重置；
- 其他真人的接受由 Demo 模拟，并明确标注；
- 不接入真实 AI、多人服务或评价后台；
- 不加入商店、现金流、认证、成长树和孵化器工作台；
- 不同时展开协会、OPC 和 Agent 三层阵列。

## 18. v0.1 验收标准

- 完全不了解 MFU 的人能在 1 分钟内说出自己要做什么；
- 玩家能在 5–8 分钟内独立完成两幕；
- 玩家能看懂“放什么卡”和“怎样连接”都会影响结果；
- 玩家能明确复述被动连接与主动连接的区别；
- 玩家能够理解真人卡需要邀请并由真人接受；
- 所有按钮和场景都能实际操作，不出现只用于展示的死按钮；
- 提取脚本后通过 `node --check`；
- 常用桌面尺寸下无需横向滚动。

## 19. v0.1 之后再决定的内容

以下内容不阻塞第一版实现：

2. 自由画布和复杂拓扑编辑；

4. 真人评价与真实 AI 生成交付物；

## 20. v0.2：作为玩家的首个教学订单

v0.1 证明了核心循环可以成立。v0.2 不再把前两页作为 Pitch 说明，而是按卡牌闯关游戏的节奏重构首个教学订单。

### 20.1 体验顺序

```text
关卡背景
→ 准备好了，开始闯关
→ 独立卡牌编排
→ 暂存或确认执行
→ Agent 离线运行
→ 玩家回来处理判断
→ 查看交付结果
→ 复盘并升级 Agent 卡
→ 邀请上下游
→ 组成新组织并完成更大订单
```

### 20.2 关卡背景页

第一页只回答四个问题：

- 谁需要帮助：社区旧书店；
- 发生了什么：开学季没有新生知道这家店；
- 完整订单是什么：设计并验证一套开学季推广活动；
- 玩家负责什么：增长验证。

页面可以显示一张订单委托书和一个只读的小型项目阵列，但不出现可操作卡牌、连接按钮和资源明细。

唯一主要按钮：

> 准备好了，开始闯关

### 20.3 独立编排页

第二页只用于编排：

- 中间：三个任务位置；
- 下方：本人“小满”和 Agent“小角”；
- 右侧：截止时间、本人可用时间、Agent 算力和当前风险；
- 底部：“暂存编排”和“确认编排，让 Agent 开始执行”。

第一次教学只开放串行关系。检查关系在第一次结果反馈后开放，并行关系在第二幕开放。

### 20.4 时间与算力

第一关采用最小资源限制：

- 距离截止还有 4 个时间单位；
- 小满本人只有 2 个可用时间；
- 小角拥有 24 点算力；
- 一次人工判断消耗 1 时间；
- Agent 制作一项素材消耗 6 算力；
- 增加人工检查更稳，但会增加时间；
- 并行更快，但可能产生接口返工。

数字必须通过截止时间、机会成本和返工风险产生意义，而不是只显示在信息栏中。

### 20.5 离线执行与恢复

v0.2 使用几十秒模拟正式平台中数小时或数天的执行过程。

玩家确认编排后：

- 记录开始执行的真实时间；
- 显示当前工作卡、已用算力、预计完成时间和下一次需要玩家回来的节点；
- 明确提示玩家可以关闭页面；
- 玩家重新打开页面后，根据真实经过时间恢复进度；
- 执行到“客户范围存在歧义”时暂停，必须等待玩家本人判断；
- Agent 不得自动替人完成该判断。

Demo 只使用浏览器本地状态，不接入账号和服务器。

### 20.6 首次卡牌升级

第一次交付后，小角暴露出“需求不清时会自行猜测”的问题。玩家完成复盘后，可以为小角增加一条经过本次实践得到的守则：

> 需求不清时暂停并提醒主人

升级前：

- 制作快；
- 遇到含糊需求时可能自行猜测。

升级后：

- 消耗相同算力；
- 遇到歧义会暂停并请求人类判断。

该升级用于解释“Agent 成长是把失败转化为更可靠的工作资产”，不在第一关展示完整升级树。

### 20.7 教学安全与结束出口

- 标明“教学订单，不消耗真实信用，可以随时重试”；
- 支持拿回卡牌、覆盖位置和清空编排；
- 第一次反馈后可以“调整阵列，再试一次”；
- 教学完成后只给一个主要出口：“领取第一份自由订单”；
- 经验、成长树和认证继续在后台读取本次证据，但不在结束页同时弹出。

### 20.8 v0.2 验收标准

- 玩家打开后先理解关卡，再主动点击开始；
- 点击开始后立即进入独立拖拽页面；
- 玩家能感到时间和算力会限制选择；
- “暂存编排”后刷新页面，阵列仍然存在；
- “确认执行”后刷新或离开再回来，执行进度按真实时间恢复；
- 执行到歧义节点后必须停下来等待人类；
- 玩家能通过一次复盘为小角增加新守则；
- 玩家能复述：人负责理解和最终判断，Agent 可以离线执行；
- 原有的主动邀请、三人阵列和完整交付仍能完成。
