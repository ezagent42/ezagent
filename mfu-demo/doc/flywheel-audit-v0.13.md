# MFU 飞轮完整性审计 v0.13

> 日期：2026-07-23
> 目标：基于「假设 → 模式 → 飞轮 → 目标」四层漏斗，逐段检验当前 demo 的优化机会

---

## 使用方法论

本审计综合运用了以下分析框架：

### 飞轮完整性审计（Flywheel Integrity Audit）

将 MFU 的目标循环——`聚集 OPC → 遴选导入孵化器 → 平台持续运营 → 优化游戏 → 回到起点`——拆为四段，逐段对照 demo 检验：机制是否存在、若存在是否完整、若不存在是 demo 阶段省略还是设计空白。

### 玩家动机类型（Bartle Taxonomy）

将玩家按核心驱动分为四类，检验 demo 是否只为单一类型设计：

| 类型 | 核心驱动 | 在 MFU 中的价值 |
|------|---------|---------------|
| **Achiever**（成就者） | 目标、完成、认证 | 高质量交付物 → 孵化器入驻管线 |
| **Explorer**（探索者） | 发现、秘密、实验 | 发现最优路由策略 → 构成判断力基准 → 提升推演器精度 |
| **Socializer**（社交者） | 互动、社区、关系 | 生态粘性 → 降低流失 → 教练/评审员培养管道 |
| **Killer**（竞技者） | 竞争、统治、排名 | 拉升竞争水位 → 认证含金量 → 旁观者吸引力 |

### Progression Design（四类型 × 四节奏）

将玩家成长拆为四个维度，检验每一维在 demo 中是否有对应的机制与反馈：

| 类型 | 含义 | 检验问题 |
|------|------|---------|
| **Skill** | 玩家自己变强 | 学生能感受到自己的路由判断力在增长吗？ |
| **Power** | 角色/资产变强 | Agent 能力分的增长有非线性突破时刻吗？ |
| **Content** | 新内容解锁 | 每次解锁有仪式感吗？节奏合理吗？ |
| **Story** | 叙事推进 | 学生感受到「我的公司在经历一段旅程」吗？ |

辅以四条节奏原则检验 pacing：**Early wins**（快速上手）→ **Gradually increase challenge**（渐进挑战）→ **Rest beats**（强度间的休息节拍）→ **Meaningful choices**（有意义的选择）。

### 奖励排程（Reward Schedules）

检验 demo 中的反馈是固定间隔（Fixed）、随机变量（Variable）、还是努力比例（Ratio），以及各类型是否被用在合适的场景。

### 游戏→真实过渡点分析

将 demo 中所有简化环节按过渡难度分三层——自然过渡（只需换界面）→ 需要平台基础设施支撑 → 需要真实机构和角色介入——梳理「关掉包装层」的实际路径。

## 0. 审计基准

**关键假设**：未来的企业一开始就是 AI-native。管理的核心是**人机协作关系**（而非传统资源调度），扩张靠**网络中能力的互联**（而非人力资本叠加）。

**运营模式**：平台提供平台 / 学校提供算力与学生 / 孵化器提供场地、订单与资金。

**飞轮目标**：
```
游戏聚集 OPC → 遴选优秀 OPC 导入孵化器 → 平台提供持续运营支持 → 优化游戏获得更多优质企业 → (循环)
```

以下按飞轮四段逐段审计。

## 1. 第一段：游戏聚集 OPC

### 1.1 聚集起点：学校 × 校历

> **2026-07-24 修正（Allen 反馈）**：不存在「课堂 45 分钟」场景。MFU 定位为教务系统/课程表式的异步工具，在课外使用，无固定时间限制。

**GDD 有没有覆盖？** 有框架，无细节。

| 来源 | 内容 | 是否落到 demo |
|------|------|---------------|
| GDD §3.2 | 学校对外提供算力、教练时长、题库；获取教改数据、实训成果 | Demo 中学校是「数据源」：算力 100/周自动到账，教练时长 2/周，练习单自动刷新。学校没有自己的操作界面 |
| GDD §4.4 | 「课堂周节拍」：每周一课 = 回合结算/发题/开奖；学期 = 赛季 | **修正理解**：不是「上课」的同步时刻，而是**校历驱动的异步节拍**。学校有 18 个教学周，不同课程有不同的考试时间和作业 deadline。每周在固定时间结算（如周日 12:00），新命题发布、竞赛开奖、教练周复盘等事件统一发布，学生各自在不同时间登录看到 |
| GDD §5.9 | 学校提供「教练 Agent 免费时长」，是学校的第二项生态投入（与算力并列） | Demo 中教练时长自动到账，但学生不知道「这是学校花钱买的」 |

**判断**：校历作为聚集起点的场景是 GDD 明确设想的，但 demo 将世界时钟简化为「下一周」按钮，丢失了校历驱动的节拍感。关键缺失：

- ❌ **班级归属感**：学生注册时选学校，但之后几乎感受不到「我是城南学院的学生」。没有班级频道、没有同学列表、没有「同班同学在做什么」的信息流。**→ 与 [§C.4 中期真空](#c4-最大的-progression-缺口中期真空) 相关：缺乏班级社会参照，Skill/Power 的增长只是孤独的数字变动，没有「你在班里排第几」「你的 Agent 在班里什么水平」的比较语境。→ 与 [§C.5 Content Progression](#content-progression给每个解锁加上仪式感) 相关：业务线解锁没有社会维度——「你是全班第 3 个解锁高端设计线的」比「你解锁了高端设计线」更有意义。**
- ❌ **结算日仪式**：每周 tick 只是点一下按钮。缺乏结算日（如周日 12:00）的集体事件感——新命题统一发布 + 上周竞赛统一开奖 + 教练周复盘统一推送。事件可以异步消费，但**发布是同步的**，这构成了全班共享的节拍。**→ 与 [§C.5 节奏优化](#节奏优化铺出完整的-progression-曲线) 高度相关：结算日是 progression 阶段划分（探索期→成长期→验证期→突破期）的天然锚点。没有结算仪式，progression 的「休息节拍」（Rest beats）就失去了社会性载体。**
- ❌ **教师在场**：老师作为独立角色（工作室经营者）和作为课堂组织者（发布命题、看班级数据）的双重身份没有呈现。**→ 与 [§C.5 Story Progression](#story-progression把世界变成活的故事) 相关：老师是 Story 维度最自然的叙事代理人——命题发布时的引言、周复盘的点评、学期末的总结。没有教师在场，Story progression 失去了最经济的叙事载体。→ 与 [§5 科技树](#5-设计回应科技树作为统一的-progression-与权限体系) 相关：老师也是一个「企业」，初始状态与学生的视图完全相同，差异来自解锁了教练科技树分支。**

### 1.2 只有竞争，没有协作

**GDD 有没有覆盖？** 提到但未设计。

GDD §5.1 末尾有一句：「未来其他 OPC 之间也可互相发单（生态内循环）」。GDD 开放问题 #3：「OPC 之间互相发单的边界：允许转包吗？」。GDD §5.4 打工市场是单向雇佣，不是双向协作。

Demo 中 OPC 之间的关系矩阵：

| 交互类型 | Demo 中 | 竞争者 | 协作者 |
|----------|---------|--------|--------|
| 同题竞赛 | ✅ | ✅ | — |
| 排行榜 | ✅ | ✅ | — |
| 打工（被雇佣） | ✅ | — | ❌（是雇佣关系，不是协作关系） |
| 资产市场交易 | ✅ | — | ❌（是买卖，不是协作） |
| **组队接单** | ❌ | — | — |
| **联合竞标**（两家 OPC 合投一个命题） | ❌ | — | — |
| **转包**（接了单分给其他 OPC 做某个环节） | ❌ | — | — |
| **同学互评** | ❌ | — | — |
| **知识分享**（调教经验、路由策略） | ❌ | — | — |

**协作缺口不是 demo 简化的问题——是设计层面的空白。** GDD 的核心动词是「路由、调教、兜底、经营」，全部是单人动作。但 AI-native 组织之间的协作恰恰是「网络中能力的互联」这一核心假设的落脚点。

**建议补充的最小协作机制**：

| 机制 | 描述 | 优先级 |
|------|------|--------|
| 组队接单 | 2–3 家 OPC 联合接一个复杂命题，各自路由擅长的环节，共享奖金 | 高 |
| 同学互评 | 练习单的评审不由系统自动打分，而是由同班同学互评（老师监督）。生产的是**评审能力**——这也是协会评审员的培养管道 | 高 |
| 知识市场 | 学生可分享自己调教出的守则模版（收费或免费），加速全班的 Agent 质量基线 | 中 |
| 联合竞标 | 面对孵化器的高难度命题，多家 OPC 组成临时联盟竞标 | 低（远期） |

## 2. 第二段：遴选优秀 OPC 导入孵化器

### 2.1 遴选是全自动的 → 没有人做决策

Demo 代码第 1309–1315 行：
```javascript
function checkEnd(){
  if(S.endShown)return;
  const avg=S.realQ.length?S.realQ.reduce((a,b)=>a+b,0)/S.realQ.length:0;
  if(S.rank>=2&&S.realN>=2&&avg>=74){
    S.endShown=true;$('endCo').textContent=S.co;
    setTimeout(()=>$('mEnd').classList.add('show'),700);
  }
}
```

三个硬编码条件（黄金认证 + ≥2 单真单 + 均分 ≥74）触发自动弹窗。这与 GDD D15「真实对抗为世界基本法则」存在张力——如果系统自动判定赢家，就不是真实对抗。

**需要补充**：孵化器 Scouting Agent 的中间信号系统。在学生达到黄金认证后、正式收到入驻邀请前，应该有：

| 信号 | 含义 | 当前状态 |
|------|------|----------|
| Scouting Agent 标记 | 「DHS 孵化器已开始追踪你的数据」 | ❌ 缺失 |
| 定向命题邀请 | 孵化器发来一个仅限你和少数几队可见的高难度命题 | ❌ 缺失 |
| Grant 发放 | 小额资金注入，观察资金使用效率 | ✅ 有（加入预备营自动发 ¥3,000），但无后续追踪 |
| 投后 Agent 接触 | 孵化器的人通过平台与你沟通 | ❌ 缺失 |
| 入驻邀请 | 顶级会籍 offer，包含具体条款 | ✅ 有，但触发条件纯自动 |

### 2.2 不同动机类型的学生如何为世界创造价值

引用 Bartle 四分法（Achiever / Explorer / Socializer / Killer），当前 demo ≈ 90% 面向 Achiever。

#### 当前状态：四种类型在 demo 中的存在感

| 类型 | 驱动 | Demo 中 | 问题 |
|------|------|---------|------|
| **Achiever** 🏆 | 目标、完成、认证 | ✅ 核心循环完整 | 唯一有终局的类型。但「胜利条件」过于单一（入驻孵化器） |
| **Explorer** 🔍 | 发现、秘密、实验 | ⚠️ 少量 | Agent 性格是随机的（有点发现乐趣）。路由适配度部分隐藏。但无隐藏内容、无 easter egg、无世界 lore。**探索产生的数据不反哺系统** |
| **Socializer** 💬 | 互动、社区、关系 | ❌ 几乎为零 | 「商务社交」按钮消耗 1AP → 人脉 +1。没有玩家间聊天、没有公会活动、没有师徒关系 |
| **Killer** ⚔️ | 竞争、统治、排名 | ⚠️ 有但弱 | 排行榜存在，但对手是随机生成的 NPC。击败 NPC 的满足感远低于击败真人 |

#### 每种类型如何为飞轮创造价值

```
┌──────────────────────────────────────────────────────────────┐
│                    Achiever 🏆                                │
│  行为：追求认证、完成高难度真单、冲击入驻                         │
│  为飞轮贡献：高质量交付物 → 孵化器入驻管线 → 飞轮第 2→3 段的燃料  │
│  风险：只做「能刷分」的事，忽视探索和社交                         │
├──────────────────────────────────────────────────────────────┤
│                    Explorer 🔍                                │
│  行为：尝试非主流路由组合、发掘冷门业务线、找 Agent 最优调教策略   │
│  为飞轮贡献：发现最优实践 → 构成判断力「基准」→ 提升推演器精度     │
│          发现系统边界案例 → 帮助平台迭代 → 飞轮第 4 段（优化游戏） │
│  风险：不追求认证，可能被系统判定为「不成功」而流失                 │
├──────────────────────────────────────────────────────────────┤
│                    Socializer 💬                              │
│  行为：组织公会活动、建立同学网络、做知识分享、带新人               │
│  为飞轮贡献：生态粘性 → 降低流失率 → 飞轮第 1 段（聚集 OPC）      │
│          师徒/教练管道 → 未来教练 Agent 出品方 → 飞轮第 2 段       │
│          社区信任 → 降低资产市场交易摩擦 → 平台流动性               │
│  风险：自身经营数据可能不出色，需要被认可其社区贡献                  │
├──────────────────────────────────────────────────────────────┤
│                    Killer ⚔️                                  │
│  行为：冲击榜首、研究对手策略、追求最高评级                        │
│  为飞轮贡献：拉升竞争水位 → 所有人被迫进步 → 飞轮第 2 段产出更优   │
│          对抗戏剧 → 旁观者吸引力 → 飞轮第 1 段（吸引新玩家）       │
│  风险：可能打击弱者的参与意愿（需分层匹配兜底）                     │
└──────────────────────────────────────────────────────────────┘
```

#### 关键洞察：飞轮依赖 Achiever，但需要另外三种类型让 Achiever 的产出有价值

- 没有 Explorer 的探索数据，判断力基准就是空的（系统无法知道什么是「好」的路由决策）
- 没有 Socializer 的网络，Achiever 赢了也没人知道——飞轮第 1 段的「聚集」靠的是社区传播
- 没有 Killer 的压力，Achiever 的认证含金量下降——因为竞争不够激烈

**四种类型的「毕业」出口不应相同**：

| 类型 | 可能的出口 | 对飞轮的价值 |
|------|-----------|-------------|
| Achiever | 入驻孵化器（现有路径） | 第 2→3 段 |
| Explorer | 成为平台的**命题设计师** / **基准数据贡献者** / **推演器精度提升者** | 第 4 段 |
| Socializer | 成为**公会组织者** / **教练 Agent 出品方** / **协会评审员** | 第 1→2 段 |
| Killer | 入驻孵化器（高强度竞争者） / 或成为**评审专家**（有辨别优劣的能力） | 第 2 段 |

### 2.3 进度可见性

当前学生只能看到声望条和认证等级。缺少：

- ❌ 「孵化器 Scouting 状态」：你是否在被追踪？被几个孵化器追踪？
- ❌ 「离入驻还有多远」：不是精确的进度条（那会变成刷分目标），而是模糊信号——「你的设计业务线正在引起孵化器注意」「你还差 1–2 单 A 级以上的真单」。
- ❌ 孵化器侧的「候选企业全貌」：Scouting Agent 的 dashboard 只存在于概念中，没有 demo。

## 3. 第三段：平台提供持续运营支持

> 这是飞轮最大的黑洞，也是用户最困惑的部分。

### 3.1 GDD 怎么说的：从「游戏」到「真实」的过渡模型

GDD §6（真实性映射表）第 390 行给了最关键的句子：

> **不存在迁移，只存在关掉教学包装层**。学生从 day 1 就运行在真实系统上。

GDD §7（教学/转化目标映射）定义了每条机制教的真实能力和服务的商业目标。

但 GDD **没有详细说明**的是：这套「真实系统」（ezagent）在 demo 阶段不存在时，哪些环节的简化是可以接受的（教学目的达成），哪些环节的简化会导致学生产生根本性的误解。

### 3.2 完整简化清单：10 个被简化环节及其实过渡策略

以下按「从游戏到真实」的过渡难度排列，从最自然到最需要外部介入。

---

#### 🔵 第 1 层：过渡自然（游戏中的动作 ≈ 真实系统中的动作）

这些环节的简化不影响教学目的——学生理解了概念，关掉包装层后面对的是「同一个动作但更复杂的界面」。

| # | 游戏动作 | 真实世界等价物 | Demo 简化方式 | 教学目的是否达成 | 过渡策略 |
|---|---------|---------------|-------------|----------------|---------|
| 1 | **路由决策**：在弹窗中点选「谁来干」 | 评估任务需求 → 匹配能力 → 分配资源 → 设定验收标准 | 固定环节 × 3 选项 × 星级提示 | ✅ 已达成（学生理解了「编排力」的概念） | 关掉包装层后，路由界面从「三选一」变成真实的资源调度面板——但核心决策逻辑不变 |
| 2 | **调教 Agent**：二选一 / 填空写守则 | Prompt 工程、few-shot 示例构建、eval 集设计 | 预制题库 × 选择题形式 | ⚠️ 部分达成（理解了「教 AI」的概念，但不等于会写 prompt） | 训练资产（prompt/守则）本身是真实可迁移的。关掉包装层后，调教界面从选择题变成自由文本 + eval 反馈循环 |
| 3 | **交付确认**：点「确认并提交」 | QA 审查、客户沟通、修改迭代、最终签收 | 一键确认 + 自动质量评分 | ✅ 已达成（理解了「责任在人」的原则——这是 GDD 唯一不可路由的环节） | 关掉包装层后，确认环节需要人实际审查交付物。但原则没变——「人做最终确认」 |

---

#### 🟡 第 2 层：需要平台基础设施支撑（简化是为了 demo 能跑，但真实运营需要 ezagent 真的存在）

| # | 游戏动作 | 真实世界等价物 | Demo 简化方式 | 缺失什么 | 过渡策略 |
|---|---------|---------------|-------------|---------|---------|
| 4 | **算力消耗**：进度条自动扣减 | API 调用量监控、GPU 配额管理、成本核算 | 算力条 = 100，每周重置，Agent 执行时自动扣 12–15 | 没有让学生理解「算力是花钱的」「不同模型算力成本不同」「算力用完了是真的会用完」 | 学校配额的「保底 + 竞争增量」模式（GDD #5）。当学生进入真单区时，算力消耗可视化从「进度条」变成「用量 + 成本报表」 |
| 5 | **订单流转**：接单 → 自动计时 → 交付 | 合同签订、里程碑管理、变更请求、验收争议处理 | 固定环节、固定周期、无中途变更 | Scope creep、客户变更需求、验收争议——这些是真实商业中最常见的摩擦 | 真单区引入「客户沟通环节」（可通过对话界面与发单方 Agent 沟通）。变更请求消耗额外时间/费用 |
| 6 | **竞赛评审**：系统自动算分 + 随机对手分数 | 多评委盲评、Rubric 评分、偏见控制、反馈报告 | `quality = formula + rnd(-4,6)` | 评审的 subjectivity（不同评委不同标准）、反馈的具体性（「信息层级混乱」vs 一个分数） | 练习单：同学互评（老师监督）。真单：协会评审 Agent 初评 + 人类专家抽查。评审反馈从「一个分数」变成「具体评语 + 改进建议」 |
| 7 | **现金流管理**：每周自动扣费 | 发票管理、应收/应付、税务申报、现金流预测 | 每周 tick 自动结算：Agent 托管费、成员工资、基座租用、会费 | 应收账款（客户不付款）、应付账款（可以延期付外包）、税务、多币种 | 真单区开启后，现金流面板从「自动结算」变成「应收/应付/实际到账」三层。Runway 计算从 demo 中的简单除法变成真实的财务模型 |

#### 🔴 第 3 层：需要真实机构和角色介入（游戏中的简化无法仅靠「换界面」过渡）

这是最关键的一层。以下环节在游戏中的简化不只影响操作复杂度——它们**在真实世界中需要新的人、新的机构、新的法律关系进入**。

| # | 游戏动作 | 真实世界等价物 | 为什么不能只靠「换界面」过渡 | 谁需要介入 | 介入时机 |
|---|---------|---------------|--------------------------|-----------|---------|
| 8 | **雇佣 Agent**：花 ¥2,200 点一下就入职 | 选择 AI 模型/服务、配置 Agent、设定访问权限、签署数据处理协议 | Agent 处理客户数据 → 涉及数据隐私合规。Agent 产出内容 → 涉及知识产权归属。Agent 使用第三方模型 → 涉及服务条款。这些不是「更复杂的界面」能解决的——**是法律问题** | **平台**：提供 Agent 使用协议模版、数据隐私合规框架。**孵化器**：入驻后协助处理 IP 归属。**协会**：制定 Agent 使用的行业标准 | 学生接第一个真单时，平台需要弹出简化版的 Agent 使用协议（数据去哪了、IP 归谁）。入驻孵化器后，由孵化器协助升级为正式法律协议 |
| 9 | **外部资源**：花 ¥800–1,200 点一下就外包 | 寻找 freelancer/供应商、谈判合同、管理交付、处理争议、支付结算 | 外部资源的交付质量不可控——游戏中是一个固定的 quality 公式。真实外包涉及：筛选、议价、中途换人、交付物不合格的追责。**平台需要有纠纷解决机制** | **平台**：提供外包匹配 + 托管支付 + 争议仲裁。**孵化器**：推荐可信的外部资源池。**协会**：认证外部资源的质量等级 | 练习单阶段只能使用「平台预审的外部资源池」（简单版）。真单区开放后，可使用更广泛的外部资源市场，但配套托管支付与评价系统 |
| 10 | **破产清算**：弹窗 → 选一个选项 → 带着档案重开 | 公司注销、债务清偿、资产处置、员工遣散、法律实体关闭 | 当涉及真实资金（真单收入）时，「破产」不再是学习体验——**是真实的财务事件**。谁的钱损失了？客户预付款怎么办？Agent 资产卖给了谁、卖了多少钱是真的吗？ | **平台**：提供清算流程的合规框架、资金托管与结算。**孵化器**：桥贷评估（已经涉及真实资金决策）。**协会**：破产记录是否影响认证？ | 练习单区：破产 = 纯游戏机制（GDD 现有设计 OK）。真单区：破产触发时，平台需要有真实的资金结算流程——客户已付的款项如何处理、Agent 资产的真实交易如何执行 |

### 3.4 Demo 现在能做什么来桥接这个过渡

当前 demo 停在 Phase A，且入驻邀请后直接弹「关掉包装层」但没有展示 Phase C 长什么样。

**最小可行的桥接方案**：

1. **入驻邀请弹窗改造**：不只说「关掉包装层」，而是展示一个 **Phase C 界面的静态预览**——同一套数据（公司名、Agent 资产、订单档案），但界面从「游戏风」变成了「运营风」。学生看到：「我调教出的设计 Agent 的 prompt 文本，在这里可以直接编辑和导出」。
2. **真单区的「半透明」设计**：当学生第一次接真单时，某些游戏化的 UI 元素（星级、进度条）开始出现「底层数据」的 tooltip。例如鼠标悬停在「算力条」上时显示：「学校配额：100 CU/周 ·本周已用 48 CU · 折合成本约 ¥12（由学校承担）」。
3. **Agent 资产的「可导出预览」**：在训练室中增加一个「查看原始资产」按钮，展示调教出的 prompt/守则的实际文本。学生意识到「我其实一直在写 prompt」。

## 5. 设计回应：科技树作为统一的 Progression 与权限体系

> 2026-07-24 新增。综合 Allen 反馈与讨论，提出以科技树为骨架，统一解决前四段审计中识别的 progression 缺失、目标模糊、角色视图差异等问题。

### 5.1 核心模型：学分 + 资格认证 → 科技树 → 功能模块/视角

**基本逻辑链**：

```
学分（课程教会的技能）+ 资格认证（禀赋）
        ↓
解锁科技树节点
        ↓
解锁功能模块 / 角色视图
```

**具体映射示例**：

| 触发条件 | 解锁科技树 | 解锁能力/视图 |
|---------|-----------|-------------|
| 学生积累足够的设计学分 | 设计科技树 | 更好地训练设计 Agent、解锁高级设计命题 |
| 学生完成公司注册 | 公司运营科技树 | 解锁发单、财务管理、资产管理等模块 |
| 教师获得创业培训师资格认证 | 教练科技树 | 解锁教练视图：看到所管理学生的企业数据、带队面板 |
| 孵化器获得孵化平台认证 | 场地运营科技树 | 解锁场地管理视图：看到孵化中企业、Scouting 配置、投后面板 |
| ezagent 团队获得平台运营资质 | 平台运营科技树 | 平台级配置、团队目标管理、系统健康监控 |

### 5.2 统一起点的设计含义

**所有角色初始状态 = 「学生」**。教师也是一个企业，孵化器也是一个企业，ezagent 团队也是一个企业——它们共享同一套基础界面（接单/发单/Agent 管理/资产管理/现金流）。差异仅在于解锁了哪些科技树分支，从而获得了哪些额外的功能模块和视角。

这与 GDD D27（单一组织面板）完全一致，但将「禀赋差异」具象化为**科技树的解锁状态**。一个孵化器的完整面板 = 学生基础面板 + 场地运营科技树解锁的额外模块。

**关键推论**：

- **不需要「做其他角色的界面」**——只需要做同一张界面的不同解锁状态。开发上可以先做基础面板，再逐步往上叠加科技树分支对应的模块。
- **科技树可被公开查看**（GDD D28 纪律：树位置对外公开）。一个学生可以看到孵化器的科技树解锁了哪些节点——这是「我想成为孵化器」的野心机制。
- **科技树的分支价值由市场决定**（D28）。哪条分支「值钱」不由系统预设，而由命题供给、会籍需求、认证含金量等市场力量决定。

### 5.3 与原 D28「三棵成长树」的关系

GDD D28 定义了三棵成长树：人的树（技能 + 角色资格）、企业资质树、企业业务树。

科技树模型**吸收并扩展**了 D28：

| D28 三棵树 | 在新模型中的位置 |
|-----------|----------------|
| 人的树（技能连续 + 角色资格离散） | **学分线**：技能对应学分积累（连续），资格认证对应节点解锁（离散）。例如：评审员资格 = 黄金认证 + 履约 ≥ 20 单 |
| 企业资质树（发单→开公会→教练服务→…） | **资质分支**：由资格认证触发。例如：教师获创业培训师认证 → 解锁教练科技树 → 解锁教练服务供给 |
| 企业业务树（Agent × Connector × 案例数） | **业务分支**：由学分 + 接入 + 交付量触发。例如：设计学分 + 图像 Pro + 设计真单 ≥ 4 → 高端设计线 |

**新增的维度**：科技树模型引入了 D28 没有显式覆盖的「平台运营」维度——ezagent 团队自己作为平台上的一个企业，拥有「平台运营」资质及其对应的科技树。这意味着平台自身的迭代（发 PR、关旧 PR、设定团队目标）也可以被视为同一棵科技树上的分支。这种泛化是否合理待讨论——见 §5.5。

### 5.4 科技树如何解决此前识别的核心问题

| 此前识别的问题 | 科技树如何回应 |
|--------------|-------------|
| **Progression 有骨架无感知**（§C.4） | 科技树**就是** progression 的骨架。节点 = 里程碑，解锁 = 有仪式感的事件，分支 = 可选路径。学生随时可以看到树的全局和自己当前的位置 |
| **白银→黄金中期真空**（§C.4） | 两棵独立的树（例如设计科技树 + 公司运营科技树）有各自的中间节点。学生在等声望积累的同时，可以看到「还差 2 个节点解锁高端设计线」——短期目标链天然形成 |
| **四种 Bartle 类型不同出口**（§2.2） | 不同分支 = 不同类型的追求。Achiever 追求资质树深度（认证→入驻），Explorer 追求业务树广度（解锁冷门业务线），Socializer 追求教练/评审分支（解锁后可以带人），Killer 追求排行榜可见的高难度节点 |
| **教学工具 vs 创业平台**（§2.4） | 学分 = 学习成果（教学侧），资格认证 = 市场信号（创业侧）。同一棵树同时承载两种目标——不需要二选一 |
| **其他角色界面要不要做**（§2.5） | 角色差异 = 同一界面 + 不同解锁状态。孵化器面板 = 学生基础面板 + 场地运营科技树解锁的模块。先做基础面板，再按需解锁 |
| **目标透明度**（§2.4） | 树的结构是公开的（D28），但**解锁条件**可以部分不透明——学生知道「设计科技树有哪些节点」，但不一定知道每个节点的精确数值门槛。这平衡了 Achiever 需要方向感和 Explorer 需要发现感 |

### 5.5 开放问题：科技树泛化为「目标树」？

（待讨论）ezagent 团队自己也是平台上的企业，可以通过设定团队目标不断扩充技能树。在 website-demo 的 world.cup tab 中，每个 PR 可以视为一个 skill tree 的 branch。这意味着科技树的节点不一定是系统预设的——可以是「目标」本身，完成了就变成已解锁节点。

**如果技能树泛化为「目标树」**：
- 平台运营者可以**定义新目标**（例如「本季度增加 3 个 Connector」）→ 目标成为树的临时节点 → 完成后转为永久节点 → 其他企业可以看到并借鉴
- 这模糊了「系统设计的内容」和「用户生成的内容」的边界——树是活的、由平台上所有组织的目标共同编织的

**不确定的是**：这种泛化是否合理？会不会让「树」失去作为 progression 骨架的清晰性？如果每个 PR 都是一个 branch，树会不会无限膨胀变成噪音？

## 附录 C：Progression Design 审计

> 框架来源：Game Design SKILL.md §5 Progression Design + §3 Reward Schedules + §4 Difficulty Balancing
> 核心问题：MFU 的 progression 在哪里？学生从「第一天」到「入驻孵化器」之间，经历了什么？

### C.1 框架速览：Progression Design 的四类型 + 四节奏

**四种 Progression 类型**：

| 类型 | 含义 | 回答的问题 |
|------|------|-----------|
| **Skill** | 玩家自己变强 | 「我比上周更会做路由决策了吗？」 |
| **Power** | 角色/资产变强 | 「我的 Agent 能力分涨了吗？」 |
| **Content** | 新内容解锁 | 「有什么新东西可以玩了？」 |
| **Story** | 叙事推进 | 「这个世界在发生什么？我的公司在经历什么？」 |

**四条节奏原则**：

| 原则 | 含义 |
|------|------|
| Early wins（快速上手） | 前 60 秒内体验到成功 |
| Gradually increase challenge（渐进挑战） | 难度平滑爬升，不突然跳崖 |
| Rest beats between intensity（强度间的休息节拍） | 紧张之后有放松，冲刺之后有缓冲 |
| Meaningful choices（有意义的选择） | 选择影响后续体验，不是假选项 |

### C.2 MFU Demo 当前 Progression 盘点

#### Skill（玩家变强）—— ⚠️ 有数据，无感知

| 维度 | Demo 中是否有 | 如何增长 | 学生能看到吗 |
|------|-------------|---------|------------|
| 路由判断力 | ✅ `S.profile.judgeG / S.profile.judgeT` | 每次交付后判断环节质量是否跑赢基准 | ⚠️ 藏在主理人档案深处，不主动展示 |
| 个人专业技能 | ✅ `S.profile.skill[domain]` | 亲自干时 +0.5/次 | ⚠️ 仅在打工市场选单和档案页显示 |
| 评审能力 | ❌ 不存在 | — | — |
| 教练/教学能力 | ❌ 不存在（仅老师角色有带队指数概念） | — | — |

**问题**：Skill 维度的数据在积累，但学生**感受不到自己在变强**。路由判断力从 0% 涨到 70% 的过程没有任何反馈——没有「恭喜，你的路由判断力已超过同层 80% 的玩家」、没有「你上周的策略路由全部跑赢基准」。数字在后台默默涨，这是 Capsim 式表格地狱的温床。

#### Power（资产变强）—— ✅ 最完善的维度

| 维度 | 如何增长 | 可见性 |
|------|---------|--------|
| Agent 能力分 | `cap(a)` = 2 + assets×0.7 + min(wins,10)×0.18 | ✅ 办公室卡片直接显示 |
| Agent 训练资产 | 调教 +1/次，复盘 +2/次 | ✅ 即时弹出 + 卡片更新 |
| 基座模型 | 校园版 → 进阶版（¥600/周）→ 旗舰版（¥1,400/周） | ✅ 商店切换，质量乘数可见 |
| Connector | 数字人引擎、图像生成 Pro | ✅ 商店购买后立即解锁新业务 |
| 公司声望 | 竞赛排名 + 真单评级 | ✅ 顶栏常驻 |
| 现金 | 订单奖金 + grant + 打工 | ✅ 顶栏常驻 |

**问题**：Power 维度的增长是线性的——`assets += 1`。没有稀缺性突破（「终于调出了第一条 S 级守则！」）、没有阶段性跃升（Agent 能力从 3.2 到 3.5 到 3.8 到 4.1——都是小数点后一位，没有「质变」的感觉）。

#### Content（内容解锁）—— ⚠️ 有框架，但节奏不清晰

| 解锁内容 | 触发条件 | 类型 | 问题 |
|---------|---------|------|------|
| 白银认证 | 声望 ≥ 30 | 资质 | ✅ 有弹窗通知 |
| 黄金认证 | 声望 ≥ 85 | 资质 | ✅ 有弹窗通知 |
| DHS 预备营 | 白银 + 信用 ≥ 70 | 会籍 | ⚠️ 需要学生自己去生态页点加入 |
| 协会会员 | 白银 + ¥400/周 | 会籍 | ⚠️ 同上 |
| 高端设计线 | 图像 Pro + 设计真单 ≥ 4 | 业务线 | ⚠️ 解锁时只有一行日志 |
| MCN 业务线 | 数字人引擎 | 业务线 | ⚠️ 同上 |
| 孵化器真单 | 预备营会籍 | 订单类型 | ⚠️ 订单板上默默出现，无「新类型订单已解锁」提示 |
| 直播电商线 | MCN 真单 ≥ 3 | 业务线（进阶） | ⚠️ 同上 |
| 办公室升级 | 声望 ≥ 30 / ≥ 85 | 视觉 | ⚠️ 仅在办公室卡片标题变化 |
| 入驻邀请 | 黄金 + ≥2 真单 + 均分 ≥74 | 终局事件 | ⚠️ 自动弹窗，无铺垫 |

**问题**：解锁事件在发生，但**学生感受不到「解锁」的愉悦**。游戏设计中的 Content progression 应该像开罗游戏——每次解锁都有仪式感（新建筑出现、新菜单亮起、NPC 发来祝贺）。Demo 中的解锁大多是一行日志或一个 tag 变化。

#### Story（叙事推进）—— ❌ 几乎不存在

| 叙事元素 | Demo 中是否有 |
|---------|-------------|
| 公司创立故事 | ⚠️ 仅有开业第一天的弹窗介绍 |
| 竞争对手的故事线 | ❌ 对手是随机生成的 NPC，没有名字背后的故事 |
| Agent 的个人故事 | ⚠️ 仅有随机性格 + 几句台词 |
| 世界事件 | ⚠️ 仅有随机日志（「学校加发 15 算力」「隔壁队提交了」） |
| 孵化器的叙事弧 | ❌ 孵化器是一个 tag + 一个弹窗，不是一个「角色」 |
| 赛季故事 | ❌ 没有赛季概念 |

**问题**：Demo 最接近 Story 的是「办公室升级」（宿舍书桌 → 共享工位 → 老厂房独立间）——这其实是很好的叙事载体，但目前只是一个字符串替换。没有过渡动画、没有空间变化、没有「搬家」的事件感。

### C.3 节奏原则对照

| 原则 | Demo 当前 | 评级 |
|------|----------|------|
| **Early wins** | ✅ 注册后 60 秒内接到第一单练习单，点几次就完成路由 | 好 |
| **Gradually increase challenge** | ❌ 订单难度是随机的。白银前只能接练习单（diff 1-2），白银后突然出现真单（diff 3-4）——这是一个难度悬崖 | **断点** |
| **Rest beats** | ⚠️ 每周 tick 后有一周的「休息」，但这一周内没有节奏变化——从头到尾都在接单/调教/交付，没有「冲刺周」「休息周」的区分 | 弱 |
| **Meaningful choices** | ✅ 路由决策（给谁干）+ 生产 vs 调教取舍 + 会籍选择 | 好 |

### C.4 最大的 Progression 缺口：中期真空

> **← 与 §1.1 课堂仪式** 强相关。课堂周节拍本应是中期节奏的天然载体——每周上课 = 新命题发布 + 上周开奖 + 教练复盘。没有课堂仪式的锚定，中期就变成了无差别的重复 tick。详见[§1.1](#11-聚集起点学校--课堂)。

```
注册 ──→ 第一单 ──→ 白银认证 ──→ ??? ──→ 黄金认证 ──→ 入驻
         ↑ 15分钟      ↑ 1-2小时      ↑  ??小时    ↑           ↑
         
         Early wins   第一个里程碑     中期真空     第二个里程碑  终局
```

**白银→黄金之间（声望 30→85）是 progression 的黑洞**。这段时间学生在做什么？

- 接单 → 路由 → 交付 → 声望 +X → 重复
- 调教 Agent → 资产 +1 → 能力分 +0.7 → 重复
- 每周 tick → 自动扣费 → 可能出现现金流危机（唯一的「事件」）

这段时间缺乏：
- **短期目标链**（「本周完成 3 单设计类订单 → 解锁设计专项认证徽章」）
- **中期追求**（「积累 10 条 S 级守则 → Agent 觉醒第二性格特质」）
- **叙事推进**（「你的公司在学校出了名——校报想采访你」）
- **能力跃升节点**（不只是小数点后一位的线性增长）

### C.5 建议：四类型 Progression 的显式化设计

#### Skill Progression：让隐式成长变为显式反馈

> **← 与 §1.1 班级归属感** 相关：技能成长的感知需要社会参照——「你的路由判断力超过 80% 同班同学」比「判断力 70%」更有意义。班级是 Skill progression 最自然的参照系。

| 优化 | 描述 |
|------|------|
| 路由判断力里程碑 | 判断力达到 50%/70%/90% 时弹出成就 + 教练点评：「你的编排手感已经超过大多数同学了」 |
| 技能雷达图 | 在档案页展示六维技能雷达（策略/设计/文案/增长/沟通/出镜），每次亲自干后雷达图有可见变化 |
| 赛季技能回顾 | 每学期末生成「本学期能力成长报告」：你的路由判断力从 X%→Y%，最擅长的环节是 _，最需要加强的是 _ |

#### Power Progression：制造非线性突破时刻

| 优化 | 描述 |
|------|------|
| Agent 能力质变点 | 能力分达到 6/8/10 时触发「觉醒」事件——Agent 获得新台词、新动画、可能解锁第二个性格特质 |
| 资产厚度里程碑 | 训练资产达到 10/25/50 时，Agent 名称从「设计 Agent」升级为「资深设计 Agent」「设计总监 Agent」 |
| 基座升级仪式 | 切换基座不只是商店点一下——应有「系统升级中…」的短暂过渡 + 升级后 Agent 的能力分重新计算（可见提升） |

#### Content Progression：给每个解锁加上仪式感

> **← 与 §1.1 班级归属感** 相关：Content 解锁加上社会维度后才有传播力——「全班第 3 个解锁高端设计线」自然会在班级频道引发讨论。班级是 Content 解锁的天然扩音器。

| 优化 | 描述 |
|------|------|
| 解锁通知升级 | 不只是日志一行字。业务线解锁 → 全屏 banner + 「新业务线已解锁」动画 + 教练 Agent 发来祝贺消息 |
| 业务树可视化 | 在办公室或 ERP 中常驻展示成长树（GDD D28），已解锁节点高亮、下一个可解锁节点闪烁提示 |
| 会籍解锁引导 | 达标后不只是让学生自己去生态页点——小 H（0 号 Agent）主动推送：「你已达标 DHS 预备营，要不要我帮你申请？」 |

#### Story Progression：把世界变成活的故事

> **← 与 §1.1 教师在场** 强相关：老师是 Story 维度最经济的叙事载体。命题发布时的引言、周复盘的点评、学期末的总结——这些本应由老师（人或 Agent）来完成。没有教师在场，Story progression 被迫依赖系统通知和随机事件，失去了「人」的温度。详见[§1.1](#11-聚集起点学校--课堂)。

| 优化 | 描述 |
|------|------|
| 赛季叙事 | 每学期有一个主题（「出海季」「AI 季」「品牌季」），命题和事件围绕主题展开。赛季末有总结叙事 |
| 办公室空间叙事 | 升级不只是换文字。用简单的 CSS 动画展示办公环境变化——宿舍书桌（杂乱温馨）→ 共享工位（多了设备）→ 老厂房（开阔、工业风） |
| 孵化器角色化 | 孵化器不只是一个会籍 tag。给它一个名字、一个联系人（「DHS 的老周」）、一段叙事弧——在白银认证时就出现，在黄金认证期间有多次互动，入驻邀请时才完整揭晓 |
| Agent 成长叙事 | Agent 不只是数字在涨。给它一条成长线——从「刚入职什么都不懂」到「能独立完成复杂任务」到「开始教新来的 Agent」。用对话界面承载这条叙事 |

#### 节奏优化：铺出完整的 Progression 曲线

```
第1周 ──── 第4周 ──── 第8周 ──── 第12周 ──── 第16周+
  │          │          │          │           │
  │ 练习单    │ 白银认证  │ 首批真单  │ 黄金认证   │ 入驻邀请
  │ 第一次路由│ 预备营    │ 第一次QA  │ 高端业务线 │ 关掉包装层
  │ 第一次调教│ 教练推荐  │ 第一次S级 │ 孵化器接触 │
  │          │          │          │           │
  └─ 探索期 ─┴─ 成长期 ─┴─ 验证期 ─┴─ 突破期 ──┘
     学基础      练手感      真刀真枪     被看见
```

每个阶段的 progression 重点不同：

| 阶段 | 主要 Progression 类型 | 节奏 |
|------|---------------------|------|
| **探索期**（W1-4） | Skill + Power（学基础、养 Agent） | 高频小胜（每单都是新的） |
| **成长期**（W4-8） | Content（解锁会籍、真单、新订单类型） | 每周至少一个解锁事件 |
| **验证期**（W8-12） | Skill + Story（真单考验判断力、孵化器开始关注） | 间歇性高压（真单 QA）+ 教练复盘缓冲 |
| **突破期**（W12+） | Story + Content（孵化器互动、终局解锁） | 叙事密集、选择权重高 |

### C.6 落到 Demo 的最小可行改动

不需要重做整个 progression 系统。以下是 3 个投入最低、感知最强的改动：

1. **解锁通知从「日志一行」升级为「全屏 banner + 音效 + 教练消息」**。触动的是 Content progression 的感知。
2. **Agent 能力分达到 6/8/10 时触发「觉醒」对话**。Agent 通过消息中心发来一段话，可能附带新的性格特质。触动的是 Power progression 的非线性感。
3. **白银→黄金之间增加 3 个中间徽章**（例如：「设计新秀」= 完成 5 单设计真单且均分 ≥ 70；「效率达人」= 连续 4 周无违约；「社交之星」= 人脉 ≥ 10）。触动的是 Skill progression 的短期目标链，同时覆盖 Explorer 和 Socializer 的动机。
