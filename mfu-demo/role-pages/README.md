# MFU v0.15 角色操作页

这一目录用于单独验证“从一个订单，到一群猎人，再到一些组织”过程中，各个真人角色需要完成的操作。

这些页面是角色操作的独立设计基准。相关机制已经开始接入基于 v0.14 重建的 `MFU-v0.15-可试玩原型.html`；正式 demo 使用自身的游戏状态，本目录仍可从第一个页面顺序试玩，也可以直接打开任意页面检查。

## 页面

| 流程 | 页面 | 操作者 | 主要操作 |
|---|---|---|---|
| 1 订单进入 | `01-issuer.html` | 老师或企业 | 写订单、设置预算与验收标准、发布 |
| 2 拆成步骤 | `02-decomposer.html` | 老师团队、孵化器、协会或平台工作人员 | 编辑步骤、检查依赖、发布拓扑 |
| 3 平台匹配 | `03-matching.html` | 猎人 | 查看匹配结果、确认是否承接 |
| 4 猎人完成 | `04-hunter.html` | 学生或 freelancer | 拆分自己的步骤，安排本人、AI 或外包，执行、检查、提交 |
| 5 汇总初验 | `05-review.html` | 拆单方 | 检查局部成果、退回或汇总 |
| 6 最终评价 | `06-evaluation.html` | 老师或企业 | 验收完整结果、填写真实反馈 |
| 7 联系上下游 | `07-network.html` | 人类猎人 | 查看相邻名片、发出合作邀请 |
| 8 形成组织 | `08-organization.html` | 受邀的人类猎人 | 确认成员、分工、作品归属并创建组织 |
| 后续筛选 | `09-incubator.html` | 孵化器 | 查看证据、追加验证或发出邀请 |

正式产品中的步骤拓扑编辑器需要支持拖动步骤，以及新增、删除和修改步骤之间的连接关系。当前角色页先保留可编辑步骤内容和固定拓扑，用于确认整体操作流程。

## 自动环节

平台匹配、状态记录、成长数据计算和建立组织档案属于系统行为，不单独伪装成真人操作页面。对应结果会出现在真人操作页中。

同一订单的协作者可以看到彼此并进入订单聊天室。猎人还可以把自己承接的步骤继续拆开：每个子步骤可以由本人、自己的 Agent 或另一名猎人完成。外包会形成一轮更小的“拆分—匹配—完成”循环，但原猎人仍对整个步骤负责。

Agent 可以执行工作、整理资料和起草内容，但不能主动发起外包、联系其他猎人、发出合作邀请或创建组织。

## 试玩方式

从 `01-issuer.html` 开始。每完成一步，页面会进入下一角色的操作页。顶部可切换“在校期间”和“真实社会”，右上角可重置全部局部进度。
