完整用户旅程

这页把同事需要理解的路径一次讲完：运营者如何从概览进入活会话，执行 routing-rule-add，经过 Manage-gate，再落到双主体审计。

打开设计确认 Demo
1

概览：先判断活会话是否健康

运营者打开 Agent Console，先看活会话数、在线成员数、被阻止操作和最近审计。这一步回答“当前运行中的团队是否健康”。

read_topology 授权只读 read-side authority 后端 gated
2

进入会话：围绕一个 session 运营

运营者点击 storefront-7f3a，进入会话设置页。这里不是工具列表，而是同一个 session 的多个 facet：健康、拓扑、路由策略、模板来源、审计、高级。

session://acme/storefront/storefront-7f3a 对象优先
3

路由策略：新增一条规则

在“路由策略”段点击“+ 规则”。MVP 唯一启用的活写操作是 routing-rule-add，receiver 必须是当前 session 的 live member role。

routing-rule-add receiver = live member role {:unknown_member_role, role_name}
4

Manage-gate：两阶段，不让 UI 铸 cap

UI 只提交 {session_uri, op, args}。Phase-1 以 operator 为 ctx.caller 做 Manage gate；Phase-2 以 orchestrator 为 ctx.caller，只投影已持有的最小 execution caps。

Phase-1 ctx.caller = operator Phase-2 ctx.caller = orchestrator :manage_unauthorized :session_not_live
5

双主体审计：操作人和执行主体都要留下

成功后，session 的审计段和概览的最近审计 feed 都展示同一条摘要。目标 schema 必须包含 authorized_operator_uri、execution_principal_uri、matched cap provenance 和 request_id。

双主体审计 authorized_operator_uri execution_principal_uri request_id

这条旅程要证明什么

不是 tool-first Routing、members、template provenance、audit 都是某个 session 的配置侧面，不是顶层工具入口。
不是免费只读 健康、拓扑、路由和模板来源都标注为授权只读；真实后端仍受 read-side authority blocker 约束。
不是 UI 授权 UI 不铸 cap，不提交 principal，只提交结构化 op；权限判断留在 Manage-gate / Grant chokepoint 后面。
不是模板编辑器 Templates 在 MVP 只读，Create / Fork / Tag / publish 均禁用。
